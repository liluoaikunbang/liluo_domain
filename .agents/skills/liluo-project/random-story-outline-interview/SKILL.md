# Random Story Outline Interview

Read `docs/系统说明/故事大纲随机提问模板.md` completely. Use the lightweight random path unless the user explicitly requests retrieval, ranking, comparison, or best-match selection. For write-back, also read the outline template and the context required by the authoring Skill.

1. Build ordinary-node candidates with non-empty `missingItems`; exclude categories, main-quest containers and withdrawn nodes unless requested.
2. For requests such as “随机”“随便”“问一个” or no selection criteria, use a local random number to select directly from the real pool. Do not invoke a subagent. Read only the selected source node and its Markdown; do not automatically expand parents, children, siblings, world options, gameplay catalogs, or plot catalogs. Follow an additional reference only when it is directly required to avoid asking something already answered.
3. Apply an optional world filter, random seed, or recently-asked exclusion locally. Report filters and seed when present; an unseeded lightweight draw need not invent a seed.
4. Invoke a read-only context/audit agent only when the user explicitly asks for retrieval or comparison, such as “找最完整的”“找最接近某条件的”“比较后选择”“检索匹配项”, or when the requested result cannot be determined from the candidate fields without cross-file evidence.
5. Distinguish an empty concept from existing narrative that lacks production information.
6. Output in order: 抽中节点、已确认上下文、当前成熟度、关键缺口、4–7 个具体问题、回写时预计涉及的文件.
7. Prefer goals, entry/exit, relationships, states, branches and gameplay. Give each question a rich set of distinct, context-compatible inspiration options whenever possible. Options are not single-choice by default: the user may combine, revise, reject, or replace them, and only the user's explicit direction becomes confirmed. If selected options conflict with each other or with accumulated context, identify the exact conflict and ask the user to resolve it instead of silently merging them. Do not promote asset-production detail into current-stage requirements.
7a. **Must-ask every interview round: 设置紧缚 RAG 标签** (CDR-009). Offer existing `external-knowledge/cards/restraint/` candidates (prefer category titles, plus relevant concepts). User may multi-select, edit, or reject all. On confirmation: look up by title/aliases; write hit IDs to `ragRefs`; if missing, create a restraint stub card (dual-branch skeleton via `$liluo-external-fiction-knowledge` / `restraint-rag:create-stub`) then write the new ID. If the card is stub or lacks verifiable body/sources, append `missingItems` entry `RAG｜紧缚RAG｜补全「{title}」正文与来源`. Never invent IDs; never write restraint labels into `storyTags`; never restore Tag fields.
7a-bis. **New restraint term gate:** When user answers or node prose introduce a restraint term not matched to an existing card/alias, **must prompt and ask** before creating anything. Use this shape:「发现可能的新紧缚概念：“XXX”。可能来源：… 系统未找到已确认同义概念。是否纳入紧缚专业 RAG？」Options: 纳入并开始整理 / 先建立空白卡 / 设为已有概念别名 / 合并到已有概念 / 不是紧缚概念 / 暂不处理 / 永不提示该词. Do not auto-formalize; record `neverPrompt` via `restraint-rag` candidates when chosen. Same term must not re-prompt while pending.
7b. When a round also introduces an event or player rule, offer concrete `plotRefs` or `gameplayRefs` candidates as applicable.
8. After each user answer, first write every newly confirmed answer to the source JSON and Markdown through `$liluo-story-outline-authoring`, preserving unresolved decisions as concrete `missingItems`; never postpone this write-back merely because another question round remains. Then reconstruct the accumulated confirmed context from the updated sources, all prior answers and the current answer. Re-audit it against the node's current maturity and scope, including contradictions between old and new answers. Replace resolved items with concrete next-layer gaps when executable flow, gameplay, states, transitions or first-version boundaries remain, and continue with a focused question round when needed. Context compaction must not be the only place where accepted answers survive.
9. Search `src/game/data/plot_outline/catalog.json` only when the user asks for matching inspiration, best-fit retrieval, comparison, or when the selected node directly references a plot entry that must be understood. Include only real matches as optional inspiration, never confirmed context.
10. After explicit adoption, append the real story key to `usedBy` and set `usageStatus` to `partial` or `used` according to remaining gaps. Keep causally linked setup and payoff in one entry. Before assigning a new plot ID to a fragment, compare it with existing entries: merge it into an existing entry when it extends the same core conflict, causal chain, setup/payoff, or intentionally shared collection of segments, preserving the stable ID and usage state. A shared world, tag, character, or broad theme alone is not enough to merge. If merge versus split is ambiguous or conflicts with confirmed structure, ask the user. Only genuinely independent fragments receive the next stable ID, `isUsed: false`, `usageStatus: unused` and empty `usedBy`.
11. Format plot titles as `主要人物-短情节名`. Omit the default protagonist 璃落; list at most three other main characters and append `等` when more exist. Preserve stable keys in `usedBy`; format each matching `usedByLabels` value as `世界名-主线名-节点名` in Chinese.
12. Record every appearing character, including 璃落, in `characters`. Keep `storyTags` only as the independent world/style taxonomy. Events use `plotRefs`, reusable restraint knowledge uses `ragRefs` (紧缚 RAG), and player rules use `gameplayRefs`; never restore `tags`, `plotTags`, `bondageTags`, or `specialGameplay`. Primary restraint labels shown on the node are derived from `ragRefs` (category title preferred).
13. When a saved story-gap candidate contains unresolved high-value alternatives, convert the real differences into focused questions rather than asking for a vague style. After the answer, update the candidate decision state through the gap workflow before authoring; do not promote unapproved options into confirmed context.

If no candidate survives, report counts and filters. Never invent a node, stable ID or context.
