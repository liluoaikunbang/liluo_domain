# 主线备忘结构

`status: 主线任务` 的节点用于组织主线、保存总体构想并为以后拆写普通剧情节点提供参考。它不是一个可直接制作的模块。

## 来源 JSON

只维护主线容器实际需要的字段：`key`、`world`、`title`、可选的简短 `summary`、`status`、`parentKey` 与 `order`。不要添加 `missingItems`、`scope`、`moduleType`、`storyTags`、`plotTags`、`bondageTags`、`specialGameplay`、`characters`、`locations`、制作引用或流程状态字段。

## Markdown

YAML 使用最小索引：`key`、`world`、`status`、可选 `summary`，并设 `detailLabel: 主线备忘`。不得使用 `isTemplated`。

正文按实际内容选择以下参考章节，不要求凑齐：

- 主线定位
- 已确认方向
- 推荐主线阶段或推荐展开方式
- 能力、人物或主题成长参考
- 前后主线衔接
- 留待正式主线设计时确认

未决内容使用自然语言保存为以后设计时的检查项，不写进 `missingItems`。不得在主线备忘中承诺具体地图、事件、玩法数值、存档字段、资源 ID、最小可玩版本或验收条件；这些内容在相应普通剧情节点中确定。

## 撰写下属普通节点时如何引用

撰写主线下的普通剧情节点前，沿 `parentKey` 向上找到最近的相关主线任务，并阅读其 Markdown 备忘；如果更上层主线备忘仍对当前节点提供世界阶段、人物成长或结局方向，也一并读取。

- “已确认方向”与已经确认的前后衔接属于连续性约束，除非用户明确修改，否则下属节点不得与其冲突。
- “推荐主线阶段”“推荐展开方式”和成长参考属于设计素材，可以按当前节点需要吸收、细化或调整，不能自动当作已经发生的事实。
- “留待正式主线设计时确认”属于问题来源；只有确实影响当前节点时，才向用户询问或转化为该普通节点的 `missingItems`，不得一次性复制全部待定项。
- 主线备忘提供方向而不替代普通节点的证据。普通节点仍需根据自身内容确定成熟度、地图、事件、玩法、状态与制作引用。
- 正文只写当前节点真正采用的内容；不得把整份主线备忘重复粘贴到每个子节点。
