# 持久性与决策分类

## 分类

- `transient`：仅本次使用，不沉淀。
- `persistent`：以后、默认、每次或项目级底线，更新权威规范。
- `user-facing`：可通过自然语言或稳定脚本重复调用，同步用户命令目录。
- `architectural`：改变结构、数据契约、职责或扩展方式，检查 ADR。
- `creative`：影响项目灵魂、创作分工或跨内容表达，检查 CDR。
- `unresolved`：已经影响后续但尚未确认，写入待确认入口。
- `historical`：记录已经发生的实现，进入功能更新而非当前契约。

明确的“以后、默认、必须、固定成规范、做成 Skill/Agent、加入用户命令”是持久候选；“仅本次、临时测试、先试试、不写入规范”是临时要求。没有形成结论的讨论不沉淀。

## 决策状态

ADR/CDR 支持 `proposed`、`accepted`、`superseded`、`deprecated`、`rejected`。只有用户已确认或项目已有充分权威证据且已经实际采用的决策可标记 `accepted`。记录结论、背景、主要替代方案、理由、代价和重新评估条件，不保存逐字聊天。
