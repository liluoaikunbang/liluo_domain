# 任务结束门禁

结束较大任务前判断：

1. 是否新增或改变长期规则？
2. 是否新增、改变或删除用户可重复调用的工作流？
3. 是否改变当前系统行为、目录职责、数据契约或扩展方式？
4. 是否形成已确认的架构、产品或创作决策？
5. 是否影响其他 Skill、Agent、系统说明、用户命令或索引？
6. 是否达到功能更新记录准入条件？

全部为否时不启动治理流程。任一为是时：分析影响，更新唯一权威源和必要消费者，执行必要的文档同步。

先把所有 Skill、文档同步和内容流程提出的检查合并成一份候选清单，按覆盖关系去重。默认只运行一项直接覆盖本次变化的目标验证；只有一项无法覆盖另一处实质变化，且第二项会改变完成结论时，才增加至多一项相关综合 profile。未修改的领域不验证；纯正文修改不自动追加 frontmatter、全内容或治理审计；局部治理规则修改不自动运行历史功能文档全量审计；相关文件未再次变化时不重跑。外部来源原创性门禁和索引末尾增量刷新只在实际触发时保留，不作为追加其他检查的理由。

最终汇报只需简短说明长期规范、用户命令、设计决策和有效验证，不罗列无关内部步骤。

如果本次实际发生了可避免的失败、重复读取、重复检查或无效重试，再做一次轻量绕圈复盘。仅当原因确认、可重复、可跨本次复用且权威归属明确时，补充既有规范和必要消费者；偶发故障、单次手误、原因不明或会扩大权限边界的候选不自动沉淀。复盘只做一轮，不递归复盘，也不另起一套验证。
