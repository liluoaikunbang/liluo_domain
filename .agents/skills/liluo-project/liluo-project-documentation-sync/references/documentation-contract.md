# 文档同步契约

功能文档位于 `docs/功能更新/<编号>-<标题>.md`，保留固定创建时间和不可覆盖的更新时间记录。目录是 `docs/功能更新目录.md`，界面记录是 `src/game/data/global/updateRecords.js`。三处共享编号、标题、创建日期和当前摘要。

编号默认为三位数字（如 `164`）。历史上确有双文档共号时，使用 `017-a` / `017-b` 这类单字母后缀，并令文件名、目录行与 `updateRecords.js` 的 `id` 三者一致；审计识别 `^\d{3}(?:-[a-z])?$`。

项目专属或用户可直接调用的技能说明位于 `docs/技能说明/<skill-name>.md`，记录用途、触发边界、路径、资源、输入输出、流程、限制、验证及相邻 Skill 边界。通用执行纪律 Skill 的内部措辞和触发范围调整不强制新建技能说明。Skill 目录不创建 README 或更新日志。

本 Skill **不会**作为 Hook 自动运行。实质变更后由主智能体主动加载；可用 `npm run docs:governance:audit` 核对三方编号。

## 功能记录准入

- 普通单个故事大纲完善、随机访谈写回、错字修正和元数据调整不创建功能更新编号，只同步权威内容与项目索引。
- Skill 的措辞、示例、内部元数据或不改变用户入口的触发收窄不进入功能记录。
- 可玩地图、事件、对话或玩法实现，代码或系统行为变化，项目工作流或 schema，重要素材批次，以及整条主线或多节点批量重构可以进入功能更新记录。
- 延续同一既有功能的维护优先追加原文档更新时间，不重复创建编号。

## 用户命令同步

新增或重命名用户可调用的项目 Skill / 工作流时，必须同步 `docs/用户命令目录.md`，并使 Skill 名称以反引号形式出现在目录中。完成前运行 `npm run docs:commands:validate`；该校验也会并入 `docs:governance:audit`。质量门禁在检测到 `.agents/skills/liluo-project/**/SKILL.md` 变更时同样会选中该命令，不再只依赖“目录文件本身被改动”。
