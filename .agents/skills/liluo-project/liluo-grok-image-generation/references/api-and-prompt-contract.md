# Grok 图像提示词契约

## 目标

把用户的视觉意图收束成一条可直接发送给 Grok 图像接口的生产提示词，同时避免空泛、跑题和事实漂移。

## 先抽锚点

先确认这些信息里哪些是已知、哪些只能轻推断：

1. 主体是谁
2. 主体在做什么
3. 场景在哪里
4. 画面情绪是什么
5. 取景和镜头关系是什么
6. 哪些元素必须避免

缺少信息时，优先补足“观感会明显跑偏”的项，不为了一次生图把需求问成表单。

## 提示词结构

按这个顺序组织，通常一段即可：

1. Subject: 谁，外观核心，当前动作
2. Scene: 地点、时间、天气、关键道具
3. Composition: 景别、机位、朝向、画面重心
4. Light and color: 主光、色温、反射、氛围色
5. Texture and finish: 材质、细节密度、画面质感
6. Output intent: poster / key art / portrait / concept art / mock cover
7. Avoid: 把最重要的排除项压成短尾句

## 写法要求

- 用可见结果说话，不堆 “amazing / masterpiece / best quality” 这类空词。
- 一个短语只承担一个作用，别把服装、姿态、镜头和情绪揉成一坨。
- 优先写“看得到的东西”，少写对创作模型没有约束力的抽象评价。
- 排除项控制在少量高价值约束，避免长串负面列表把主体压扁。
- 用户给了明确名词时保留；项目内专有名词必要时可以保留中文或拼音一次，再接英文描述。

## 变体策略

如果用户要多张图：

- 固定主体、世界观和主情绪。
- 每次只改一个维度，比如镜头、服装状态、天气、色调或动作瞬间。
- 不要把每张图都改成新概念。

## 输出给用户时的最小格式

可以按下面这个简洁格式回传：

```text
最终提示词：
<prompt>

生成命令：
npm run grok:image:generate -- --live --prompt "<prompt>" --aspect-ratio 16:9 --slug <slug>
```

如果还没到 live，命令里的 `--live` 改成 `--dry-run`。
