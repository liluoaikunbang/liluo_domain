# 故事增量 RAG 候选提议

用于故事节点、情节、地图事件、对话、玩法说明和局部设定补丁等一切将写入项目内容的任务。它是写入前的统一步骤，不替代故事、地图或对话 Skill。

1. 只读取本次准备写入的增量及其必要上下文；全面列出概念、状态变化、行动/空间限制、关系动态和表达问题。
2. 为每项判断：可复用 RAG、已有卡命中、情节、玩法、仅当前故事或暂缓。不得把普通动作、一次性发生或专属剧情事实硬塞进 RAG。
3. RAG 候选须同时具有跨故事复用价值、清晰边界和未来检索价值。领域只能是 `restraint-professional`、`general-craft` 或 `canon`；外部来源不能支撑 `canon`。
4. 所有 RAG 卡固定拥有 `knowledge` 与 `expression` 两支；可均为 `stub`，但不得省略。候选必须说明两支各缺什么，不得用模型常识补写正文。
5. 默认向用户突出 0–3 个高价值候选，但完整拆分清单可以展开。每项给出：名称、领域、故事依据、适用/排除边界、近似卡、建议父卡、未来来源问题和骨架缺口。
6. 用户确认前，只可运行 `npm run rag:propose -- --input <proposal.json>` 写入 `pending` 提案；不得创建卡、写 `ragRefs`、确认事实或扫描外部文章。
7. 用户确认后，再由相应内容 Skill 引用已有卡或建立双分支骨架；来源需求写入待办，等待用户显式要求扫描。

用户可说“补扫全部故事 RAG”“补扫这个主线 RAG”触发历史扫描：

```powershell
npm run rag:rescan-stories -- --scope "<世界、主线或节点>"
```

该命令只列出范围和待处理节点；仍须按本 Skill 生成候选、逐批请求用户裁决。
