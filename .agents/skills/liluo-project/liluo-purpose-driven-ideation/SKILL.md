# 璃落项目效用导向构思

这是四个已私有化上游方法的薄编排层，不直接写入 canon、故事正文、地图或代码。来源与排除项见 `skill-lineage.json`。现有事实、世界观、故事审批和正式写入仍分别由故事缺口、故事撰写、连续性、内容验证等工作流负责。

## 先分级，再定义内容工作

- **Micro**：一句台词、0—3 个选项、一个道具反馈/互动/CG/音效或小范围事件变化。定义功能 → 少量候选 → 硬测试 → 保留 0—3 → 最终表达清理。
- **Standard**：一个节点、一组事件、小游戏、探索流程、角色互动或既有模块明显补充。定义目标 → 找真实缺口 → 候选 → 假设 → 比较 → 保留 0—5 → 表达清理。
- **Large**：新世界、系列、核心循环、跨模块架构或显著世界观影响。可用完整机会树和阶段比较，但实施前必须由用户确认范围。

开始前只从必要项目上下文推断：本次具体要完成什么、真实缺口、玩家应感受/做到什么、完成后哪项信息/状态/关系/资源/路线会改变、允许改变与必须保持的部分，以及是否允许新增人物/地点/规则/地图/系统。只有答案会改变候选正确性时才询问。若不能确认缺口，直接说明“目前没有足够依据证明这里需要新增内容”。

## 编排和候选边界

1. Large 才用 `opportunity-solution-tree`：玩家体验或剧情变化 → 有证据的内容缺口 → 候选。
2. 用 `brainstorm-ideas-existing` 从已有元素生成候选；每项只改变行动、信息、风险、资源、参与人物、时间、路线、反馈或机制中的一个主要变量。
3. 用 `identify-assumptions-existing` 检查价值、可理解性、世界契合和制作可行性。
4. 用 `prioritize-features` 以目标契合、实际差异、因果、复用、非重复、成本、风险、世界观负担与扩展价值排序；新颖度不是独立理由。

Micro 默认不新增组织、世界规则、力量体系、核心人物、大地图或 canon。Standard 默认至多一个局部地点、一次性配角、局部规则或轻量机制，且必须必要。Large 由用户确认。禁止用多个陌生专名、抽象名词、反转或未建立规则拼接出“新颖”。

## 六项硬测试与淘汰

每个候选都必须通过：

1. **删除**：删去后玩家经历、信息、状态、资源、关系、路线、节奏或表现要有实际差别。
2. **替换**：替换人名、地名、专名后仍可塞进任意故事的候选，要具体化或淘汰。
3. **差异**：多个方案必须在行动、风险、资源、信息、关系、路线、状态、反馈或机制上不同；语气不同不算。
4. **因果**：必须能写成“选择 → 璃落具体行动 → 可观察反馈 → 信息/状态/关系/资源/路线变化”。
5. **成本**：地图、CG、角色、代码、音频、规则与维护成本须与价值相称。
6. **依据**：必须指出来自当前节点、世界观、人物目标、地图、玩法、状态、素材或用户明确要求的依据。

没有行动、反馈或变化；只差措辞；依赖未建立核心设定；为普通细节扩大世界观；不能解释当前位置；低价值高成本；陌生元素并列；需抽象升华才成立——任一命中即不推荐。允许保留零项或明确“不建议新增”。

## 选项与输出

每个内部选项都需具有“选择文本、璃落实际行动、即时反馈、获得或失去、后续影响”。不得制造“勇敢/谨慎/冷静”而后果相同的伪分支。

Micro 只输出“当前功能、建议、必要的淘汰说明”；Standard 输出目标、缺口、候选、依据、行动与后果、假设与风险、成本、推荐和淘汰项；Large 可输出机会树与阶段方向。不要展示内部草稿或推理链。

候选通过效用与假设筛选后，才按 `liluo-natural-expression` light（或已安装 stop-slop 的等价最终表达检查）清理空泛升华、AI 套路和伪深刻；表达清理不得删除必要事实，也不能替代价值判断。
