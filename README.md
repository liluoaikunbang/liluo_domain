## 为什么要做这个项目

有些世界并不缺灵感，缺的是一种能陪它活很多年的方法。
《璃落的城堡》想做的，不是一套把故事塞进功能页的壳，也不是一次性写完的短篇仓库，而是一套会持续生长的叙事游戏生产体系。这里的角色、关系、状态、地图、玩法和长期设定，都要慢慢长成一个真的能被进入的世界。

AI 在这里不是代替作者的捷径，更像一套长期陪跑的方法：它帮助我们整理世界、发现缺口、连接故事和玩法、沉淀资产与规则，让同一个宇宙可以在很长时间里继续扩展，而不是每次都从头再搭一遍。

## 同一个故事，可以长成多种正式形态

![同一个故事，多种形态](docs/assets/readme/one-story-many-forms.png)

同一个故事不必一开始就长成最终版本。它可以先是互动小说，用来验证节奏、冲突和分支；然后变成带立绘和场景的视觉叙事；再进入像素地图、事件、NPC 和状态流转；最后长成真正可游玩的完整章节。
这样做不是把内容拆碎，而是让它在不同阶段都能被认真制作、认真验证、认真保留下来。

## AI 如何让这个宇宙继续生长

![故事世界生长图](docs/assets/readme/storyworld-growth.png)

AI 在这里承担的，是“让复杂世界能够长期维护和继续生产”的工作，而不是抢走世界本身。

- 它帮助管理多世界故事、角色关系与长期状态。
- 它帮助发现剧情和玩法的真实缺口，而不是无边无际地堆点子。
- 它帮助把同一个故事拆成多种正式输出路径，同时保留来源与约束。
- 它帮助把文档、Schema、索引、素材和工作流收束成可复用的方法。

## 当前已经长出来了什么

- 可运行的 `Vue 3 + Vite + Phaser + Pinia` 像素 RPG 基底。
- 地图、事件、对话、状态流转与存档的持续化基础设施。
- 六大世界的大纲、情节库、玩法目录与长期治理文档。
- 可落成互动小说、视觉叙事与地图章节的多形态生产路线。
- 供长期协作使用的技能、工作流、索引、规则和审计体系。

## 这个世界以后还能和谁一起做

它以后不只需要程序，也需要会讲故事、会搭玩法、会做像素、会做界面、会配乐、会整理知识和会把流程跑顺的人。
不同方向的工作不是各自往仓库里堆素材，而是进入同一套故事与玩法体系，继续增强已经存在的宇宙。

- 世界观与叙事设计
- 地图、任务、事件与玩法设计
- 像素角色、场景、CG 与 UI 视觉
- 音乐、音效与氛围设计
- Vue / Phaser / 工具链开发
- AI / RAG / 自动化与工作流建设
- 测试、本地化、文档与资料治理

## 内容说明与边界

- 正式登场角色均为成年人。
- 项目可能包含冒险、悬疑、灵异、末日、战斗与拘束主题等成熟题材。
- 不同世界线和不同输出形态可以有不同强度与分级。
- 正式 canon、长期规则和世界事实仍以人工确认后的权威内容为准。
