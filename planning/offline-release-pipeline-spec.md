# Spec：离线发行包与 GitHub Release 上传

状态：启动器方案已确认，实施中

## 目标

为当前 Vue 3 + Vite + Phaser 项目新增稳定的离线发行流程。发行包解压后，用户无需安装 Node.js，双击根目录 `启动游戏.bat` 即可由内置 PowerShell 脚本在 `127.0.0.1` 启动临时静态服务并打开浏览器；维护者可用一条命令构建、校验、压缩，并将 ZIP 上传到指定 GitHub Release。

## 已确认现状

- 项目已有 `npm run build:offline` 和 `vite-plugin-singlefile`。
- 2026-07-22 实测现有离线构建在转换 1752 个模块后失败，错误为 `Invalid string length`。
- 原因是大量图片、音频、字体和脚本被强制内联到单个 HTML；项目体积已不适合单 HTML 方案。

## 假设

1. “直接打开”指先完整解压 ZIP，再双击根目录 `启动游戏.bat`；不要求直接在压缩软件预览中运行。
2. ZIP 可以包含 `index.html`、JS、CSS、图片、音频、字体等目录；不再要求所有内容内联为一个 HTML。
3. 目标为 Windows 10/11 上当前版本的 Chrome、Edge 等现代 Chromium 浏览器。
4. Release 标签由调用者显式提供，例如 `v0.1.0`；脚本不会自行猜测版本号。
5. 上传命令在 Release 不存在时创建 Release，存在时向该 Release 上传并覆盖同名 ZIP；不自动提交、推送源码或创建 Git 标签。
6. GitHub 上传使用本机已有的 GitHub CLI（`gh`）认证；未安装、未登录或无权限时明确失败，构建好的 ZIP 仍保留在本地。

## 命令

- `npm run build:offline`：生成离线 Web 构建目录；其产物由打包流程补入启动器后交付。
- `npm run package:offline`：构建、校验入口与引用，并生成带项目版本/标签信息的 ZIP。
- `npm run release:offline -- --tag v0.1.0`：构建、校验、压缩并上传 ZIP 到对应 GitHub Release。

具体参数名可在实现时保持上述语义并补充 `--title`、`--notes` 等可选项，但不得静默发布到错误标签。

## 结构

- `dist-offline/`：离线构建目录，打包前必须补入根目录 `启动游戏.bat` 与 `launcher/start-game.ps1`。
- `release/`：本地 ZIP 输出目录，不纳入 Git。
- `scripts/release/`：构建校验、压缩与 Release 上传脚本。
- `scripts/tests/`：参数解析、归档清单、失败保护等自动化测试。
- `docs/系统说明/`：当前发行流程权威说明。

## 实现约束

- 保持 Vue 3 + Vite + Phaser，不引入新的应用框架。
- 图片等大素材保持独立文件；浏览器必须通过启动器提供的本机 HTTP 地址访问，不再承诺 `file://` 运行。
- 启动器只监听 `127.0.0.1` 的动态空闲端口，拒绝越出发行根目录的请求，不依赖 Node.js、Python 或公网服务。
- 所有引用使用相对路径，禁止依赖 `/domain/`、开发服务器或公网 CDN。
- 构建失败、入口缺失、残留绝对部署路径、残留模块入口或压缩失败时禁止上传。
- Release 上传属于显式命令行为；普通构建和打包绝不访问 GitHub。
- 不把源码、存档、密钥、`node_modules`、原始设计文件或无引用素材误装入发行包；只归档构建产物。

## 测试策略

- Node 测试：命令参数、ZIP 命名、产物校验、上传前置条件与失败保护。
- 构建验证：离线构建成功，入口存在，引用目标均存在，无远程运行依赖和模块入口。
- 启动器集成测试：以不打开浏览器的测试参数启动，验证首页、静态资源、MIME、路径越界拒绝和进程关闭。
- 浏览器回归：双击 `启动游戏.bat` 后通过 `http://127.0.0.1:<动态端口>/` 验证首页、进入游戏、地图和至少一项资源加载；控制台无阻断错误。
- 发布脚本 dry-run：完整执行到上传前并输出将上传的标签、文件和大小。
- 不在开发实现阶段创建真实 Release；真实上传只在用户日后显式运行发布命令时发生。

## 成功标准

1. `npm run package:offline` 一次完成构建、校验和 ZIP 生成。
2. ZIP 解压后双击 `启动游戏.bat` 可进入游戏，核心资源正常加载；关闭启动窗口后本机服务停止。
3. ZIP 中可以包含任意必要的构建资源，根目录保留 `index.html`，但用户入口明确为 `启动游戏.bat`。
4. `npm run release:offline -- --tag <tag>` 能上传到正确 Release，并对认证、标签和网络错误给出明确提示。
5. 文档、用户命令目录、功能更新记录和项目索引同步完成。

## 边界

- 始终执行：构建后校验、ZIP 后校验、上传前确认目标标签、保留本地 ZIP。
- 需要用户显式执行：真实 GitHub Release 创建或上传。
- 永不执行：自动提交/推送源码、猜测发布标签、把失败产物上传、覆盖其他名称的 Release 资产。

## 确认结果

- 用户确认采用多文件离线包，避免单 HTML 持续增大和加载变卡。
- 2026-07-22 用户确认把“直接双击 `index.html`”调整为“直接双击 `启动游戏.bat`”，以规避 Chromium 对 `file://` WebGL 纹理和 Canvas 像素读取的跨源限制。
