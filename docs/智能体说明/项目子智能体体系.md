# 项目子智能体体系

## 体系目标与分层

本体系只辅助项目开发，不进入游戏运行时、不生成在线 NPC，也不依赖额外 API、SDK 或服务。主智能体负责调度、判断和统一写入；Skills 描述工作流；专业 Agent 承担调查、审查或验证；脚本、schema 和测试提供确定性事实；`AGENTS.md` 保存持久规则。

分层为：项目知识层、工作流 Skill 层、确定性工具层、专业 Agent 角色层、Codex 适配层。`.codex/` 仅保存当前工具的名称、发现描述、权限和角色映射。

## 主从协作与统一合同

委派输入仅包含 Task、Scope、Known context、Questions、Constraints、Expected output。子 Agent 独立调查，默认不互相通信、不递归创建 Agent、不直接宣布任务完成；主智能体等待报告后统一决策和写入，再按需委派验证。禁止多个 Agent 并行修改同一批文件。

所有输出使用短摘要：Task scope、Confirmed facts、Evidence paths、Inferences、Unresolved items、Risks、Recommended parent action。路径使用仓库相对路径，重要结论附 key、符号或命令；不复述大段原文、不返回完整索引或工具日志、不把推断写成事实。主智能体只把该摘要带回主会话。

## 上下文预算与最小任务包

项目通用规则只由 `AGENTS.md` 承担；角色细节只在对应 `docs/智能体说明/` 与任务命中的 Skill 中维护。Agent TOML 只保留角色、权限、最小读取顺序和报告契约，不复制根规则、人格正文、长验证清单或完整专业流程。

先判断是否真的需要委派：小而明确的任务不委派；中等独立调查通常一个 Agent；跨域且互不依赖时最多三个。需要定位时先查询最小索引域并核验原文，禁止默认全仓扫描。除非用户明确要求项目组讨论，不读取灵魂卡或生成多人对话。

重型 Skill、宽索引或长检查输出完成后，主智能体应保留可验证的短交接摘要；后续任务只在证据不足、来源变化或用户扩大范围时重新读取。会话承载的是当前任务，不是长期知识库；长期事实必须落在权威项目来源。

## 可迁移性

角色合同与供应商无关。`docs/智能体说明/`、Skills、脚本、schema、测试和项目文档可直接复用；迁移时主要转换 `.codex/` 配置，把角色说明映射为系统提示、触发条件和工具权限。关键事实必须保存在项目文档或结构化数据中，不依赖 Agent 私有记忆。
