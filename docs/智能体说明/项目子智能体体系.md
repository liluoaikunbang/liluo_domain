# 项目子智能体体系

## 体系目标与分层

本体系只辅助项目开发，不进入游戏运行时、不生成在线 NPC，也不依赖额外 API、SDK 或服务。主智能体负责调度、判断和统一写入；Skills 描述工作流；专业 Agent 承担调查、审查或验证；脚本、schema 和测试提供确定性事实；`AGENTS.md` 保存持久规则。

分层为：项目知识层、工作流 Skill 层、确定性工具层、专业 Agent 角色层、Codex 适配层。`.codex/` 仅保存当前工具的名称、发现描述、权限和角色映射。

## 主从协作与统一合同

委派输入尽量包含 Task、Scope、Known context、Questions、Constraints、Expected output。子 Agent 独立调查，默认不互相通信、不递归创建 Agent、不直接宣布任务完成；主智能体等待报告后统一决策和写入，再按需委派验证。禁止多个 Agent 并行修改同一批文件。

所有输出至少包含 Task scope、Confirmed facts、Evidence paths、Inferences、Unresolved items、Risks、Likely affected files、Recommended parent action、Handoff summary。路径使用仓库相对路径，重要结论附 key、符号或命令，不复述大段原文，不把推断写成事实。

## 成本与权限

小任务不委派；中等任务通常一个 Agent；跨域任务通常两个至三个；只有全项目审查才考虑更多并行。

| Agent | 权限 |
| --- | --- |
| `liluo_context_explorer` | read-only |
| `liluo_continuity_reviewer` | read-only |
| `liluo_game_architecture_explorer` | read-only |
| `liluo_content_auditor` | read-only |
| `liluo_validation_runner` | workspace-write，仅允许验证命令所需临时、缓存、报告和构建输出 |
| 主智能体 | 按用户授予权限统一写入 |

## 可迁移性

角色合同与供应商无关。`docs/智能体说明/`、Skills、脚本、schema、测试和项目文档可直接复用；迁移时主要转换 `.codex/` 配置，把角色说明映射为系统提示、触发条件和工具权限。关键事实必须保存在项目文档或结构化数据中，不依赖 Agent 私有记忆。
