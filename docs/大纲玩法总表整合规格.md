# 大纲故事与玩法整合说明

## 功能目标

原“故事”菜单升级为“大纲”，包含“故事”和“玩法”两个子栏目。玩法目录与故事树保持独立，故事节点通过稳定玩法 ID 建立关联，避免在画布中平铺大量标签。

## 实现结果

- “故事”保留原画布、表格、元信息汇总和 JSON 导出能力。
- “玩法”采用大类、玩法列表、详情三栏结构，共 16 个大类、112 个可关联玩法。
- 故事节点只显示“关联玩法”入口；打开弹层后再搜索、勾选具体玩法。
- 故事导出时保留节点的 `gameplayRefs: string[]`。
- 玩法支持按名称、说明、细分玩法、设计参考的中文名、英文名和类型词搜索。
- 搜索命中内容会在列表标题和详情正文中高亮。
- 切换玩法条目后只将右侧详情滚动区复位到顶部，分类和列表滚动位置不变。
- 玩法详情展示地图适配方式、设计参考、概要和细分玩法。
- 所有滚动区域复用项目的 `GameScrollArea` 像素风滚动条。
- 故事画布节点将操作按钮放在独立首行，标题从下一行开始；分类、区域组、主线等状态标签固定在左下角。
- 纯分类节点不提供“关联玩法”，只有实际故事节点可以选择玩法。
- 节点高度根据按钮、标题、摘要、玩法标签和状态标签动态计算；相邻布局轨道保持固定 24px 间隙。

## 数据设计

数据位于 `src/game/data/gameplay_outline/`：

- `catalog.json`：16 个顶层大类、112 个玩法及细分变体，当前模式版本为 4。
- `modules.json`：内部底层模块资料，不在玩法栏目展示。
- `presentation-patterns.json`：4 种 CG 与像素地图结合方式，仅作为内部表现设计参考。
- `gameplayOutline.js`：目录入口，以及索引、搜索、关联解析和不可变更新逻辑。

顶层大类仅用于稳定导航：置顶的紧缚状态行动、地图探索、即时战斗、随机远征、生存挑战、战场攻防、战术行动、机关调查、异常时序、角色构筑、世界建设、专项活动、叙事模拟、探索收藏、后台发展、重复挑战。

具体机制保留为玩法条目，更细差异保留为 `variants`。具有标志性类型原型的玩法使用 `designReferences` 记录具体游戏名和必要的类型词；垂钓等通用玩法不强行添加参考。新增的“命运人生推演”归入“叙事模拟”，参考《人生重开模拟器》《BitLife》和《中国式家长》。“职业小镇经营”归入“世界建设”，结合《星露谷物语》的亲自探索、居民关系与节日，以及开罗游戏式的设施升级、职业居民与轻量经营结构。

## 开发中遇到的问题

### 原始条目层级混乱

原素材同时混有玩法、表现模式、底层模块和混合模板，且存在把相近机制强行拆开、把不同机制用并列标题拼接的问题。

解决方式：表现模式与底层模块单独存放；混合模板不导入；按核心循环进行语义合并，同时将塔防与反向塔防、固定基地与区域重建及移动据点等不同机制重新拆开。标题统一使用共同机制名，来源类型移入设计参考。

### 顶层分类过细

早期整理形成 35 个大类，部分大类只有一个玩法，导航密度不协调。

解决方式：将顶层分类收敛为 15 个导航大类，每类 2 至 13 个玩法；玩法 ID 不变，因此已有故事关联不会失效。

### 搜索命中但不易定位原因

最初搜索未覆盖设计参考，随后虽然可以通过游戏名找到玩法，但正文中无法快速看出命中位置。

解决方式：将 `designReferences` 纳入搜索索引，并使用安全的文本分段渲染高亮匹配内容，不使用 `v-html`，避免数据被解析为 HTML。

### 切换长正文后停留在旧位置

玩法详情共用同一个滚动容器，选择新条目时会保留上一条的阅读位置。

解决方式：监听活动玩法 ID，在 DOM 更新后仅调用详情滚动区的 `scrollToTop()`；不引用或重置分类、列表滚动区。

### 故事节点按钮遮挡与动态高度重叠

操作按钮最初使用右上角绝对定位，容易遮挡较长标题；改为统一最大节点高度后又造成短节点浪费空间，而旧布局步长无法容纳高节点，最终导致上下节点重叠。

解决方式：将“导出 JSON、元信息、详情、关联玩法”收进节点内部独立首行；状态标签使用独立左下区域。布局阶段按节点实际内容估算高度，同一轨道取最大高度，下一轨道从上一轨道底边加固定 24px 间隙开始，并用实际高度重新计算连线端点。纯分类节点不显示“关联玩法”。

## 数据边界

- 原 Word 第一至第三十五部分提取的 117 项，经语义审查、合并、拆分和后续新增后形成当前 112 个玩法。
- 第三十六部分的 4 种 CG 结合方式不作为可关联玩法。
- 第三十七部分的底层模块只作为内部开发资料。
- 第三十八部分的混合玩法模板不导入项目数据。
- 不自动猜测故事节点应关联哪些玩法。
- 关联编辑存在当前运行会话中，导出 JSON 时写入导出内容，不声称直接改写故事源码。
- 原始 Word 已移入 Windows 回收站，可在需要时恢复。

## 后续维护约定

- 新玩法优先判断是否属于已有大类，不为单个玩法新增顶层分类。
- 只有核心循环基本一致时才合并；题材相似或标题相似不能作为合并依据。
- 合并后的标题必须是共同机制名，不使用“甲与乙”“甲、乙和丙”式拼接标题。
- 具体游戏只作为设计参考，不直接写入玩法标题。
- 调整玩法 ID 前必须检查故事节点的 `gameplayRefs`，避免产生悬空关联。
- 农场经营中的昆虫旅馆、蚯蚓塔、堆肥箱与覆盖物属于可制作生态设施：以田边放置、残料投入和堆肥回填形成短循环，分别改善授粉与虫害、土壤肥力、保水与养分，从而提高相邻田块的稳定产量。
- 跨章节复用的紧缚行动规则归入置顶的 `紧缚状态行动` 大玩法；其下直接包含常规紧缚行动、紧缚战斗、紧缚逃跑与紧缚挣扎四个小玩法。故事节点可关联其中适用的小玩法，并记录本章具体状态与解锁流程，不用单一能力标签替代动作规则。
