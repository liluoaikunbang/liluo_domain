# 图鉴 CG 真实资源与简介遮罩

## 实现思路

本次把旅途菜单图鉴里的 CG 栏从固定占位图改为读取 `src/assets/game/cg` 下的真实图片资源。

资源接入规则：

- 普通图片生成一条 CG 图鉴条目。
- 文件名以 `-body` 结尾的图片不会生成独立条目，而是作为同名 CG 的纯人物版本。
- 例如 `镜头营业-舞蹈教室-人体五角星.png` 是默认 CG，`镜头营业-舞蹈教室-人体五角星（body）.png` 是它的纯人物版本。
- 没有 `-body` 版本的 CG 只显示普通预览和大图，不显示人物版切换按钮。

大图预览层新增底部半透明简介遮罩。打开 CG 时默认展开简介，显示编号、标题与简介文本；点击“收起”后只保留右下角“展开”按钮，不再显示标题或编号。CG 编号标签固定在大图左上角。纯人物版本切换按钮固定在左下角，简介展开时会随遮罩上移，避免遮挡简介内容。

## 遇到的问题

1. `-body` 文件不能作为独立 CG 条目展示。

   如果直接把文件夹下所有图片都铺到图鉴中，纯人物版本会变成另一张 CG，玩家会看到重复条目。

2. CG 大图预览中的交互元素容易互相遮挡。

   最初 CG 编号在右下角，简介收起后的“展开”按钮也在底部，容易重叠。

3. 纯人物版本按钮需要兼顾简介展开和收起两种状态。

   简介展开时按钮如果仍贴左下角，会盖在简介遮罩上；简介收起时如果保留上移位置，又会显得离角落太远。

4. 文档与中文内容需要保持 UTF-8。

   本次涉及中文文件名、中文简介和素材清单，必须避免被终端编码显示误导。

## 解决方法

1. 数据层按基础文件名聚合同一组 CG。

   `getRegularCgName` 会把 `-body` 后缀去掉，同名普通图和纯人物图写入同一个条目。只有存在普通图的条目才会进入 CG 列表。

2. 大图编号移动到左上角。

   这样编号不再和底部简介、展开按钮、纯人物切换按钮抢位置。

3. 纯人物按钮按简介状态调整位置。

   默认贴左下角；简介展开时通过相邻选择器上移到遮罩上方，保持按钮始终可见且不挡文字。

4. 简介遮罩收起后只保留展开按钮。

   收起态不再渲染编号、标题和简介内容，遮罩背景也变为透明，只留下右下角的展开按钮。

5. 使用构建和编码检查确认结果。

   已执行：

   ```bash
   npm run build:web
   npm run docs:check-encoding
   ```

   构建通过。构建过程中仍会出现既有的 partial 旧路径与 `student1.png` 路径 warning，不是本次 CG 图鉴改动引入的问题。
