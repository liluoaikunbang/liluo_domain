# 053-存档菜单条目化与布局收口

## 实现思路

本次是在 `052-本机存读档与首页继续旅程入口` 的基础上，继续完善游戏内旅途菜单的存档栏目。

核心目标是让“存档”更像 RPG 里的存档列表，而不是只有一个默认保存按钮：

- 存档栏目中直接列出已有存档。
- 每条存档展示人物行走图正面站立帧、人物状态、所在地图和保存时间。
- 点击已有存档的“覆盖这个存档”会覆盖该槽位。
- 不选择已有存档时，点击“新增一个存档条目”会生成新的存档槽位。
- 新增、覆盖和失败时都给出提示。
- 存档栏目上方当前进度区域收口为紧凑状态条，避免占用太多列表空间。
- 存档列表区域改为内部滚动，底部“导出全部存档 JSON”按钮保持在菜单框内。

这次没有修改各地图 `map.json` 数据，也没有新增素材文件。

## 相关代码路径

- `src/game/core/saveStorage.ts`
  - `GameSaveFileSummary` 增加存档条目展示需要的摘要字段：人物状态、拘束状态、位置、人物预览帧。
  - 增加 `createNewGameSaveSlotId()`，保存时如果没有传入槽位，则生成 `save-001`、`save-002` 这类新槽位。
  - `saveGameToFile()` 默认改为新增存档槽位；传入 `slotId` 时继续覆盖指定存档。
- `src/game/data/playerCharacter.ts`
  - 为每种主角外观补充 `savePreview` 配置。
  - 记录存档列表中用于显示正面站立姿势的帧编号与列数。
- `src/game/views/GameView.vue`
  - `handleSaveGame(slotId)` 支持可选槽位。
  - 不传槽位时新增存档，传入槽位时覆盖对应存档。
  - 新增 `saveMenuFeedbackText`，在菜单内显示保存结果。
  - 保存成功或失败仍同步推送普通游戏通知。
- `src/game/views/components/base/GameMenuOverlay.vue`
  - 存档栏目改为已有存档条目列表。
  - 条目展示人物正面站立行走图、中文地图名、人物状态和保存时间。
  - 空人物状态使用 `defaultPlayerStatusLabel`，即“自由”。
  - 移除存档条目里的坐标行，减少信息噪音。
  - 当前进度区域改为紧凑状态条。
  - 修正人物行走图预览背景为透明，去除边框。
  - 修正存档列表和底部导出按钮的 flex 溢出问题。
- `src/game/views/components/base/GameNotificationBar.vue`
  - 提高通知层级，使菜单打开时新增/覆盖存档通知不会被菜单遮住。
- `scripts/tests/save-storage.test.mjs`
  - 补充默认保存生成新槽位的测试。
  - 补充存档摘要里人物预览帧信息的断言。

## 开发过程中遇到的问题

### 1. 原保存行为默认覆盖 `default`，不符合“新增条目”语义

旧逻辑中 `saveGameToFile(saveData)` 不传槽位时会保存到 `default`，这会让菜单里的“保存”更像覆盖默认档，而不是新增存档。

解决方法：

- 在 `saveStorage.ts` 增加自动槽位生成逻辑。
- 默认保存生成 `save-001`、`save-002` 等新槽位。
- 覆盖存档时由菜单显式传入 `save.slotId`。

### 2. 存档条目需要显示人物正面站立帧

存档里只有人物运行时外观 id，没有现成的 UI 预览图字段。

解决方法：

- 在 `playerCharacter.ts` 的角色外观配置中增加 `savePreview`。
- 根据外观对应 spritesheet、帧尺寸、正面 idle 帧和列数生成预览信息。
- 菜单侧使用 CSS `background-position` 截取该帧。

### 3. 人物行走图预览初版有背景框，不够像存档头像

初版为了让帧位置可见，给人物预览加了深色背景和边框，但用户确认希望透明背景，不需要框住。

解决方法：

- 移除 `.save-slot-sprite` 的边框和背景色。
- 保留 `image-rendering: pixelated`，让像素角色本体清晰显示。

### 4. 保存通知被菜单遮住

保存时已经调用 `pushNotification()`，但菜单打开时看不到通知。排查后发现通知层 `z-index: 4`，菜单层 `z-index: 8`。

解决方法：

- 将 `GameNotificationBar.vue` 的通知层提升到 `z-index: 30`。
- 该层级高于菜单，低于对话框的 `z-index: 1000`，避免影响正式对话层。

### 5. 当前进度区域过高，压缩后又出现文字溢出和观感不协调

最初当前进度卡片高度较大，占用存档列表空间。压缩为横向条后，又出现三列 grid 在宽度不足时挤出边框的问题。

解决方法：

- 当前进度区域改为横向 flex 状态条。
- 给地点和提示文字加 `min-width: 0`、`overflow: hidden`、`text-overflow: ellipsis`。
- 将高度调整为更协调的状态条高度，并加强标签、地点、坐标、按钮之间的视觉层次。

### 6. 底部导出按钮被存档列表顶出菜单框

存档列表使用 flex 占剩余空间，但缺少 `min-height: 0` 与内部滚动约束。存档条目多时，列表会把 footer 推出菜单面板。

解决方法：

- 给菜单内容和存档面板增加 `overflow: hidden`。
- 给 `.save-slot-list` 增加 `min-height: 0` 和 `overflow-y: auto`。
- footer 改为固定参与面板底部布局，不再依赖 `margin-top: auto` 被列表挤压。

  - 存档条目显示中文地图名。
  - 空状态显示“自由”。

## 后续维护建议

1. 之后如果新增更多人物外观，需要同步在 `playerCharacter.ts` 为该外观配置 `savePreview`，否则存档列表无法正确截取正面站立帧。
2. 存档槽位生成规则目前是顺序填充 `save-001` 至 `save-999`，后续如果加入删除存档，需要确认是否复用空缺槽位。
3. 存档条目现在只展示摘要信息，正式读档仍以 `loadGameFromFile(slotId)` 读取完整存档为准，避免 UI 摘要成为第二套存档源。
4. 菜单内列表区域后续新增更多栏目时，应继续保持“列表内部滚动，footer 留在面板内”的布局约束。
