# 随机大纲访谈轻量抽取规则

创建时间：2026-07-21

当前摘要：随机大纲访谈默认本地轻量抽取并提供丰富的非单选灵感选项；每轮重审全部累计答案，有缺口继续提问，无缺口自动写回大纲。

## 更新时间记录

- 2026-07-21：区分轻量随机与检索筛选两条路径，取消普通随机请求默认读取完整父子链、世界选项、玩法目录、情节目录及调用子智能体。
- 2026-07-21：增加回答后默认处理规则；仍有关键缺口时继续提问，没有当前成熟度缺口时自动同步来源 JSON 与 Markdown。
- 2026-07-21：修正把“旧问题已回答”误判成“条目完整”的规则漏洞；每轮都重建来源、历次答案与本轮答案，复查旧答案、新缺口及前后冲突。
- 2026-07-21：要求每个问题尽量提供丰富且有实质差异的灵感选项；选项允许多选、组合、修改或替换，冲突时必须明确提示并由用户裁决。

## 实现说明

“随机”“随便”“问一个”或未指定筛选条件时，从真实 `missingItems` 候选池使用本地随机数直接抽取，只读取抽中节点的来源 JSON 与对应 Markdown。父节点、子节点、同级节点、世界选项、玩法目录和情节目录不再作为默认上下文；仅在避免重复提问确有必要时补读直接引用。

“找最完整的”“找最接近某条件的”“比较后选择”“检索匹配项”等明确要求跨节点证据的请求，才进入检索筛选路径，并可按需委派只读上下文或审查智能体。

用户回答访谈问题后，先将答案与现有上下文合并并重新审计。仍有会改变当前成熟度设计的决定时继续聚焦提问；不存在关键缺口时默认进入故事大纲撰写流程并完成写回。用户明确要求阶段性写入时可以提前同步，但未解决事项必须继续保留在 `missingItems`。

完整性判断不能只看本轮或上一轮问题是否全部回答。每轮审计都要重建来源 JSON/Markdown、之前各轮已接受或写入的答案及本轮答案，按当前成熟度与最新体量复查旧答案是否仍不完整、是否与新决定冲突，并将新暴露的可执行缺口登记为下一层 `missingItems`。

每个访谈问题应尽量给出丰富、彼此有实质差异且符合已确认上下文的灵感选项。选项不是默认单选题，用户可以组合、修改、否定或完全自行指定；只有用户明确采用的内容才能写入。多个选择彼此矛盾或与旧答案冲突时，必须说明冲突位置并让用户决定取舍。
