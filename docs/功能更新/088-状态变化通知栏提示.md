# 状态变化通知栏提示

## 本次实现思路

本次调整的目标，是让“添加/移除主角状态”这类变化能够像 RPG 中获得物品、失去效果一样，在地图左侧通知栏给出即时反馈。

实现上没有把提示写进单个对话或单张地图数据里，而是接在玩家状态写入链路上：

- 地图事件或对话选项执行 `setPlayerStatus`。
- `WorldScene` 在真正写入状态前后读取旧状态与新状态。
- 如果状态列表发生变化，就把 `{ previousStatus, nextStatus }` 回调给 Vue 侧。
- `GameView` 计算新增状态与移除状态，并推送到现有通知栏。

这样后续无论状态变化来自地图事件、对话选项，还是其它通过世界场景写入状态的玩法入口，都可以复用同一套通知逻辑。

通知文案规则：

- 新增状态显示为 `状态增加：状态名`
- 移除状态显示为 `状态解除：状态名`
- 多个状态同时变化时，用 ` / ` 串联状态名

读档恢复状态属于“恢复快照”，不是剧情中的状态变化，因此读档时会临时关闭状态变化通知，避免读取存档后误弹一串状态提示。

## 相关代码路径

- `src/game/scenes/WorldScene.ts`
  - 新增 `playerStatusChangeCallback`。
  - 地图事件中的 `setPlayerStatus` 改为走 `WorldScene.setPlayerStatus`。
  - `setPlayerStatus` 内部比较旧状态与新状态，变化后回调 Vue 层。

- `src/game/core/createPhaserGame.ts`
  - 在 Phaser 与 Vue 的 UI 回调配置中增加 `onPlayerStatusChange`。
  - `world-scene-ready` 后把状态变化回调注册到 `WorldScene`。

- `src/game/views/composables/usePhaserGameBridge.ts`
  - 桥接 `onPlayerStatusChange` 参数，让 `GameView` 可以接收 Phaser 场景中的状态变化。

- `src/game/views/GameView.vue`
  - 新增 `pushPlayerStatusChangeNotifications`，负责把状态差异转成通知栏消息。
  - 新增 `runWithoutPlayerStatusNotifications`，用于读档时静默恢复状态。
  - 引入 `resolvePlayerStatusLabels`，确保通知显示玩家可读的状态名，而不是状态 id。

## 开发过程中遇到的问题

### 问题 1：状态变化入口不只在对话选项里

一开始最容易想到的是只在 `useGameDialogueBridge` 的 `playerRuntimeActions.setStatus` 外面包一层通知。

但项目里状态变化不只可能来自对话选项，也可能来自地图事件本体的 `playerStatusChange`。如果只包 Vue 侧对话桥接，就会漏掉地图事件触发的状态变化。

**解决方法：**

把通知触发点放到 `WorldScene.setPlayerStatus` 之后。这样对话选项、地图事件，以及后续其它通过世界场景修改玩家状态的入口，都能统一被捕获。

---

### 问题 2：读档同步状态不应该弹通知

读档时会把存档里的 `player.status` 写回世界场景。如果这一步也触发通知，就会让玩家误以为刚刚在剧情中新增或解除了一批状态。

**解决方法：**

在 `GameView.vue` 中增加静默包装：

- 平时 `shouldNotifyPlayerStatusChanges` 为 `true`。
- 读档调用 `setPlayerStatusInWorld(saveData.player.status)` 时，临时切为 `false`。
- 状态恢复完成后再切回 `true`。

这样读档仍然能同步行走图、状态图标和移动表现，但不会打扰通知栏。

---

### 问题 3：通知里要显示状态名，而不是内部 id

状态系统内部使用 `no_shoes`、`barefoot`、`hands_bound` 之类 id，但通知栏面向玩家，应显示状态定义中的中文名称。

**解决方法：**

在 `GameView.vue` 中复用 `src/game/data/playerStatus.ts` 的 `resolvePlayerStatusLabels`，先把差异状态 id 转成展示名，再写入通知。

## 后续可扩展方向

后续如果状态系统继续扩展，可以在这条链路上继续沉淀：

- 为不同状态变化配置更细的通知文案，例如“进入失明状态”“解开腿部束缚”。
- 如果出现持续时间、层数或强度变化，可以在同一回调里扩展为状态详情变化通知。
- 如果未来有道具、装备、剧情旗标等更多运行时变化，也可以参考本次做法：在状态写入的统一出口比较前后差异，再交给通知栏显示。

当前这次改动的重点，是先让状态变化成为地图探索与事件反馈的一部分，让玩家在冒险过程中能及时感知“璃落现在发生了什么变化”，而不是只在菜单里事后查看。
