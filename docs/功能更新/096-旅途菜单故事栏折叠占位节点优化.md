# 旅途菜单故事栏折叠占位节点优化

## 本次实现思路

本次是在故事栏已经支持分类折叠的基础上，继续优化折叠后的画布观感。

原先分类节点收回后，只保留分类卡片和一条预览连线，后面的故事块会完全消失。这样虽然能减少画布内容，但视觉上会显得分支突然断掉，不够像一棵仍然有后续内容的故事树。

本次改成：分类节点收回后，除了保留分类节点自身，还在它的下一层生成一个虚拟的省略占位节点：

```text
...
已收回 N 块
```

这个节点不写入故事 JSON 数据，只在画布布局生成时临时创建，用来提示“这里还有一组被收起的故事块”。表格视图仍沿用原本折叠规则，不额外插入占位行，避免表格信息变杂。

## 相关代码路径

- `src/game/views/components/base/StoryMenuPanel.vue`
  - 在画布节点渲染中识别 `isCollapsedPreview`，将虚拟节点渲染为省略号占位块。
  - 新增 `countDescendantNodes`，递归统计被折叠分类下实际隐藏的所有后代节点数量。
  - `createNodeLayout` 在分类节点折叠时生成虚拟子节点，并继续参与画布连线与画布尺寸计算。
  - 维持折叠状态只存在于组件本地，不写回 `storyOutlinePlaceholder.json`。

- `src/game/views/components/base/gameMenuOverlay.css`
  - 新增省略占位节点样式。
  - 让占位节点尺寸与普通故事节点一致，避免折叠后画布块高低不齐。
  - 调整省略号与“已收回 N 块”的排版，避免文字重叠。
  - 将颜色收回到项目原本的暗紫、浅青、柔粉体系，避免棕色块跳出整体风格。
  - 降低条纹底纹透明度，保证文字可读性。

## 具体实现说明

### 1. 折叠后生成虚拟占位节点

当一个 `status === '分类'` 且带有子节点的故事节点被收回时，画布布局不再只跳过后代节点，而是额外生成一个虚拟子节点：

```js
{
  key: `${node.key}__collapsed-preview`,
  parentKey: node.key,
  title: '...',
  summary: `已收回 ${childCount} 块`,
  isCollapsedPreview: true
}
```

这样画布上仍然保留一块明确的后续内容标记，用户可以看出这里不是故事线结束，而是当前分类被临时收起。

### 2. 递归统计被收回块数

最初统计只使用 `children.length`，只能算第一层子节点。对于故事栏这种多层级大纲来说，这会低估实际被收起的内容。

本次改为递归统计：

```js
function countDescendantNodes(node) {
  const children = Array.isArray(node.children) ? node.children : [];

  return children.reduce((count, child) => count + 1 + countDescendantNodes(child), 0);
}
```

因此“已收回 N 块”显示的是该分类下所有被隐藏的后代节点总数，而不是只显示直属子节点数量。

### 3. 占位节点保持普通故事节点尺寸

用户反馈省略节点太小会破坏剩余块的观感。本次将占位节点高度恢复为普通故事节点一致的 `126px`，并让布局连线也按普通节点高度计算。

这样折叠前后，故事树仍然保持稳定的节点节奏，不会出现某一块明显矮一截导致连线或内容重心不协调。

### 4. 样式回到项目整体色系

开发过程中曾短暂使用偏棕金色的占位块，但它和当前菜单整体的暗紫、青色、柔粉风格不够匹配。

最终样式调整为：

- 背景：暗紫色。
- 边框：低透明度浅青色。
- 省略号：浅青色。
- “已收回 N 块”：柔粉白色，字号加大并增加字重。
- 条纹：仅保留很淡的青紫纹理，不再抢文字对比度。

这样占位节点既能和普通故事块区分开，又不会脱离旅途菜单现有视觉语言。

## 开发过程中遇到的问题

### 1. 只有连线没有块，折叠后的画布显得断裂

**现象：**

分类收回后，其后代节点全部隐藏，只剩分类卡片本身和一段预览线。视觉上像故事树突然断掉，用户不容易判断这里还隐藏了多少内容。

**解决方法：**

在折叠分类后方生成一个虚拟省略节点，让它作为被隐藏内容的代表块继续参与画布布局和连线。

### 2. 只统计第一层子节点会低估收回内容

**现象：**

很多故事分类下面还嵌套多层章节和节点，如果只显示直属 `children.length`，提示数字不准确。

**解决方法：**

新增递归统计函数，把所有后代节点都算入“已收回 N 块”。

### 3. 占位块尺寸过小会破坏节点节奏

**现象：**

省略块一开始被做成较矮的小块，和其他故事节点大小不一致，折叠后的剩余块不够整齐。

**解决方法：**

将占位块恢复到普通节点高度，并让布局计算统一使用普通节点尺寸。

### 4. 底纹和颜色会影响文字可读性

**现象：**

占位块底纹太明显时，“已收回 N 块”的文字会被背景条纹干扰；偏棕色方案也不符合当前项目菜单风格。

**解决方法：**

降低条纹透明度，改用暗紫青色系，并把说明文字字号调大、字重提高。

## 后续可继续扩展的方向

后续如果故事栏继续扩展，可以考虑：

- 给省略占位节点增加鼠标悬停提示，显示被收起分类的名称和数量。
- 允许点击省略占位节点直接展开对应分类。
- 如果未来有更明确的像素 UI 图标系统，可以把 `...` 替换为统一的折叠分支图标。

当前这次优化的重点，是先让故事栏在大量分类被收起后仍然保持清晰、稳定、符合项目风格的故事树观感。
