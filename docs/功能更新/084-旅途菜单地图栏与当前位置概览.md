# 旅途菜单地图栏与当前位置概览

## 本次实现思路

本次目标是在旅途菜单中新增“地图”栏目，让菜单不再只展示人物、物品、任务和存档信息，也能直接承接 RPG 中常见的“当前位置查看”能力。

实现时围绕三件事展开：

1. **新增地图栏页签**
   - 在全局菜单数据中增加 `map` 栏目。
   - 将地图栏放在“人物”之后，让玩家先看角色，再看所在地图。

2. **显示地图层级面包屑**
   - 在地图注册表条目中补充 `breadcrumb` 字段。
   - 例如“四季花园”显示为 `慕妮卡帝国 / 缚神领地 / 四季花园`。
   - 这样地图栏第一行可以表达从外部区域到当前内部地图的层级关系。

3. **生成当前地图全图概览并标记角色位置**
   - 新增 `MapMenuPanel.vue`，直接读取注册表中的 Tiled 地图数据。
   - 根据 tilelayer 中的非空图块生成轻量化网格概览。
   - 使用当前人物世界坐标换算成百分比位置，在概览图上用箭头和定位点突出当前位置。

这次没有改动任何地图 `map.json` 内容。地图栏的概览是从现有地图数据派生出来的显示层能力，避免把临时 UI 需求写回地图原始数据里。

---

## 相关代码路径

- `src/game/data/global/gameMenuData.js`
  - 新增 `map` 菜单页签。

- `src/game/data/registry.ts`
  - 为现有地图注册条目补充 `breadcrumb`。
  - 继续保留地图数据、资源、动画、提示等原有注册职责。

- `src/game/views/GameView.vue`
  - 增加 `currentMapEntry` 计算属性。
  - 打开旅途菜单时，将当前地图 ID、地图条目、地图名称和人物坐标传给菜单。

- `src/game/views/components/base/GameMenuOverlay.vue`
  - 接入 `MapMenuPanel`。
  - 增加地图栏键盘焦点导航。

- `src/game/views/components/base/MapMenuPanel.vue`
  - 新增地图栏面板。
  - 负责面包屑、地图概览、坐标箭头和空状态显示。

- `src/game/views/components/base/gameMenuOverlay.css`
  - 增加地图栏、面包屑、地图概览网格、当前位置箭头的样式。

## 具体实现说明

### 1. 菜单栏新增“地图”栏目

`gameMenuData.js` 中新增：

```js
{
  key: 'map',
  label: '地图',
  title: '当前地图',
  description: '查看当前位置所在的地图层级与全图概览。'
}
```

这样地图栏成为旅途菜单的正式栏目，而不是占位页或临时调试入口。

---

### 2. 地图层级由注册表维护

本次在 `GameMapRegistryEntry` 上增加：

```ts
breadcrumb?: ReadonlyArray<string>;
```

并为当前已注册地图补齐层级，例如：

- `liluo_estate`：`慕妮卡帝国 / 缚神领地 / 四季花园`
- `liluo_house_living_room`：`慕妮卡帝国 / 缚神领地 / 住宅区 / 小别墅`
- `liluo_room`：`慕妮卡帝国 / 缚神领地 / 住宅区 / 小别墅 / 璃落的房间`
- `city_desire`：`慕妮卡帝国 / 醉欲之城`
- `city_jingjiang_school`：`现代城区 / 荆南大学`

这样后续新增地图时，只要在注册表补充层级，就能自动进入地图栏展示。

---

### 3. 地图概览从 Tiled 数据派生

`MapMenuPanel.vue` 会读取当前地图注册条目的 `data`，从 `layers` 中挑选可见的 `tilelayer` 生成概览。

处理时会跳过：

- `event`
- `collision`
- `debug`
- `path`

这些图层更偏运行逻辑或调试，不适合直接作为玩家菜单中的视觉地图。

为了避免大地图在菜单中生成过多 DOM，概览最多采样到：

- 72 列
- 72 行

这是一种轻量概览，不是逐像素复刻真实地图。它的用途是让玩家知道当前地图大致范围和自己的位置。

---

### 4. 当前位置箭头使用世界坐标换算

菜单打开前，`GameView` 会调用已有的 `getPlayerWorldPosition()` 刷新人物坐标。

地图栏拿到坐标后，按地图像素尺寸换算：

```js
currentPosition.x / mapPixelWidth
currentPosition.y / mapPixelHeight
```

再转成 CSS 百分比，定位到概览图上。显示上使用一个朝下箭头加中心点，表达“这里是当前人物所在位置”。

## 开发过程中遇到的问题

### 问题 1：首次接入后用户读档进入时地图栏显示占位

**现象：**

用户通过读档进入地图后打开菜单，地图栏仍显示“当前地图暂时无法生成概览”的占位。

**原因：**

初版只在 `GameMenuOverlay` 内部根据 `currentMapId` 再解析地图注册条目。读档进入时，地图名称和坐标已经在 `GameView` 层更新，但菜单内部解析地图条目的时序存在不稳定风险，一旦拿不到 `mapEntry.data` 就会进入空状态。

**解决方法：**

- 在 `GameView.vue` 增加 `currentMapEntry` 计算属性。
- 由 `GameView` 将 `currentMapEntry` 直接传给 `GameMenuOverlay`。
- `GameMenuOverlay` 优先使用外部传入的地图条目，必要时再用 `currentMapId` 做兜底解析。

这样地图名称、地图 ID、地图条目和人物坐标都从同一层桥接出去，读档进入和正常进入都能稳定拿到地图数据。

---

### 问题 2：地图数据中可能存在异常 chunk 或空 layer 宽度

**现象：**

Tiled 地图既可能是普通 `data` 图层，也可能是 infinite map 的 `chunks` 图层。若某个 chunk 缺少宽度或数据不是数组，直接计算会产生无效坐标。

**解决方法：**

- `forEachLayerTile()` 中先检查 `chunk.data` 是否为数组。
- 当 `chunk.width` 或 `layer.width` 小于等于 0 时直接跳过。
- 只处理有效的非空 gid。

这样地图栏不会因为单个异常图层影响整个菜单。

---

### 问题 3：不能为了地图栏去修改各地图 `map.json`

**现象：**

地图栏需要全图展示，但项目规则要求尽量不要改动各地图数据的 `map.json`，因为这些数据可能随地图编辑器导出随时更新。

**解决方法：**

- 不在 `map.json` 中新增菜单专用字段。
- 地图层级放到 `registry.ts`。
- 地图概览由运行时读取现有 Tiled 数据生成。

这样 UI 能力和地图源数据保持分离，后续地图重导出时不容易丢失菜单配置。

## 验证结果

本次实现后执行：

```powershell
npm run build:web
```

结果：构建通过。

构建过程中仍然存在既有提示：

```text
new URL("../../../../../assets/game/sucai/Modern/school/NPCs/student1.png", import.meta.url) doesn't exist at build time
```

该提示来自已有现代校园素材路径解析，不是本次地图栏新增逻辑导致的问题。

用户随后反馈“菜单中的地图栏还是占位”，已针对读档进入流程补充 `currentMapEntry` 透传，并再次执行 `npm run build:web`，构建通过。

## 当前实现结果

本次完成后，旅途菜单具备：

1. “地图”栏目。
2. 当前地图层级面包屑。
3. 当前地图全图概览。
4. 当前人物位置箭头标记。
5. 读档进入地图后也能稳定拿到地图注册数据。
6. 键盘导航可以从左侧页签进入地图概览，再返回菜单页签。

这让旅途菜单更接近 RPG 中的系统菜单，而不是纯功能页面集合。

## 后续可继续扩展的方向

后续地图栏还可以继续扩展：

- 把事件点、传送点、已发现地点标记到概览图上。
- 按地图注册表补充更精细的区域名或小地图名称。
- 为大地图增加缩放或拖拽查看。
- 将不同地貌、建筑、道路的颜色分类从图层名推断升级为地图注册配置。

当前版本先完成“能看到地图层级、能看到全图、能看到自己在哪”的基础体验。
