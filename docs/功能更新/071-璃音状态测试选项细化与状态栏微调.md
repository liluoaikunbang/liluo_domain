# 071-璃音状态测试选项细化与状态栏微调

## 实现思路

本次把璃音“功能测试”里的“测试人物状态”从一次性写入全部状态，改成了更适合调试的状态选择分支：进入状态测试后，可以单独添加某个状态，也可以一键添加全部状态，最后保留“去掉所有状态”用于清空。

为了让“添加状态”符合语义，新增了 `playerStatusChange.mode: "append"`。默认 `playerStatusChange` 仍然保持原来的整组设置行为，只有明确写了 `mode: "append"` 的选项才会读取当前状态并追加新状态。这样床铺休息、换衣离房等需要清空状态的旧流程不会被影响。

清空状态后不再直接关闭对话，而是进入一个小引导节点：玩家可以继续回到状态列表添加状态，也可以结束对话。这让测试状态的流程更连贯，尤其适合反复确认左侧人物框里的状态图标。

人物框左侧的状态栏也做了轻量视觉调整：状态图标和“状态”标签整体稍微放大一圈；侧栏标题在尝试单独放大左侧“璃落的冒险”后，最终按用户反馈改回与右侧“当前位置”标题完全一致的通用字体样式。

## 遇到的问题与解决方法

### 1. 添加状态实际是替换状态

问题：原来的 `playerStatusChange.status` 只有整组设置语义。璃音测试分支每次选择一个状态时，会把当前已有状态替换掉，不符合“添加状态”的直觉。

解决：保留默认 set 行为不变，新增 `mode: "append"`。append 模式通过 `getPlayerStatus()` 读取当前状态，再把新状态拼接后交给 `setPlayerStatus()`。最终状态仍由 `setPlayerStatus()` 和状态规范化逻辑处理去重与非法状态过滤。

### 2. 清空状态后测试流程中断

问题：清空所有状态后对话直接结束，如果想继续测试，需要重新和璃音对话并重新进入状态测试分支。

解决：清空选项增加 `next: "player_status_cleared"`，清空后出现“继续添加状态”和“结束对话”两个选项，让调试流程自然回环。

### 3. 标题样式改动影响了右侧当前位置

问题：最初放大“璃落的冒险”时改到了通用侧栏标题 `.panel-tag`，导致右侧“当前位置：四季花园”也被放大；之后又留下了左侧专用 class，视觉仍然与右侧不一致。

解决：删除 `panel-tag--left` 和相关计算 class，左右标题都只使用同一个 `.panel-tag` 样式。这样左侧和右侧标题字体、字号、字重完全一致。

### 4. 状态栏需要更明显但不能压过人物框

问题：状态图标和“状态”标签原尺寸偏小，多个状态叠在左侧时辨识度不足。

解决：只在 `GamePortraitPanel.vue` 内提高状态栏一档尺寸：图标从 36px 提到 42px，标签宽高、字号、间距和边距同步轻微放大。调整仍局限在人物框状态列，不改变其他主界面布局。
