## 实现说明

这一轮的核心不是继续往首页堆概念，而是把“项目门户”真正收束到用户想要的呈现方式上。

前一版虽然已经把 README 从架构说明页改成了更像独立游戏门户的入口，但世界展示仍然停留在草案级 SVG 卡片，角色展示也还误用了游戏内像素代替立绘。第三轮修正之后，根 README 的前半段彻底改成了以正式宣传图和真实运行截图为主的表达层：

- 璃落角色展示改为单独生成的正式角色图，不再使用游戏内像素代替立绘。
- 六大世界全部替换为世界优先的 AI 宣传图，不再用简化 SVG 卡片顶替世界氛围。
- 新增一张“璃落在不同世界中的融合图”，承担世界总览横幅，强化项目门户的整体意境。
- 原型段落接入两张真实运行截图，明确区分“宣传图”和“当前已跑起来的可见原型”。

这轮也把素材说明与清单同步收口到新的正式资产集，避免旧草案再次被 README 误引用。继续扩编之后，README 不再只是“有一张海报和几张旧图”的门户，而是拥有可持续扩展的公开展示骨架：

- 六大叙事域从单张世界卡升级成每域三联图：总海报、局部场景、事件落点。
- 璃落角色段补齐新的公开基准立绘、六域服装变体和“不变身份 / 可变状态”说明图。
- `art-manifest.json` 从首版轻量登记扩到 `45` 项，提示词记录扩到 `6` 份，可追溯到每批次新图。

除此之外，README 也被拆成了三条公开证据线：

- 概念视觉：只负责传达世界、角色与气质。
- 真实截图：只使用真实运行中的现有证据，不能拿概念图冒充。
- 自动统计：由脚本直接从仓库数据回算地图、节点、Schema、Skill、截图归档状态与视觉元数据。

这让根 README 从“漂亮入口”真正升级成了“可公开展示、可招募协作者、可自证边界”的项目海报页。

继续扩编之后，这个“海报页”开始更接近原始目标里的整套公开门户，而不是只在首页加几张世界图：

- 为了进入正式官网建设前的“资产迁移准备”阶段，本轮额外把公开视觉资产的宿主从“默认留在 Git 仓库”改成了“仓库保存索引，R2 保存外链变体”的方向：`docs/assets/registry/website-r2-manifest.json` 先登记了 README 大图、六域整板和首批游戏展示截图，确保后续切换时不是临时手填 URL。
- `scripts/assets/visual-asset-manager.mjs` 现在提供 `status / prepare / upload` 三个入口；其中 `prepare` 负责调用 Pillow 生成 `large / medium / thumb` 三档 WebP，`upload` 默认 dry-run，只有显式 `--live` 才会真正上传并把 public URL 写回 manifest。
- 现在同一套脚本已经扩展为 `status / prepare / upload / prune` 四个入口：`prune` 会按 manifest 顶层 `managedRoots` 去列举 Cloudflare R2 桶内当前由本项目管理的对象，并在 dry-run 阶段只报告“已不再被当前 manifest 引用的旧 key”，只有显式 `--live` 时才真正删除。
- 这也让后续“全项目公开图尽量都迁到图床”这件事有了长期治理前提：如果只是替换同一路径图，R2 会直接覆盖，不会额外累积；只有当 slug、用途路径或资产条目本身发生变化时，才需要额外跑一次 `prune` 回收旧对象，避免存储逐步失控。
