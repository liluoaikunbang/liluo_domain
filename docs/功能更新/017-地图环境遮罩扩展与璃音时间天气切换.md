# 地图环境遮罩扩展与璃音时间天气切换

## 本次实现思路

这次功能是在原本“白天 / 黄昏”切换的基础上，继续把地图环境遮罩往前推进一层：

1. 保留地图本体、图层和素材资源不动；
2. 继续用运行时环境遮罩来表达整体氛围变化；
3. 将环境表现从单一黄昏扩展为“时间 + 特殊天气”两类；
4. 把 NPC 对话结构也同步改成更符合设定的双分支入口，由璃音分别引导到“调整时间”与“调整天气”。

这次没有把雨滴、雾粒子或整套后处理强行塞进去，而是优先用朴素稳定的多层半透明遮罩，把可玩、可切换、可继续扩展的环境基础先落地。

最终效果是：

- 默认仍然是白天；
- 时间分支下可切换为白天 / 黄昏 / 夜晚；
- 特殊天气分支下可切换为雨天 / 雾天；
- 夜晚使用蓝紫色半透明遮罩；
- 雨天使用偏灰、偏冷的双层遮罩压低整体色温；
- 雾天使用浅灰雾层和更发白的叠层，做出低对比的空气感；
- 入口仍然挂在当前地图的 NPC 交互点上，但语义上已经从“单一黄昏切换”升级为“璃音调整庭院环境”。

---

## 相关代码路径

- `src/game/data/timeOfDay.ts`
  - 存放环境表现配置。
  - 将原本单层 `overlayColor` / `overlayAlpha` 扩展为 `overlayLayers`，让一个环境状态可以配置一层或多层遮罩。
  - 当前已定义：`day`、`dusk`、`night`、`rain`、`fog`。

- `src/game/systems/environment/timeOfDayOverlay.ts`
  - 地图环境遮罩控制器。
  - 从单个矩形遮罩改为最多两层矩形遮罩叠加，并统一处理切换动画、相机视口同步和销毁逻辑。
  - 当前夜晚、雨天、雾天都通过这套多层遮罩能力表达。

- `src/game/systems/map/worldSceneRuntime.ts`
  - 在地图运行时创建环境遮罩控制器。
  - 默认进入地图时仍设为 `day`。
  - 对外暴露 `setTimeOfDay(...)`，供事件和对话选项调用。

- `src/game/scenes/WorldScene.ts`
  - 负责把场景层的 `setTimeOfDay(...)` 桥接给事件执行与 UI 调用。

- `src/game/core/eventExecution.ts`
  - 事件上下文继续支持 `timeOfDayChange`，不需要因为新增天气而重做事件执行链路。

- `src/game/core/dialogueExecution.ts`
  - 负责对话选项里的副作用执行。
  - 当前仍通过 `timeOfDayChange` 驱动环境状态切换，既可用于时间，也可用于特殊天气。

- `src/game/views/GameView.vue`
  - Vue 对话层在用户点击选项后，把环境切换请求回传给 `WorldScene`。

- `src/game/data/liluo_estate/dialogues.json`
  - 将原本“白天 / 黄昏”平铺选项，重构为璃音的双分支对话：
    - 调整时间 → 白天 / 黄昏 / 夜晚
    - 调整天气 → 雨天 / 雾天
  - 同时把说话人明确为“璃音”，并补上各状态对应的反馈文本。

- `src/game/data/liluo_estate/events.json`
  - 继续使用当前地图里的环境切换交互入口，承接璃音这段对话。

## 具体实现说明

### 1. 从单层遮罩扩展到多层遮罩

原本黄昏效果只需要一层轻微的橙粉色覆盖层，因此单个矩形遮罩就够用。

但夜晚、雨天、雾天的表现更适合做“主色 + 辅助色”的叠加：

- 夜晚需要比较明确的蓝紫色压暗感；
- 雨天除了偏灰，还需要一点冷色倾向；
- 雾天除了发灰，还要有一层更浅、更白的雾气感。

所以这次没有继续往单层配置里硬塞更多参数，而是直接把环境配置改成 `overlayLayers` 数组，再在运行时统一创建两层遮罩对象。

这样处理有几个好处：

- 白天仍然可以用空数组表示，无需特殊分支；
- 黄昏和夜晚仍然只占一层，保持简单；
- 雨天、雾天可以自然升级为双层表现；
- 以后如果还要补“室内暖光”“诅咒天色”“月光庭院”等状态，也不需要重写底层结构。

---

### 2. 时间与天气共用一套环境切换接口

虽然设定上“白天 / 黄昏 / 夜晚”属于时间变化，“雨天 / 雾天”属于特殊天气，但在当前运行时层面，它们本质上都只是“切到另一套环境遮罩配置”。

因此这次没有额外新造一套 `setWeather(...)` 系统，而是继续沿用现有 `setTimeOfDay(...)` 调用入口，让事件系统和对话系统都不需要改接口。

这样做的好处是：

- 现有事件执行链路可以直接复用；
- 对话选项副作用逻辑不用拆两套；
- 先把表现和交互跑通，后面如果真的需要把“时间”和“天气”拆成两个独立运行状态，再继续演进也不迟。

也就是说，这次在“设定表达”上做了区分，在“运行时调用”上保持了简单。

---

### 3. 璃音的对话按“时间 / 天气”分支重组

用户确认后，这次又进一步调整了 NPC 对话结构。

原本的平铺方式虽然能切换，但会把“黄昏”和“雨天”“雾天”都摆在同一层，看起来像一组同类选项，不太符合世界内语义。

所以最终改成：

1. 先由璃音询问“调整时间，还是添一点特别的天气”；
2. 进入“调整时间”分支后，再选白天 / 黄昏 / 夜晚；
3. 进入“调整天气”分支后，再选雨天 / 雾天；
4. 两个分支里都保留返回上层的选项，避免交互卡死。

这样处理后，这个入口更像 RPG 场景中的人物互动，而不是一排环境调试按钮。

---

### 4. 视觉目标保持“朴素可读”，不强行上复杂特效

这次用户要求的是：

- 夜晚：蓝紫色半透明遮罩
- 雨天：整体稍微偏灰、偏冷
- 雾天：低对比度和浅灰雾层

在当前项目阶段，这类需求更适合通过稳定的整体氛围控制先落地，而不是立刻扩成：

- 粒子雨丝
- 动态雾流
- 后处理对比度矩阵
- 地图专属天气 shader

原因是当前项目核心还是“地图可探索、事件可推进、氛围能支撑冒险感”，不是先堆重特效。

所以这次选择了更稳妥的方案：

- 让夜晚、雨天、雾天都先具备明确可感知的视觉差异；
- 维持代码结构简单；
- 保证后续还能继续往更复杂的环境表现扩展。

## 开发过程中遇到的问题

### 问题 1：原本的环境配置只适合单层遮罩

最开始的数据结构只有单个颜色和透明度，适合白天 / 黄昏这种简单切换；但一到雨天、雾天，就会发现只靠一层色板很难同时做出“偏冷”和“发雾”的感觉。

### 解决方法

把环境配置升级为 `overlayLayers` 数组，并让遮罩控制器一次管理两层矩形遮罩。

这样无需引入新渲染技术，就能把夜晚、雨天、雾天的差异明显拉开。

---

### 问题 2：设定上时间和天气不同，但代码里不适合立刻拆两套系统

如果完全按概念硬拆成“时间系统 + 天气系统”，这次会额外波及事件上下文、对话副作用、场景桥接与状态组合逻辑，超出当前需求范围。

### 解决方法

运行时仍统一走现有环境切换接口，只在内容层和对话层把“时间”与“天气”明确分开。这样既满足设定表达，也避免为当前需求引入过多结构复杂度。

---

### 问题 3：NPC 对话入口原先的文案和结构已经不再匹配功能范围

原文档和原对话都偏向“黄昏切换”，但这次功能已经扩展成多种环境状态。如果继续沿用旧标题和旧分支，会让内容表达越来越不准确。

### 解决方法

把 NPC 说话人统一明确为“璃音”，把对话树改成“时间 / 天气”双分支，并在本次文档补录时同步更新文档标题与目录登记，让实现内容和记录内容保持一致。

---

## 最终验证结果

- 已保留地图默认白天表现；
- 已支持通过环境遮罩切换到黄昏、夜晚、雨天、雾天；
- 夜晚为蓝紫色半透明遮罩；
- 雨天为偏灰偏冷的双层遮罩；
- 雾天为浅灰、低对比感的双层雾层；
- 璃音对话已改为“调整时间 / 调整天气”两个分支；
- 时间分支下可切换白天 / 黄昏 / 夜晚；
- 天气分支下可切换雨天 / 雾天；
- 已执行验证：
  - `npm run build:web`
- 用户已实际测试确认“没问题了”，因此本次功能实现与文档补录完成。
