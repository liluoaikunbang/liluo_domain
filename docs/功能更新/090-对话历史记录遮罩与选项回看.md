# 对话历史记录遮罩与选项回看

## 本次实现思路

本次为地图对话框增加“历史记录”入口，让玩家在一段对话进行中可以回看本次已经出现过的台词和已经选择过的选项。

实现时没有把历史记录做成独立功能页，也没有写进存档或长期日志，而是定位为**当前对话会话内的临时回看层**：

1. 对话开始时清空历史记录。
2. 每个对话节点显示时，把当前文本写入本次历史。
3. 玩家选择选项时，把选项文本也写入历史，并用不同颜色区分。
4. 点击对话框里的“历史记录”按钮后，打开覆盖整个地图栏目的遮罩层。
5. 查看历史时隐藏当前对话框，只显示历史记录遮罩；关闭后回到原对话流程。

这样它更接近 RPG 对话中的“临时回想日志”，不会把对话框本体变成同时展示当前聊天和历史记录的混合面板。

---

## 相关代码路径

- `src/game/views/composables/useGameDialogueBridge.ts`
  - 维护本次对话的 `dialogueHistory`。
  - 在对话节点出现时记录普通台词。
  - 在选项被选择时记录选项文本。
  - 对话关闭或重新打开新对话时清空历史。

- `src/game/views/components/base/DialogBox.vue`
  - 增加“历史记录”按钮。
  - 只负责发出 `open-history` 事件，不在对话框内部渲染历史遮罩。

- `src/game/views/components/base/DialogHistoryOverlay.vue`
  - 新增对话历史遮罩组件。
  - 覆盖整个地图栏目，展示本次对话历史。
  - 支持点击空白遮罩或按 `Esc` 关闭。
  - 历史文本使用 `说话人：文本` 的单行格式；选项显示为 `选择：选项文本`。

- `src/game/views/GameView.vue`
  - 统一控制历史遮罩开关。
  - 历史遮罩打开时暂停显示当前 `DialogBox`。
  - 把历史遮罩纳入 UI 覆盖层状态，避免地图输入穿透。

## 具体实现说明

### 1. 对话桥接层记录本次会话历史

`useGameDialogueBridge.ts` 中新增 `dialogueHistory`，历史条目包含：

- `id`
- `type: 'dialogue' | 'choice'`
- `speaker`
- `text`

普通对话节点通过 `applyDialoguePayload(...)` 进入当前对话状态后追加历史；选项则在 `handleDialogChoice(...)` 执行分支逻辑前追加历史。

这样即使某个选项选择后直接结束对话，也能先被记录下来。

### 2. 历史入口留在对话框，但遮罩状态交给外层

最初实现曾把历史面板直接放在 `DialogBox.vue` 内部。后续根据实际体验调整为：

- `DialogBox.vue` 只显示“历史记录”按钮。
- 点击按钮后向外发出 `open-history`。
- 历史遮罩由 `GameView.vue` 挂在地图模式栈内。

这样历史记录不再随着对话框尺寸、位置和透明度变化，而是默认覆盖整个地图栏目，职责边界更清晰。

### 3. 历史记录遮罩独立展示，不和当前聊天混排

`DialogHistoryOverlay.vue` 是单独的地图栏目遮罩。它打开后：

- 当前对话框不显示。
- 历史记录独立居中展示。
- 关闭遮罩后回到当前对话。

这避免了“上面看历史、下面还显示当前对话”的混合界面，让玩家查看记录时只关注历史内容。

### 4. 选项与台词共用列表，但保留视觉区分

历史列表里普通台词和玩家选择都按时间顺序记录。

展示格式统一为：

```text
璃音：……
选择：……
```

选项条目额外使用偏蓝色左边框与底色，保证玩家能快速区分“角色说过的话”和“自己做过的选择”，但文本结构不再拆成两行。

### 5. 长历史通过内部滚动处理

历史遮罩面板使用固定可用高度，并采用纵向 flex 布局：

- 标题栏固定在顶部。
- `GameScrollArea` 占据剩余空间。
- 内容过多时在滚动区域内部滚动，不撑破面板。

这避免了历史文本增多后溢出历史框的 CSS 隐患。

## 开发过程中遇到的问题

### 问题 1：历史面板放在对话框上方，会被误理解为对话框的一部分

**现象：**

第一版历史记录直接作为 `DialogBox.vue` 内部浮层显示在对话框上方。这样虽然能看到记录，但它会随着对话框宽度和位置变化，看起来像对话框扩展栏，而不是独立回看页面。

**解决方法：**

将历史遮罩拆成 `DialogHistoryOverlay.vue`，由 `GameView.vue` 挂到地图模式栈里统一控制。`DialogBox.vue` 只保留按钮和事件，不再承担历史遮罩渲染。

### 问题 2：只记录台词会漏掉玩家选过的选项

**现象：**

如果历史记录只追加对话节点文本，玩家做过的选择不会出现在回看里。分支对话越多，历史越难还原实际对话路径。

**解决方法：**

在 `handleDialogChoice(...)` 中根据 `choiceId` 查找当前选项，并在执行分支前写入历史。选项条目使用 `type: 'choice'`，展示时用 `选择：...` 和不同颜色标记。

### 问题 3：遮罩打开时仍显示当前对话，会变成“记录和当前聊天一起展示”

**现象：**

历史遮罩如果只覆盖在对话框之上，玩家视觉上仍会把当前对话和历史记录一起理解。

**解决方法：**

`GameView.vue` 在 `isDialogueHistoryOpen` 为真时不渲染 `DialogBox`。历史遮罩关闭后，对话状态仍保留，玩家可以继续当前对话。

### 问题 4：说话人和正文拆成两行后，每句都显得被切开

**现象：**

历史列表初版把 `璃音` / `选择` 作为单独一行标签，再在下一行显示正文。记录一多，每句话都像被拆成两段，阅读节奏不自然。

**解决方法：**

改为内联格式：`璃音：文本`、`选择：选项文本`。说话人前缀仍保留颜色和加粗，但不再独占一行。

### 问题 5：历史文本过多时可能撑破历史框

**现象：**

历史面板只设置 `max-height` 时，内部滚动区没有稳定获得剩余高度，长列表存在撑开面板的风险。

**解决方法：**

将历史面板改为固定可用高度的 flex 容器，标题栏 `flex: 0 0 auto`，内容区 `flex: 1 1 auto` 并设置 `min-height: 0`。滚动交给 `GameScrollArea`。

## 最终验证结果

本次功能已完成并通过以下验证：

- 对话框内出现“历史记录”按钮。
- 点击后打开地图栏目级历史遮罩。
- 遮罩打开时当前对话框隐藏，关闭后回到原对话。
- 已出现台词会按顺序记录。
- 已选择选项会写入历史，并以不同颜色区分。
- 历史条目显示为 `说话人：文本` 的内联格式。
- 长历史列表在面板内部滚动，不撑破外框。
- `npm run build:web` 通过。

构建时仍存在既有资源警告：

```text
new URL("../../../../../assets/game/sucai/Modern/school/NPCs/student1.png", import.meta.url) doesn't exist at build time
```

该警告来自荆南大学地图资源路径，与本次对话历史记录功能无关。

## 后续可继续扩展的方向

后续如果继续增强对话历史，可以考虑：

1. 给历史遮罩增加自动滚动到底部，让打开时默认看到最新一句。
2. 在历史条目中记录头像、说话侧或时间戳，但要避免让临时回看层变成复杂日志系统。
3. 如果未来需要“旅途回忆”或“剧情日志”，应另做长期记录系统，不直接复用本次临时对话历史。

当前版本先保证对话中可回看、选项可追踪、界面不干扰地图与对话主流程。
