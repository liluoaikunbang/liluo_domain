# 旅途菜单故事栏侧向分支与任务节点整理

## 本次实现思路

本次围绕旅途菜单“故事”栏继续整理故事树的结构表达。

原本故事节点只有普通父子层级：子节点在画布上只能按主链路继续向下展开。随着“主线节点旁边引出支线”的需求出现，这种单一层级无法清楚表达“主线继续推进，同时从当前节点侧边伸出一条支线”的关系。

本次新增了轻量的侧向分支语义：故事 JSON 节点可以通过 `branchLayout: "side"` 标记为侧枝节点。画布布局会让它从父节点侧面引出，主链路仍然按普通子节点继续向下排列。

同时，本次也把故事栏里的占位进度状态收口掉：`大纲`、`大纲草稿`、`预留` 等不再作为节点标签显示，避免故事画布被临时整理状态干扰。`分类`、`主线任务`、`支线任务` 这类结构性标签仍然保留。

## 相关代码路径

- `src/game/data/global/storyOutlinePlaceholder.json`
  - 继续作为故事栏大纲数据源。
  - 为需要侧向引出的故事节点增加 `branchLayout: "side"`。
  - 移除占位进度类 `status` 字段，只保留结构和任务类型相关状态。

- `src/game/views/components/base/StoryMenuPanel.vue`
  - 新增 `branchLayout: "side"` 的布局识别。

  - 普通主线子节点保持原来的向下推进关系。
  - 侧枝能放下时不拉长主线；只有侧枝通道可能和下一段主线侧枝重叠时，才自动增加主线段间距。
  - 没有 `status` 的节点不再渲染空状态徽标，表格视图中用 `-` 表示空状态。

## 具体实现说明

### 1. 侧向分支语义

故事节点新增可选字段：

```json
{
  "branchLayout": "side"
}
```

这个字段只描述画布布局语义，不改变故事数据本身的父子关系。

普通子节点仍然表示主链继续向下走；带 `branchLayout: "side"` 的节点则表示从父节点侧边伸出一条支线。

### 2. 侧枝连线从侧面引出

布局生成连线时会识别 `branchLayout === "side"`：

- 纵向画布中，侧枝从父节点右侧连到侧枝节点左侧。
- 普通主线仍从父节点底部连到子节点顶部。

这样画布能同时表达两种关系：

```text
主线：父节点 -> 下方子节点
支线：父节点 -> 侧边节点
```

### 3. 侧枝不再无限拓宽画布

早期处理侧枝时，侧枝位置会跟随全局排布游标移动。节点越多，侧枝越容易被推到更远的横向位置，画布宽度也会被带着变大。

本次改为固定侧枝通道：侧枝优先放在父节点旁边。如果侧枝自身往下延伸，先尝试在旁边容纳；只有当它会和下一段主线节点的侧枝通道重叠时，才拉长主线段，为旁路腾出空间。

这样能保持两个目标：

- 能放下时，主线保持最短间距。
- 放不下时，通过拉长主线连接段避让，而不是横向无限扩展。

### 4. 任务节点颜色区分

故事栏原本只对 `主线任务` 和 `分类` 做了特殊卡片颜色。新增 `支线任务` 后，如果继续使用普通故事块颜色，不利于快速识别。

本次为 `支线任务` 增加独立的蓝色系卡片和状态徽标，让它与：

- 主线任务的金棕色
- 分类节点的青绿色
- 普通故事块的紫色

形成清晰区别。

## 开发过程中遇到的问题

### 1. 普通父子关系无法表达侧向支线

**现象：**

只用 `children` 排布时，支线和主线都会成为同一种子节点，画布无法表达“主线继续向下，支线从侧边引出”。

**解决方法：**

保留 `children` 表示故事归属关系，再增加 `branchLayout: "side"` 作为画布布局提示。

### 2. 侧枝连线从底部引出不符合视觉关系

**现象：**

侧枝节点虽然被放在旁边，但连线仍按普通子节点规则从父节点底部引出，视觉上仍像主线下属节点。

**解决方法：**

在连线计算中识别侧枝节点，改为从父节点侧面连接到侧枝节点侧面。

### 3. 侧枝会推动画布横向变宽

**现象：**

侧枝节点使用全局排布游标时，会随着已有节点数量不断往更远的横向位置排布，导致画布横向空间被不必要地撑开。

**解决方法：**

侧枝使用固定侧枝通道，并通过检测侧枝堆叠深度决定是否需要拉长主线段。能放下时不额外拉长，放不下时才为主线段增加间距。

### 4. 占位状态标签干扰故事浏览

**现象：**

`大纲`、`大纲草稿`、`预留` 这类整理状态会显示在每个故事块上，让故事栏更像资料表，而不是剧情结构图。

**解决方法：**

从故事数据中移除这些占位状态，并让组件在缺少 `status` 时不渲染空状态徽标。

## 后续可继续扩展的方向

- 如果后续侧枝类型增加，可以把 `branchLayout` 扩展为更明确的分支布局枚举。
- 可以给侧枝连线增加更明确的视觉差异，例如虚线或更浅的颜色，用来区分主线和支线。
- 如果故事树规模继续增长，可以继续优化侧枝碰撞检测，让多条侧枝在同一区域内更稳定地避让。
