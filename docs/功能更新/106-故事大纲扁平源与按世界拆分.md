# 故事大纲扁平源与按世界拆分

## 本次实现思路

本次更新处理的是故事大纲数据源的长期维护问题。

原本 `storyOutlinePlaceholder.json` 使用深层 `children` 嵌套来表达主线顺序。故事栏运行时读取这种树结构很方便，但人工维护会越来越困难：

- 主线越长，JSON 缩进越深。
- 插入或移动章节时容易误动括号。
- 一条主线如果只是顺序推进，也必须靠一层套一层表达。
- 后续继续增加世界、章节、支线后，单个 JSON 文件会变得很难查找和核对。

本次把故事大纲源数据改成“编辑时扁平、运行时组树”的结构：

- 编辑源按世界拆到 `src/game/data/story_outline/sources/`。
- 每个节点用 `parentKey` 表达父子关系，用 `order` 表达同级顺序。
- 运行时通过 `buildStoryOutlineTree()` 组装回原本故事栏需要的 `children` 树。
- `storyOutline.js` 继续导出合成后的 `storyOutline`，故事栏组件不需要知道底层数据已经变成扁平源。

这样保留了故事栏的树状展示，同时让后续维护故事结构时不再进入很深的 JSON 嵌套。

## 相关代码路径

- `src/game/data/story_outline/sources/`
  - 新的故事大纲编辑源目录。
  - 当前按世界拆分为：
    - `0-munika.json`
    - `1-modern.json`
    - `2-apocalypse.json`
    - `3-ancient.json`
    - `4-fantasy.json`
    - `5-science.json`

- `src/game/data/story_outline/storyOutlineSource.js`
  - 汇总所有世界源文件。
  - 导出合并后的 `storyOutlineSource`。

- `src/game/data/story_outline/storyOutlineTreeBuilder.js`
  - 将扁平节点列表转换为 `children` 树。
  - 校验重复 key、缺失父节点和缺失根节点。
  - 转换时移除编辑期字段 `parentKey`、`order`，避免它们进入故事栏运行时节点。

- `src/game/data/story_outline/storyOutline.js`
  - 从 `storyOutlineSource` 生成树。
  - 再调用 `applyStoryOutlineFrontmatter()` 合并 Markdown frontmatter 与正文。
  - 对外仍导出 `storyOutline`。

- `scripts/tests/story-outline-tree-builder.test.mjs`
  - 覆盖扁平节点组树、排序、不污染源数据、重复 key、缺父节点和魔幻主线不分叉等校验。

- `src/game/data/story_outline/storyOutlinePlaceholder.json`
  - 已移除。
  - 后续不再作为故事大纲编辑入口。

## 具体实现说明

### 1. 节点从嵌套 children 改为 parentKey

新的源数据中，一个节点大致是：

```json
{
  "key": "world-6-cursebound-echoes-dreambound-continent",
  "parentKey": "world-6-cursebound-echoes",
  "world": "6-咒缚回响",
  "title": "逐梦大陆",
  "status": "主线任务",
  "storyTags": ["咒缚回响"],
  "order": 10
}
```

其中：

- `key` 是节点唯一标识。
- `parentKey` 指向父节点；顶层世界分类节点不写 `parentKey`。
- `order` 决定同一个父节点下的排序。
- 展示字段仍沿用原来的 `world`、`title`、`status`、`summary`、`storyTags`、`tags` 等。

### 2. 主线不分叉时也不需要深层缩进

例如魔幻线现在维护在 `sources/4-fantasy.json` 中。

虽然运行时仍会组装成：

`咒缚回响（魔幻） -> 逐梦大陆 -> 秘纹学院 -> ... -> 深渊契约`

但编辑源里每章只是一个扁平节点。新增下一章时，只需要追加一个节点，并把它的 `parentKey` 指向当前链尾节点。

### 3. 运行时仍输出旧的树结构

`StoryMenuPanel.vue` 之前依赖 `children` 树来生成画布、表格、汇总和导出。

本次没有让视图组件直接理解扁平源，而是在数据入口处完成转换：

```js
export const storyOutline = applyStoryOutlineFrontmatter(
  buildStoryOutlineTree(storyOutlineSource),
  markdownModules
);
```

这样故事栏现有能力可以继续复用，迁移风险集中在纯数据转换层。

### 4. 按世界拆分源文件

单个故事源会继续增长，所以本次没有只做一个新的大 JSON，而是按世界拆分。

后续维护时优先打开对应世界文件：

- 都市线：`sources/1-modern.json`
- 魔幻线：`sources/4-fantasy.json`
- 科幻线：`sources/5-science.json`

这样新增章节、调整顺序或核对 key 时，范围更小，也更容易做局部检查。

## 开发过程中遇到的问题

### 问题 1：不能让故事栏组件背上新数据格式

**现象：**

如果直接让 `StoryMenuPanel.vue` 读取扁平节点，就需要同时重写画布布局、表格、汇总、详情、导出等逻辑，风险过大。

**解决方法：**

在 `storyOutline.js` 入口处把扁平源转换成旧树结构。组件继续拿 `children` 树，不感知底层编辑源变化。

### 问题 2：迁移过程中不能丢节点或产生重复 key

**现象：**

从深层 JSON 迁移到扁平列表时，如果手动复制，很容易漏掉节点、重复 key 或挂错父节点。

**解决方法：**

先用脚本机械展开旧树，生成扁平源，再用测试校验：

- 当前源节点数为 73。
- 所有 key 无重复。
- 缺失父节点会抛错。
- 根节点缺失会抛错。

### 问题 3：魔幻主线要保持单链，不变成分叉

**现象：**

扁平结构下，如果多个章节都挂到同一个 `parentKey`，运行时就会变成并列分叉。

**解决方法：**

新增测试专门核对 `world-6-cursebound-echoes` 下的魔幻主线顺序，并断言链上每个主线节点最多只有一个子节点。

当前顺序为：

`逐梦大陆 -> 秘纹学院 -> 逐潮孤海 -> 圣印群岛 -> 熔辉机城 -> 森誓妖境 -> 秘塔长歌 -> 锁角荒原 -> 深渊契约`

### 问题 4：历史文档仍会提到旧文件

**现象：**

过往功能文档中会继续出现 `storyOutlinePlaceholder.json`，这些记录对应当时的实现状态。

**解决方法：**

保留历史文档不大范围改写，只在本篇记录当前新结构。后续维护以本篇和 `storyOutlineSource.js`、`sources/` 目录为准。
