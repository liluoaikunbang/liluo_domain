# 故事大纲模板、关联展示与璃落房间自缚动作

## 更新概述

本次更新统一了故事大纲条目的补充方式，并完善故事节点与 CG、玩法目录之间的关联展示。

故事内容方面新增“瓦窑封灾”和“穹顶狩猎”，补充“深夜城市探险”的都市夜班短篇结构。维护规则方面新增故事大纲 Markdown 模板和像素行走图提示词模板，并把“不说明 side 时默认不分叉”的约束写入 `AGENTS.md`。

界面方面，故事节点只有在配置了关联内容后才显示对应标签。关联 CG 采用单封面列表，点击后打开大图并在大图内切换差分；关联玩法采用只读弹窗，一个故事条目可以列出多个玩法，不再允许在每个节点上临时搜索和勾选玩法。

## 实现思路

### 故事条目与模板

- JSON 继续负责节点结构、父子关系、顺序和 `gameplayRefs`。
- Markdown frontmatter 负责条目元信息，并增加 `cgRefs` 字段。
- Markdown 正文承载完整剧情说明，新增条目默认插入单向主链；只有用户明确指定时才使用 side。
- `docs/系统说明/故事大纲条目模板.md` 固定条目字段和正文骨架。
- `docs/系统说明/像素行走图生成提示词模板.md` 固定 5×4 行走图的版式要求，角色定制信息统一由参考图提供。

### 关联 CG

- `storyOutlineFrontmatter.js` 读取 Markdown 中的 `cgRefs`。
- `storyCgLinks.js` 根据 CG 标题解析图鉴条目，保持引用顺序、去重并忽略失效引用。
- 故事节点只在解析到有效 CG 后显示一个 `CG` 标签。
- 关联 CG 弹窗每个条目只显示一张封面，不平铺全部差分。
- 点击封面打开大图；差分按钮只在大图预览中出现，并支持关闭按钮、遮罩和 Esc 返回上层列表。

### 关联玩法

- 故事源通过 `gameplayRefs` 保存一个或多个玩法 ID。
- 当前只有“人生模拟器”配置 `gameplay-118`，对应“命运人生推演”。
- 只有解析到有效玩法的节点才显示一个“关联玩法”标签。
- 点击标签打开只读列表，展示玩法名称、分类和简介；点击“查看玩法”后切换到玩法栏目并定位对应条目。
- 删除原先逐节点搜索、勾选、取消和保存关联的交互，避免运行时临时状态与正式故事源不一致。

## 遇到的问题与解决方法

### 新条目容易被误接成 side

旧约束只说明主线不要随意分支，但没有明确新节点插入已有单向链时如何处理。现在补充为：用户未指定 side 时，默认执行 `A → B → C` 式插入，并把原后继节点改挂到新节点下方。

### 关联 CG 弹窗一次展示全部差分

全部差分平铺会使关联栏目冗长，也混淆“CG 条目”和“图片差分”两个层级。现在列表只保留封面，差分统一放到大图预览中切换。

### 所有故事节点都能编辑关联玩法

原界面根据玩法目录是否存在显示入口，导致几乎每个故事节点都出现“关联玩法”，并允许产生只存在于页面状态中的临时配置。现在入口完全由节点已有的 `gameplayRefs` 决定，弹窗改为只读，并原生支持一个节点关联多个玩法。

## 合并记录：璃落房间自缚动作与分层立绘

## 本次实现思路

本次更新为璃落房间增加了一个地图动作入口：当主角处于 `liluo_room` 时，右侧信息栏会自动出现“自缚”按钮。

这类按钮后续可能随地图、区域、剧情状态继续扩展，所以本次没有把按钮和选项直接堆在 `GameView.vue` 里，而是把它整理成“地图动作配置 -> 动作按钮栏 -> 动作选项框 -> 运行时效果”的链路：

- 地图动作数据统一放在 `src/game/data/mapPanelActions.ts`。
- 右侧动作栏由 `GameMapActionPanel.vue` 渲染，并保持与既有“离开房间”按钮栏一致的视觉形式。
- 需要二级选择时，由 `GameMapActionChoiceDialog.vue` 弹出选项框。
- `GameView.vue` 只负责接收动作事件、打开选项框、应用选择结果和同步 UI 覆盖层状态。

当前“自缚”动作只有一个选项：“日式捆绑”。选择后会：

- 将左侧人物立绘切换为分层立绘。
- 给主角运行时状态追加 `hands_bound`。
- 在消息区域给出提示：“璃落完成了日式捆绑，双手已经被牢牢束住。”

## 开发过程中遇到的问题

### 问题 1：地图动作不能继续堆在 GameView

**现象：**

“自缚”只是第一个地图动作。后续不同房间、不同区域、不同剧情状态都可能给右侧动作区增加按钮。如果直接写在 `GameView.vue`，入口组件会越来越难维护。

**解决方法：**

新增 `mapPanelActions.ts` 作为地图动作配置入口，再用 `GameMapActionPanel.vue` 和 `GameMapActionChoiceDialog.vue` 承担具体 UI。`GameView.vue` 保留调度职责，不直接沉淀每个动作的显示细节。

### 问题 2：自缚按钮需要和离开房间按钮协调

**现象：**

角色站在门口时，右侧栏已经会出现“离开房间”。如果“自缚”使用另一套按钮样式或容器，右侧区域会显得割裂。

**解决方法：**

让地图动作按钮进入同一个右侧信息栏结构，并复用既有动作按钮的视觉形式。这样“自缚”和“离开房间”同时出现时，是同一组动作区块中的并列操作。

### 问题 3：原有左侧立绘只支持单张图片

**现象：**

“日式捆绑”需要由头、腿、裙子、双臂缚、胸部缚多张图片组合。如果继续只传 `src`，就必须先产出一张整图，不方便后续复用局部素材。

**解决方法：**

在 `DialoguePortraitData` 中增加可选的 `layers`。`GamePortraitPanel` 和人物菜单面板在有 `layers` 时按图层顺序叠加渲染，没有 `layers` 时继续使用原来的单图模式。

### 问题 4：选择动作后需要同时改外观、状态和提示

**现象：**

自缚不是单纯换一张图，还会影响主角状态。用户选择后如果没有提示，也不容易确认动作已经生效。

**解决方法：**

地图动作选项支持声明结果：

- `playerPortraitKey`：切换主角立绘。
- `appendPlayerStatus`：追加运行时状态。
- `resultNotification`：推送结果提示。

当前“日式捆绑”会切换到 `portrait_liluo_japanese_binding`，追加 `hands_bound`，并显示完成提示。
