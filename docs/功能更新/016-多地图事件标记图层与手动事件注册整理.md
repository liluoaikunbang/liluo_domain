# 多地图事件标记图层与手动事件注册整理

## 本次实现思路

这次调整的重点，是把“手动交互事件”的注册方式从**直接写死坐标**，整理成更适合后续多地图扩展的方案。

原先 `events.json` 里的手动事件主要依赖：

- `zone`
- `zones`

也就是在数据里直接写 `tileX / tileY`。这种方式在单张地图、少量事件时还算直观，但地图一多、地块一改、事件点要整体挪动时，就会出现几个问题：

- 事件配置和地图编辑器里的实际标记容易脱节；
- 同一个入口如果占多个 tile，要在 JSON 里手填一串坐标；
- 后续新地图扩展时，事件注册逻辑会越来越依赖“人工对坐标”。

所以这次改成：

1. 保留旧的 `zone / zones` 兼容能力；
2. 新增按事件标记图层注册的方式：`tileMarker / tileMarkers`；
3. 运行时在进入地图后，自动扫描对应事件图层里的非空 tile，生成当前地图的手动事件注册表；
4. 同时把 `_event` 图层从地图渲染、内容边界计算里排除，避免它们作为可见图层或内容范围参与场景逻辑。

这样后面做多地图时，优先在 Tiled 里用 `House_event`、`Portal_event` 这类图层标记事件范围，再在 `events.json` 里声明“哪个事件绑定哪个图层”就够了，扩展成本会低很多。

## 具体实现说明

### 1. 事件注册从“直接查坐标”改为“先建当前地图注册表”

这次没有继续把“事件查询”写散在 `WorldScene` 或 `playerController` 里，而是新增了 `manualEventRegistry.ts` 专门处理这件事。

进入地图时会执行：

1. 读取当前 `mapId` 下所有 `triggerType === manual` 的事件；
2. 如果事件配置了 `zone / zones`，就直接注册这些 tile；
3. 如果事件配置了 `tileMarker / tileMarkers`，就去对应图层扫描所有非空 tile；
4. 最后统一生成当前地图的：
   - 可交互 tile key 集合；
   - 某个 tile 上能触发哪些事件的映射。

这样做的好处是：

- 地图运行时只构建一次，不需要每帧重新扫事件数据；
- 场景层和角色控制层只消费结果，不再自己拼逻辑；
- 后面多地图扩展时，也能继续沿用同一个运行时注册入口。

---

### 2. 保留坐标注册兼容，同时新增图层注册

这次不是彻底砍掉旧结构，而是让事件数据同时支持两种写法：

- 旧写法：`zone / zones`
- 新写法：`tileMarker / tileMarkers`

其中 `tileMarker` 结构为：

```json
{
  "mapId": "liluo_estate",
  "layerName": "House_event"
}
```

这样即使后面某些旧地图暂时还是靠坐标注册，也不会被这次改动打断；而新地图、新事件则可以优先改用图层标记方式。

这一步的目标不是“一次性强制迁移全部地图”，而是先把扩展路径铺好。

---

### 3. `_event` 图层不再参与正常渲染和内容边界计算

既然事件图层现在成为运行时注册来源，就不能再把它们当成普通可视 tile layer 使用。

所以这次统一抽了 `shouldHideRuntimeTileLayer(...)`，把以下图层从运行时可视内容里排除：

- `collision`
- 所有以 `_event` 结尾的图层

这一步同时影响了几个地方：

- `tileLayerRenderer.ts`：不渲染事件标记图层；
- `cameraLayout.ts`：不把事件标记图层算进内容边界；
- `runtimeMapNormalizer.ts`：运行时裁边时，也不再让 `_event` 图层决定地图内容范围。

这样处理后，事件图层会彻底回到“逻辑标记层”的角色，不会污染画面和镜头计算。

---

### 4. 璃落庄园三个入口事件改为按图层接入

这次一并把用户提到的三个事件换成图层绑定：

- `House_event` 地块 -> `estate_house_entry`
  - action: `enter_estate_house`
- `Hole_event` 地块 -> `north_cave_entry`
  - action: `enter_north_cave`
- `Portal_event` 地块 -> `empire_portal_entry`
  - action: `empire_portal_entry`

对应地，`src/game/data/liluo_estate/events.json` 不再维护一串传送门入口坐标，而是直接绑定图层名。

后面如果地图中入口 tile 稍微调整，只要在 Tiled 里改对应 `_event` 图层，不需要再回头修改事件 JSON 里的坐标数组。

## 开发过程中遇到的问题

### 问题 1：如果只改事件查询，不改运行时图层筛选，事件标记图层会被渲染出来

如果只是新增 `tileMarker` 读取能力，而不处理 `_event` 图层的显示问题，那么这些专门用来标记事件的 tile 仍然会作为普通图层渲染到地图上。

### 解决方法

统一增加 `shouldHideRuntimeTileLayer(...)`，让 `_event` 图层在渲染、内容边界计算、运行时内容识别里都被排除。

---

### 问题 2：如果只保留图层注册，会让旧坐标事件失去兼容性

当前项目已经在逐步扩地图，直接一次性把所有事件都强制改成图层注册风险比较高，也不利于渐进迭代。

### 解决方法

保留 `zone / zones`，同时新增 `tileMarker / tileMarkers`。运行时注册时统一合并两种来源，这样旧地图不受影响，新地图可以优先用新方式。

---

### 问题 3：多 tile 入口如果继续手填坐标，维护成本会越来越高

传送门这类入口经常不是单 tile，如果还是手写 `zones`，地图一改就要同步改一串坐标，容易漏。

### 解决方法

改为扫描事件标记图层上的全部非空 tile，把图层本身作为“入口范围”的真实来源。以后只维护地图，不再重复维护一份坐标清单。
