# 地图时间遮罩切换与黄昏事件接入

## 本次实现思路

这次补录对应的是后续修正：

原先庭院里的“时间”和“天气”虽然都已经能切，但它们实际上共用了同一套互斥环境状态，结果就是：

- 切到雨天时，会把黄昏 / 夜晚直接顶掉；
- 切回白天时，也会顺手把天气一起清掉；
- 设定上明明应该是“任何天气下都有昼夜变化，任何时间下都能叠加天气”，运行时却做成了二选一。

这次调整的核心，就是把环境状态从“单一环境 ID”改成“时间 + 天气”两个独立维度：

1. 时间只负责白天 / 黄昏 / 夜晚；
2. 天气只负责晴朗 / 雨天 / 雾天；
3. 地图最终遮罩由两边配置叠加生成；
4. 事件、对话、场景桥接同步补上独立的天气切换入口；
5. 原有渐变过渡逻辑继续保留，叠加后的环境切换仍然是平滑变化。

这样处理后，庭院环境终于符合原本的设定语义：

- 可以是“夜晚 + 雨天”；
- 可以是“黄昏 + 雾天”；
- 只改时间时不会把天气清掉；
- 只改天气时不会把昼夜状态顶掉。

## 具体实现说明

### 1. 把“时间”和“天气”从同一组 ID 里拆开

之前的环境数据把：

- `day`
- `dusk`
- `night`
- `rain`
- `fog`

全都放在同一个 `TimeOfDayId` 里。

这在最初做环境切换时虽然省事，但问题很明显：

- `night` 和 `rain` 在语义上根本不是同一维度；
- 一旦底层只有一个当前状态，就天然只能互相覆盖；
- 后续想支持“夜雨”“薄雾黄昏”时，结构会越来越别扭。

所以这次先把数据层拆正：

- 时间：`day / dusk / night`
- 天气：`clear / rain / fog`

这样运行时不再去理解“rain 到底算时间还是天气”，而是明确知道：

- 时间永远有一个值；
- 天气永远也有一个值；
- 画面表现由这两个值共同决定。

---

### 2. 新增环境组合状态整理层

这次没有把“叠加逻辑”直接塞进对话、事件或场景代码里，而是新增了 `environmentOverlayState.ts` 作为中间整理层。

它主要做三件事：

1. 给出默认环境状态：`day + clear`；
2. 在收到“只改时间”或“只改天气”的请求时，生成新的完整环境状态；
3. 把时间遮罩层和天气遮罩层拼成最终渲染层数组。

例如：

- `night + clear` → 只使用夜晚主遮罩；
- `day + rain` → 只使用雨天双层冷灰遮罩；
- `night + rain` → 先叠夜晚，再叠雨天两层；
- `dusk + fog` → 先叠黄昏，再叠雾天两层。

这样做之后，控制器本身只需要处理“最终层数组如何过渡”，而不用到处散落“如果是雨天就怎样、如果是夜晚又怎样”的分支。

---

### 3. 环境遮罩控制器改成维护完整状态

`timeOfDayOverlay.ts` 原先内部只维护一个活动时间状态。现在改成维护完整环境状态：

- `activeEnvironmentState.timeOfDayId`
- `activeEnvironmentState.weatherId`

对外也从单一入口扩成两个入口：

- `setTimeOfDay(...)`
- `setWeather(...)`

这两个入口都会先生成新的完整环境状态，再把它转换成目标遮罩层，然后复用已有 tween 逻辑完成平滑过渡。

因此这次并不是把旧渐变方案推翻重写，而是在保留原有优点的基础上，把“目标状态来源”升级成了可组合的结构。

---

### 4. 事件和对话执行链路补上独立天气入口

光底层能叠加还不够，如果内容层仍然把雨天、雾天写成 `timeOfDayChange`，那运行时依然会走错语义。

所以这次把内容执行链路也一起补齐：

- `EventExecutionContext` 增加 `setWeather`；
- `eventExecution.ts` 支持 `weatherChange`；
- `dialogueExecution.ts` 支持 `weatherChange`；
- `EventRunner.ts` 的类型声明同步扩展；
- `GameView.vue` 新增 `applyWeatherChoice(...)`；
- `WorldScene` / `WorldSceneRuntime` 新增 `setWeather(...)` 桥接。

这样一来：

- 时间选项只调时间；
- 天气选项只调天气；
- 两者都不会再误伤对方当前状态。

---

### 5. 璃音天气分支的数据语义改正

之前璃音的“雨天 / 雾天”分支虽然表面上能切效果，但底层写法其实是：

- `timeOfDayChange: { timeOfDayId: 'rain' }`
- `timeOfDayChange: { timeOfDayId: 'fog' }`

这等于是把天气硬塞进时间切换口，结果当然会覆盖当前昼夜状态。

这次改成：

- `weatherChange: { weatherId: 'rain' }`
- `weatherChange: { weatherId: 'fog' }`

改完后，璃音这段对话才真正符合现在的设计：

- “调整时间”改的是天色；
- “调整天气”添的是环境气氛。

---

### 6. 用测试把“叠加关系”固定下来

这次不是只改代码逻辑，也补了直接对应 bug 的测试。

新增测试重点包括：

- `night + rain` 会生成叠加后的三层遮罩；
- 只修改时间时，原有天气状态会被保留；
- 默认环境状态会回到 `day + clear`；
- 对话里的天气切换会走 `setWeather(...)` 而不是误走时间上下文。

这些测试的意义，不只是证明本次修好了，也是在后续继续扩环境表现时，防止再次回退成“互斥状态”。

## 开发过程中遇到的问题

### 问题 1：时间和天气在设定上独立，但底层状态是互斥的

之前代码把雨天、雾天直接并进时间状态，导致切任何一个天气都会覆盖当前昼夜状态。

### 解决方法

从数据层开始拆分：

- `TimeOfDayId` 只保留昼夜相关状态；
- 新增 `WeatherId` 和 `weatherRegistry`；
- 运行时统一维护组合环境状态。

---

### 问题 2：叠加后不能只靠单一配置源生成目标遮罩

原先控制器只需要把“当前环境 ID”映射成一组层配置；但拆成时间和天气后，目标遮罩必须来自两套配置叠加。

### 解决方法

新增 `environmentOverlayState.ts`，专门负责：

- 解析默认环境；
- 应用局部变化；
- 构建最终叠加层数组；
- 统一计算过渡时长。

把组合逻辑从渲染控制器里抽出来后，整体职责更清楚，也更方便以后继续扩展。

---

### 问题 3：内容层已经把天气写进了时间切换字段

如果只修底层，不改对话和事件数据，天气分支还是会沿用旧接口，实际行为依然不对。

### 解决方法

把事件 / 对话执行链路统一补成双入口，并把璃音天气分支数据改为显式 `weatherChange`，保证内容表达和运行时语义一致。

---

### 问题 4：修完后需要有明确回归验证，避免以后再混回去

这种 bug 很容易在未来继续加天气或环境状态时被重新写坏。

### 解决方法

新增独立测试，直接验证：

- 环境层构建结果；
- 局部切换对另一维状态的保留；
- 天气副作用是否走独立上下文。

这样后面再动环境系统时，有一层基础保护。

---

- 任意时间下都可以继续叠加天气遮罩；
- `night + rain`、`dusk + fog` 这类组合状态现在都能成立；
- 只改时间时，不会把当前天气清掉；
- 只改天气时，不会把当前昼夜状态顶掉；
- 璃音天气分支已经改为独立 `weatherChange` 语义；
- 渐变过渡逻辑继续保留，叠加态下切换仍然平滑；

  - `node --test scripts/tests/environment-overlay-state.test.mjs scripts/tests/event-runner.test.mjs`
