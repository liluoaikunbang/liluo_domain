# 璃落主角独立帧缓存行走图

> 当前主角行走图已继续演进为分层动态图层正式方案，维护入口见 `docs/功能更新/115-主角行走图动态图层拼接规范.md`。其中切图脚本已整理为 `scripts/assets/build-liluo-character-frames.ps1`，npm 入口为 `assets:build-liluo-character-frames`。

## 当时方案

主角地图行走图以 `src/assets/game/sprite/liluo.png` 作为唯一母版。母版固定为 4 行 × 5 列：方向依次为 down、left、right、up；每行第 1 帧为待机，第 2 至第 5 帧为行走。

资源脚本首次处理母版时，会先将纯绿色背景转为透明，再识别每一帧的有效人物矩形，校验结果必须是 20 帧。每一帧按有效矩形的水平中心和脚底统一对齐到固定画布后，写入与母版同名的目录：`src/assets/game/sprite/liluo/`。

缓存帧命名固定为：

- `<direction>_idle.png`
- `<direction>_walk_1.png` 至 `<direction>_walk_4.png`

例如 `down_idle.png`、`left_walk_3.png`。游戏运行时直接加载这 20 张独立图片并组成动画，不再依赖合成运行图。

## 缓存与重建规则

- `npm run dev` 和 `npm run build:web` 会先执行帧缓存脚本。
- 同名目录存在、20 个预期文件齐全，且每张帧图不早于母版时，直接复用缓存。
- 母版更新、目录缺失或任一帧缺失时，自动重新识别并生成完整的 20 帧。
- 不生成 32×48 图、合成 `walk` 图或调试图；母版和同名帧目录是当前唯一的生成产物。

脚本接受源图相对路径参数，因此后续 NPC 也可以复用相同的“母版 → 同名帧目录”流程。

## 遇到的问题与解决方法

问题：原始母版包含透明留白，不能直接按等分网格当作人物实际边界；同时单独按每帧尺寸缩放会导致各方向和各动作的角色位置不稳定。

解决：先用 alpha 通道提取每帧有效矩形，必要时先去除纯绿色背景；然后保留人物像素，仅以有效矩形确定水平中心与脚底基线，输出统一尺寸的独立帧。运行时切换纹理时，角色的显示基线保持一致。
