# 072-人物状态信息框与状态说明

## 实现思路

本次在人物框左侧状态图标上补充了状态信息框。每个状态图标都可以作为入口展示状态名称、状态描述和功能信息：桌面端鼠标悬停时显示，移开后隐藏；点击图标时固定显示，再点击状态图标列表以外的位置或按 `Esc` 后关闭，用来兼容移动端触控操作。

状态信息仍然以 `src/game/data/playerStatus.ts` 作为单一来源。状态定义在原有 `id`、`label`、`iconUrl` 的基础上补充 `description` 和 `functionInfo`，由 `GameView` 解析当前运行态状态后透传给人物框。这样后续地图事件、对话分支和存档仍然只需要维护状态 id，UI 展示文案则集中在状态表里继续扩展。

状态描述文案改成偏状态栏说明的写法，避免写成系统设计说明，也避免承诺“越走越痛”这类渐变机制。当前说明主要表达状态带来的即时影响：未穿鞋和赤脚影响移动，双手被缚限制动作并轻微影响平衡，双腿被缚限制移动并保留跳动可能，禁锢固定位置，蒙眼失去视觉，封嘴只能发出含混声音。功能信息暂时保留占位，用于之后接入真实系统效果。

## 相关代码路径

- `src/game/data/playerStatus.ts`
  - `PlayerStatusDefinition` 增加 `description` 和 `functionInfo` 字段。
  - 为未穿鞋、赤脚、双手被缚、双腿被缚、禁言、失明、禁锢补充状态说明与功能占位。
- `src/game/views/GameView.vue`
  - `playerStatusIcons` 透传 `description` 和 `functionInfo`，让人物框组件不用再反查状态表。
- `src/game/views/shell/GamePortraitPanel.vue`
  - 状态图标从静态容器改为可点击按钮。
  - 增加状态信息框结构，展示名称、描述和功能信息。
  - 通过 CSS `:hover` / `:focus-visible` 支持悬停显示。
  - 通过 `pinnedStatusId` 支持点击固定显示，并用全局 `click`、`touchstart`、`keydown` 处理点外部和 Esc 关闭。

## 遇到的问题与解决方法

### 1. 悬停显示不稳定

问题：最初使用 `pointerenter` / `pointerleave` 管理悬停状态，但实际测试中鼠标放到状态图标上没有稳定弹出。

解决：把悬停显示改成 CSS 控制：`.portrait-status-icon:hover .portrait-status-popover` 直接显示信息框。这样悬停逻辑不依赖 Vue 状态，也不会受 pointer 事件兼容差异影响。

### 2. 点击非图标区域后信息框没有关闭

问题：第一次实现时把整个人物立绘区域都判断为“内部点击”，导致点击立绘空白、地图或其他面板时，固定的信息框不会消失。

解决：把内部判断范围收紧到状态图标列表 `statusListRef`。只要点击目标不在状态图标列表内，就清空 `pinnedStatusId`。同时补充 `touchstart`，让移动端点击其他区域也能关闭。

### 3. 状态文案容易写成机制承诺

问题：早期状态描述里出现过“走得越久越痛”一类表达，容易让玩家理解成存在随时间或步数逐渐加重的机制，但当前系统并未实现这种渐变效果。

解决：将描述改成静态状态说明，只写“当前状态造成的行动影响”，不写持续累积、逐步加重或随时间变化的机制。功能效果仍放在 `functionInfo` 里作为后续系统接入占位。

### 4. 文案口吻需要避免开发说明感

问题：初版文案有“适合用于”“待接入”混在描述里的问题，读起来像开发备注，不像游戏内状态说明；之后又出现了“她”这类带主体称呼的表达，和状态栏客观说明风格不一致。

解决：`description` 只保留状态表现和直接影响，尽量使用中性说明，不写“她 / 璃落 / 角色”等称呼；开发占位统一放到 `functionInfo`。这样信息框上半部分更像游戏内文案，下半部分才是明确的功能占位。
