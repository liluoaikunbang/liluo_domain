# 地图 NPC 规则替换与角色缩放统一

## 实现思路

地图 JSON 继续只负责放置 `sprites_liluo` 占位图块，不直接写入具体角色外观。每张地图通过自己的 `meta.ts` 声明 NPC 替换规则，运行时再把相连的占位图块识别为一个 NPC，并按规则换成指定方向、状态和图层组合的角色帧。

庄园初始地图当前将 NPC 配置为朝右站立的 `bondage_legs_bound` 外观，即保留下身、头部等正常图层，同时叠加上身和腿部捆绑层。地图 JSON 没有改动。

地图级 `playerScale` 现在作为角色公共缩放参数，同时作用于主角和规则生成的 NPC；NPC 规则仍可通过自己的 `scale` 在公共缩放基础上做局部微调。

## 相关代码路径

- `src/game/data/registry.ts`
  - 定义地图 NPC 替换规则的数据结构。
- `src/game/data/maps/munika/liluo_estate/meta.ts`
  - 配置庄园地图的 `sprites_liluo` NPC 占位图替换规则。
- `src/game/systems/map/renderers/npcReplacementRenderer.ts`
  - 识别相连占位图块、解析角色拼图帧、计算落点与最终缩放。
- `src/game/systems/map/renderers/tileLayerRenderer.ts`
  - 渲染地图时仅跳过命中替换规则的占位图块。
- `src/game/systems/map/foregroundTileOverlay.ts`
  - 防止已替换的占位图块又在前景层重复出现。
- `src/game/systems/map/worldSceneRuntime.ts`
  - 组织 NPC 替换流程，并把同一个地图角色缩放参数传给主角和 NPC。
- `src/game/data/playerCharacter.ts`
  - 提供按外观、方向和状态解析最终角色帧纹理 key 的统一入口。
- `scripts/tests/npc-replacement-rendering.test.mjs`
  - 验证占位图识别、外观帧选择、局部隐藏和主角/NPC 缩放一致性。

## 遇到的问题与解决方法

### NPC 占位图不应直接写死为某种角色

如果直接修改地图 JSON，地图重新导出后容易覆盖配置，也不利于同一种占位图在不同地图中显示不同 NPC。

解决方法是在地图 `meta.ts` 中维护替换规则，地图 JSON 保持纯占位数据。

### 隐藏整个 NPC 图层会误伤其他地图内容

NPC 图层以后可能同时包含其他图块，不能因为替换一个 NPC 就隐藏整个图层。

解决方法是按 tileset 来源精确跳过 `sprites_liluo` 占位图块，并让基础图层和前景覆盖层共用同一判断。

### 主角缩小后 NPC 仍保持原尺寸

最初 NPC 只应用角色外观自身的 `scale` 和规则局部 `scale`，没有继承地图的 `playerScale`，因此两者在同一地图中比例不一致。

解决方法是把 `playerScale` 解释为地图角色公共缩放参数，NPC 最终缩放统一计算为：

`角色外观 scale × 地图角色 scale × NPC 规则 scale`

## 当前结论

地图 NPC 已从固定贴图切换为地图规则驱动的角色外观。主角和 NPC 复用同一套动态图层帧，并共享地图级缩放参数；新增 NPC 时无需修改地图 JSON，只需在对应地图配置中增加替换规则。
