# 065-任务栏树形列表与详情面板

## 实现思路

本次围绕旅途菜单里的“任务”栏目做了第一版 RPG 任务日志骨架。

任务栏从原来的通用占位卡片改成左右两区：左侧是可展开和收起的树形任务列表，右侧是当前选中任务的详情面板。左侧任务树按“主线任务 / 支线任务 / 伙伴人物 / 已完成”四个一级分类整理，其中“已完成”下面继续按主线、支线、伙伴人物分组，便于后续把已完成任务按来源沉淀到回顾记录里。

当前所有任务条目仍是占位数据，只负责建立展示结构和交互规则。后续接入真实任务系统时，可以把占位任务替换为玩家当前任务、伙伴事件和完成记录。

任务栏默认不展开任何分支，也不选中任何任务。只有玩家主动展开任务分类并选择任务后，右侧才显示对应任务详情。这样可以避免打开菜单时自动给玩家制造“已选中任务”的误导。

键盘控制使用一条统一的任务树导航序列。任务分支和任务条目都归入同一个 `quest-tree-items` 组，展开分支后按方向键向下会按视觉顺序进入分支内部任务，不再跳过任务直接移动到下一个分支。

## 开发过程中遇到的问题

### 1. 一开始把需求理解成了人物栏目

用户最初描述为“菜单中的人物栏目”，但随后明确修正为“任务栏目，不是人物栏目”。

解决方法：

- 不新增人物栏或角色资料页。
- 只针对菜单中已有的 `quests` tab 建立任务栏专属界面。
- 保持功能服务 RPG 的任务日志和冒险推进，而不是转向人物资料库。

### 2. 初版任务栏默认展开并选中了任务

第一版实现为了展示右侧详情，给 `expandedQuestBranchKeys` 和 `activeQuestTaskKey` 设置了默认值。这会导致打开任务栏时自动展开主线，并显示一个占位任务详情，不符合“默认应该不选中和开启任何一个任务”的要求。

解决方法：

- 将 `expandedQuestBranchKeys` 初始值改为空数组。
- 将 `activeQuestBranchKey` 和 `activeQuestTaskKey` 初始值改为空字符串。
- `activeQuestTask` 不再兜底返回第一个任务。
- 右侧详情面板增加“尚未选择任务”的空态提示。
- `clearActiveQuestState()` 在关闭菜单或切换栏目时重置任务树状态。

### 3. 展开分支后按下键选不中内部任务

第一版把任务分支放在 `quest-branches` 组，把任务条目放在 `quest-tasks` 组。键盘移动时 `moveLinearGroup()` 只会在当前组内移动，所以展开分支后按下键仍然只在分支按钮之间移动，无法进入视觉上位于下方的任务条目。

解决方法：

- 将分支按钮和任务条目统一标记为 `data-menu-group="quest-tree-items"`。
- 增加 `data-quest-kind="branch"` / `data-quest-kind="task"` 区分当前焦点类型。
- `handleMenuKeydown()` 根据 `data-quest-kind` 分派到分支或任务键盘处理函数。
- `↑ / ↓` 在 `quest-tree-items` 这个统一线性组里移动，让键盘顺序和视觉顺序保持一致。
- 展开分支时不再自动选中第一个任务，玩家需要继续按下键或点击任务来选中详情。

## 后续维护建议

1. 后续接入真实任务系统时，可以保留 `questSections` 的树形展示结构，将占位数据替换为玩家任务状态。
2. 任务详情建议从任务数据源提供标题、状态、摘要、阶段说明和完成记录，不要把正式任务文案硬编码在 UI 组件里。
3. 已完成任务可以继续按当前二级分类沉淀，后续如果新增地点任务或副本任务，再扩展二级分类即可。
4. 任务树键盘导航依赖统一的 `quest-tree-items` 组，后续新增嵌套层级时应继续保持视觉顺序和 DOM 顺序一致。
