# 旅途菜单地图栏图片版全图与贴边缩放

## 本次实现思路

本次是在 `084-旅途菜单地图栏与当前位置概览` 的基础上继续收口地图栏显示效果。

`084` 中的地图栏已经可以显示当前地图层级、概览和角色位置，但初版概览是根据 Tiled 图层采样出来的色块网格。用户实际查看后反馈：地图栏太简陋，希望能展示“全地图的图片版”，并且缩略图应该在不变形的前提下尽量放大到地图框边缘，剩余区域用黑色填充。

因此本次调整的目标是：

1. 把地图栏概览从色块采样改成真实 tileset 图片绘制。
2. 保持地图比例，不拉伸变形。
3. 让可见地图内容至少有一边贴住地图框边缘。
4. 黑色区域只作为比例不一致时的填充背景。
5. 不修改任何地图 `map.json` 数据。

---

## 相关代码路径

- `src/game/views/components/base/MapMenuPanel.vue`
  - 从当前地图注册条目读取 Tiled 数据和资源 bundle。
  - 使用 canvas 按 tileset 逐层绘制真实地图图片。
  - 跳过事件、碰撞、调试、寻路等非视觉图层。
  - 裁掉生成图片外围没有实际图块的空白区域。
  - 根据裁剪偏移重新计算当前位置箭头。
  - 使用 `ResizeObserver` 读取地图框实际尺寸，计算图片框等比贴边尺寸。

- `src/game/views/components/base/gameMenuOverlay.css`
  - 移除旧的色块网格样式。
  - 地图框背景改为黑色。
  - 增加真实地图图片框与像素图显示样式。

本次没有新增 `src/assets/game` 下的素材图片，因此不需要更新素材图片清单。

## 具体实现说明

### 1. 从色块网格改为真实地图图片

旧版 `MapMenuPanel.vue` 会把地图 tilelayer 采样成最多 `72 x 72` 的 DOM 网格，再按图层名推断地面、建筑、水面等颜色。

本次改为：

1. 读取当前地图注册条目的 `data`。
2. 使用 `normalizeRuntimeMapData()` 展开 chunk 地图数据。
3. 通过 `getTilesetForTileGid()` 找到 gid 对应的 tileset。
4. 根据地图资源 bundle 中的 texture key 找到实际图片 URL。
5. 用 `canvas.drawImage()` 把每个图块画到离屏 canvas。
6. 将 canvas 转成 PNG data URL 后显示在地图栏里。

这样地图栏看到的不再是概念色块，而是和 Phaser 地图同源的像素地图图像。

---

### 2. 菜单地图跳过运行标记图层

菜单地图只展示玩家应该看到的地图内容，因此生成图片和裁剪边界时会跳过以下图层名片段：

- `event`
- `collision`
- `debug`
- `path`

这些图层属于事件、碰撞或调试用途，不适合直接进入菜单地图，也不能拿来决定缩略图裁剪范围。

---

### 3. 裁剪掉图片内部空白

用户反馈地图框已经贴边，但实际地图内容仍然很小。排查后判断：问题不只是 CSS 缩放，而是生成出来的地图图片内部本身带着较大空白。

本次在绘制时记录所有实际画出的图块边界：

- `minX`
- `minY`
- `maxX`
- `maxY`

绘制完成后再生成一个裁剪后的 canvas，只保留真实有图块的区域。最终展示的是裁剪后的图片，而不是整张原始地图画布。

这样缩放时被放大的就是实际地图内容，而不是一张包含大量空白的 PNG。

---

### 4. 当前位置箭头按裁剪偏移重新计算

裁剪地图图片后，原来的坐标百分比不能再直接使用：

```js
currentPosition.x / mapPixelWidth
currentPosition.y / mapPixelHeight
```

否则角色箭头会按原始未裁剪画布定位，显示位置会偏移。

现在会先减去裁剪偏移：

```js
(currentPosition.x - offsetX) / croppedPixelWidth
(currentPosition.y - offsetY) / croppedPixelHeight
```

再转成 CSS 百分比。这样箭头仍然标在裁剪后的真实地图图像上。

---

### 5. 用实际容器尺寸计算贴边缩放

单靠 CSS `aspect-ratio` 和容器单位时，用户实际测试发现只有图片框边框贴边，内部地图内容仍然没有按预期放大。

本次改为在 Vue 组件中使用 `ResizeObserver` 监听地图框实际尺寸：

1. 读取地图框宽高。
2. 读取裁剪后地图图片宽高。
3. 按比例计算图片框尺寸。
4. 如果地图框更宽，则图片高度贴边。
5. 如果地图框更高，则图片宽度贴边。
6. 将计算结果写入图片框的 `width` / `height`。

这样显示规则更明确：地图内容不变形，且至少有一边触及地图框边缘。

## 开发过程中遇到的问题

### 问题 1：色块概览不够像 RPG 地图栏

**现象：**

地图栏可以显示概览，但视觉上更像调试网格，不像真正的地图册。

**解决方法：**

改为从 Tiled 数据和资源 bundle 派生真实地图图片，直接绘制 tileset 图块。

---

### 问题 2：只改外层地图框后，实际地图内容仍然小

**现象：**

地图框黑色区域已经按预期铺开，但可见地图内容仍然很小。

**原因：**

缩放目标是整张生成图片，而生成图片内部包含外围空白。即使图片框贴边，真实地图内容仍然只占图片内部一小块。

**解决方法：**

绘制后根据实际图块边界裁剪 canvas，只展示真实有内容的区域。

---

### 问题 3：裁剪后角色位置标记可能偏移

**现象：**

如果继续按原始地图像素宽高计算角色百分比，裁剪后的缩略图会让位置标记偏移。

**解决方法：**

在渲染结果中记录 `offsetX` 和 `offsetY`，计算位置标记时先减去裁剪偏移。

---

### 问题 4：CSS 容器单位在菜单嵌套布局里不够稳定

**现象：**

尝试用 CSS 容器单位和 `aspect-ratio` 让图片框自动贴边，但用户测试后仍然反馈实际地图内容没有放大。

**解决方法：**

改为组件主动读取地图框实际尺寸并计算图片框尺寸，减少浏览器布局推导的不确定性。

## 验证结果

本次实现后执行：

```powershell
npm run build:web
```

结果：构建通过。

构建过程中仍然存在既有提示：

```text
new URL("../../../../../assets/game/sucai/Modern/school/NPCs/student1.png", import.meta.url) doesn't exist at build time
```

该提示来自已有现代校园素材路径解析，不是本次地图栏图片版全图改动导致的问题。

用户已要求写入文档，因此将本次地图栏图片版全图与贴边缩放修正沉淀为功能更新记录。

## 当前实现结果

本次完成后，旅途菜单地图栏具备：

1. 真实 tileset 图片版地图概览。
2. 黑色地图框背景。
3. 裁剪后的实际地图内容。
4. 不变形的等比贴边缩放。
5. 基于裁剪偏移修正后的当前位置箭头。
6. 不修改地图 `map.json` 的派生式显示逻辑。

这个改动让地图栏更接近 RPG 菜单中的地图册，而不是临时调试概览。
