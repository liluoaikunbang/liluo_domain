# 旅途菜单故事栏无限画布与大纲数据源

## 本次实现思路

本次功能是在旅途菜单里补上“故事”栏目，并把它先做成可长期扩展的大纲浏览入口。

故事栏不是普通资料页，也不是单纯的文字列表，而是一个从左到右展开的树状无限画布：

- 根节点表示不同故事线或世界线，例如“慕妮卡帝国”“浮光掠影”“寂土挽歌”“尘寰问道”“星宇织梦”。
- 第二层节点表示分类段落，例如“街景一隅”“诡影侵临”“暗痕追迹”等。
- 第三层节点表示具体章节、事件或玩法大纲条目。

实现时把分类性质的信息集中写入一个 JSON 数据源，Vue 组件只负责读取、排布和展示，后续继续扩展故事大纲时优先改数据，不需要改组件结构。

故事画布当前支持：

- 横向和纵向滚动条。
- 鼠标拖拽移动视图。
- 缩小、放大、重置按钮。
- Ctrl / Command 加滚轮缩放。
- 节点展示状态、时间线、简介和玩法标签。

## 相关代码路径

- `src/game/data/global/gameMenuData.js`
  - 新增旅途菜单里的“故事”栏目入口。

- `src/game/data/global/storyOutlinePlaceholder.json`
  - 故事大纲的集中数据源。
  - 当前按 `world -> section -> 条目` 组织。
  - 已删除“命锁谕令”线，并把“慕妮卡帝国”提到根节点第一位。

- `src/game/views/components/base/GameMenuOverlay.vue`
  - 接入 `StoryMenuPanel`。
  - 当当前栏目为 `story` 时渲染故事画布。

- `src/game/views/components/base/StoryMenuPanel.vue`
  - 故事栏画布组件。
  - 负责把 JSON 树转换成画布节点和连线。
  - 负责拖拽、滚动、缩放和重置视图。

- `src/game/views/components/base/gameMenuOverlay.css`
  - 新增故事画布、节点、连线、缩放控件和移动端布局样式。

## 数据组织方式

当前 `storyOutlinePlaceholder.json` 的根节点是故事线：

```text
慕妮卡帝国 > 浮光掠影 > 寂土挽歌 > 尘寰问道 > 星宇织梦
```

单个具体条目常用字段包括：

- `world`：所属世界线。
- `section`：所属分类段落。
- `title`：节点标题。
- `status`：节点状态，例如“设定”“大纲”“大纲草稿”“预留”。
- `timeline`：时间线排序标识。
- `summary`：简介。
- `foreshadowing`：伏笔或铺垫信息。
- `tags`：玩法标签。
- `specialGameplay`：特殊玩法。
- `characters`：主要角色。
- `requiredAbilities`：需要的异能。
- `locations`：所在地点。
- `reference`：参考来源。

组件当前只展示其中一部分字段：标题、状态、时间线、简介、玩法标签和特殊玩法。其余字段先保留在 JSON 中，方便后续做详情面板、筛选、搜索或节点点击展开。

## 开发过程中遇到的问题

### 1. 故事栏不能继续用普通占位卡

最初“故事”栏目只是菜单里的一个占位入口，会走通用占位面板。

但用户后续明确要求故事栏整体是一个无限画布，并且要承载整个故事大纲。通用占位卡无法承接拖拽、缩放、滚动和树状排布，因此拆成了独立的 `StoryMenuPanel.vue`。

解决方式：

- 保留菜单栏入口在 `gameMenuData.js` 中。
- 新增 `StoryMenuPanel.vue` 作为故事栏专用面板。
- 在 `GameMenuOverlay.vue` 中对 `activeTab.key === 'story'` 单独分支渲染。

### 2. 分类信息不应写死在组件里

用户明确要求“这些分类性质的信息写入一个 JSON 就行”。

如果把 `world`、`section`、状态、时间线和标签写死在 Vue 组件中，后续继续补大纲会变得很难维护，也不符合项目里“数据放 data，视图只负责展示”的分层习惯。

解决方式：

- 把故事数据集中到 `src/game/data/global/storyOutlinePlaceholder.json`。
- Vue 组件只接收 `outline` 数据并递归排布。
- 节点展示内容从 JSON 字段读取。

### 3. 大纲节点数量增多后需要更大的节点与间距

从占位三四个节点扩展到几十个节点后，原本的节点尺寸和行距会显得拥挤，标签和时间线也容易挤压简介。

解决方式：

- 扩大节点宽度和高度。
- 增大列距与行距。
- 节点内增加状态 / 时间线行和标签区域。
- 标签只展示前几项，避免长文本撑破画布节点。

### 4. 命锁谕令与慕妮卡帝国的根线顺序调整

用户后续要求删除“命锁”线，并把“慕妮卡帝国”提到最前面。

解决方式：

- 从 JSON 根节点中删除 `world-0-fettered-decree`。
- 将 `world-4-monica-empire` 移到根数组第一位。
- 不改组件逻辑，因为画布排序完全由 JSON 根数组顺序决定。

```bash
npm run build:web
```

结果：构建通过。

同时验证 `storyOutlinePlaceholder.json` 可正常解析，当前根节点顺序为：

```text
慕妮卡帝国 > 浮光掠影 > 寂土挽歌 > 尘寰问道 > 星宇织梦
```

当前故事节点总数为 `48`。

构建过程中仍会出现既有的 `student1.png` 路径 warning，这不是本次故事栏改动引入的问题。

## 后续可继续扩展方向

- 给故事节点增加点击后的详情面板，展示伏笔、主要角色、地点、异能、参考来源等完整字段。
- 增加按世界线、状态、玩法标签筛选节点的能力。
- 增加搜索节点并自动移动画布到目标节点。
- 将 `storyOutlinePlaceholder.json` 从占位数据逐步拆分或升级为正式故事大纲注册表。
- 后续如果故事大纲规模继续扩大，可以考虑增加折叠 / 展开分支，避免一次性展示过多节点。
