# 旅途菜单故事栏表格视图

## 本次实现思路

本次是在 `092-旅途菜单故事栏无限画布与大纲数据源` 的基础上，继续给旅途菜单“故事”栏补充第三种查看方式。

原本故事栏已经有：

- 纵向画布视图
- 横向画布视图

这次新增：

- 表格视图

表格视图的目标不是替代无限画布，而是提供一种更适合快速扫描、核对大纲条目的目录式视图。画布继续负责展示故事节点之间的结构感，表格则负责把节点标题、状态、故事线、概要、标签和父子关系集中展示出来，方便后续整理大纲时查漏补缺。

实现时继续沿用现有 `storyOutlinePlaceholder.json` 数据源，没有新增第二套故事数据，也没有改动地图数据或 `src/game/data/global/storyOutlinePlaceholder.json` 的内容。

## 相关代码路径

- `src/game/views/components/base/StoryMenuPanel.vue`
  - 在原有 `vertical` / `horizontal` 布局模式之外新增 `table` 模式。
  - 通过 `isCanvasMode` 区分画布视图和表格视图。
  - 新增 `createTableRows`，把故事树递归整理成表格行。
  - 表格行保留当前节点标题，并补充直接父节点与当前子节点列。

- `src/game/views/components/base/gameMenuOverlay.css`
  - 将故事视图切换按钮从两项扩展为三项。
  - 新增表格容器、表格标题、滚动区、表头、行层级提示和列宽样式。
  - 表格视图保持在菜单卡片内部滚动，避免撑破旅途菜单布局。

## 具体实现说明

### 1. 展示模式扩展为三种

`StoryMenuPanel.vue` 中的 `layoutModeOptions` 增加了 `table`：

```text
纵向 / 横向 / 表格
```

纵向和横向仍然走原本的无限画布逻辑，保留拖拽、滚轮缩放、按钮缩放和重置视图。

表格模式则切换到独立的 `<table>` 结构，不显示画布缩放控件。这样可以避免用户在表格视图里看到对表格无意义的缩放按钮。

### 2. 表格行复用同一份故事树数据

表格数据没有另建 JSON，而是通过 `createTableRows(outline)` 从传入的 `outline` 树生成。

每一行代表一个故事节点，主要字段包括：

- `title`：当前节点标题。
- `status`：节点状态。
- `summary`：节点概要。
- `storyTags`：故事线标签。
- `tags`：普通玩法标签与特殊玩法。
- `parentTitle`：直接父节点标题。
- `depth`：节点深度，用于行左侧层级提示色。

这样后续继续补故事大纲时，只要更新 `storyOutlinePlaceholder.json`，三种视图都会同步得到新内容。

### 3. 表格列顺序按扫描优先级调整

表格最终列顺序为：

```text
标题 / 状态 / 故事线 / 概要 / 标签 / 父节点 / 子节点
```

中途曾经尝试把“章节”做成缩进列，后来根据实际使用反馈调整为：

- 去掉“时间”列。
- 不再通过缩进表达层级。
- 用“父节点 / 子节点”两列显式展示层级关系。
- 再额外补回第一列“标题”，让每行当前节点一眼可见。

其中“子节点”列当前显示当前节点标题，和“父节点”组合后用于核对直接上下级关系；第一列“标题”则用于表格主阅读顺序。

### 4. 表格标题和滚动区分离

表格视图顶部新增：

```text
故事大纲表格
```

这个标题放在滚动区外层，而不是放进表格内部。这样横向滚动表格时，标题不会跟着表格内容一起偏移，视觉上更像菜单里的一个稳定面板。

## 开发过程中遇到的问题

### 1. 只有画布视图时，大纲核对不够直接

画布适合展示结构和分支，但在节点多起来之后，如果只是想快速查看所有节点状态、简介和标签，需要不断拖动画布。

解决方法：

- 保留画布作为结构浏览入口。
- 新增表格视图作为目录式核对入口。
- 三种视图共用同一份 `outline` 数据，避免维护两套内容。

### 2. 表格初版缺少明确标题

初版表格直接出现在故事栏卡片里，顶部只有视图切换按钮，用户进入表格模式后缺少一个明确的内容标题。

解决方法：

- 在表格视图外层新增 `story-table-panel`。
- 在滚动区上方增加 `story-table-panel-title`，显示“故事大纲表格”。

### 3. 层级关系用缩进表达不够清楚

最初表格沿用了树形阅读习惯，在“章节”列里通过缩进表达父子层级。

但用户希望父子关系更明确，因此调整为独立列：

- `父节点`
- `子节点`

解决方法：

- `createTableRows` 递归时额外记录 `parentTitle`。
- 表格不再输出缩进样式。
- 父子列移动到表格最后，避免干扰前面主要信息的扫描。

### 4. 当前节点标题一度只出现在“子节点”列

父子列移动到最后后，表格第一列变成了状态，当前节点标题只在最后的“子节点”列里出现，阅读时不够自然。

解决方法：

- 新增第一列“标题”。
- 第一列使用当前节点标题作为主阅读入口。
- 最后的“父节点 / 子节点”继续保留，用于查看直接层级关系。
