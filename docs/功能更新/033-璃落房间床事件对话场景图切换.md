# 璃落房间床事件对话场景图切换

## 本次实现思路

这次要做的不是单纯给 `liluo_room` 的 `bed_event` 塞一张图，而是把“**事件触发后，对话期间把中间地图框从实时地图切到指定场景图**”这件事整理成可以继续复用的能力。

项目里原本已经有对话数据上的 `sceneImage` 字段，但这条链路没有真正接到中间地图框显示上，所以这次的重点分成了三层：

1. **数据层继续沿用 `dialogues.json` 的 `sceneImage.assetKey` 声明方式**；
2. **资源层把这类事件场景图放进地图自己的对话资源包里**，保证进入对应地图时才加载；
3. **界面层在 `GameView` 的中间地图区域增加对话场景图覆盖层**，只有对话开启且声明了 `sceneImage.assetKey` 时才显示。

这样处理后，`liluo_room_bed_event` 只是第一个落地案例。后续如果别的地图、别的事件也要在对话时切换成回忆图、特写图、插图或特殊场景图，只需要：

- 在对应 `dialogues.json` 里声明 `sceneImage.assetKey`；
- 在对应地图的 `dialogues.ts` 资源包里登记图片；
- 不需要再额外加一套 UI 或重新写死判断。

## 开发过程中遇到的问题

### 问题 1：事件场景图需要可复用，但不能把逻辑写死在床事件里

如果这次直接在 `GameView` 或事件执行器里写成“当事件是 `liluo_room_bed_event` 时显示 `Liluo_bed.png`”，当前虽然能跑，但以后每加一张事件图都得继续追加条件分支，最后会把事件层、资源层和 UI 层搅在一起。

### 解决方法

继续使用对话数据里的 `sceneImage.assetKey` 作为统一入口，不把 UI 绑定到具体事件 id 上。

这次只是把原本没接完的链路补完整：

- 对话决定“要不要显示场景图”；
- 资源包决定“图片在哪里、何时加载”；
- `GameView` 只负责“当前对话有图就显示”。

这样后续新增事件场景图时，只需要补数据和资源，不需要再改一遍显示层逻辑。

---

### 问题 2：这类图片不能一直全局加载，但也不能等点击事件时才临时拉取

如果把 `Liluo_bed.png` 放到全局资源里，会让只在 `liluo_room` 床事件里用到的图片长期常驻；但如果等点到床事件才动态再加载一次，又容易影响第一次触发时的流畅度，也会让事件执行链路变复杂。

### 解决方法

把这类图片归到**地图级对话资源包**，而不是全局资源包，也不是地图基础 tileset 资源包。

这次的具体做法是：

- 从 `src/game/data/liluo_room/assets.ts` 中移出床事件背景图；
- 放入 `src/game/data/liluo_room/dialogues.ts` 的 `liluoRoomDialogueAssetBundle`；
- 继续依靠 `registry.ts` 里 `mergeAssetBundles(liluoRoomAssetBundle, liluoRoomDialogueAssetBundle)` 的现有结构，在进入 `liluo_room` 时统一预加载。

这样既满足“不要一直全局加载”，又满足“进入地图时就准备好”。

---

### 问题 3：最初补丁里只接通了脚本逻辑，但 UI 模板没有真正插入覆盖层

第一次落补丁时，`GameView.vue` 的脚本和样式已经补上了，但中间地图区域模板里没有真正插入场景图覆盖层节点，结果会导致逻辑准备好了，界面上却看不到切图效果。

### 解决方法

再次补齐 `GameView.vue` 的 `#center` 插槽内容，在 `#phaser-game-container` 上方加入：

- `v-if="activeSceneImageSrc"` 的覆盖层容器；
- 实际展示图片的 `<img>` 节点；
- 保持 `pointer-events: none`，避免挡住原有 UI 操作。

补完后再通过测试和构建一起确认没有遗漏。

---

## 最终验证结果

本次改动后，当前已确认的结果是：

1. `liluo_room` 的 `bed_event` 对话可声明并使用场景图；
2. 对话显示期间，中间地图框会从地图画面切换为 `src/assets/game/backgrounds/Liluo_bed.png`；
3. 这套能力复用的是通用的 `sceneImage.assetKey` 链路，不是写死给床事件的单次实现；
4. 事件场景图已改为随 `liluo_room` 地图进入时预加载，而不是全局长期加载；
5. 相关测试与构建验证均已通过。

本次代码侧执行并通过了以下验证：

```bash
node --test scripts/tests/liluo-room-leave-event.test.mjs
npm run build:web
```

结果：

- `liluo-room-leave-event.test.mjs` 共 4 项测试全部通过；
- 新增测试已确认 `liluo_room_bed_dialogue.sceneImage` 与 `liluoRoomDialogueAssetBundle` 保持一致；
- `vite build` 构建通过；
- 构建产物中可以看到 `Liluo_bed-*.png` 已被正常打包。
