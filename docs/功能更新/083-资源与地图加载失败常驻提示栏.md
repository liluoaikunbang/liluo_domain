# 资源与地图加载失败常驻提示栏

## 本次实现思路

这次功能的目标，是让资源缺失、地图资源加载失败、地图初始化解析失败这类问题，不再只停留在浏览器控制台里，而是在游戏地图区域顶部给出明确、不会自动消失的错误提示。

实现时没有把它混进原有的短通知系统。原来的 `GameNotificationBar` 更适合“获得物品”“读档完成”这类会自动消失的即时反馈；加载失败属于需要玩家和开发者持续看见的问题，所以单独新增了一条运行时错误通道：

1. Phaser 侧在 `BootScene` 和 `MapLoadingScene` 捕获加载异常。
2. 通过 `createPhaserGame` 和 `usePhaserGameBridge` 把错误上报到 Vue 侧。
3. `GameView` 保存当前游戏会话内的运行时错误。
4. `MapMode` 在地图中心区域顶部渲染常驻错误栏。

这样后续继续扩展地图和资源时，如果某个资源路径写错、素材丢失或地图入口解析失败，游戏内能直接看到具体是哪类失败、对应的资源 key 或路径是什么。

## 相关代码路径

- `src/game/core/runtimeError.ts`
  - 新增 `GameRuntimeError` 结构。
  - 新增 Phaser 加载失败文件信息格式化工具。

- `src/game/core/createPhaserGame.ts`
  - 在 Phaser 创建参数里接入 `onRuntimeError` 回调。
  - 把错误回调传给 `BootScene` 和 `MapLoadingScene`。

- `src/game/scenes/BootScene.ts`
  - 捕获全局资源 `loaderror`。
  - 在控制台输出之外，同步上报“全局资源加载失败”。

- `src/game/scenes/MapLoadingScene.ts`
  - 捕获地图初始化解析失败。
  - 捕获地图资源 `loaderror`。
  - 在缺少已解析地图初始化数据时，上报明确错误再抛出异常。

- `src/game/views/composables/usePhaserGameBridge.ts`
  - 扩展 Phaser / Vue 桥接参数，允许传入运行时错误回调。

- `src/game/views/GameView.vue`
  - 新增 `runtimeErrors` 状态。
  - 每次收到运行时错误时追加记录。
  - 新开局、读档进入、组件卸载时清理当前会话错误。

- `src/game/views/modes/map/MapMode.vue`
  - 接收 `runtimeErrors`。
  - 在 Phaser 地图容器上层挂载错误栏。

- `src/game/views/components/base/GameRuntimeErrorBar.vue`
  - 新增常驻错误栏组件。
  - 使用 `role="alert"` 和 `aria-live="assertive"`，保证这是明确的错误状态。
  - 默认显示最近 3 条错误，防止大量资源失败时铺满整个画面。

## 开发过程中遇到的问题

### 问题 1：原有通知栏会自动消失，不适合加载失败

原有 `GameNotificationBar` 是面向普通游戏反馈的短通知，默认 3 秒后移除。资源缺失和地图加载失败如果也走这个通道，玩家很容易错过提示，开发时也不方便定位问题。

解决方式：

- 不改动原有短通知行为。
- 单独新增 `runtimeErrors` 和 `GameRuntimeErrorBar`。
- 错误栏不设置自动消失逻辑，只在重新进入游戏会话或卸载视图时清理。

### 问题 2：Phaser 加载错误原本只在 Scene 内部打印

`BootScene` 和 `MapLoadingScene` 原本只通过 `console.error` 输出加载失败，Vue 侧不知道发生了什么，因此无法在游戏 UI 中显示。

解决方式：

- 给 `createPhaserGame` 增加 `onRuntimeError` 回调参数。
- 创建场景实例时把回调传入 `BootScene` 和 `MapLoadingScene`。
- Scene 捕获 `loaderror` 后同时执行控制台输出和 UI 上报。

### 问题 3：地图解析失败发生在加载前，需要单独捕获

地图加载失败不只有资源文件 404。一些地图入口、注册表或初始化数据异常，会在 `resolveWorldSceneInitData` 阶段直接抛错，此时还没进入资源加载队列。

解决方式：

- 在 `MapLoadingScene.init` 中用 `try/catch` 包住地图初始化解析。
- 捕获后上报“地图加载失败”，再继续抛出原始异常，避免把真实问题吞掉。

## 后续维护建议

- 后续新增地图资源时，如果资源是 Phaser 动态加载资源，建议继续走 `queueAssetBundle` 和地图资源注册表，这样加载失败可以被统一捕获。
- 如果后面还有事件、对话、互动小说等运行时错误也需要游戏内常驻显示，可以复用 `GameRuntimeError` 通道，但要先区分“开发错误提示”和“玩家叙事提示”，不要让错误栏承担普通剧情反馈。
- 当前错误栏显示最近 3 条错误；如果后续需要调试大量资源，可以再增加展开详情或复制错误信息能力。
