# 181-项目图像生成判层与治理协议

- 创建日期：2026-08-02
- 更新时间：2026-08-02

## 更新时间记录

- 2026-08-02：把原先主要服务于官网海报的视觉反馈与 prompt 规则上升为全项目图像生成治理层，统一覆盖 `Image 2` 批次、Grok 草稿图与后续项目内图像生成链路。

## 本次目标

解决一个越来越明显的问题：项目里的图像规范会持续变多，但不能每次都把全部限制硬塞进同一条 prompt，也不能让不同模型、不同入口各自长出一套互相脱节的规则。

这次要做的不是“再补几条提示词”，而是把图像生成正式拆成：

1. 长期 authority
2. 按需 prompt 组装
3. 成图后 QA

并要求所有新增反馈先经过同一套判层协议，再决定应该落在哪一层。

## 这次具体做了什么

### 1. 新增项目级图像治理 authority

新增 `docs/系统说明/项目图像生成判层与治理系统.md`，把以下内容收口为唯一权威源：

- 图像反馈的四问判层协议
- `ruleKind / scopeLevel / persistence / enforcement` 规则卡字段
- authority / prompt / QA 三层落点规则
- 默认收窄原则
- 模型无关的 prompt 装配顺序
- 璃落项目级身份锚点
- `Image 2` 批次与 Grok live/dry-run 的不同执行方式

原 `docs/系统说明/官网海报视觉反馈归档系统.md` 保留为兼容页，不再承担当前 authority。

### 2. 新增共享治理模块

新增 `src/content/site/imageGenerationGovernance.js`，把项目级图像治理协议变成代码可调用的共享模块，提供：

- 规则卡枚举与判层标签
- 规则卡验证
- prompt 装配层顺序
- 璃落身份锚点规则
- 通用图像 prompt preflight

这层不再只给官网海报用，而是作为项目内图像生成链路的共享治理入口。

### 3. 让站点 Image 2 批次接入同一套协议

更新 `src/content/site/siteBlueprint.js` 与 `scripts/site/site-visual-pipeline.mjs`：

- `visualFeedbackLedger` 条目不再只是自由文本，而是改为结构化规则卡
- 每条规则卡补齐 `ruleKind`、`scopeLevel`、`persistence`、`enforcement`、`negativeExamples`、`promotionGate`
- `site-visual-pipeline` 现在会验证规则卡本身是否成立
- 璃落角色批次与 `Batch 00` 在原有硬校验之外，再跑一次共享治理 preflight
- 生成出来的 `visual-feedback-ledger` 与 `image2-prompt-authoring-standard` 文档同步改成项目级口径，不再只讲“海报页怎么写 prompt”

这意味着站点链路仍保留最严格的身份锚点校验，但它已经成为项目级协议在站点生产中的一种“严格执行模式”，而不是孤立特例。

### 4. 让 Grok 链路接入同一套协议

更新 `.agents/skills/liluo-project/liluo-grok-image-generation/scripts/grok-image.mjs`：

- `generate --dry-run` 现在会返回项目图像治理 preflight 结果
- `generate --live` 也会先跑同一套 preflight
- 如果 prompt 明确在生成璃落，却漏掉核心身份锚点，live 会直接阻断
- 如果只是探索阶段，则把问题留在 warning，先提醒补齐

这样 Grok 不再只是“把一句话润成一条 prompt”的孤立脚本，而是进入了和 `Image 2` 批次一致的治理体系。

### 5. 同步治理注册与用户入口

更新：

- `AGENTS.md`
- `docs/系统说明/README.md`
- `docs/系统说明/Grok图像生成API配置与提示词润色工作流.md`
- `docs/技能说明/liluo-grok-image-generation.md`
- `docs/用户命令目录.md`

把 authority 指向、消费者列表、用户入口说明与跨模型边界同步到新的项目级图像治理协议。

## 现在的执行模型

以后只要用户给出新的图像反馈或规范，都不再靠“感觉上像全局规则”来决定怎么写，而是先过规则卡：

- 它纠正的到底是什么类型的问题
- 它影响到多大范围
- 它要持续多久
- 它该落在 authority、prompt 还是 QA

只有完成这一步，才允许继续回写长期字段或升级到批次默认 prompt。

## 结果

- 站点批次与 Grok 链路现在共享同一套项目图像治理协议。
- 新规范不会再默认被硬塞进所有 prompt，而是先判定该不该进入 authority、prompt 或 QA。
- 璃落身份锚点不再只在海报页文档里生效，而是正式成为跨图像生成链路的一致约束。
