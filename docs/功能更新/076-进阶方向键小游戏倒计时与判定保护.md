# 076-进阶方向键小游戏倒计时与判定保护

## 实现思路

本次围绕进阶方向键小游戏补了三类体验保护：

1. 进阶节奏模式开始前增加 `3 / 2 / 1` 倒计时。倒计时期间小游戏处于 `countdown` 状态，中心画面显示遮罩，左侧方向键按钮禁用，键盘输入也不会被核心判定消费。
2. 修复键盘按键被处理两次的问题。原先中心视图模板和 `window` 同时监听 `keydown`，当焦点落在中心区域时一次按键会触发两次，导致一个错误输入连续影响前两个移动块。
3. 增加竖线前重复按键保护。移动块还没有到达竖线阈值时，多次按键只会覆盖当前移动块的临时判定，不会提前推进到后面的移动块；到达竖线后才结算当前块并切到下一块。

核心规则仍放在 `DirectionPadGameRunner` 中，Vue 组件只负责显示倒计时、滚动块、临时判定颜色，并把输入和过期检查交回运行器处理。这样键盘、左侧按钮和后续可能新增的触控输入都会走同一套判定逻辑。

另外，本批还完成了人物框状态图标列的标签文案微调：原来的“状态”改为“拘束 / 状态”两行显示，语义更贴近当前状态栏用途。

## 开发过程中遇到的问题

### 1. 倒计时不能只做成 UI 遮罩

如果倒计时只在 Vue 上显示遮罩，而核心状态仍然是 `playing`，键盘事件或后续其它输入入口仍可能直接调用运行器并消耗音符。

解决方法：

- 在运行器状态中增加 `countdown`。
- `pressDirection` 只在 `state.status === 'playing'` 时消费输入。
- 倒计时结束后由 `completeCountdown` 统一切换到 `playing`。
- 节奏模式真正的 `startedAtMs` 从倒计时结束时开始计算，避免倒计时期间移动块已经提前错过判定线。

### 2. 第一个按键按错后前两个移动块都变红

问题原因是 `GameDirectionPadView.vue` 同时存在两条键盘监听路径：

- 模板上的 `@keydown="handleKeyDown"`。
- `onMounted` 中注册的 `window.addEventListener('keydown', handleKeyDown)`。

当焦点在中心区域时，一次按键会先触发组件自身监听，再冒泡到 `window` 触发第二次。节奏判定每次按键都会消费当前音符，因此一个错误输入被连续消费了两次。

解决方法：

- 删除模板上的 `@keydown="handleKeyDown"`。
- 只保留 `window` 级监听，让小游戏不依赖中心区域焦点。
- 增加 `direction-pad-keyboard-listener.test.mjs` 检查该组件只保留一条键盘监听路径。

### 3. 竖线前多次按键会误伤后续移动块

原节奏模式中，每次按键都会直接向 `resolvedNotes` 追加一条判定结果，并把 `currentNoteIndex` 推进到下一个音符。这样玩家在第一个块还没过竖线时连续按几次，会把后面的块也提前判掉。

解决方法：

- 增加 `activeNote` 表示当前块的临时判定。
- 当 `timingOffsetMs < 0`，也就是移动块还没到竖线时，只更新 `activeNote`。
- 后续重复按键继续覆盖同一个 `activeNote`。
- 当动画帧检查到当前块已经到达竖线时，调用 `resolveExpiredNotes` 把 `activeNote` 推入 `resolvedNotes`。
- 只有 `resolvedNotes.length` 才代表已经正式推进到第几个块，`activeNote` 不再让后续块提前被消费。

## 后续注意

1. 节奏小游戏的输入消费规则应继续以 `DirectionPadGameRunner` 为准，避免 UI 单独维护判定状态。
2. 如果后续要把“过竖线才结算”改成“过判定窗口才结算”，应同步调整 `activeNote` 结算条件和测试预期。
3. 如果要增加连击、评级或音效，建议基于 `resolvedNotes` 做正式结算反馈，基于 `activeNote` 做当前块即时反馈。
4. 新增节奏小游戏时优先通过 `countdownDurationMs` 配置倒计时，不要在具体 Vue 组件中写死某个小游戏的等待时间。
