# 地图面包屑集中管理

## 本次实现思路

这次调整的目标，是把各张地图在旅途菜单地图栏中显示的层级路径，从 `src/game/data/registry.ts` 的地图注册项里拆出来，统一沉淀到 `src/game/data/maps` 下。

面包屑本质上描述的是地图在世界中的位置关系，例如“慕妮卡帝国 / 缚神领地 / 住宅区 / 小别墅”，它属于地图内容数据的一部分，不应该继续散落在注册表配置里。注册表仍然负责汇总地图入口，但具体的层级路径交给独立文件维护。

这次没有改动各地图的 `map.json`，也没有调整旅途菜单地图栏的显示组件，避免把纯数据整理扩散成 UI 或地图内容改造。

---

## 相关代码路径

- `src/game/data/maps/breadcrumbs.ts`
  - 本次新增。
  - 集中维护各地图 `mapId` 对应的面包屑层级。
  - 对外提供 `getMapBreadcrumb(mapId)`。

- `src/game/data/registry.ts`
  - 保留 `GameMapRegistryEntry.breadcrumb` 字段。
  - 不再直接内联每张地图的面包屑数组，改为通过 `getMapBreadcrumb(meta.id)` 读取。

- `src/game/views/components/base/MapMenuPanel.vue`
  - 本次未修改。
  - 继续从 `props.mapEntry?.breadcrumb` 读取并渲染面包屑。

## 具体实现说明

### 1. 新增地图面包屑数据文件

新增：

```text
src/game/data/maps/breadcrumbs.ts
```

文件中定义：

- `GameMapBreadcrumb`
- `mapBreadcrumbs`
- `getMapBreadcrumb(mapId)`

当前已经集中记录以下地图：

- `city_desire`
- `city_jingjiang_school`
- `liluo_estate`
- `liluo_house_living_room`
- `liluo_room`
- `mumu_room`

这样后续新增地图时，可以在地图数据目录体系下补充路径关系，而不是继续把世界层级写进注册表主体。

---

### 2. 注册表继续作为汇总入口，但不再直接管理路径文案

`src/game/data/registry.ts` 中仍然保留：

```ts
breadcrumb?: GameMapBreadcrumb;
```

每张地图注册项改为：

```ts
breadcrumb: getMapBreadcrumb(cityDesireMeta.id)
```

这样做的结果是：

- 对外结构不变，`MapMenuPanel` 等使用方无需调整。
- 面包屑数据集中到 `maps/breadcrumbs.ts`。
- `registry.ts` 的职责更接近“地图注册与资源汇总”，而不是承载地图世界观层级文案。

---

### 3. 显示端保持原有逻辑

旅途菜单地图栏原本已经通过 `mapEntry.breadcrumb` 渲染层级路径。

这次没有改动：

```text
src/game/views/components/base/MapMenuPanel.vue
```

原因是显示逻辑本身没有问题，需要整理的是数据来源。保持显示端不动，可以降低回归风险，也让这次改动更接近一次清晰的数据分层整理。

## 开发过程中遇到的问题

### 问题 1：面包屑原先和地图注册信息混在一起

**现象：**

`registry.ts` 里每张地图都直接写了 `breadcrumb: [...]`，随着地图继续增加，注册表会同时承担地图入口、资源、动画、渲染配置和世界层级文案，文件职责会越来越杂。

**解决方法：**

新增 `src/game/data/maps/breadcrumbs.ts`，把路径数据按 `mapId` 集中维护，注册表只按地图 id 读取结果。

---

### 问题 2：不希望为了整理面包屑改动地图原始数据

**现象：**

面包屑可以放进每张地图的 `meta.ts`，但它描述的是地图之间的层级关系，不完全是单张地图自身属性；同时项目约定中也提醒尽量不要随意改动地图数据主体。

**解决方法：**

没有修改各地图的 `map.json`，也没有把层级路径塞进单张地图的地图文件中，而是在 `maps` 目录下建立专门的 `breadcrumbs.ts` 作为地图关系数据入口。

---

### 问题 3：需要避免影响现有地图栏显示

**现象：**

旅途菜单地图栏已经依赖 `mapEntry.breadcrumb` 正常显示。如果直接改显示组件的数据结构，容易把一次数据整理扩大成 UI 改造。

**解决方法：**

保留 `GameMapRegistryEntry.breadcrumb` 字段和 `MapMenuPanel` 的读取方式，只改变 `registry.ts` 内部取值来源。这样外部行为保持一致。

## 后续维护建议

后续新增地图时，如果需要在旅途菜单地图栏显示层级路径，优先在：

```text
src/game/data/maps/breadcrumbs.ts
```

补充对应 `mapId` 的路径数组。

如果后面地图层级需要支持“可点击返回上级地图”或“区域、地点、房间、副本”这类更复杂关系，可以在这个文件的基础上把字符串数组扩展为结构化对象，但当前阶段先保持简单字符串数组即可。
