# 064-装备栏四区布局与键盘选中规则

## 实现思路

本次围绕旅途菜单里的“装备”栏目做了第一版 RPG 装备栏骨架。

装备栏从原来的通用占位卡片改成四区布局：左上是装备分栏，右上是当前分栏的装备条目列表，左下是真实人物立绘预览，右下是装备详情栏。装备条目使用连续列表而不是方格，后续接入真实装备数据时，可以自然替换当前占位条目。

左下预览区不再使用存档里的小行走帧，而是读取当前玩家运行时立绘，按比例缩小后放入装备预览框。这样如果剧情切换了主角立绘，装备栏里的预览也会跟着当前状态显示。

右下详情栏拆成两层：上方详情说明独立滚动，底部固定两个并列按钮：“穿戴（替换）装备”和“卸下装备”。目前按钮仅作为装备系统占位操作，不执行真实穿戴逻辑。

键盘控制也做了收口：装备栏默认不选中任何分栏或装备，只把焦点留给可操作控件。左侧分栏上下移动焦点不改变选中，只有按右键、回车或空格才选中分栏并进入右侧装备列表。

## 开发过程中遇到的问题

### 1. 初版装备栏仍像通用占位页

最初装备栏目沿用旅途菜单的通用占位分支，只能显示两张占位卡，无法表达 RPG 装备栏需要的分栏、列表、预览和详情层级。

解决方法：

- 为 `equipment` 单独建立模板分支。
- 将界面拆成“装备分栏 / 装备列表 / 立绘预览 / 装备详情”四块。
- 装备列表使用条目式连续列表，而不是背包式方格，贴合用户要求。

### 2. 立绘预览一开始用了小行走帧

早期预览区复用了存档当前进度栏的小 sprite 背景帧，人物过小，也不符合“人物立绘栏”的要求。

解决方法：

- 引入 `resolvePlayerRuntimePortrait()`。
- 装备预览区改用真实立绘 `<img>`。
- 使用 `object-fit: contain` 和尺寸上限，让立绘按比例缩小并固定在预览框内。

### 3. 四区比例需要反复收口

装备预览区最初显得人物偏小，左侧栏又偏宽；装备条目之间也有多余空隙，整体不够紧凑。

解决方法：

- 将装备左侧列逐步收窄到 `minmax(92px, 0.27fr)`。
- 提高底部预览行高度，压低上方列表区高度。
- 将装备条目改成一个连续列表框，条目之间只保留分隔线。
- 限制立绘最大宽度和高度，避免左栏被图片撑宽。

### 4. 默认选中和键盘控制混乱

装备栏一开始默认选中“武器”和第一件占位装备，并且复用了物品/技能的格子导航逻辑。这样会让“焦点移动”和“实际选中”混在一起，尤其是左侧分栏上下移动时容易误改右侧内容。

解决方法：

- 装备栏默认不选中任何分栏或装备。
- 移除装备分栏 `focus` 时自动选中的行为。
- 新增装备栏专用键盘规则：
  - 左侧分栏 `↑ / ↓` 只移动焦点。
  - 左侧分栏 `→ / Enter / Space` 才选择当前分栏，并进入装备列表。
  - 装备列表 `↑ / ↓` 在线性条目里移动。
  - 装备列表 `←` 回到当前分栏，`→` 进入底部操作按钮。
  - 操作按钮 `← / →` 在两个按钮之间移动，`↑` 回到当前装备条目。
- 没有选中装备时，底部穿戴和卸下按钮禁用。

## 后续维护建议

1. 后续接入真实装备系统时，可以保留当前 `equipmentCategories` 的展示层级，但将占位数据替换为玩家装备库存和已穿戴状态。
2. “穿戴（替换）装备”和“卸下装备”按钮目前只是 UI 骨架，后续应接入玩家运行时装备状态，并同步更新立绘或属性详情。
3. 如果未来装备会改变立绘外观，建议让装备详情或装备数据显式提供预览资源，不要在 UI 层硬编码外观切换逻辑。
4. 装备栏键盘规则已经和物品/技能分开，后续维护时不要再直接套用格子导航，避免默认选中和焦点移动再次混乱。
