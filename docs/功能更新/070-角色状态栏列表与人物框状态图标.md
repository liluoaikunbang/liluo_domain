# 070-角色状态栏列表与人物框状态图标

## 实现思路

本次把角色“状态”从临时文字改成了可扩展的数据列表：状态定义集中放在 `src/game/data/playerStatus.ts`，角色运行时只保存状态 id，展示时再从状态表解析中文名称与图标资源。这样后续剧情、事件或菜单只需要写入状态 id，就能统一得到存档、状态文字和图标展示。

璃音的“功能测试”分支新增了“测试人物状态”选项，会一次性把当前状态表里的全部状态写到主角身上，用来快速确认状态写入和 UI 展示是否正常。旧的“拘束睡袋”不再作为角色状态写入；床事件仍可保留对应剧情和外观切换，但不再污染状态列表。

人物框左侧新增状态图标列：当角色存在状态时，左上角显示“状态”文字，下面从上往下排列所有状态图标。图标使用深粉边框和白底，图片缩放改为 `image-rendering: auto`，让浏览器平滑压缩大图资源。

## 遇到的问题与解决方法

### 1. 状态文字和状态定义混在一起

问题：早期状态只是运行时字符串，例如“自由”或旧的“拘束睡袋”，后续继续扩展会导致剧情、存档和 UI 各自拼状态文字。

解决：新增 `playerStatusDefinitions`，让运行时保存状态 id，展示时通过状态表解析 label 和 icon。事件或测试可以写中文 label，也可以写 id，最终都会规范成状态 id。

### 2. 旧状态不应继续兼容

问题：“拘束睡袋”属于旧的床事件状态文本，如果继续过滤兼容，会让旧状态入口看起来仍然存在。

解决：从床事件中删除写入 `playerStatusChange: ["拘束睡袋"]` 的逻辑。状态规范化只保留状态表中的状态，旧状态不会再进入运行时和存档。

### 3. 状态图标需要跟随人物框，而不是散落在页面里

问题：状态是角色动态信息，如果放在其他 UI 区域，会削弱人物框本身作为角色状态面板的作用。

解决：由 `GameView` 统一解析当前角色状态图标，再经 `MapMode` / `InteractiveFictionMode` / `GameShell` 传入 `GamePortraitPanel`，由人物框组件自己渲染左侧状态列。

### 4. 大图缩小后小图标不够清楚

问题：当前状态图片大多是 600px 到 1024px 的图像，缩到几十像素时细节会被压缩，容易看不清。

解决：先将 `image-rendering` 从 `pixelated` 改为 `auto`，让浏览器平滑缩放。后续如果要进一步提升可辨识度，建议单独制作 32px / 48px 级别的小图标版本，减少细节、加粗轮廓。
