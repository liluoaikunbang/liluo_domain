# 180-大型视觉海报官网升级与运行时视觉计划体系
日期：2026-08-02

## 背景

`178-GitHub Pages 官网结构化扩展` 已经把 README 海报页扩展成结构化官网，但站点仍然主要依赖单体 `siteData.js` 和单页实现，难以继续承载真正的大规模视觉计划、截图证据任务与批次推进。用户这次要求直接把官网升级成更像“长期视觉展台”的形态，并明确要求落实 1000+ 视觉元素级别的海报页升级。

## 实现内容

- 新增 `src/content/site/sitePlanRuntime.js`，把官网公开素材、1248 条视觉计划、96 条截图任务、52 个生成批次、六界统计与首页指标统一收敛到运行时数据层。
- 新增 `src/components/site/SiteShellPoster.vue`，绕开旧站点壳子，重做亮色、长滚动、海报感更强的官网外壳，并保留 `/game` 作为正式旗舰入口。
- 新增 `src/pages/SitePosterPage.vue`，重构首页、六界总览、世界详情、系列页、角色页、图鉴、证据、生产体系、路线图、开发日志与协作页。
- 将 `src/router/index.js` 与 `src/readme-pages-main.js` 的 Pages 站点入口切换到 `SitePosterPage.vue`。
- 将 `src/content/site/siteCatalog.js` 改为读取运行时视觉计划层，而不再依赖当前环境中难以安全写入的中间 JSON 目录。
- 新增 `scripts/site/validate-site-runtime.mjs`，对视觉计划数量、截图任务数量、素材路径、路由矩阵和预览素材引用做统一校验。
- 更新 `package.json` 中的 `site:content:validate`、`site:assets:validate` 与 `site:build`，使官网校验与构建走新的运行时数据链路。

## 约束与处理

- 当前环境对 `src/content/site` 下新增子目录与脚本直接写入存在 `EPERM / Access denied` 限制，因此本轮没有继续依赖“先生成 JSON 再供前端导入”的目录式方案。
- 视觉计划和截图计划仍然保持结构化、可统计、可校验，但改为在前端运行时直接生成，避免把执行成败绑定到受限目录写入。
- `/game` 入口继续保留在站点导航、首页 CTA 和证据说明里，官网不替代正式旗舰体验。
- 真实截图、文档图板与概念海报继续严格分层，避免把计划稿误写成已实现内容。

## 验证

- `npm run site:content:validate` 通过。
- `npm run build:pages` 通过，Pages build entry check passed。
- 构建期间存在 Vite chunk 大小警告，但不阻塞本轮官网升级落地。

## 后续

- 如果后续环境允许安全写入站点中间产物，可再把运行时计划层反向落盘为可审计 JSON/Schema 工件。
- 图鉴页当前已经能承载 1248 条计划与 60 条已发布素材，下一步可以继续补齐分页异步化与更细粒度筛选。
- 证据页目前已接入 7 条真实截图并预留 96 条任务，后续可逐步把更多 `/game` 运行截图回填到公开官网。
