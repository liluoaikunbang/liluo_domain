# 璃落房间自缚动作与分层立绘

## 本次实现思路

本次更新为璃落房间增加了一个地图动作入口：当主角处于 `liluo_room` 时，右侧信息栏会自动出现“自缚”按钮。

这类按钮后续可能随地图、区域、剧情状态继续扩展，所以本次没有把按钮和选项直接堆在 `GameView.vue` 里，而是把它整理成“地图动作配置 -> 动作按钮栏 -> 动作选项框 -> 运行时效果”的链路：

- 地图动作数据统一放在 `src/game/data/mapPanelActions.ts`。
- 右侧动作栏由 `GameMapActionPanel.vue` 渲染，并保持与既有“离开房间”按钮栏一致的视觉形式。
- 需要二级选择时，由 `GameMapActionChoiceDialog.vue` 弹出选项框。
- `GameView.vue` 只负责接收动作事件、打开选项框、应用选择结果和同步 UI 覆盖层状态。

当前“自缚”动作只有一个选项：“日式捆绑”。选择后会：

- 将左侧人物立绘切换为分层立绘。
- 给主角运行时状态追加 `hands_bound`。
- 在消息区域给出提示：“璃落完成了日式捆绑，双手已经被牢牢束住。”

## 相关代码路径

- `src/game/data/mapPanelActions.ts`
  - 新增地图动作配置入口。
  - 当前定义了璃落房间的“自缚”动作和“日式捆绑”选项。
  - 选项可声明 `playerPortraitKey`、`appendPlayerStatus` 和 `resultNotification`。

- `src/game/views/modes/map/GameMapActionPanel.vue`
  - 右侧地图动作按钮栏组件。
  - 负责把当前地图可用动作渲染成按钮。

- `src/game/views/modes/map/GameMapActionChoiceDialog.vue`
  - 地图动作选项框组件。
  - 当前用于展示“日式捆绑”。

- `src/game/views/modes/map/MapMode.vue`
  - 接收地图动作、选项框状态和分层立绘数据。
  - 将动作按钮栏、选项框和游戏外壳串起来。

- `src/game/views/shell/GameInfoPanel.vue`
  - 在右侧栏中接入 `GameMapActionPanel`。
  - 让“自缚”和“离开房间”保持统一的上级按钮栏表现。

- `src/game/views/GameView.vue`
  - 根据当前地图计算可用地图动作。
  - 处理地图动作点击、选项框打开关闭、选项结果应用。
  - 在选择“日式捆绑”后同步主角立绘、状态和提示消息。

- `src/game/data/dialoguePortraits.ts`
  - 为对话立绘数据补充分层立绘能力。
  - 新增 `portrait_liluo_japanese_binding`，用于“日式捆绑”后的左侧展示。

- `src/game/views/shell/GamePortraitPanel.vue`
  - 支持用多个图层叠加渲染左侧人物立绘。

- `src/game/views/shell/GameShell.vue`
  - 透传主角分层立绘数据。

- `src/game/views/components/base/CharacterMenuPanel.vue`
  - 旅途菜单人物栏同步支持分层立绘，避免主界面和菜单显示能力不一致。

- `src/game/views/components/base/gameMenuOverlay.css`
  - 为人物栏分层立绘补充层叠样式。

## 分层立绘说明

“日式捆绑”立绘没有使用单张整图，而是复用了已有的 partial 素材，以固定顺序叠加：

1. `src/assets/game/standee/partial/头.png`
2. `src/assets/game/standee/partial/腿.png`
3. `src/assets/game/standee/partial/裙子.png`
4. `src/assets/game/standee/partial/双臂缚.png`
5. `src/assets/game/standee/partial/胸部缚.png`

其中头部和腿部作为底层，裙子、双臂缚、胸部缚作为上层。后续如果继续增加不同束缚、服装或姿态，可以继续通过 `layers` 组合，而不一定每次都新增完整立绘。

本次没有新增 `src/assets/game` 下的素材文件，只是让已有素材进入当前功能链路。

## 开发过程中遇到的问题

### 问题 1：地图动作不能继续堆在 GameView

**现象：**

“自缚”只是第一个地图动作。后续不同房间、不同区域、不同剧情状态都可能给右侧动作区增加按钮。如果直接写在 `GameView.vue`，入口组件会越来越难维护。

**解决方法：**

新增 `mapPanelActions.ts` 作为地图动作配置入口，再用 `GameMapActionPanel.vue` 和 `GameMapActionChoiceDialog.vue` 承担具体 UI。`GameView.vue` 保留调度职责，不直接沉淀每个动作的显示细节。

### 问题 2：自缚按钮需要和离开房间按钮协调

**现象：**

角色站在门口时，右侧栏已经会出现“离开房间”。如果“自缚”使用另一套按钮样式或容器，右侧区域会显得割裂。

**解决方法：**

让地图动作按钮进入同一个右侧信息栏结构，并复用既有动作按钮的视觉形式。这样“自缚”和“离开房间”同时出现时，是同一组动作区块中的并列操作。

### 问题 3：原有左侧立绘只支持单张图片

**现象：**

“日式捆绑”需要由头、腿、裙子、双臂缚、胸部缚多张图片组合。如果继续只传 `src`，就必须先产出一张整图，不方便后续复用局部素材。

**解决方法：**

在 `DialoguePortraitData` 中增加可选的 `layers`。`GamePortraitPanel` 和人物菜单面板在有 `layers` 时按图层顺序叠加渲染，没有 `layers` 时继续使用原来的单图模式。

### 问题 4：选择动作后需要同时改外观、状态和提示

**现象：**

自缚不是单纯换一张图，还会影响主角状态。用户选择后如果没有提示，也不容易确认动作已经生效。

**解决方法：**

地图动作选项支持声明结果：

- `playerPortraitKey`：切换主角立绘。
- `appendPlayerStatus`：追加运行时状态。
- `resultNotification`：推送结果提示。

当前“日式捆绑”会切换到 `portrait_liluo_japanese_binding`，追加 `hands_bound`，并显示完成提示。
