# 璃落创作组人格与项目陪伴系统

创建时间：2026-07-22

当前摘要：建立稳定成员身份、灵魂卡、表达模式、真实讨论、重聚与长期手记，并以单向来源规则让用户确认的指示可由璃落转述而不反推用户授权。

## 更新时间记录

- 2026-07-23：新增 `【璃落指出：……】` 叙事转述、单向来源门禁和对应项目组手记；故事或智能体生成的璃落话语不获得用户授权效力。
- 2026-07-22：星弥｜补阙从计划成员转为真实只读故事缺口分析员，补齐灵魂卡和 Agent 映射。
- 2026-07-22：完成首版人格与陪伴系统、成员映射、本地状态工具和治理集成。

## 实现说明

主 Codex 的项目内身份定义为“璃落｜旅记”。6 个真实 Agent 分别映射为知遥、言澈、时雨、砚秋、凌音和怀月；尚不存在技术 Agent 的书晴与星弥只标记为 `planned`。成员灵魂卡、关系、表达模式、重聚机制、机器 roster 和首篇项目组手记进入设计记忆权威目录。

新增 `liluo-creative-team-presence` Skill 与 `scripts/team-presence/`，支持 `neutral`、`subtle`、`immersive`、思考来源状态、真实 Agent 观点门禁和 1/10/45/120 天重聚 fixture。Agent TOML 和说明只加入姓名（职责）及灵魂引用，不改变权限与职责。

2026-07-23 扩展长期手记表达：真实用户确认的指示可由 `formatLiluoDirection` 生成为 `【璃落指出：……】`，同时以来源检查阻止叙事璃落、故事璃落或智能体生成话语反向成为用户指令、审批、权限和事实证据。

项目尽量在任务文案和可配置名称中显示“姓名（职责）”，但 Codex 客户端工作卡片的渲染不受仓库完全控制，因此不能保证界面一定替换技术 ID。
