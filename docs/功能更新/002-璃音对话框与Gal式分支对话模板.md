# 璃音对话框与 Gal 式分支对话模板

## 本次实现思路

这次的目标，不是只给“和璃音交谈”单独拼一个临时事件，而是先把它整理成一套以后能长期复用的 **GalGame 风格半透明对话框模板**。

用户希望的核心方向有三个：

1. 对话呈现要更像 GalGame 常见的底部半透明对话框
2. 先专注文字对话，不放头像
3. 这套结构以后要能继续复用到别的 NPC、地图事件和剧情节点里

因此这次没有把逻辑写死在某个单独事件里，而是同时改了：

- 对话框组件
- 选项列表组件
- 事件运行器里的对话数据结构
- `dialogues.json` 里的具体对话内容

这样“璃音”只是第一批接入对象，后面别的可交谈 NPC 也可以直接套这套结构继续扩展。

---

## 相关代码路径

- `src/components/base/DialogBox.vue`
  - 负责底部半透明对话框的主体显示
  - 支持显示说话人、正文、继续提示、分支选项
  - 负责键盘输入：上下切换、数字直选、Enter / Space 确认
  - 在分支对话中禁止通过底部按钮或 `Esc` 强制结束

- `src/components/base/DialogChoiceList.vue`
  - 负责渲染对话选项列表
  - 支持当前高亮项样式
  - 支持鼠标悬停时同步当前选中项

- `src/game/core/EventRunner.ts`
  - 把原本偏单句式的对话读取方式扩展成节点式多轮对话
  - 支持 `startDialogue / advanceDialogue / selectDialogueChoice`
  - 统一输出对话框需要的 `DialoguePayload`

- `src/game/data/dialogues.json`
  - 新增璃音对话的节点式结构
  - 定义起始节点、分支选项、跳转节点和结束节点

## 对话模板的结构调整

### 1. 对话框改成可长期复用的 Gal 式底部模板

`DialogBox.vue` 现在承担的是统一剧情对话层，而不只是简单弹一句文本：

- 固定出现在页面底部
- 半透明背景
- 带说话人标签
- 带正文区域
- 带底部提示语
- 可在正文下方接选项列表

这符合项目现在的目标：

- 地图中触发事件
- 弹出剧情对话
- 再由事件继续推进内容

而不是把每一次交谈都拆成一堆分散、不可复用的小弹窗。

---

### 2. 选项单独抽成组件，避免以后重复写

为了让后续更多 NPC 对话能继续复用，这次把选项列表抽成了单独的：

```vue
src/components/base/DialogChoiceList.vue
```

它负责的事情比较单纯：

- 接收 `choices`
- 渲染按钮列表
- 显示选项编号
- 显示当前高亮项
- 鼠标点击后抛出 `select`
- 鼠标悬停时抛出 `hover`

这样主对话框只负责“对话流程”，选项组件只负责“选项显示和选中态”，职责会更清晰。

---

## 事件和数据结构的扩展方式

### 1. 从单句对话扩展到节点式对话

原本的对话数据更接近：

- 一个 `id`
- 一段 `text`

这种结构适合“路牌提示”或“暂未开放”的简单文本，但不够支撑真正的可交谈 NPC。

所以这次在 `EventRunner.ts` 里扩展了两种对话结构：

- `DialogueSingleData`：保留单句文本兼容能力
- `DialogueBranchData`：新增节点式多轮对话结构

新的分支对话数据核心格式是：

```ts
{
  id: string,
  startNodeId?: string,
  nodes: Record<string, DialogueNodeData>
}
```

每个节点可以拥有：

- `speaker`
- `speakerSide`
- `text`
- `next`
- `choices`

于是同一套运行器就同时支持：

- 单句直接显示后结束
- 多轮继续推进
- 分支选项跳转到不同节点

---

### 2. EventRunner 负责统一推进对话流程

这次在 `EventRunner.ts` 中重点补了三类入口：

- `startDialogue(dialogueId)`：进入起始节点
- `advanceDialogue(dialogueId, nodeId)`：无分支时继续到下一个节点
- `selectDialogueChoice(dialogueId, nodeId, choiceId)`：根据选项进入目标节点

最终统一整理成：

```ts
interface DialoguePayload {
  id: string;
  nodeId: string;
  speaker?: string;
  speakerSide?: 'left' | 'right';
  text: string;
  choices: DialogueChoiceData[];
  canAdvance: boolean;
}
```

这样前端对话框不用关心原始 JSON 到底是单句结构还是节点结构，只管接收当前应该显示的这一帧对话内容。

## 璃音对话的接入方式

这次在 `src/game/data/dialogues.json` 里，把璃音的交谈内容接成了一段真正的分支结构。

入口是：

```json
"blindfold_girl_house_front_talk_pending"
```

它包含：

- `opening`：开场节点
- `placeholder_options`：主选项节点
- `answer_estate / answer_world / answer_liyin`：不同回答节点
- `farewell`：结束节点

这次内容还是以占位性质为主，但结构已经是正式可复用的：

- 先说开场白
- 再进入多选提问
- 根据提问回到主菜单或结束

这样后面补正式设定时，重点只需要改 JSON 内容，不需要再重做整套交互框架。

## 键盘交互的补充

用户后续又明确要求，选项不能只靠鼠标点，要支持更接近 GalGame 的键盘操作。

因此这次补上了：

### 1. 数字键直选

按 `1 / 2 / 3 / 4` 可以直接选中并确认对应选项。

### 2. 上下键切换当前选中项

- `ArrowUp`：向上切换
- `ArrowDown`：向下切换

并且支持循环切换，不会切到边界就卡住。

### 3. Enter / Space 确认当前高亮选项

在有分支选项时：

- `Enter` 可以确认当前高亮项
- `Space` 也可以确认当前高亮项

这样手感会更像常见 GalGame 的菜单选择。

### 4. 分支状态下禁止强制结束

用户提出一个很关键的问题：

- 如果在分支节点允许玩家直接点“结束对话”或者按 `Esc` 强退，后面很可能会埋下剧情状态 bug

所以这次做了收紧：

- 有选项时，不再显示底部“结束对话”按钮
- 有选项时，`Esc` 不再强制关闭对话框

也就是说，分支节点必须通过合法选项推进，避免事件流程被硬掐断。

## 开发过程中遇到的问题

### 问题 1：原本的对话框更偏单句提示，不适合做真正问答

**现象**：

- 原结构更适合显示一段文本后结束
- 很难自然支持“继续到下一句”与“进入分支选项”这两类行为

**原因**：

- 对话数据层没有节点概念
- 运行层也没有“当前节点 -> 下一个节点”的统一推进逻辑

**解决方法**：

- 在 `EventRunner.ts` 中补充节点式结构
- 统一通过 `DialoguePayload` 驱动界面
- 把单句对话也兼容进同一套系统里

---

### 问题 2：选项如果只靠鼠标，后续实际体验会比较弱

**现象**：

- 初版选项只能点击
- 虽然能用，但不像真正的 GalGame 对话体验

**原因**：

- 选项组件最初只负责展示，没有“当前高亮项”概念
- 主对话框也没有接管选项状态和键盘事件

**解决方法**：

- 给 `DialogChoiceList.vue` 增加 `activeIndex`
- 增加高亮样式
- 在 `DialogBox.vue` 中维护当前选中项
- 接入数字键、上下键、Enter / Space 的行为

---

### 问题 3：分支对话如果允许强退，可能破坏事件流

**现象**：

- 分支节点原本还保留了底部按钮
- `Esc` 也可以关闭
- 用户担心这会在后续正式剧情里制造状态错误

**原因**：

- 分支状态本质上不是普通提示框，而是剧情流程的一部分
- 强制关闭会导致“应该被选中的节点”没有发生

**解决方法**：

- 分支节点隐藏底部关闭按钮
- 分支节点禁用 `Esc` 关闭
- 只允许通过合法选项推进剧情

---

### 问题 4：需要重新确认构建命令

**现象**：

- 调整完成后需要重新验证有没有引入编译错误

**解决方法**：

- 使用项目已有脚本 `npm run build:web` 进行验证
- 构建通过，说明这轮修改没有引入新的编译问题

---

## 当前实现要点总结

### 1. 已经有了可长期复用的 Gal 式对话框骨架

这次不是只给璃音写了一段文本，而是把：

- 对话框外观
- 分支选项显示
- 多轮推进逻辑
- 键盘交互

整理成了一套后续可以继续复用的模板。

### 2. 单句提示与多轮对话现在共用同一套运行系统

这样以后地图里的：

- 路标提示
- 暂未开放提示
- NPC 交谈
- 正式剧情分支

都可以继续走同一个事件入口，不容易越做越散。

### 3. 分支对话已经开始考虑“剧情安全性”

这次不是只把 UI 做出来，而是已经先限制了强制退出分支的路径，避免后面剧情状态越来越复杂时出问题。

## 后续扩展建议

后面如果继续往“更像冒险 RPG”方向推进，建议按这个顺序扩展：

1. 给不同 NPC 继续接入正式节点式对话
2. 在对话节点中接入剧情状态判断与条件分支
3. 再考虑是否加入头像、立绘切换或打字机效果
4. 让对话节点和地图事件、任务状态、存档状态联动

这样这套系统会越来越接近真正的事件驱动冒险 RPG 对话框架，而不是一次性页面效果。
