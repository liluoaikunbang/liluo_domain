# 074-状态流转与存档长状态布局修复

## 实现思路

本次围绕人物状态继续收口了三块体验：

1. 失明后的自动寻路不再能直接走到视野外目标。玩家仍然可以点击远处，但实际寻路目标会被限制在当前可见区域内，路径搜索也不会把备用终点选到可见区域之外。
2. 璃落房间床铺事件改为写入更完整的状态组合：普通睡觉后保留未穿鞋；拘束睡衣休息后写入未穿鞋、双手被缚、双腿被缚；被解开后只保留未穿鞋；离开房间时只移除未穿鞋，避免以后新增状态被 `status: []` 误清空。
3. 存档卡片在状态变多后需要稳定显示。状态文字最多显示两行，完整内容通过悬停标题保留；存档卡片不再裁剪内容，列表自身负责滚动，避免状态换行把按钮顶出或与按钮重叠。

状态图标信息框里的功能文案也做了同步调整：只描述玩家直接关注的效果，不再写“切换立绘”“叠加”“跳动表现”等实现细节，并统一使用“效果：”。

## 遇到的问题与解决方法

### 1. 失明遮罩只改变视觉，不限制自动寻路

问题：失明后虽然地图可见区域变小，但点击远处仍会自动寻路到视野外，视觉表现和实际行动范围不一致。

解决：增加 `autoPathVision.ts`。点击点先按当前玩家位置和失明半径裁剪到可见区域边缘，再把同一可见区域传给寻路算法作为 `isTileAllowed`。这样目标和路径候选都受视野限制。

### 2. 清空状态容易误删未来新增状态

问题：房间里睡觉、换衣、出门原本使用 `status: []`，这在状态变多后风险很高。以后如果有临时剧情状态、异常状态或祝福状态，也会被离房逻辑顺手清掉。

解决：新增 `mode: "remove"`。离开房间只移除 `no_shoes`，被解开后用明确的 `status: ["no_shoes"]` 表达“只保留未穿鞋”，不再依赖清空全部。

### 3. 存档卡片状态文本换行后挤压按钮

问题：状态增多后，存档卡片中的“状态：A / B / C...”会换行，原布局可能把按钮顶出卡片。

解决：状态文本限制为最多两行，资源信息保持单行；按钮区放在内容之后，由卡片自然高度承接，而不是压缩内容区。

### 4. 初版存档卡片修复出现重叠与裁剪

问题：第一次尝试用固定 grid 行约束内容区，导致内容区被压缩后文本与按钮重叠；之后保留 `overflow: hidden` 又导致卡片底部显示不全。

解决：移除会压缩内容的 grid 行约束，恢复自然流式纵向布局；卡片本身不再裁剪内容，网格行高按内容生成，滚动交给 `.save-slot-list`。
