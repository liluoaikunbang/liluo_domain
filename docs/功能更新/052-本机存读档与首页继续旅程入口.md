# 052-本机存读档与首页继续旅程入口

## 实现思路

本次实现的是游戏主流程中的第一版存读档能力。根据最终确认，存档不写入项目根目录文件，也不通过本地服务生成 `save/` 目录，而是全部暂存在浏览器 `localStorage` 中。

存档内容按“冒险 RPG 主流程可恢复”为优先级，至少保存：

- 人物运行时状态：外观、立绘 key、状态标签、拘束标签、背包、装备。
- 当前所处地图：`mapId`。
- 当前地图中的人物世界坐标：`x` / `y`。
- 当前地图会话状态：`mapSession.flags`。

读档时先校验存档结构，再恢复人物运行时状态，并通过 Phaser 初始化参数或地图加载参数把角色放回对应地图坐标。

入口上分为两条路径：

1. 游戏内旅途菜单：“存档”栏目保存当前进度，“读档”栏目读取本机暂存；同时支持导出全部存档 JSON，以及从本地 JSON 导入覆盖。
2. 首页入口：“继续旅程”先打开存档选择面板，选择具体存档后才进入该存档对应的地图与坐标。

存档和读档成功提示使用普通通知模板，避免显示成“获得”模板。

## 相关代码路径

- `src/game/core/saveData.ts`
  - 定义 `GameSaveData`、`MapSessionSaveState`、`WorldPosition`。
  - 提供 `createGameSaveData()`、`parseGameSaveData()`、`applyGameSaveData()`。
  - 负责保存数据结构整理、基础校验和人物运行时状态恢复。
- `src/game/core/saveStorage.ts`
  - 使用 `localStorage` 保存、读取和列出存档。
  - 存储 key 前缀为 `liluo_domain:game_save:`。
  - 提供导出全部存档 JSON、导入覆盖全部本机存档的能力。
- `src/game/core/playerRuntime.ts`
  - 为人物运行时状态补充 `inventory`、`equipment` 的 patch 应用能力。
- `src/game/systems/map/MapLoader.ts`
  - `WorldSceneInitRequest` 与 `WorldSceneInitData` 增加 `playerPosition`。
  - 支持从指定世界坐标进入地图。
- `src/game/systems/map/worldSceneRuntime.ts`
  - 支持用 `playerPosition` 覆盖出生点。
  - 暴露 `getPlayerWorldPosition()`，用于保存当前角色坐标。
- `src/game/scenes/WorldScene.ts`
  - 暴露当前地图 id、玩家世界坐标。
  - 增加 `loadMapAtPosition()`，用于读档后进入指定地图坐标。
- `src/game/views/composables/usePhaserGameBridge.ts`
  - Vue 侧桥接当前地图、当前玩家坐标和按坐标加载地图。
- `src/game/views/GameView.vue`
  - 组织存档、读档、导出、导入和首页继续旅程流程。
  - 首页存档选择后，通过 `mountGame({ mapId, playerPosition })` 进入对应进度。
- `src/game/views/components/base/GameMenuOverlay.vue`
  - 游戏内菜单新增正式“存档”和“读档”栏目内容。
  - 提供导出全部存档和导入本地 JSON 的 UI。
- `src/game/views/GameEntryScreen.vue`
  - 首页“继续旅程”改为先展示存档选择列表。
  - 选择具体存档后再进入游戏。
- `scripts/tests/save-data.test.mjs`
  - 覆盖存档数据创建、人物状态恢复和非法坐标拒绝。
- `scripts/tests/save-storage.test.mjs`
  - 覆盖 `localStorage` 存档列表、读取、导出和导入覆盖。

## 开发过程中遇到的问题

### 1. 根目录 `save/` 文件方案与浏览器运行环境不匹配

最初考虑通过 Vite 本地 API 写入项目根目录 `save/`。但游戏主流程运行在浏览器内，直接写项目文件会引入开发服务依赖，也不适合之后离线构建或普通浏览器运行。

解决方法：

- 放弃文件写入方案。
- 存档统一进入浏览器 `localStorage`。
- 需要落到本地文件时，通过“导出全部存档 JSON”让用户选择下载目录。

### 2. 读档需要恢复地图坐标，而原有地图加载只支持出生点

原先 `MapLoader` 和 `WorldSceneRuntime` 主要通过 `spawnId` / `spawnMarker` 决定角色位置。读档需要恢复到精确世界坐标，不能只回到地图默认出生点。

解决方法：

- 在 `WorldSceneInitRequest` / `WorldSceneInitData` 中增加 `playerPosition`。
- `worldSceneRuntime` 优先使用 `playerPosition`，没有时再走原出生点解析。
- `WorldScene` 增加 `loadMapAtPosition()`，供游戏内读档切图使用。
- 首页继续旅程则通过 `mountGame({ mapId, playerPosition })` 初始进入。

### 3. 首页“继续旅程”不能直接读取默认存档

一开始首页“继续旅程”直接读取 `default` 存档，但用户确认希望先出现存档选择界面，选择具体存档后才进入对应入口。

解决方法：

- `GameEntryScreen` 接收 `saves` 列表。
- 点击“继续旅程”只切换到首页内的存档选择面板。
- 点击具体存档后通过 `select-save` 把 `slotId` 交给 `GameView`。
- `GameView` 按该 `slotId` 读取并进入对应地图坐标。

### 4. 导入本地 JSON 会覆盖现有存档，需要明确风险

导入全部存档 JSON 会替换当前浏览器里的全部存档，如果没有确认，容易误覆盖。

解决方法：

- 在读档栏“从本地 JSON 导入”选择文件后，先弹出二次确认。
- 只有确认后才解析并覆盖 `localStorage`。
- 导入前先校验导入包和每个存档结构，校验失败时不覆盖现有存档。

### 5. Node 测试直接依赖地图 registry 会触发 JSON import attribute 问题

`saveData.ts` 最初直接依赖 `getMapRegistryEntry()` 校验地图存在。Node 测试加载 registry 时会继续加载地图 JSON，在当前 Node 环境下触发缺少 JSON import attribute 的报错。

解决方法：

- `saveData.ts` 保持为纯存档结构逻辑，只校验基础结构和坐标合法性。
- 地图是否存在放回 Vue/游戏入口层通过 `getMapRegistryEntry()` 校验。
- 这样纯逻辑测试不会被地图 JSON 加载方式影响。

结果：

- `localStorage` 存档列表、读取、导出、导入覆盖测试通过。
- Vite Web 构建通过。
- 用户实际测试确认：
  - 存档与读档无报错。
  - 存档/读档成功提示使用普通通知模板。
  - 首页“继续旅程”先显示存档选择界面，再按所选存档进入对应进度。

## 后续维护建议

1. 之后新增需要持久化的 RPG 状态时，优先扩展 `GameSaveData`，不要在 UI 里临时拼额外字段。
2. 如果后续背包、装备、任务、剧情 flags 进入正式系统，应把对应状态纳入 `saveData.ts` 的结构与测试。
3. 读档前的地图存在性校验应继续留在靠近游戏 registry 的入口层，避免纯存档模块过度依赖地图数据。
4. 如果以后要支持多个命名存档槽，优先扩展 `saveStorage.ts` 的 slot 生成和菜单 UI，不需要改变底层 `localStorage` 前缀规则。
