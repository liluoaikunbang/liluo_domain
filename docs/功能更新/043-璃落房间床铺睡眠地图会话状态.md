# 璃落房间床铺睡眠地图会话状态

## 本次实现思路

这次调整解决的是 `liluo_room` 床铺事件的重复睡眠问题。

床铺原本有两个睡觉相关选项：普通上床休息，以及体验拘束睡袋休息。玩家在当前房间里睡过一次后，再次回到床铺旁触发事件时，不应该继续展示睡觉选项，而是提示“现在暂时不想睡觉了。”

这个状态不适合写成长期存档状态，因为需求只限定在“当前地图内是否睡过”。离开地图后再次进入房间，应当恢复为未睡过。因此实现上新增了轻量的地图会话状态：

1. 对话选项支持 `mapSessionFlagChange`，用于在选中某个选项时写入当前地图会话 flag。
2. 事件数据支持 `mapSessionFlagRequired`，用于在触发事件前检查当前地图会话 flag 是否符合预期。
3. `liluo_room_bed_event` 要求 `liluo_room_has_slept` 为 `false` 时才进入原床铺对话。
4. 两个睡觉选项都会把 `liluo_room_has_slept` 设置为 `true`。
5. 如果再次触发床铺事件时该 flag 已经为 `true`，事件会转入 `liluo_room_bed_already_slept` 提示对话。
6. `GameView.vue` 按当前 `mapId` 保存地图会话 flags；当 `currentMapId` 变化时清空，符合“出地图后复原”的要求。

这套机制不是床铺硬编码，后续其他地图事件也可以复用同样的“当前地图临时状态”能力。

## 相关代码路径

- `src/game/core/EventRunner.ts`
  - 新增 `EventMapSessionFlagRequiredData` 类型。
  - 在 `EventData` 中加入 `mapSessionFlagRequired`。
  - 在 `DialogueChoiceData` 中加入 `mapSessionFlagChange`。

- `src/game/core/eventExecution.ts`
  - 在 `EventExecutionContext` 中加入 `getMapSessionFlag` 与 `setMapSessionFlag`。
  - 执行事件动作前先检查 `mapSessionFlagRequired`。
  - 当当前 flag 不符合预期时，转入 `fallbackDialogueId`。

- `src/game/core/dialogueExecution.ts`
  - 选中对话选项时执行 `mapSessionFlagChange`。

- `src/game/views/GameView.vue`
  - 新增 `mapSessionState`。
  - 提供 `getMapSessionFlag` 与 `setMapSessionFlag` 给 Phaser 事件触发链路。
  - 提供 `mapSessionActions.setFlag` 给 Vue 对话选项链路。
  - 当前地图变化、新旅程开始、卸载时重置地图会话状态。

- `src/game/core/createPhaserGame.ts`
  - 将地图会话状态回调透传给 `WorldScene`。

- `src/game/views/composables/usePhaserGameBridge.ts`
  - 接收并传递 `getMapSessionFlag` / `setMapSessionFlag`。

- `src/game/views/composables/useGameDialogueBridge.ts`
  - 对话选项执行上下文中补充 `setMapSessionFlag`。

- `src/game/scenes/WorldScene.ts`
  - 事件触发时把地图会话状态读写能力传入 `eventRunner.runEvent`。

- `src/game/data/liluo_room/events.json`
  - `liluo_room_bed_event` 新增 `mapSessionFlagRequired`。

- `src/game/data/liluo_room/dialogues.json`
  - `sleep_on_bed` 与 `sleep_in_tie_bag` 新增 `mapSessionFlagChange`。
  - 新增 `liluo_room_bed_already_slept` 提示对话。

- `scripts/tests/event-runner.test.mjs`
  - 增加地图会话 flag 写入、fallback 判断、真实床铺数据回归测试。

## 开发过程中遇到的问题

### 问题 1：睡眠状态不应该进入长期全局状态

如果把“是否睡过”写入全局玩家状态或持久剧情状态，玩家离开房间后再回来也可能继续被判定为睡过，这不符合当前需求。

### 解决方法

新增地图会话状态，而不是复用玩家外观、状态标签或长期剧情变量。

`GameView.vue` 维护：

```ts
const mapSessionState = ref({
  mapId: INITIAL_MAP_ID,
  flags: {}
});
```

当地图变化时调用 `resetMapSessionState(mapId)`，保证状态生命周期只覆盖当前地图停留期间。

---

### 问题 2：床铺逻辑需要可扩展，不能只写死在 `liluo_room_bed_event`

如果直接在床铺事件里写特殊判断，后续其他地图也需要“本地图内只触发一次”的事件时，还会继续复制逻辑。

### 解决方法

把能力抽象到事件数据层：

```json
"mapSessionFlagRequired": {
  "flagId": "liluo_room_has_slept",
  "expected": false,
  "fallbackDialogueId": "liluo_room_bed_already_slept"
}
```

对话选项则通过：

```json
"mapSessionFlagChange": {
  "flagId": "liluo_room_has_slept",
  "value": true
}
```

这样后续事件只要声明自己的 flag 与 fallback，就能复用同一条事件执行链路。

---

### 问题 3：睡眠选项从 Vue 对话链路执行，床铺事件从 Phaser 事件链路执行

床铺事件第一次触发发生在 `WorldScene -> eventRunner.runEvent`；而玩家选择“睡觉”发生在 `useGameDialogueBridge -> selectDialogueChoiceWithContext`。如果只在其中一边接入地图会话状态，就会出现能读不能写或能写不能读的问题。

### 解决方法

把地图会话状态回调同时接入两条链路：

1. `WorldScene` 触发事件时传入 `getMapSessionFlag` / `setMapSessionFlag`。
2. `useGameDialogueBridge` 处理选项时传入 `setMapSessionFlag`。
3. 两边都指向 `GameView.vue` 维护的同一个 `mapSessionState`。

## 最终验证结果

```bash
node --test scripts\tests\event-runner.test.mjs
npm run build:web
```

- `npm run build:web` 通过。
- 构建中仍有项目既有的两个 tileset `new URL(...) doesn't exist at build time` warning，与本次地图会话状态功能无关。
- 用户已确认可写入文档，因此本功能按项目文档规则沉淀记录。
