# 璃落庄园小地图黑边修正与相机显示收口

## 本次实现思路

这次处理的目标，是解决 `liluo_estate_1` 在实际运行时仍然出现的**右侧和下方黑色边缘**问题，并把地图显示逻辑收口成更符合当前项目需求的方式：

1. **地图较小时，不再让内容缩在地图框里**
   - 改为按短边把地图内容放大到尽量贴近地图框。

2. **地图较大时，不强行整体缩放**
   - 保持原始倍率。
   - 通过相机跟随主角来查看地图不同区域。

3. **把“看起来为空，但 gid 不为 0 的透明占位 tile”也排除出有效边界计算**
   - 这类 tile 之前会被脚本和运行时逻辑误判为“地图还有内容”，导致地图右下边界被撑大。

这次不是只改一个显示参数，而是同时从**地图数据裁边脚本**和**运行时地图边界计算**两边收口，避免以后再次把透明占位图块算进地图范围。

---

## 相关代码路径

- `src/game/scenes/WorldScene.ts`
  - 修正运行时地图内容边界计算。
  - 让相机布局继续遵循“小地图按短边贴合、大地图保持 1 倍 + 相机跟随”的规则。
  - 渲染时跳过已确认的透明占位 tile，避免它们再次参与显示和范围判断。

- `scripts/maps/trim-empty-map-border.js`
  - 补充透明占位 tile 的识别规则。
  - 避免后续再用脚本裁图时，把这些透明 tile 当成真实地图内容保留下来。

- `src/game/data/maps/liluo_estate_1.json`
  - 清理右侧和底部残留的无效占位数据。
  - 让静态地图数据本身更贴近真实可见内容。

- `docs/功能更新目录.md`
  - 登记本次功能文档，便于后续回查。

## 具体实现说明

### 1. 先确认黑边不是单纯容器样式问题，而是地图边界判断偏大

虽然前一轮已经把 `liluo estate 1` 的边缘多余信息裁掉了一部分，但实际运行时依然还能看到右边和下边的黑边。

这说明问题不只是：

- 地图文件里有没有明显的空白区

还包括：

- 运行时是否把某些“不可见但 gid 非 0”的 tile 继续当成了有效内容
- 相机内容边界是否仍然被这类 tile 撑大

这次排查后确认，旧农场 tileset / object 素材里存在一部分**整格透明占位帧**。这些 tile 在视觉上什么都没有，但之前只要 gid 大于 0，就会被边界统计逻辑算进去。

---

### 2. 在运行时边界计算里跳过透明占位 tile

本次在 `WorldScene.ts` 里补了透明占位 tile 的判断逻辑，重点接入到三处：

1. **运行时裁剪地图内容范围**
   - `getRuntimeTileContentBounds()`
   - 之前是 `gid > 0` 就算有效。
   - 现在改为：如果是已知透明占位 tile，也视为空白。

2. **地图显示内容边界计算**
   - `getMapContentBounds()`
   - 小地图放大时依赖这块边界。
   - 如果边界把透明占位 tile 算进去，就会把黑边也一起放大出来。

3. **图层渲染**
   - `renderTileLayers()`
   - 避免这些透明占位 tile 继续参与渲染流程，保持逻辑一致。

这样做之后，地图真正“有内容”的区域会更接近玩家实际看到的区域，相机边界和放大比例也会更准确。

---

### 3. 保留“小地图放大、大地图跟随”的相机规则

这次没有把相机逻辑改成固定缩放，而是继续保留当前更适合 RPG 地图探索的规则：

- **小地图：**
  - 按短边贴合的方式放大。
  - 让地图内容尽量占满地图框。

- **大地图：**
  - 保持 1 倍倍率。
  - 不因为容器大小而把整张图缩小。
  - 通过相机跟随主角去浏览地图。

对应实现主要在：

- `updateMainCameraLayout()`

这样能保证：

- 小地图不会显得缩在中间一小块。
- 大地图也不会因为“强行适配整个框”而丢掉探索感。

---

### 4. 去掉会被放大成黑边的额外内容 padding

之前内容边界计算时，为了避免地图看起来太贴边，曾经在有效内容外再补一点额外边距。

这个思路在普通缩放下问题不大，但在“小地图放大贴合”的场景里，会出现一个副作用：

- 原本只有半格左右的额外边距
- 在放大后会变成很明显的一圈黑边

所以这次把 `getMapContentBounds()` 调整为使用**更紧的内容边界**，不再额外补这一圈显示 padding。

这一步对去掉小地图右侧、下方残余黑边是关键收口之一。

---

### 5. 同步修正裁边脚本，避免以后重新把问题写回来

如果只改运行时逻辑，而脚本层仍然把透明占位 tile 当成有效内容，那么后面重新裁地图时，问题还是会再出现。

所以本次也同步调整了：

- `scripts/maps/trim-empty-map-border.js`

脚本中新增了透明占位 tile 的判断规则，当前先把本项目已经确认的旧农场透明 tile 做成白名单识别：

- `Farm_tileset.png` 中的 `localId 94`
- `Farm_object.png` 中的 `localId 6`
- `Farm_object.png` 中的 `localId 344`

这样后续再用脚本处理类似地图时，脚本和运行时逻辑会保持一致，不会出现“脚本认为有内容、运行时又想裁掉”的分裂状态。

---

### 6. 顺手清理 `liluo_estate_1.json` 里底部和右侧残留占位数据

除了逻辑层修正，这次还直接清掉了 `src/game/data/maps/liluo_estate_1.json` 中底部和右侧几段残留的无效占位数据。

这样做的意义是：

- 地图源数据本身更干净
- 后续继续调庄园地图时更容易判断真实边界
- 不用每次都依赖运行时去“补救”脏数据

## 开发过程中遇到的问题

### 问题 1：地图已经裁过边，但运行时还是出现黑边

**现象：**

- 用户确认边缘多余信息已经去掉一轮。
- 但进入实际地图后，右侧和下方仍然有明显黑边。

**原因：**

- 不是单纯的地图尺寸问题。
- 运行时仍然把一些透明占位 tile 当成有效内容，导致相机边界和内容边界偏大。

**解决方法：**

- 在运行时内容边界统计中，把已确认透明占位 tile 排除掉。
- 同时修正图层渲染与地图裁剪逻辑，保证判断一致。

---

### 问题 2：旧素材里存在“视觉为空、数据不为 0”的 tile

**现象：**

- 某些 tile 的 gid 非 0。
- 但实际检查素材后，整格 alpha 为 0，属于透明占位帧。

**解决方法：**

- 先确认具体透明帧对应的 localId。
- 在脚本和运行时都建立同一套透明 tile 识别规则。

这避免了再用“只要 gid > 0 就是有效内容”的粗判断。

---

### 问题 3：边界补白在放大后会被放大成肉眼可见的黑边

**现象：**

- 之前为了不让地图内容贴边，边界上额外补了一点 padding。
- 小地图放大后，这点 padding 被一并放大，变成明显黑边。

**解决方法：**

- 改为使用紧内容边界。
- 小地图优先解决“尽量占满地图框”的目标，不再保留这层显示补白。

---

## 对应问题的解决方法汇总

本次最终采用了三层一起收口的方式：

1. **运行时层**
   - `WorldScene.ts` 中跳过透明占位 tile。
   - 修正内容边界、运行时裁剪、图层渲染。

2. **脚本层**
   - `trim-empty-map-border.js` 中同步加入透明占位识别。

3. **数据层**
   - 直接清理 `liluo_estate_1.json` 中残留的无效占位数据。

这样不是只修某一个点，而是把“边界被透明 tile 撑大”这条链路整体掐掉。
