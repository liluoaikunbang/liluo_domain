# 旅途菜单故事栏分类折叠与类别整理

## 本次实现思路

本次继续整理旅途菜单里的“故事”栏，让它更适合作为长期扩展的故事树，而不是只展示一串不可收纳的大纲节点。

调整目标有三点：

- 让顶层大分支明确成为“分类”节点，而不是继续显示“设定”“预留”等进度状态。
- 在故事树中补入新的大类别“咒缚回响”，并放在“尘寰问道”和“星宇织梦”之间。
- 让所有 `status` 为“分类”的节点都可以折叠自己的后代分支，为以后非根节点的分类块预留同样能力。

这里没有新增素材，也没有改动地图数据。故事栏仍然使用原本的 JSON 大纲数据源和同一个 Vue 面板。

## 相关代码路径

- `src/game/data/global/storyOutlinePlaceholder.json`
  - 将顶层大分支的 `status` 统一调整为“分类”。
  - 新增顶层大类别“咒缚回响”。
  - 为“咒缚回响”保留一个“未命名”的预留子节点，方便后续继续补章节、地点与事件。

- `src/game/views/components/base/StoryMenuPanel.vue`
  - 新增 `collapsedCategoryKeys`，记录当前被折叠的分类节点 key。
  - 新增 `isCategoryStatus`，统一判断哪些节点属于可折叠分类块。
  - `createNodeLayout` 和 `createTableRows` 都接入折叠状态：分类节点被折叠时保留自身，但不再遍历它的后代。
  - 画布视图与表格视图共享同一套折叠状态。
  - 分类卡片右下角显示半透明方块 `+` / `-` 按钮，用于展开或收回该分类块后面的所有子类别与子节点。

- `src/game/views/components/base/gameMenuOverlay.css`
  - 新增分类卡片与普通进度卡片的颜色区分。
  - 保留状态 flag 的颜色区分：“分类”与“大纲 / 预留 / 大纲草稿”等进度 flag 使用不同颜色。
  - 新增故事分类折叠按钮样式，并将画布里的按钮固定在对应分类卡片右下角。

## 具体实现说明

### 1. 分类节点与进度节点分离

原本顶层大类别里有的显示“设定”，有的显示“预留”，这些词更像内容完成度，不适合表达“慕妮卡帝国”“浮光掠影”这类大分支本身。

本次将顶层大分支统一标记为：

```json
"status": "分类"
```

这样故事栏渲染时可以清楚地区分：

- `分类`：世界线、大篇章、大类别。
- `大纲` / `预留` / `大纲草稿`：具体故事节点的进度状态。

后续如果某个非根节点也需要成为分类块，只要将它的 `status` 写为“分类”，它就会自动获得同样的卡片颜色与折叠能力。

### 2. 新增“咒缚回响”大类别

在 `storyOutlinePlaceholder.json` 的顶层数组中新增：

```text
咒缚回响
```

它的位置位于：

```text
尘寰问道 -> 咒缚回响 -> 星宇织梦
```

为了让画布和表格中能自然显示它的分支结构，当前先保留一个“未命名”的预留子节点。后续补充正式内容时，可以继续在这个分类下追加真实章节。

### 3. 分类块折叠逻辑

折叠状态没有写回 JSON，而是保存在 Vue 组件本地：

```js
collapsedCategoryKeys
```

这样用户临时收起分支不会污染故事数据源。

布局生成时的规则是：

- 如果节点不是“分类”，正常渲染。
- 如果节点是“分类”但没有子节点，不显示折叠按钮。
- 如果节点是“分类”且有子节点，显示折叠按钮。
- 如果该分类节点已折叠，只保留分类卡片本身，不再遍历它的所有后代。

这个逻辑同时用于画布视图和表格视图，因此两个视图看到的展开/收起状态是一致的。

### 4. 折叠按钮位置调整

开发过程中尝试过把折叠按钮放到连接线上，但实际观感不够稳定，也不够符合当前故事卡片的像素 UI 语气。

最终方案是：

- 按钮恢复为半透明方块。
- 展开状态显示 `-`。
- 折叠状态显示 `+`。
- 画布里固定在对应分类卡片右下角。
- 表格里继续放在标题左侧，作为列表行操作入口。

这样按钮既属于对应分类块，又不会挤占卡片顶部的状态、故事线与时间线信息。

## 开发过程中遇到的问题

### 1. 只针对根节点折叠会限制后续扩展

如果只判断 `depth === 0`，当前顶层分类可以折叠，但以后中间层出现新的分类块时还要重新改逻辑。

解决方法：

- 不按层级判断。
- 统一按 `status === '分类'` 判断。
- 任意层级的分类节点只要有 `children`，都可以折叠。

### 2. 折叠后不能直接删除分类节点本身

如果折叠时把整个分类节点都隐藏，用户就失去了重新展开的入口。

解决方法：

- 折叠只跳过后代遍历。
- 分类节点自身始终保留。
- 展开按钮挂在分类节点自身上。

### 3. 折叠按钮位置需要兼顾直观与美观

尝试把按钮放在连接线上时，语义更接近“控制分支”，但视觉上显得突兀。之后又尝试圆形箭头图标，但与当前菜单 UI 不够协调。

最终解决方法：

- 回到半透明方块按钮。
- 放到分类卡片右下角。
- 保持 `+` / `-` 的直接含义。

### 4. 状态 flag 与卡片颜色容易混淆

最初只调整了 flag 颜色，但实际需求是区分整张分类卡片和普通进度卡片。

解决方法：

- 保留 flag 的颜色区分。
- 额外为卡片本体增加 `story-node-card-category` 与 `story-node-card-progress` 两类样式。
- 让“分类”卡片与“大纲 / 预留 / 大纲草稿”卡片在底色上也能直接区分。
