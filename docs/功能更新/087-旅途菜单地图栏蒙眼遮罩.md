# 旅途菜单地图栏蒙眼遮罩

## 本次实现思路

这次调整的目标，是让旅途菜单里的“地图”栏目也能响应人物的蒙眼状态。

之前蒙眼状态已经会影响主地图中的视野表现和自动寻路范围，但菜单地图仍然直接显示完整全图。这样在状态体验上会有割裂：角色明明处于看不清全景的状态，打开地图栏却仍然能毫无限制地查看全貌。

本次没有重做菜单地图渲染，也没有改动地图数据，而是在已有地图栏全图上叠加一层状态遮罩：

- 如果当前人物没有蒙眼状态，地图栏保持原样显示。
- 如果当前人物处于蒙眼状态，地图栏只在人物当前位置周围保留亮光区域。
- 亮光范围沿用已有 `blindMask.radiusInTiles` 和 `edgeFadeInTiles` 的配置思路。
- 亮光区域外使用 86% 黑色遮罩，让地图全貌仍能隐约看见，但不能像正常状态那样清晰浏览。

这样菜单地图仍然是“地图栏”，但它会更贴近当前人物状态，而不是变成独立于 RPG 处境之外的纯功能页面。

## 具体实现说明

### 1. 从旅途菜单容器透传当前视野状态

`GameMenuOverlay.vue` 原本已经会读取人物运行时状态，用于人物栏、存档栏和状态图标展示。

这次在同一层增加：

- `currentPlayerVisionPresentation`

并传入 `MapMenuPanel`。这样地图栏不需要自己重新判断“哪些状态会导致遮罩”，只负责根据视野表现数据决定是否显示遮罩。

这种做法让状态规则继续集中在 `playerMovementPresentationRules.ts` 和 `playerRuntime.ts`，避免菜单组件里再写一份“蒙眼状态”的重复判断。

---

### 2. 在地图栏内按实际显示尺寸计算遮罩

地图栏的全图不是直接显示原始地图尺寸，而是：

- 先由 `MapMenuPanel.vue` 根据 tileset 绘制成图片。
- 再裁剪空白边界。
- 最后按地图栏面板尺寸等比贴边缩放。

因此蒙眼遮罩不能只使用原始世界坐标，还需要把人物当前位置换算到菜单地图图片内部：

1. 用 `renderedMap.offsetX / offsetY` 抵消地图裁剪偏移。
2. 用 `renderedMap.pixelWidth / pixelHeight` 转成百分比中心点。
3. 根据当前面板内图片实际显示宽高，换算 `radiusInTiles` 对应的屏幕像素半径。

这样即使不同地图尺寸不同、菜单面板尺寸变化，亮光区域也能尽量贴着人物当前位置显示。

---

### 3. 用 CSS 径向渐变完成轻量遮罩

本次没有增加 canvas 二次绘制，也没有修改地图缩略图生成逻辑，而是在图片层上方叠加：

- `.map-blind-mask`

遮罩使用 `radial-gradient`：

- 中心到 `--map-blind-radius` 保持透明。
- 从 `--map-blind-radius` 到 `--map-blind-fade-radius` 渐变过渡。
- 外侧统一使用 `rgba(0, 0, 0, 0.86)`。

这个方案足够轻量，也便于后续继续调遮罩强度、亮光范围或边缘过渡。

## 开发过程中遇到的问题

### 问题 1：主地图已有蒙眼遮罩，但菜单地图是独立渲染的图片

**现象：**

主地图中的蒙眼效果由 Phaser `Graphics` 绘制，菜单地图则是 Vue 组件里生成的静态全图图片。两者不是同一套渲染对象，不能直接复用 Phaser 遮罩。

**解决方法：**

复用状态数据与半径配置，不复用 Phaser 绘制实现。

菜单地图使用 Vue + CSS 叠层来表达同一类状态效果，让两边体验一致，但实现仍符合各自所在层的技术边界。

---

### 问题 2：菜单地图经过裁剪和缩放，人物坐标不能直接拿来当遮罩中心

**现象：**

地图栏图片会裁掉空白边界，如果直接用世界坐标换算，遮罩中心会和人物标记一样出现偏移风险。

**解决方法：**

沿用人物标记已有的换算思路：

- 先减去 `renderedMap.offsetX / offsetY`
- 再除以裁剪后的 `pixelWidth / pixelHeight`
- 最后转成 CSS 百分比

遮罩中心和人物标记使用同一套位置基准，因此不会因为裁剪造成错位。

---

### 问题 3：用户希望地图全貌仍能稍微看到

**现象：**

如果完全照主场景 90% 的遮罩强度，菜单里的地图全图会更难辨认；但如果太浅，又会削弱蒙眼状态的反馈。

**解决方法：**

先按需求做成 80% 不透明度，之后根据用户反馈调整为 86%。

最终菜单地图遮罩强度固定为：

- `MENU_MAP_BLIND_MASK_ALPHA = 0.86`

主地图原本的 `blindMask.overlayAlpha` 不受影响。

---

## 最终验证结果

本次调整完成后：

- 人物没有蒙眼状态时，旅途菜单地图栏保持原来的全图显示。
- 人物处于蒙眼状态时，地图栏会显示以人物位置为中心的亮光区域。
- 亮光区域外有 86% 不透明度遮罩，地图全貌仍可隐约辨认。
- 人物坐标标记仍显示在遮罩上方。
- 没有改动地图 `map.json` 数据，也没有新增素材。

已执行：

```text
npm run build:web
```

构建通过。构建过程中仍有一个既有 Vite warning：

```text
new URL("../../../../../assets/game/sucai/Modern/school/NPCs/student1.png", import.meta.url) doesn't exist at build time
```

该 warning 与本次菜单地图遮罩改动无关，本次没有处理它。

## 后续可继续扩展的方向

后续如果继续扩展状态对菜单地图的影响，可以考虑：

- 把不同状态对应的地图遮罩规则整理成独立配置。
- 让某些道具或技能临时扩大菜单地图可见范围。
- 在地图栏中区分“记忆中知道的地形”和“当前确实能看清的位置”。

当前这次先解决蒙眼状态下地图栏和主地图体验不一致的问题，让旅途菜单继续向 RPG 状态反馈靠拢。
