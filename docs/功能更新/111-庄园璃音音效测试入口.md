# 庄园璃音音效测试入口

## 实现思路

本次把 `src/assets/game/audio/sfx` 下已经整理好的细节音效接入游戏资源加载流程，并在璃音所在的庄园互动位置增加一个可反复试听的测试按钮组。

接入方式保持在地图与事件体系内完成：

- 音频作为庄园地图资源包的一部分加载，不额外做全局页面或独立工具。
- 对话选项新增 `soundEffectPlay` 动作，用于从剧情/事件按钮中触发 Phaser 音效播放。
- 璃音原有“功能测试”分支中新增“测试细节音效”，进入后可以试听扎带收紧 1-4 和脚镣声。
- 每个试听按钮播放后仍回到音效测试节点，方便连续比较不同版本。

这样后续如果继续新增小型动作音效，可以沿用同一条链路：资源登记到地图 asset bundle，再通过对话或事件选项触发播放。

## 遇到的问题

1. 原资源 manifest 只支持图片和精灵图。

   庄园地图资源包原本只处理 `image` 和 `spritesheet`，如果直接在对话里写音效 key，运行时不会加载 mp3，也无法稳定播放。

2. 音效触发需要进入现有事件/对话执行链路。

   如果只在 Vue 里做临时按钮，会变成脱离地图事件的功能页面，不符合项目“冒险 RPG 优先”的方向。音效测试应该挂在璃音所在的互动位置上，作为世界内测试入口。

3. 音效按钮需要能连续试听。

   普通对话选项如果没有 `next` 会直接关闭对话，不适合比较多个音效版本。

4. `scripts/tests/event-runner.test.mjs` 当前不能直接用 Node 完整运行。

   脚本会先遇到既有的 extensionless import 解析问题：`src/game/data/dialoguePortraits.ts` 引用了 `src/game/data/portraits/registry`，Node 直接执行时无法解析该无扩展名导入。

## 解决方法

1. 扩展统一资源包能力。

   在 `src/game/data/assets.ts` 中新增 `GameAudioAssetEntry`，让地图资源包可以声明 `type: 'audio'`。加载时使用 `scene.load.audio`，已加载判断使用 `scene.cache.audio.exists`。

2. 让音效播放成为对话选项动作。

   在 `dialogueExecution.ts`、`eventExecution.ts`、`EventRunner.ts` 中补齐 `soundEffectPlay` 与 `playSoundEffect` 类型和执行逻辑。这样以后剧情节点、事件节点都可以通过相同方式触发音效。

3. 通过 Phaser WorldScene 实际播放。

   `WorldScene.playSoundEffect` 会先检查音频缓存是否存在，再调用 `this.sound.play(soundKey)`。如果 key 不存在，会输出 warning，而不是静默失败。

4. 把测试入口放在璃音原有互动树里。

   在 `liluo_estate/dialogues.json` 的 `function_test_branch` 中插入“测试细节音效”，并新增 `sound_effect_test_branch`。所有试听按钮都设置 `next: "sound_effect_test_branch"`，播放后回到同一个按钮组。

5. 用构建与数据校验确认结果。

   已执行：

   ```bash
   npm run build:web
   ```

   构建通过，产物中能看到 5 个 mp3 被打包。构建中仍有既有的 partial 图片路径和 `student1.png` warning，不是本次音频接入引入。

   另外执行了只读数据校验，确认璃音音效测试入口、5 个 `soundEffectPlay.key` 和实际音频文件可以对应。
