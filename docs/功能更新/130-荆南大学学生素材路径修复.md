## 更新时间记录

- 2026-07-21：首次修复荆南大学学生精灵图文件名与资源清单不一致的问题，补充资源路径回归测试，并确认生产构建不再出现 `student1.png` 缺失警告。

## 实现思路

沿着 Vite 构建警告检查学校地图资源清单、实际素材和原始 TMX，确认真实文件与 TMX 均使用 `student_1.png`，只有运行时 `assets.ts` 错写为 `student1.png`。保持地图 tileset 名、纹理 key 和 `map.json` 不变，仅把资源 URL 修正为真实文件名，避免触碰可能由地图工具重新生成的数据。

- `src/game/data/maps/modern/city_Jingjiang_school/assets.ts`

## 开发过程中遇到的问题

资源清单引用了不存在的 `NPCs/student1.png`。Vite 无法在构建期解析该 URL，只能保留原始字符串等待运行时加载，因此持续输出警告，并存在进入学校地图后学生纹理加载失败的风险。

首次在普通沙箱内执行生产构建时，esbuild 派生进程被系统以 `spawn EPERM` 拒绝。这是执行权限限制，不是代码或资源错误。

## 对应问题的解决方法

将资源 URL 改为真实存在的 `NPCs/student_1.png`，并增加回归测试，同时断言真实文件存在、清单使用带下划线文件名且不再引用旧名称。随后在允许 esbuild 派生进程的环境中重新执行生产构建。

- `npm run build:web`：通过，构建产物包含 `student_1-*.png`，原 `student1.png` 缺失警告已消失。
- `git diff --check`：通过。
