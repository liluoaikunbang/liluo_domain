# 床事件分支休息与全局主角立绘切换

## 本次实现思路

这次要补的不是单纯把 `liluo_room_bed_event` 的文案改成两个选项，而是把“**事件或对话选项可以更新全局主角立绘**”这条链路真正整理成可复用能力。

床事件只是这次的首个落地点：

1. 在 `liluo_room` 的床事件对话里增加两个休息选项；
2. 选项本身声明要切换到哪个主角立绘 key；
3. 对话执行层或事件执行层把这个 key 往上抛；
4. Phaser 与 Vue 之间的桥接层负责把这个变化同步到左侧主角立绘面板。

这样处理后，后续如果别的地图、别的事件也要让主角在剧情中切换成“受伤”“睡着”“换装”“特殊状态”立绘，就不需要在 `GameView` 里继续写死事件 id 判断，而是继续沿用：

- 数据层声明 `playerPortraitChange.portraitKey`
- 执行层调用 `setPlayerPortrait`
- UI 层统一接收并更新当前主角立绘

这能让地图事件、剧情对话和主角状态表现继续沉淀成同一条扩展路径，而不是做成一次性的床事件特判。

## 开发过程中遇到的问题

### 问题 1：只改床事件对话还不够，事件层的主角立绘更新没有真正穿透到 Vue UI

这次床事件的直接需求看起来只是“加两个选项并切图”，但项目当前左侧主角立绘是在 Vue 的 `GameView` 里管理的，而地图事件执行主要发生在 Phaser 的 `WorldScene` 和事件执行器里。

如果只在事件执行上下文里支持 `setPlayerPortrait`，但没有把这个变化继续桥接回 Vue，那么逻辑层会显示“已切换”，实际界面却不会更新。

### 解决方法

把这条链路补完整：

1. `WorldScene` 接收 `setPlayerPortrait`
2. 通过 `game.events.emit('player-portrait-change', portraitKey)` 派发
3. `createPhaserGame` 监听并转成 `onPlayerPortraitChange`
4. `usePhaserGameBridge` 继续透传给 `GameView`
5. `GameView` 统一修改 `activePlayerPortraitKey`

这样以后不管是事件动作触发，还是别的 Phaser 侧逻辑触发，只要走这条桥接链路，都能稳定更新到 Vue 侧 UI。

---

### 问题 2：对话选项触发与事件触发是两条相邻但不完全相同的路径

项目里已经有对话桥 `useGameDialogueBridge`，之前部分选项效果（比如时间、天气、通知）是直接在对话选择时处理的。这意味着主角立绘切换不能只补事件层能力，否则床事件这种“在对话选项上直接切图”的需求还是不完整。

### 解决方法

这次没有强行把所有逻辑改成单一路线，而是保持现有分层：

- **对话选项切换主角立绘**：继续走 `useGameDialogueBridge` 的 `applyPlayerPortraitChoice`
- **事件动作切换主角立绘**：走 `WorldScene -> createPhaserGame -> GameView` 这条桥接链路

同时在 `scripts/tests/event-runner.test.mjs` 里分别补测试，保证这两条路径都可用。

这样既没有打乱当前项目已有的对话桥结构，也把“事件更新全局主角立绘”的能力真正补齐了。

---

### 问题 3：新增 standee 素材后，需要同步维护素材清单

这次用到的两张主角休息立绘已经在代码里接入，但素材清单中原本还没有这两张 standee 的登记信息。如果漏掉这一步，后续追溯资源用途时会断层，也不符合仓库里的素材维护规则。

### 解决方法

同步更新 `docs/游戏素材图片清单.md`：

- 把图片总数从 `42` 更新为 `44`
- 补登记：
  - `src/assets/game/standee/Liluo_sleep.png`
  - `src/assets/game/standee/Liluo_sleep_tie.png`
- 明确这两张图当前都用于 `liluo_room` 床事件后的主角左侧立绘展示

这样资源记录和代码接入保持一致，后续继续扩展主角状态立绘时也更好追踪。
