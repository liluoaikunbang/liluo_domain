# 055-首页旅程入口与存档确认框视觉整理

## 实现思路

本次是在 `052-本机存读档与首页继续旅程入口`、`053-存档菜单条目化与布局收口`、`054-存档栏布局与编号整理` 的基础上，继续把首页入口和存档操作从“功能页面感”往“像素风冒险 RPG 菜单感”收拢。

目标是让首页的“新的旅程 / 继续旅程”和菜单里的读档、存档操作使用更统一的视觉语言：

- 首页“继续旅程”展开内容复用菜单内的存档列表结构，而不是维护一套单独样式。
- 首页继续旅程展开区默认占满三栏舞台空间，和主界面的三栏结构更协调。
- 首页“新的旅程”和“继续旅程”收进同一个命令框中，避免一个按钮一个框造成视觉割裂。
- 命令框改成半透明、低模糊、弱边框、白色描边的轻量 RPG 指令窗口。
- 删除存档不再使用浏览器默认 `confirm()`，改为项目内自定义确认框。
- 覆盖存档也增加确认框，避免误操作。
- 新增存档后的长期提示文案移除，只保留通知栏提示。

本次没有修改各地图 `map.json`，也没有新增 `src/assets/game` 下的素材图片。

  - 菜单读档、菜单存档、首页继续旅程统一使用同一套存档卡片结构。

## 开发过程中遇到的问题

### 1. 首页继续旅程和菜单读档维护了两套 UI

首页继续旅程最初有自己的展开列表样式，菜单读档页也有自己的存档列表。两者展示的是同一种存档摘要，却分别维护布局和交互，后续很容易出现风格不一致。

解决方法：

- 抽出 `SaveSlotList.vue` 作为游戏视图内部的基础组件。
- 首页继续旅程、菜单读档、菜单存档统一使用它。
- 差异通过 `mode` 和按钮插槽式配置收口，而不是复制整套 DOM 与 CSS。

### 2. 首页入口像功能按钮，不像 RPG 标题菜单

“新的旅程”和“继续旅程”分开成按钮与展开框后，视觉上更像网页功能入口，和项目“像素风冒险 RPG”的方向不够贴合。

解决方法：

- 将两个入口放进同一个命令框。
- 命令框缩小尺寸，减少页面中心的块状压迫感。
- 调整为半透明窗口、轻量白边、弱内部描边和低模糊背景。
- 按钮改成更接近指令菜单的行项目，使用悬停指示符而不是厚重按钮边框。

### 3. 浏览器默认确认框破坏游戏 UI 氛围

删除存档使用 `window.confirm()` 时会跳出浏览器原生弹窗，视觉上脱离游戏界面，也难以和菜单遮罩、像素风按钮保持一致。

解决方法：

- 新增 `GameConfirmDialog.vue`。
- 删除存档和覆盖存档都改为项目内确认框。
- 将确认框文案、危险操作按钮、取消按钮统一纳入游戏菜单风格。

### 4. 新增存档反馈长期停留在菜单内部

新增存档后，菜单内部长期显示“已新增存档 save003”这类文字，会把一次性反馈变成常驻信息，挤占存档列表空间。

解决方法：

- 移除菜单内部的长期反馈文本。
- 继续使用已有通知栏显示新增、覆盖、删除等操作结果。
- 让存档菜单只负责展示当前存档状态，不堆积历史操作提示。

## 后续维护建议

1. 后续继续调整首页入口时，优先保留“同一个 RPG 命令框承载主要入口”的方向，避免再次拆回多个独立功能按钮。
2. 存档卡片展示信息继续优先扩展 `SaveSlotList`，避免首页和菜单出现两套列表。
3. 涉及删除、覆盖、导入等可能改变数据的操作，优先复用 `GameConfirmDialog`，不要再回退到浏览器默认弹窗。
