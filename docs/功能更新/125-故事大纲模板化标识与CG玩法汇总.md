# 故事大纲模板化标识与 CG 玩法汇总

创建时间：2026-07-20

## 更新时间记录

- 2026-07-20：首次增加故事条目模板化标识、CG 具体内容序列、主要玩法规范与故事汇总玩法列，并修复汇总类别列宽度。

## 实现思路

故事条目 Markdown 新增 `isTemplated`，明确区分已经按当前模板完成整理的条目和仍沿用旧结构的条目。缺少该字段的旧条目统一按“旧版未模板化”展示，只有完成当前成熟度所需的 YAML 与正文章节后才能标记为 `true`。

CG 使用 `cgRefs` 保存真实图鉴资源引用，使用 `cgSequence` 按播放顺序保存 `CG标题｜出现时机｜具体画面内容`。右上角 CG 弹窗同时展示序号、时机、具体画面和资源预览；未制作 CG 不进入序列，只记录在正文需求和 `missingItems` 中。

主要玩法继续使用稳定的 `gameplayRefs`。模板要求先从玩法总表选择正式玩法；没有合适玩法时，必须先把新玩法完整加入玩法目录，再回填大纲。故事汇总新增“主要玩法”列，通过玩法 ID 解析正式标题，避免自由文本和失效引用污染统计。

## 遇到的问题

旧版故事 Markdown 与新版模板没有可靠的界面区分，无法快速判断哪些条目已经完成游戏化整理。原有 CG 关联只展示图鉴图片，没有携带该 CG 在故事中的出现时机和具体画面。主要玩法虽然已有 ID 关联，但模板没有强制从玩法总表选择，故事汇总也无法按正式玩法名称统计。

故事汇总增加玩法列后，原有表格最小宽度不足，类别列被浏览器压缩；改为固定宽度后又产生过多空白。

## 解决方法

前置信息解析器增加布尔字段处理，并对缺少 `isTemplated` 的旧节点使用安全默认值。CG 序列解析仅接受同时存在于 `cgRefs` 和图鉴资源中的条目，从数据层排除未制作 CG。

玩法名称统一由玩法目录解析，故事汇总只消费解析后的正式名称。类别列最终采用内容自适应宽度和单行显示，并在横向滚动时固定于左侧，既避免文字被压缩，也不预留多余宽度。
