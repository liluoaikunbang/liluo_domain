# 059-方向键小游戏模式与璃音场景测试入口

## 实现思路

本次目标是先做出一个像素 RPG 中常见的“上下左右方向键小游戏”壳子，让它可以作为一种可复用的场景模式，从地图事件或对话里启动。它不是独立工具页，而是和互动小说一样，作为游戏视图内的覆盖模式存在。

整体设计沿用现有 `GameView` 的模式分层：

- 底层仍然保留地图模式。
- 当对话选项触发方向键小游戏时，关闭对话并打开方向键小游戏覆盖层。
- 小游戏覆盖层使用现有三栏舞台布局，但不显示主角立绘，因为这类场景未来会以中间 CG / 背景图作为主要视觉。
- 左侧放标题、说明和上下左右按钮。
- 中间只展示背景图，并在底部半透明显示方向序列。
- 右侧只显示进度、错误比例、输入方式、重新开始和离开。

小游戏运行逻辑目前是最小可用壳子：

- 每个小游戏通过 `gameId` 在注册表中声明。
- 数据里配置标题、说明、背景图和目标方向序列。
- 玩家可以点击左侧方向键，也可以使用键盘方向键 / WASD。
- 按错不会立即失败或重开，只会让中间对应位置的方向格变红。
- 输入完整个序列后进入完成状态，并统计错误次数与错误比例。

璃音处的测试入口也做了分层整理：根节点保留“功能测试”和“场景测试”两个入口。天气、天色、通知仍放在“功能测试”；互动小说和方向键小游戏并列放在“场景测试”里。

## 开发过程中遇到的问题

### 1. 测试入口最初放错分组

方向键小游戏最初被放进璃音的“功能测试”分支，但这个小游戏更像一段可展开的场景模式，语义上应当和互动小说并列，而不是和天气、通知这类小功能调试项放在一起。

解决方法：

- 保留根节点的“功能测试”分支，用于天气、天色、通知等系统表现测试。
- 新增 `scene_test_branch`。
- 把互动小说入口和方向键小游戏入口并列放入“场景测试”。

### 2. 小游戏 UI 最初过于像操作台

第一版 UI 把标题、方向键、序列提示都集中在中间，导致中间主视觉被操作控件占满，不适合未来以 CG / 背景图表达场景氛围。

解决方法：

- 取消该模式下的左侧主角立绘。
- 左侧改为标题、说明和上下左右按钮。
- 中间只保留背景图作为主体视觉。
- 方向序列下放到底部，并做半透明处理，降低对背景图的遮挡。
- 右侧只保留状态和操作。

### 3. 错误输入不应该直接失败

早期运行逻辑在按错后直接进入 `failed` 状态，并显示“顺序乱了，重新来一次就好”。这不符合这类小游戏常见的节奏：更自然的行为是继续输入，只在对应位置标红，最后结算错误比例。

解决方法：

- 移除 `failed` 终止态。
- 每次输入都记录到 `inputSequence`。
- 对比当前输入和目标序列，UI 上只给对应位置标红。
- 序列输入完后进入 `success`。
- 在 payload 中增加 `errorCount` 和 `errorRate`，供右侧状态栏展示。

### 4. Node 测试不能直接导入图片模块

为了给小游戏配置背景图，最初在 `directionPadGames.ts` 中直接 `import` 了 `.png`。Vite 构建可以处理图片模块，但 Node 的 `node --test` 直接导入该 TypeScript 文件时不认识 `.png` 扩展，导致测试报错。

解决方法：

- 改用 `new URL('../../../assets/game/backgrounds/Liluo_bed.png', import.meta.url).href`。
- 这样 Vite 构建仍能正确处理资源路径，Node 测试也不会尝试把图片作为模块加载。

## 后续注意

1. 后续新增同类方向键小游戏时，优先在 `directionPadGameRegistry` 中新增配置，不要为每个地点重写一套运行逻辑。
2. 如果某个场景需要不同背景图，优先在小游戏定义里配置 `backgroundSrc`，不要在 Vue 组件里硬编码。
3. 当前模式是“按完整序列并统计错误比例”的壳子；如果后续要加入限时、判定窗口、音效或奖励结算，应继续扩展 `DirectionPadGameRunner`，让 UI 只负责展示。
4. 璃音处的测试入口应保持“功能测试 / 场景测试”分层，避免角色对话重新变成平铺调试菜单。
