# 068-旅途菜单拘束栏与动态状态接入

## 实现思路

本次在旅途菜单的“装备”与“任务”之间新增“拘束”栏目。拘束栏先沿用装备栏的四区布局：左侧分栏、条目列表、角色立绘预览、详情与操作区，保证后续扩展时界面结构和键盘导航都能继续复用。

分层上没有把新栏目内容直接堆进 `GameMenuOverlay`。静态占位定义放在 `data/global`，运行时状态继续使用已有的 `playerRuntime.restraints`，菜单 resolver 负责把静态定义和动态拘束 id 合并成可显示数据。`GameMenuOverlay` 只负责栏目接入、状态桥接和焦点导航。

同时更新了 `AGENTS.md` 中 `src/game` 目录约定，补充菜单数据解析、全局菜单静态数据、菜单面板组件拆分等必要说明，避免后续继续把菜单数据和 UI 外壳混在一起。

## 相关代码路径

- `src/game/views/components/base/RestraintMenuPanel.vue`
  - 新增拘束栏独立面板组件。
  - 复用装备栏布局样式和详情展示方式。

- `src/game/views/components/base/GameMenuOverlay.vue`
  - 接入 `restraints` 菜单 Tab。
  - 增加拘束栏独立选中状态和方向键导航组。
  - 通过 resolver 获取拘束栏展示数据。

- `src/game/data/global/gameMenuData.js`
  - 新增“拘束”菜单项。
  - 新增拘束栏静态分栏、占位条目与详情占位段落。

- `src/game/core/gameMenuDataResolver.ts`
  - 新增 `resolveRestraintMenuCategories()`。
  - 根据 `playerRuntime.restraints` 标记“已拘束”条目。
  - 对运行时存在但静态定义缺失的拘束 id 归入“未归档”分栏。

- `AGENTS.md`
  - 更新 `src/game` 目录约定，明确菜单静态数据、resolver、面板组件与 `GameMenuOverlay` 的职责边界。

## 遇到的问题与解决

### 1. 新栏目不应直接写进菜单外壳

问题：如果把拘束栏内容直接写在 `GameMenuOverlay`，菜单外壳会重新变成大组件，后续物品、装备、任务、拘束各自扩展时会互相挤在一起。

解决：新增 `RestraintMenuPanel.vue`，`GameMenuOverlay` 只做接入和导航协调。

### 2. 静态数据和动态状态需要分开

问题：拘束栏既需要静态分栏和占位说明，也需要读取当前角色实际拥有的拘束状态。

解决：静态定义放入 `gameMenuData.js`，动态状态读取已有 `playerRuntime.restraints`，由 `resolveRestraintMenuCategories()` 统一合并。

### 3. 运行时可能出现未定义拘束 id

问题：剧情或旧存档可能先写入某个拘束 id，但静态菜单定义还没补齐。

解决：resolver 为未知拘束生成“未归档”条目，保留真实 id，不在 UI 层静默丢弃。
