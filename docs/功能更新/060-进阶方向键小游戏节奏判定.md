# 060-进阶方向键小游戏节奏判定

## 实现思路

本次是在已有“方向键小游戏”模式上增加一个进阶版本，让它从普通的顺序输入小游戏，扩展为简易节奏判定玩法。

普通版本仍保持原样：玩家按顺序输入目标方向，系统记录正确与错误，最后统计错误比例。

进阶版本复用同一套三栏小游戏框架：

- 左侧继续复用标题、说明和方向键按钮。
- 右侧继续复用进度、错误比例、重新开始和离开。
- 中间区域在 `mode: 'rhythm'` 时切换为滚动轨道。
- 方向提示从左向右移动，在偏右的判定线附近按下对应方向才算命中。
- 如果方向提示超过判定窗口仍未输入，会自动判定为 `miss`。

核心判断放在 `DirectionPadGameRunner` 中，UI 只负责展示滚动位置、接收输入，并在当前音符超过窗口时通知运行器推进状态。这样后续如果要继续做音效、连击、评级或更复杂的音游规则，不需要把判定逻辑散落在 Vue 组件里。

## 开发过程中遇到的问题

### 1. 第一版进阶 UI 没有稳定滚动

最初中间区域主要依赖 CSS animation 和 `animationDelay` 来滚动方向 note。构建可以通过，但实际进入进阶小游戏后，用户反馈方向提示没有滚动起来。

原因是该实现把时间推进交给 CSS 动画延迟，Vue 状态变化后缺少明确的运行时钟。组件只在渲染时计算延迟，后续没有稳定地按小游戏开始时间刷新当前位置，实际体验容易像是停住。

解决方法：

- 移除 note 的 CSS keyframes 滚动。
- 在 `GameDirectionPadView.vue` 中使用 `requestAnimationFrame` 更新 `nowMs`。
- 每个 note 的 `left` 位置都按当前时间实时计算：
  - `noteHitAtMs = startedAtMs + leadInMs + index * noteSpacingMs`
  - `noteEnterAtMs = noteHitAtMs - travelMs * hitTravelRatio`
  - `leftPercent = -12 + progress * 124`
- 这样滚动与运行器使用的判定时间来源保持一致。

### 2. 进阶版最初只有按键判定，没有漏按判定

进阶版本初步能滚动后，用户继续指出：方向 note 超过判定范围后不会自动 Miss，只有玩家按键时才会结算。

这不符合节奏小游戏的基本预期。玩家如果完全不按，也应该随着 note 离开判定窗口自动计入错误并推进进度。

解决方法：

- 在 `DirectionPadGameRunner` 中新增 `resolveExpiredNotes`。
- 当 `checkedAtMs - expectedHitAtMs > hitWindowMs` 时，把当前 note 记为：
  - `input: null`
  - `result: 'miss'`
  - `timingOffsetMs` 记录超出的时间偏移
- 如果一次检查时已经过期多个 note，会用 `while` 一次性追上所有过期项。
- 在 `GameDirectionPadView.vue` 的动画帧中只检查当前 note 是否过期，过期时发出 `expire`。
- 在 `GameView.vue` 中调用运行器更新状态，避免 UI 自己直接改核心状态。

### 3. 右侧进度不能只看输入次数

自动 Miss 接入后，右侧原本用 `inputSequence.length` 显示进度。漏按没有实际输入，因此进度不会前进，容易误导玩家。

解决方法：

- 运行器 payload 中统一使用 `currentNoteIndex` 表示当前已经判定到的位置。
- 右侧面板改为显示 `payload.currentNoteIndex / targetSequence.length`。
- 普通模式下 `currentNoteIndex` 等同已输入数量；节奏模式下则包含自动 Miss。

## 后续注意

1. 后续新增同类节奏方向键小游戏时，优先在 `directionPadGameRegistry` 中新增 `mode: 'rhythm'` 配置。
2. 节奏判定相关参数应尽量留在数据配置中，不要在 Vue 组件里硬编码具体小游戏的速度和窗口。
3. 如果后续要加入连击、评分、音效或失败结算，应继续扩展 `DirectionPadGameRunner` 的 payload，而不是让 UI 单独维护一套结算状态。
4. 当前漏按自动判定只在节奏模式启用，普通顺序输入模式不受影响。
