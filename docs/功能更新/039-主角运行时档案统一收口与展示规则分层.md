# 主角运行时档案统一收口与展示规则分层

## 本次实现思路

这次重构的核心目标，不是单独修一处“状态栏显示什么”的小问题，而是把主角相关信息的分层重新立住：

**静态定义继续留在 `data/`，主角当前档案统一收口到 `playerRuntime`，所有写入走 actions，所有 UI 展示走 selectors。**

在这次整理前，项目里已经同时存在：

- 主角外观定义；
- 当前主角外观；
- 主角默认立绘与运行时立绘切换；
- 状态栏默认文案与运行时状态标签；
- 对话 / 事件对主角表现的局部修改入口。

这些内容虽然都“和主角有关”，但它们分散长在不同文件与桥接层里，导致几个问题：

1. `data/` 层混入运行时当前值；
2. `GameView.vue` 这种 UI 层自己承担了一部分业务判断；
3. `useGameDialogueBridge.ts` 里的 callback 随着功能增加不断横向膨胀；
4. “原始状态”和“展示文案”之间没有统一收口，容易在别处偷偷推导。

因此这次没有继续沿着旧结构补洞，而是先做了一个最小但完整的统一入口：

- 新增 `src/game/core/playerRuntime.ts`；
- 用它承载主角当前运行时档案；
- 把外观、立绘、状态、拘束的读取与修改都统一到这里；
- 让 UI 只消费 selector，不再自己拼默认优先级。

这样做之后，后面即使继续加入：

- 装备；
- 物品；
- Buff；
- 剧情标记；

也可以继续沿着同一套模式扩展，而不是再长出一批散装全局变量。

## 相关代码路径

- `src/game/core/playerRuntime.ts`
  - 新增统一主角运行时档案入口；
  - 定义 `PlayerRuntimeState`；
  - 提供 `setPlayerAppearance`、`setPlayerPortrait`、`setPlayerStatus`、`setPlayerRestraints`、`resetPlayerRuntimeState` 等 actions；
  - 提供 `resolvePlayerRuntimeCharacterDefinition`、`resolvePlayerRuntimePortrait`、`resolvePlayerRuntimeStatusLabel` 等 selectors。

- `src/game/data/playerCharacter.ts`
  - 只保留主角外观、spritesheet、动画配置等静态定义；
  - 移除 `currentPlayerAppearanceId` 这一类运行时状态。

- `src/game/data/playerStatus.ts`
  - 收缩为默认状态展示文案等静态常量；
  - 运行时状态逻辑不再留在这里。

- `src/game/views/GameView.vue`
  - 左侧主角面板改为通过 `playerRuntime` selector 读取：
    - 当前立绘；
    - 当前状态文案；
  - 新旅程、挂载与卸载时的主角重置统一改走 `resetPlayerRuntimeState()`。

- `src/game/views/composables/useGameDialogueBridge.ts`
  - 对话桥接层不再继续堆散装 callback；
  - 改为暴露统一的 `playerRuntimeActions` 给事件 / 对话链路调用。

- `src/game/views/composables/usePhaserGameBridge.ts`
- `src/game/core/createPhaserGame.ts`
  - 回收只为主角立绘或外观单独存在的桥接接口，统一对接 `playerRuntime`。

- `src/game/systems/map/worldSceneRuntime.ts`
  - 场内玩家精灵当前使用的外观定义改为从 `playerRuntime` 读取；
  - 外观切换后同步写回统一主角档案。

- `src/game/scenes/WorldScene.ts`
  - 地图 / 事件层对主角外观与立绘的改动统一写入 `playerRuntime`。

- `scripts/tests/event-runner.test.mjs`
  - 补充并更新运行时外观、立绘、状态 selector 的测试覆盖。

## 开发过程中遇到的问题

### 问题 1：`data/` 层同时承载静态定义和当前运行值，职责已经混乱

之前 `src/game/data/playerCharacter.ts` 里既有主角外观表，也有当前主角外观状态与 set/reset 方法。

这在功能少的时候还勉强能用，但一旦主角信息继续增长，就会出现：

- 静态资源定义和运行时档案混在一起；
- UI 和场景都能直接读写同一份“散装当前值”；
- 后续难以判断某个字段到底属于世界定义，还是当前角色状态。

### 解决方法

新增 `src/game/core/playerRuntime.ts` 作为统一运行时入口，并明确约束：

1. `data/` 只放静态定义；
2. 当前主角档案统一进 `playerRuntime`；
3. 所有修改都通过 actions；
4. 所有展示都通过 selectors。

这样主角运行时状态终于和静态定义彻底分层。

---

### 问题 2：UI 自己拼业务规则，状态显示优先级容易四处分叉

这次最直接暴露出来的问题就是左栏状态文案：

- 到底显示 `status` 还是 `restraints`；
- 都为空时默认显示什么；
- 能不能从立绘反推状态。

如果把这些逻辑散落在 `GameView.vue` 或别的组件里，之后每加一个展示位置，就会复制出一份近似但不完全相同的规则。

### 解决方法

把展示规则收口成 selector：

- `resolvePlayerRuntimeStatusLabel()`

目前统一规则为：

1. 有 `status` 时优先显示 `status`；
2. `status` 为空时回退 `restraints`；
3. 两者都为空时回退默认值 `自由`。

这样 UI 层只负责展示结果，不再自己拼接业务文案。

---

### 问题 3：桥接层 callback 越长越横向膨胀，后续难扩展

在这次整理前，`useGameDialogueBridge.ts` 里已经有多组 callback：

- `setTimeOfDay`
- `setWeather`
- `setPlayerPortrait`
- `setPlayerAppearance`

如果继续按这个方向长，后面很容易继续加出：

- `setPlayerStatus`
- `setPlayerRestraints`
- `addItem`
- `equipItem`

这样桥接层会越来越像一个散装转接板，不利于维护。

### 解决方法

这次先做最小统一：

- 桥接层改为收口主角相关动作到 `playerRuntimeActions`；
- 对话 / 事件层对主角的改动统一走主角动作入口；
- 天气、时间这类环境能力继续保留独立职责，不和主角档案混写。

这样至少主角相关链路已经形成清晰边界，后续再接物品、装备时有明确落点。

---

### 问题 4：Node 测试环境下新增运行时模块后，ESM 路径解析暴露了扩展名问题

这次新增 `src/game/core/playerRuntime.ts` 后，运行：

```bash
node --test scripts/tests/event-runner.test.mjs
```

测试最初报错：

- `Cannot find module 'src/game/data/dialoguePortraits' imported from src/game/core/playerRuntime.ts`

原因不是逻辑本身错了，而是 Node 的 ESM 测试环境在当前链路下需要显式扩展名，不能像 Vite 开发态那样默认帮忙补齐。

### 解决方法

把 `playerRuntime.ts` 里对应的导入路径改成显式 `.ts`：

- `../data/dialoguePortraits.ts`
- `../data/playerCharacter.ts`
- `../data/playerStatus.ts`

修正后，测试重新通过，说明这次重构在浏览器构建链路和 Node 测试链路下都能正常工作。

## 最终验证结果

本次重构完成并经实际测试确认后，当前结果如下：

1. 主角当前外观、立绘、状态、拘束已统一收口到 `src/game/core/playerRuntime.ts`；
2. `data/` 层已回到“只放静态定义”的职责边界；
3. `GameView.vue` 不再自己拼主角状态展示规则，而是统一消费 selector；
4. 对话 / 事件对主角外观与立绘的改动已统一走主角运行时 actions；
5. 新旅程与主角重置流程已统一走 `resetPlayerRuntimeState()`；
6. 这套结构已经为后续接入物品、装备、更多状态字段预留好了扩展位置。

本次验证命令：

```bash
node --test scripts/tests/event-runner.test.mjs
npm run build:web
```

验证结果：

- `event-runner` 相关测试通过，包含主角运行时外观 / 立绘 / 状态 selector 的新增覆盖；
- `vite build` 构建通过；
- 构建中仍保留项目原有的 tileset `new URL(...) doesn't exist at build time` warning；
- 未因这次主角运行时重构新增新的构建错误；
- 已由用户实际测试确认当前功能无报错，可以作为已完成沉淀记录。
