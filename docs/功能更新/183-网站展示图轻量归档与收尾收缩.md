# 183-网站展示图轻量归档与收尾收缩

## 背景

官网视觉批次进入“正式收录”阶段后，单次归档经常把几类动作混在一起：

- 把候选图复制到正式展示位
- 做哈希校验
- 手工回写 `art-manifest.json`
- 再补批次记录和基础总账

这类操作本身并不重，但以前主要靠手工串联，导致“图已经定了，归档还要再花几分钟”的体感偏重。

## 本次调整

1. 新增 `scripts/site/promote-site-asset.mjs`，并通过 `npm run site:asset:promote -- ...` 暴露入口。
2. 脚本默认收口最常见的正式收录动作：
   - 候选图复制到正式展示位
   - `sha256` 校验源文件与正式位一致
   - 定向更新 `docs/assets/readme/art-manifest.json` 对应条目
   - 可选地给对应批次记录补一条“已正式收录”的说明
3. 在《项目图像生成判层与治理系统》中补上“正式收录收尾收缩”规则：
   - 同一批次、同一资产的连续微调继续留在批次记录和视觉反馈账本
   - 只有正式收录或新增长期规则时，才补基础总账
   - 正式展示位替换优先走脚本，不再默认手工串联

## 这样收缩后的边界

- 轻量脚本负责“机器确定性步骤”。
- 批次记录负责“这轮图像是怎么演进到正式收录的”。
- `control/records/foundation-updates/` 只保留正式收录或长期规则变化的可复盘摘要，不再把每次小变体都当成新主题。

## 相关文件

- `scripts/site/promote-site-asset.mjs`
- `package.json`
- `docs/系统说明/项目图像生成判层与治理系统.md`

## 验证

- 用当前 `浮光掠影` 六区总图的正式收录信息做一次回归运行，确认脚本能稳定完成：
  - 正式展示位与候选图 `sha256` 一致
  - `art-manifest.json` 可解析
  - 已存在的批次说明不会重复追加
