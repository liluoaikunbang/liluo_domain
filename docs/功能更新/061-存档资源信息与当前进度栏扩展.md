# 061-存档资源信息与当前进度栏扩展

## 实现思路

本次是在已有本机存读档系统上补齐更像 RPG 档案的信息展示：存档不只记录地点和角色状态，也要把全局资源一起纳入保存、读取和档位摘要。

实现分成两层：

1. 数据层把“绮欲结晶”接入全局运行时状态，与金币一样进入 `GameSaveData.global`，旧存档缺少该字段时默认补为 `0`。
2. UI 层把存档/读档档位卡片和存档页“当前进度”栏改成横向信息展示，统一显示状态、金币与绮欲结晶；当前进度栏额外补上主角行走图预览。

最终存档页当前进度栏的横向顺序为：

```text
行走图 -> 地图/坐标 -> 状态 -> 金币 -> 绮欲结晶
```

档位卡片保留原来的角色预览、地图名、状态和保存时间，并在状态同一行补充金币与绮欲结晶数量。

## 开发过程中遇到的问题

### 1. 金币最初只存在于完整存档，不存在于档位摘要

档位卡片只拿 `listGameSaveFiles()` 返回的摘要对象，不直接读取完整 `GameSaveData`。因此只在 `saveData.ts` 写入金币还不够，卡片没有可用字段。

解决方法：

- 在 `GameSaveFileSummary` 中加入 `goldAmount`。
- 在 `createSaveFileSummary()` 中从 `saveData.global.gold` 派生摘要字段。
- 对无效或旧数据做默认值兜底。

### 2. 绮欲结晶需要同时进入运行时、存档和 UI

如果只在 UI 写死一个显示值，会变成假数据；如果只加进存档，物品栏和当前进度栏又无法显示当前值。

解决方法：

- 把绮欲结晶作为 `gameRuntime` 的全局资源字段。
- 存档创建、解析、读档恢复都走同一份 `GameRuntimeState`。
- 存档列表摘要再从存档中的 `global.desireCrystals` 派生显示值。

### 3. 资源文本在 UI 中一度没有稳定显示

物品栏和存档卡片中直接写 `金币：{{ amount }}`、`绮欲结晶：{{ amount }}` 后，用户反馈实际页面没有看到绮欲结晶。项目中部分历史文件存在编码显示问题，终端读取时也能看到中文片段与 Vue 插值在同一行时容易呈现为乱码，不利于定位。

解决方法：

- 改为在脚本中通过 `formatResourceText(label, amount)` 生成完整文本。
- 模板中只渲染 `{{ formatResourceText(...) }}`。
- 构建后确认产物中包含对应的 `绮欲结晶` 渲染文本。

### 4. 当前进度栏原本只适合显示地图和坐标

存档页上方的“当前进度”栏原本结构是标签、地图名、坐标和新增存档按钮。直接塞入更多字段会导致拥挤或顺序不清。

解决方法：

- 将当前进度栏改成横向信息条。
- 第一项使用当前主角行走图 `savePreview` 帧。
- 地图和坐标组成一组，后面依次排列状态、金币、绮欲结晶。
- 行走图使用 `image-rendering: pixelated` 与 spritesheet 背景定位，保持像素风一致。

## 后续维护建议

1. 后续新增全局资源时，优先扩展 `gameRuntime.ts`、`saveData.ts`、`saveStorage.ts` 的同一条链路，不要只在 UI 中补显示。
2. 存档卡片和当前进度栏应继续使用摘要/运行时数据，不直接读取 `localStorage`。
3. 如果资源种类继续增加，建议先评估是否需要抽出统一的资源显示配置，但在资源数量很少时保持当前直写结构更清晰。
4. 当前进度栏的行走图预览使用角色定义中的 `savePreview`，后续新增主角外观时应同步补齐 `savePreview`，避免当前进度和档位卡片显示不一致。
