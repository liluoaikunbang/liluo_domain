# 049-对话入口收束与说话人高亮

## 实现思路

本次围绕地图对话体验做了两处轻量优化。

第一处是收束璃音在庄园里的测试对话入口。原先第一层选项直接暴露“调整时间”“调整天气”“测试通知”，站在璃音面前的交互说明也明确写出天色、天气与通知表现，整体更像调试面板。现在将这些内容合并到“功能测试”下，让璃音入口先保持角色对话感，再把具体测试项放到下一层。

第二处是给对话中的当前说话人增加视觉高亮。对话期间如果右侧存在 NPC 立绘，并且当前节点声明了 `speakerSide`，系统会让正在说话的一侧边框更亮，另一侧稍微压暗。玩家不需要只靠名字判断是谁在说话。若当前对话没有其他 NPC 立绘，则主角面板保持原样，不会被无意义压暗。

## 相关代码路径

- `src/game/data/maps/liluo_estate/dialogues.json`
  - 将璃音入口第一层选项收束为“功能测试”。
  - 新增 `function_test_branch`，把天色、天气、通知测试统一放到功能测试分支下。
  - 调整璃音对话文案，避免过度绑定具体时间和天气。
- `src/game/data/maps/liluo_estate/events.json`
  - 将站在璃音面前的选项改为“和璃音聊聊（Space）”。
  - 调整描述为璃音帮忙照看庭院功能，不再直接写天色、天气与通知测试。
- `src/game/views/modes/map/MapMode.vue`
  - 根据 `showDialog`、`activeDialogue.speaker`、`activeDialogue.speakerSide` 与 NPC 立绘是否存在，计算左右侧说话状态。
  - 只有存在真实对话对象时才启用高亮/压暗，避免单人对话时主角状态异常变化。
- `src/game/views/shell/GameShell.vue`
  - 将主角侧说话状态传给左侧 `GameSidePanel`。
- `src/game/views/shell/GameSidePanel.vue`
  - 新增 `speakerState`，支持 `neutral`、`active`、`muted` 三种状态。
  - 为当前说话侧增加更亮边框、内发光和标题栏高亮。
  - 为非当前说话侧降低亮度与饱和度。

## 开发过程中遇到的问题

### 1. 璃音入口过于具体，角色感被测试项压住

最初璃音对话第一层直接列出“调整时间”“调整天气”“测试通知”，站在角色面前时的选项说明也写明这些能力。这样虽然方便测试，但在地图中看起来更像工具入口，不太像 RPG 里的角色互动。

解决方法：

- 保留原有测试能力，不删除已有功能。
- 将时间、天气、通知统一收进“功能测试”分支。
- 第一层文案改为“庭院这边有些东西刚接好，要不要顺手看一眼？”。
- 站前选项改为“和璃音聊聊（Space）”，让玩家先感知到是在和角色互动。

### 2. 说话人高亮不能影响没有 NPC 的对话

如果只按 `speakerSide` 直接给左右侧套 active/muted，单句事件或没有 NPC 立绘的对话也可能把主角压暗，造成“明明只有主角面板却被暗下去”的误读。

解决方法：

- 在 `MapMode.vue` 中先判断 `hasDialoguePartner`。
- 只有满足以下条件时才启用说话人状态：
  - 当前正在显示对话。
  - 当前不在过场切换中。
  - 当前节点有 `speaker`。
  - 当前对话存在 NPC 立绘资源。
- 不满足条件时左右面板都使用 `neutral`。

### 3. 高亮需要足够明显，但不能打断像素 RPG 的整体氛围

对话 UI 原本已经是暗紫色像素风舞台，如果高亮做得太强会像现代网页卡片状态；如果太弱又无法承担“不用看名字也知道谁在说话”的目标。

解决方法：

- 高亮侧只增强边框、标题栏和轻微内发光，不改变布局。
- 压暗侧只降低亮度与饱和度，并保留人物可读性。
- 状态变化加短过渡，避免切换说话人时闪得太硬。

## 后续维护建议

1. 后续新增双人对话时，继续在对话节点里显式维护 `speakerSide`，让 UI 能稳定判断当前说话侧。
2. 没有 NPC 立绘的事件对话不需要为了高亮强行补占位立绘，保持 `neutral` 更自然。
3. 调试性质的地图功能可以继续挂在角色对话下，但第一层尽量保留角色互动感，具体测试项放到二级分支。
