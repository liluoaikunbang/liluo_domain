# 主角行走图动态图层拼接规范

本次把主角行走图整理成可继续扩展、可正式维护的动态图层拼接规范。

最终规则是：

1. `LiLuo_body_down` 作为主角行走图的底层，保留下身等身体下半部分像素。
2. 正常状态下，运行时在底层之上叠加 `LiLuo_body_up`。
3. 当主角处于双手被缚状态时，不更换底层，只把上身层从 `LiLuo_body_up` 替换为 `bondage_body_up`。
4. 当主角处于双腿被缚状态时，`legs_bound` 的移动表现优先级高于普通 20 帧行走循环：只使用四个方向的站立帧，并由 hop 移动表现负责“蹦跳”。
5. 双腿被缚状态不会吞掉其它身体图层。它只额外把 `bondage_body_down` 作为腿部最上层叠加；如果同时有双手被缚，上身仍然使用 `bondage_body_up`。
6. `LiLuo_head` 作为头部顶层叠加，普通状态、双手被缚状态和双腿被缚状态共用；`bondage_body_down` 最后叠加，保证腿部束缚层压在腿部区域最上面。
7. 所有子图继续共用 `liluo.png` 推导出的模板裁剪坐标，保持每帧固定尺寸，避免后续图层叠加时出现相对位置错位。
8. 图层合成仍在角色资源初始化时动态生成，不提前输出整套已经合成好的预览帧。

## 相关代码路径

- `src/game/data/playerCharacter.ts`
  - `default` 外观现在使用 `LiLuo_body_down + LiLuo_body_up + LiLuo_head`。
  - `bondage` 外观现在使用 `LiLuo_body_down + bondage_body_up + LiLuo_head`。
  - `legs_bound` 外观现在使用 `LiLuo_body_down + LiLuo_body_up + LiLuo_head + bondage_body_down`，并只注册四个方向的站立帧作为移动动画帧。
  - `bondage_legs_bound` 外观现在使用 `LiLuo_body_down + bondage_body_up + LiLuo_head + bondage_body_down`，用于双手和双腿同时被缚时保留上身束缚层。
  - 资源 manifest 按 key 去重，避免默认外观和束手外观重复加载同一组底层帧。
- `src/game/data/playerMovementPresentationRules.ts`
  - `hands_bound` 状态继续解析到 `bondage` 外观，因此只替换上身层，不改变底层。
  - `legs_bound` 状态会切换为四方向站立帧 + `hop` 移动；如果同时存在 `hands_bound`，实际外观解析为 `bondage_legs_bound`，保留双手被缚上身层。
  - `legs_bound` 同时承担移动表现参数：当前速度减速为 50%，`hopAmplitude` 为 18，`hopSpeed` 为 0.02。视觉蹦跳和实际移动速度要一起调，避免角色看起来像滑行。
- `src/game/systems/animation/character/layeredCharacterTexture.ts`
  - 继续负责运行时动态图层合成与显示锚点计算。
- `scripts/assets/build-liluo-character-frames.ps1`
  - 继续负责从母版图按统一模板坐标生成固定尺寸独立帧缓存。
  - 构建前置仍会调用该脚本作为兜底；脚本会先检查 20 张目标帧是否齐全、且是否不早于 `liluo.png` 模板和对应源图。缓存新鲜时直接跳过，只有源图变化或缓存缺失时才重建。
- `docs/游戏素材图片清单.md`
  - 已同步记录 `LiLuo_body_down`、`LiLuo_body_up`、`LiLuo_head`、`bondage_body_up`、`bondage_body_down` 的最终用途。

## 处理过的问题

### 问题 1：早期验证状态把默认主角直接接成了束手上身层

之前为了快速验证图层叠加效果，默认外观直接使用了 `bondage_body_up`。

解决方式：

- 默认外观改回普通上身层 `LiLuo_body_up`；
- 束手状态专门使用 `bondage` 外观；
- `bondage` 外观只替换上身层，底层仍复用 `LiLuo_body_down`，顶层仍复用 `LiLuo_head`。

### 问题 2：默认外观和束手外观共用底层与头部层，可能导致资源清单出现重复 key

动态图层方案下，`default` 和 `bondage` 都需要加载 `LiLuo_body_down` 底层帧和 `LiLuo_head` 顶层帧。

解决方式：

- 在 `playerCharacterAssetBundle.manifest` 生成阶段按资源 key 去重；
- 保留每个外观自己的完整 `textureAssets` 描述，方便单独检查外观资源；
- 全局加载时避免重复注册同一个底层贴图。

### 问题 3：构建前置切图会和手动切图重复执行

为了防止换图后忘记生成独立帧，`build:web` 前仍保留自动切图兜底。

但如果每次构建都重新裁切所有图层，会让构建变慢，也会让“手动切过图”显得没有意义。

解决方式：

- 保留 `prebuild:web -> assets:build-liluo-character-frames`；
- 在切图脚本开头检查每个源图对应的 20 张缓存帧；
- 如果缓存帧齐全，且都不早于 `liluo.png` 模板和对应源图，则输出跳过信息；
- 只有源图更新、模板更新或缓存缺失时，才重新计算模板裁剪框并重建对应图层。

### 问题 4：双腿被缚状态不应该继续播放 20 帧行走循环

`bondage_body_down` 是腿部束缚层，当前只需要覆盖四个方向的站立姿态。如果它仍然沿用普通 20 帧行走循环，就会和“腿部被缚只能蹦跳移动”的表现相冲突，也容易在其它动态图层仍然存在时误播走路帧。

解决方式：

- 新增 `legs_bound` 分层外观，专门服务双腿被缚状态；
- 新增 `bondage_legs_bound` 组合外观，服务双手和双腿同时被缚的状态；
- 两个外观仍动态拼接底层、上身层、头部层和腿部束缚层，不提前输出合成帧；
- 动画配置只把每个方向的站立帧注册为 walk / idle 可用帧；
- 状态规则中 `legs_bound` 只负责把移动表现切为四方向站立帧 + hop；外观图层仍按当前状态组合解析，双手被缚的 `bondage_body_up` 不会被腿部束缚吞掉。

### 问题 5：只调 hop 不调移动速度会让角色看起来像飘着走

双腿被缚时，角色虽然只播放四个方向的站立帧，但如果地图实际移动速度仍然太快，画面上会像角色被平移滑过去，而不是绑腿后一步一蹦。

解决方式：

- `legs_bound` 的 hop 表现参数调为 `hopAmplitude: 18`、`hopSpeed: 0.02`，让起跳和落地更明显；
- `legs_bound` 的实际速度减速调为 50%，由 `playerMovementPresentationRules.ts` 和其它状态减速一起加法叠加；
- 当前典型叠加结果：
  - 只有双腿被缚：速度倍率为 `0.5`；
  - 无鞋 + 双手被缚 + 双腿被缚：速度倍率为 `0.35`；
  - 无鞋 + 赤脚 + 双手被缚 + 双腿被缚：速度倍率为 `0.3`。

## 当前结论

主角行走图现在按“底层固定、上身层按状态替换”的方式组织：

- 普通：`LiLuo_body_down + LiLuo_body_up + LiLuo_head`
- 双手被缚：`LiLuo_body_down + bondage_body_up + LiLuo_head`
- 双腿被缚：`LiLuo_body_down + LiLuo_body_up + LiLuo_head + bondage_body_down`，只取四个方向站立帧并使用 hop 移动，速度减速 50%
- 双手与双腿同时被缚：`LiLuo_body_down + bondage_body_up + LiLuo_head + bondage_body_down`，只取四个方向站立帧并使用 hop 移动，双手和双腿减速继续叠加

后续新增 NPC 或新增衣装/拘束层时，优先沿用这套方式：先生成固定尺寸独立帧，再在角色资源初始化时动态合成。

## 正式化整理

这套主角行走图方案已经从验证方案转为正式资源管线：

- npm 脚本统一为 `assets:build-liluo-character-frames`；
- 构建脚本统一为 `scripts/assets/build-liluo-character-frames.ps1`；
- `src/game/data/playerCharacter.ts` 中移除了临时验证开关和旧 32px 默认行走图回退分支；
- 当前默认主角外观直接使用分层独立帧方案；
- 对应测试文件整理为 `scripts/tests/player-layered-character-frames.test.mjs`。
