# 璃落房间睡眠过场与离房换衣检查

## 本次实现思路

这次功能围绕 `liluo_room` 的床铺事件和离开房间事件做了一次完整的事件链路扩展。

核心目标不是把“睡觉黑屏”“拘束睡袋醒来”“出门前换衣服”写成几个临时特判，而是继续沿用项目当前的 RPG 事件数据方式：

1. 对话选项只声明要发生什么；
2. 对话 / 事件执行层负责解释这些声明；
3. Vue 侧负责过场与对话 UI；
4. Phaser 侧负责地图跳转和场内行走图刷新；
5. 主角当前立绘、行走图和状态继续走 `playerRuntime` 统一运行时档案。

最终形成了三段可玩的流程：

- 选择“上床休息”或“体验下拘束睡袋休息”后，会播放中间地图栏黑屏过场，显示“一夜无话……”；
- 选择拘束睡袋休息后，醒来会提示“才发现自己还被捆着呢”，并可选择是否让女仆解开；
- 从璃落房间门口离开时，如果当前立绘不是默认立绘，会先提示“穿成这样出去不太好吧，还是换身衣服吧”，点击“换身衣服”后恢复默认状态并继续离开房间。

这三段流程都服务于“地图中移动、触发事件、推进状态变化”的冒险 RPG 主线体验，而不是额外做一个独立换装页面。

## 开发过程中遇到的问题

### 问题 1：第一版只有等待，没有真正显示黑屏和字幕

最初实现时，对话桥接层已经等待了 cutscene 的持续时间，但 `GameView.vue` 中黑屏层的显示依赖一次 `0ms` timer 把 `isVisible` 从 `false` 切到 `true`。

这导致逻辑层确实延迟了几秒，但前端黑屏层没有稳定进入可见状态，用户实际看到的是“等了一下，然后直接切换对话”。

### 解决方法

把 cutscene 状态改成更直接的阶段模型：

- `phase: 'visible'`
- `phase: 'leaving'`

过场状态一出现，中间地图栏的黑屏层就立即挂载并可见；淡入淡出交给 CSS animation 处理，不再依赖额外的 0ms 状态切换。

这样前端表现与事件等待时间绑定在同一份 `activeCutscene` 状态上，显示更稳定。

---

### 问题 2：黑屏结束后会短暂闪出原始地图

第二版黑屏可以显示了，但黑屏淡出后会先露出 Phaser 原始地图，再切回床铺背景图。

原因是当 `activeCutscene` 存在时，`GameView.vue` 同时隐藏了事件场景图 `sceneImage`。黑屏层淡出到移除之间，底下没有床铺背景图，只剩原始地图。

### 解决方法

调整中间地图栏层级策略：

1. 过场期间不再隐藏 `sceneImage`；
2. 床铺背景图保持在黑屏层下方；
3. 过场结束时先应用下一句对话，再移除黑屏层。

这样黑屏淡出时，底下已经是床铺事件背景图，不会再闪出原始地图。

---

### 问题 3：拘束睡袋醒来后需要保留或恢复两种状态

拘束睡袋分支不是单纯“睡醒后恢复默认”，而是要给玩家一个选择：

- 不解开：保持当前拘束睡袋立绘、`full_body_bondage` 行走图和“拘束睡袋”状态；
- 解开：恢复空状态、默认行走图，并切到 `Liluo_sleep.png` 对应的休息立绘。

如果在醒来节点里直接恢复默认，就会丢掉“不解开”的分支表达。

### 解决方法

把 `sleep_in_tie_bag_selected` 改成带选项的对话节点：

- `ask_maid_to_untie`
  - `playerAppearanceChange.appearanceId = "default"`
  - `playerStatusChange.status = []`
  - `playerPortraitChange.portraitKey = "portrait_liluo_sleep"`

- `stay_tied_after_sleep`
  - 不声明任何状态修改字段，因此保持现状。

这样状态变化完全由对话选项声明，不需要额外写 UI 或场景特判。

---

### 问题 4：门口离开事件原本是直接地图跳转，无法先弹提示

`liluo_room_leave` 原本只有 `mapTransition`。只要触发门口事件，就会直接切到客厅。

这无法表达“当前立绘不是默认立绘时，先拦下提示换衣服；恢复默认后再离开”的条件流程。

### 解决方法

新增一个窄范围事件条件字段：

```json
"defaultPlayerPortraitRequired": {
  "fallbackDialogueId": "liluo_room_leave_change_clothes_required"
}
```

事件执行时：

1. 先通过 `isPlayerPortraitDefault()` 判断当前立绘是否为默认立绘；
2. 如果不是默认立绘，返回 fallback 对话，不执行 `mapTransition`；
3. 如果已经是默认立绘，则照常执行原来的离开房间地图跳转。

判断逻辑使用 `playerRuntime` 中的当前立绘 key 和默认立绘 key，不从 UI 或素材路径反推。

---

### 问题 5：换衣服对话选项需要在恢复状态后继续触发地图跳转

出门换衣提示只有一个选项“换身衣服”。点击后不仅要恢复默认立绘、行走图和状态，还要继续执行原本的离开房间流程。

之前对话选项只支持角色状态、天气、时间、通知等副作用，不支持地图跳转。

### 解决方法

给对话选项补充 `mapTransition` 支持：

- `dialogueExecution.ts` 识别 `choice.mapTransition`；
- `useGameDialogueBridge.ts` 把 `changeMap` 放进对话选项执行上下文；
- `usePhaserGameBridge.ts` 暴露 `changeMap()`；
- `WorldScene.ts` 抽出共用 `changeMap()`，供事件和对话选项复用。

因此“换身衣服”可以在同一个选项里声明：

1. 恢复默认行走图；
2. 恢复默认立绘；
3. 清空状态；
4. 跳转回客厅。

---

### 问题 6：测试直接导入统一 registry 时暴露 Node JSON import 限制

新增 live 数据测试时，一开始直接从 `src/game/data/registry.ts` 读取 `eventRegistry`。

但 Node 的 ESM 测试环境会直接解析 registry 中多个 `.json` import，而部分旧 import 没有 `with { type: 'json' }` 属性，导致测试报：

```text
ERR_IMPORT_ATTRIBUTE_MISSING
```

这不是本次事件逻辑错误，而是 Node 测试环境和 Vite 构建环境对 JSON import 的差异。

### 解决方法

测试改为直接导入本次需要验证的：

```js
import liluoRoomEvents from '../../src/game/data/liluo_room/events.json' with { type: 'json' };
```

这样测试只读取 `liluo_room` 的 live 事件源数据，避免无关 registry JSON import 影响本次验证。

## 最终验证结果

本次功能完成后，已经由用户实际测试确认无报错，效果符合预期：

1. 床铺休息会播放中间地图栏黑屏过场；
2. 黑屏过场会显示“一夜无话……”；
3. 过场期间左侧主角立绘保持不变，右侧栏为空；
4. 黑屏结束后不会再闪出原始地图；
5. 拘束睡袋醒来后可选择是否让女仆解开；
6. “先这样待着”会保持拘束睡袋状态；
7. “让女仆帮忙解开”会恢复空状态、默认行走图和休息立绘；
8. 从璃落房间门口离开时，如果主角立绘不是默认立绘，会先提示换身衣服；
9. “换身衣服”会恢复默认立绘、默认行走图、空状态，并继续离开房间回到客厅；
10. 当前实现仍沿用数据驱动事件链路，没有把这几段流程写成 UI 层硬编码。
