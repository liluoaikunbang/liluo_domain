# 056-清空全部存档与导入校验收紧

## 实现思路

本次围绕菜单存档界面补齐“清空全部浏览器本机存档”的能力，并把导入/读档链路的校验收紧。

新版 RPG 存档使用 `liluo_domain:game_save:` 作为 localStorage key 前缀，因此清空全部存档时只删除这个前缀下的键，不清理 `appVersion` 等非存档数据。菜单按钮放在存档页底部操作区，点击后先弹出项目已有的确认框，确认后再执行删除。

导入存档时不再用“补默认角色”的方式容错。`player` 缺失、玩家外观 id 不合法、头像 key 为空，都会被判定为不可读存档，避免坏数据被伪装成正常存档继续进入地图。

旧菜单的 `loadLocalStage()` 也补了空 localStorage 键保护，避免清空后再读取旧存档时触发 `null.includes(...)` 报错。

## 相关代码路径

- `src/game/core/saveStorage.ts`
  - 新增 `deleteAllGameSaveFiles()`，只清理 `liluo_domain:game_save:` 前缀的浏览器存档。
  - 导入导出仍保留完整 `GameSaveData`，包括 `player`、`location`、`mapSession`。
- `src/game/views/components/base/GameMenuOverlay.vue`
  - 存档页新增“清空全部浏览器存档”按钮。
  - 点击后使用 `GameConfirmDialog` 二次确认。
- `src/game/views/GameView.vue`
  - 接入 `delete-all-saves` 事件。
  - 清空后刷新存档列表并推送结果通知。
  - 菜单内读档时，如果地图切换没有真正启动，会提示失败，不再误报“已读取存档”。
- `src/game/core/saveData.ts`
  - 收紧 `parseGameSaveData()` 校验。
  - 缺少 `player`、外观 id 无效、头像 key 为空时拒绝读档/导入。
- `src/store/store.js`
  - 旧版 `loadLocalStage()` 遇到缺失的 localStorage key 时跳过，避免清空旧存档后读取时报错。
- `scripts/tests/save-data.test.mjs`
  - 覆盖坏外观、缺 `player` 的拒绝解析。
- `scripts/tests/save-storage.test.mjs`
  - 覆盖清空全部存档不影响非存档 localStorage。
  - 覆盖 `导出 -> 清空 -> 导入 -> 读取` 后玩家数据仍完整。

## 遇到的问题

### 1. 清空全部存档不能直接 `localStorage.clear()`

浏览器 localStorage 里不只有游戏存档，还可能有版本号、其他旧模块数据或浏览器侧状态。直接清空会扩大影响范围。

解决方法：只枚举并删除 `liluo_domain:game_save:` 前缀的键。

### 2. 一开始误判为存档坐标不安全

排查“清空后再导入，进地图角色消失”时，曾考虑过旧坐标对当前地图不可通行的问题。但实际读档会按存档里的 `mapId` 加载对应地图，坐标不应该因为“当前地图不同”而失效。这个方向没有继续保留。

解决方法：撤回坐标自动修复思路，转而验证导出/清空/导入的数据循环。

### 3. 不应该用默认角色掩盖坏存档

曾短暂尝试在解析存档时，如果 `player` 缺失或外观异常就补默认角色。用户指出这会掩盖真正问题，这个判断是正确的。

解决方法：改为严格校验。坏存档直接拒绝，不自动恢复默认角色。

### 4. 旧菜单读取已清空的 localStorage 会报错

旧版 `loadLocalStage()` 默认每个 store key 都能从 localStorage 读到字符串，清空后会出现 `null.includes(...)` 报错。

解决方法：读取时如果 `data === null` 就跳过该字段。

## 后续注意

- 导出 JSON 应保持完整 `GameSaveData` 结构，不应在导出阶段裁剪坐标或补写运行时数据。
- 坐标来自保存存档那一刻的 `getPlayerWorldPosition()`，导出只是导出已有存档，不会重新读取当前坐标。
- 如果未来修改 `player` 存档结构，应同步升级解析校验和导入测试，而不是静默补默认值。
