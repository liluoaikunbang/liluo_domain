# GameView 入口页与“新的旅程”入口

## 本次实现思路

这次调整的目标，是先让 `GameView` 在真正进入地图前，拥有一个更像日式 RPG 的入口页，而不是用户一打开页面就直接看到游戏主界面。

本次入口页实现围绕下面几件事展开：

1. **先提供单独的入口舞台**
   - 在 `GameView` 中增加 `hasEnteredGame` 状态。
   - 未进入游戏时，先显示入口页。
   - 点击“新的旅程”后，再挂载 Phaser 并进入原有游戏界面。

2. **入口页整体继续保持 20:9 舞台比例**
   - 入口页不是另起一套零散页面，而是沿用当前游戏主界面的舞台感。
   - 这样进入前后的视觉语言更统一，也更适合后续继续扩展“继续游戏 / 设置 / 回想”等典型 RPG 入口功能。

3. **底层使用用户提供的立绘图 `src/assets/images/index.jpg`**
   - 图片按原比例居中显示，不拉伸、不裁切主体。
   - 由于 `object-fit: contain` 会在两侧留下空白，因此额外补了一层接近立绘底色的背景渐变，让空白区自然过渡，不显得突兀。

4. **入口样式向日式 RPG 主菜单靠拢**
   - 让标题和开始按钮居中悬浮在立绘之上。
   - 通过柔和的暗角、粉紫系高光、轻玻璃感按钮边框来保留幻想感。
   - 再根据用户的几轮反馈，持续微调按钮大小、透明度、边框粗细、标题与按钮之间的距离。

## 页面结构说明

### 1. 入口页显示时机

现在 `GameView` 分成两种显示状态：

- **未进入游戏**：显示入口页
- **已进入游戏**：显示原有三栏主界面与 Phaser 地图

模板结构上通过：

```vue
<section v-if="!hasEnteredGame" class="entry-shell">
  ...入口页...
</section>

<template v-else>
  ...原有游戏界面...
</template>
```

这样处理的好处是：

- 不需要额外新建路由
- 不破坏现有 `GameView` 的核心挂载点
- 后续如果继续补“继续旅程”“读取存档”“系统设置”，也可以直接扩展这个入口层

---

### 2. “新的旅程”功能

这次不是只做一个静态封面，而是把入口动作真正接到已有游戏流程里。

`startNewJourney()` 的处理逻辑是：

1. 重置对话和交互相关 UI 状态
2. 把 `hasEnteredGame` 切为 `true`
3. 等待 DOM 更新完成
4. 再挂载 Phaser 游戏实例

核心代码思路如下：

```js
const startNewJourney = async () => {
  resetGameUiState();
  hasEnteredGame.value = true;
  await nextTick();
  mountGameInstance();
};
```

这样可以避免 Phaser 在入口页阶段提前创建，也能保证“新的旅程”确实是从当前初始状态开始进入。

---

### 3. 入口页视觉构成

入口页主要由四层组成：

1. **底色层**
   - 使用接近立绘背景色的粉灰紫底色先铺底。

2. **立绘层**
   - `index.jpg` 居中显示。
   - 使用 `object-fit: contain`，确保立绘比例不变。

3. **氛围层**
   - 通过左右与上下渐变形成轻暗角。
   - 让中间主体更聚焦，同时减少两侧留白的突兀感。

4. **标题与菜单层**
   - 标题“璃落的冒险”居中悬浮。
   - “新的旅程”按钮做成轻透明、可悬浮的 RPG 风格菜单按钮。

这样入口页不是单纯把一张图铺上去，而是先把“舞台感”和“入口感”搭出来。

## 用户反馈后的视觉微调

这次入口页并不是一次性定稿，而是根据用户实测连续做了多轮微调。

### 第一轮微调

用户反馈：

- “新的旅程”
- 边框小些明显些，再透明些

对应调整：

- 按钮整体缩小
- 边框提亮，让轮廓更清楚
- 按钮底色透明度进一步降低

### 第二轮微调

用户反馈：

- 边框再粗些，再小些
- 字体不变，让边框稍微贴近字体些，尤其是上下
- 大标题和新的旅程边框分开的再远些

对应调整：

- 按钮边框从 `1px` 提到 `2px`
- 在不改字体大小的前提下压缩上下内边距
- 进一步缩小按钮宽高
- 拉开标题与按钮之间的垂直间距

最终这一版由用户确认“没问题了”。

## 开发过程中遇到的问题

### 问题 1：入口页不能在 Phaser 已挂载状态下直接硬切

**现象**：

- 如果仍按原先方式在组件挂载时立即创建 Phaser，入口页就只会成为一个视觉遮罩，不能真正作为“进入前”的独立阶段。

**原因**：

- 原来的 `GameView` 默认是在进入组件后直接准备游戏实例。
- 这与“先显示入口页，再点击进入游戏”的流程不一致。

**解决方法**：

- 改为在点击“新的旅程”后再执行 `mountGameInstance()`。
- 同时保留已有的 `destroyGameInstance()` 与 UI 状态重置逻辑，确保流程可控。

---

### 问题 2：立绘居中不裁切后，两侧会出现留白

**现象**：

- 为了保证立绘不变形，需要使用 `contain`。
- 但 `contain` 会让两边出现空白区域，如果直接留空，会很像图片没铺满。

**原因**：

- 用户明确要求“立绘比例不要变，放中间”，这意味着不能直接用 `cover` 去裁图。

**解决方法**：

- 给底层先铺接近立绘底色的背景色
- 再补一层左右渐变和轻暗角
- 让留白区域看起来更像立绘环境的一部分，而不是突兀的空边

---

### 问题 3：入口按钮初稿偏大、偏厚

**现象**：

- 第一版按钮虽然有 RPG 菜单氛围，但视觉上偏厚，离“轻、细、透明”的入口按钮感觉还有距离。

**原因**：

- 初版为了先建立明显的交互感，按钮尺寸、背景和阴影都留得相对保守。

**解决方法**：

- 连续缩小按钮容器宽度和最小高度
- 调低背景透明度
- 增强边框可见度
- 收紧上下内边距
- 拉开与标题的距离，避免视觉上挤在一起

---

### 问题 4：构建验证需要使用正确脚本

**现象**：

- 本次调整完成后，需要重新确认页面能正常构建。

**解决方法**：

- 使用 `npm run build:web` 进行验证。
- 构建通过，说明本次入口页与交互调整没有引入新的编译错误。
