# 079-存档读档行走图状态同步修复

## 实现思路

本次修复的是存档读档时主角行走图没有完全跟随档位状态恢复的问题。

当前主角地图行走图已经不是单纯由 `player.appearanceId` 决定，而是会先读取 `player.status`，再通过状态移动表现规则推导实际外观。例如：

- `hands_bound` 会推导到 `bondage` 行走图。
- `legs_bound` 或 `confined` 会推导到 `full_body_bondage` 行走图。
- 没有外观类状态时才回到存档中的基础 `appearanceId`。

问题出在存档相关入口仍有部分逻辑只看基础 `appearanceId`，没有复用“状态 -> 实际行走图”的规则。因此读取某些档位时，存档列表预览或菜单读档过程可能显示成当前场景已有行走图，而不是档位状态对应的行走图。

修复后：

1. 存档槽人物预览会根据存档里的 `player.status` 推导实际外观。
2. 游戏内菜单读档时，恢复存档运行时状态后，会主动通知当前 `WorldScene` 同步外观与状态，再进入地图切换流程。
3. 首页“继续旅程”读档仍保持原有流程：先写入运行时状态，再重新挂载 Phaser 游戏；新建的 `WorldSceneRuntime` 会从运行时状态解析正确行走图。

## 相关代码路径

- `src/game/core/saveStorage.ts`
  - `createPlayerPreview()` 新增使用 `resolvePlayerMovementPresentation()`。
  - 存档槽预览不再直接使用 `saveData.player.appearanceId`，而是根据 `saveData.player.status` 和基础外观一起推导最终 `appearanceId`。

- `src/game/views/GameView.vue`
  - `handleLoadGame()` 在 `applyGameSaveData(saveData)` 后，调用 `setPlayerAppearance(saveData.player.appearanceId)` 和 `setPlayerStatusInWorld(saveData.player.status)`。
  - 这样菜单读档时，当前 Phaser 场景里的玩家 sprite 会立即按存档状态刷新，而不是继续沿用读档前场景里的纹理。

- `src/game/data/playerMovementPresentationRules.ts`
  - 本次没有修改该文件，但存档预览开始复用这里的状态外观规则。
  - 该文件仍然是状态驱动速度、行走图、跳跃、禁锢移动限制和失明视觉表现的统一来源。

- `src/game/core/playerRuntime.ts`
  - 本次没有修改该文件。
  - `resolvePlayerRuntimeCharacterDefinition()` 仍负责从当前运行时状态解析地图实际角色定义。

- `src/game/systems/map/worldSceneRuntime.ts`
  - 本次没有修改该文件。
  - 现有 `setPlayerAppearance()` / `setPlayerStatus()` 会调用内部同步逻辑刷新 `player.setTexture()` 与动画。

## 遇到的问题与解决方法

### 1. 存档预览只看基础外观

问题：存档文件保存了 `player.appearanceId` 和 `player.status`，但存档列表的角色预览只用 `player.appearanceId` 查角色定义。这样一个带有 `legs_bound` 状态的存档，预览仍可能显示普通基础行走图。

解决：在 `createPlayerPreview()` 中调用 `resolvePlayerMovementPresentation(saveData.player.status, saveData.player.appearanceId)`，先推导实际外观，再生成预览帧信息。

### 2. 菜单读档时当前场景可能短暂沿用旧行走图

问题：游戏内菜单读档会先 `applyGameSaveData()` 写入运行时状态，然后调用 `loadMapAtPosition()` 进入地图加载。但在切换开始前，当前 `WorldScene` 的玩家 sprite 没有显式同步一次存档状态，容易出现视觉上仍使用读档前行走图的情况。

解决：在菜单读档流程中补充调用 `setPlayerAppearance()` 与 `setPlayerStatusInWorld()`。这两个入口会走 `WorldSceneRuntime` 的角色同步逻辑，刷新当前 sprite 纹理、动画和状态驱动表现。

### 3. 状态外观规则需要避免复制两套

问题：如果存档预览单独判断 `hands_bound`、`legs_bound` 等状态，后续新增状态外观规则时很容易漏改，导致预览、地图角色和菜单当前进度栏表现不一致。

解决：存档预览直接复用 `resolvePlayerMovementPresentation()`。后续新增状态驱动行走图时，只要维护 `playerMovementPresentationRules.ts`，存档预览也会跟随更新。
