# 066-旅途菜单组件拆分与乱码修复

## 实现思路

本次围绕 `src/game/views/components/base/GameMenuOverlay.vue` 做了一轮维护性重构。

重构前，旅途菜单的外壳、栏目切换、键盘导航、存读档操作、物品栏、技能栏、装备栏、任务栏、占位栏目和全部样式都集中在同一个 Vue 文件里。随着菜单栏目不断增加，单文件体积已经接近 3000 行，继续扩展会让后续维护、排错和新增栏目都变得困难。

这次拆分遵循“小步迁移、保持行为不变”的原则：

1. 先抽出纯静态数据和纯辅助函数，不改变模板结构。
2. 再拆出边界最清楚的存档、读档和占位栏目。
3. 之后拆出物品、技能、装备、任务四个正式栏目面板。
4. 最后把原本 `scoped` 样式抽成共享 CSS，避免子组件拆出后样式失效。

拆分后，`GameMenuOverlay.vue` 只保留菜单外壳、左侧栏目按钮、当前栏目分发、确认弹窗、键盘导航调度和跨栏目状态协调。各个栏目自己的展示结构进入独立组件，后续新增菜单栏目时可以只新增面板组件和少量父组件接线，不再继续扩大主 Overlay 文件。

本次还修复了拆分后暴露出的任务栏空状态乱码问题。任务栏在未选择任务时，右侧详情面板曾显示乱码文案，原因是原文件中部分占位中文已经是异常编码，拆分时被原样迁移到了 `QuestMenuPanel.vue`。修复方式是重写任务面板中的静态 UI 文案和 aria 文案为正常 UTF-8 中文，并保留原有任务树事件协议。

## 开发过程中遇到的问题

### 1. 组件职责过多，直接继续扩展会拖慢维护

`GameMenuOverlay.vue` 同时承担了菜单外壳、具体栏目内容、静态占位数据、存读档交互和完整样式。继续把新栏目直接写入这个文件，会让每次修改都需要在大量无关代码之间跳转，也容易误碰键盘导航和存档逻辑。

解决方法：

- 按栏目边界拆成独立面板组件。
- 父组件只负责状态与事件协调。
- 静态数据和纯函数从 Vue SFC 中移出。
- 保留既有 `data-menu-group`、`data-menu-key` 和事件名，避免破坏键盘导航规则。

### 2. 拆出子组件后 scoped 样式会失效

原样式写在 `GameMenuOverlay.vue` 的 `<style scoped>` 中。Vue 的 scoped 样式只会匹配当前组件生成的 scope 属性，模板拆到子组件后，父组件 scoped 样式无法继续覆盖子组件内部元素。

解决方法：

- 将菜单相关样式移动到 `gameMenuOverlay.css`。
- 在 `GameMenuOverlay.vue` 中引入该 CSS。
- 保留原 class 命名，减少视觉和布局变化。

### 3. 任务栏空状态显示乱码

拆分完成后，用户测试发现任务栏未选择任务时，右侧说明显示乱码。根因是原组件中部分中文占位文案已经是异常编码，拆分时被迁移到 `QuestMenuPanel.vue` 后更容易被注意到。

解决方法：

- 重写 `QuestMenuPanel.vue` 中任务栏、任务列表、任务详情、空状态等静态文案。
- 将未选择任务文案修复为：
  - `尚未选择任务`
  - `在左侧展开一个任务分类，再选择其中的任务后，这里会显示对应详情。`
- 将任务树展开/收起符号修复为正常的 `▾` / `▸`。
- 保留 `quest-tree-items`、`data-quest-kind`、`select-task`、`toggle-branch` 等导航与事件协议。

### 4. 机械拆分时辅助函数字符串曾出现格式问题

拆分共享辅助函数时，`formatResourceText()` 的模板字符串曾被机械迁移弄坏，构建可以通过，但显示内容会不正确。

解决方法：

- 在自查阶段检查 `gameMenuHelpers.js`。
- 将函数修复为：

```js
export const formatResourceText = (label, amount) => `${label}：${amount}`;
```

## 后续维护建议

1. 后续新增菜单栏目时，优先新增独立面板组件，再由 `GameMenuOverlay.vue` 做栏目分发。
2. 菜单静态占位数据继续放在 `gameMenuData.js`，不要重新塞回主 Overlay 组件。
3. 键盘导航仍集中在 `GameMenuOverlay.vue`，如果后续继续变大，可以再单独抽成 `useGameMenuNavigation` 一类 composable。
4. 新增子组件时继续复用 `gameMenuOverlay.css` 中已有 class，除非新栏目确实需要独立视觉结构。
5. 如果继续发现旧乱码文案，优先在对应子组件或数据源中修复为正常 UTF-8 中文，不要把乱码继续沉淀到新数据结构里。
