## 实现思路

故事条目 Markdown 的 YAML 使用 `missingItems` 保存讨论后仍确认缺失的制作内容。每项采用 `类型｜所属模块｜具体缺少内容`，明确缺少哪一段的 CG、地图、事件、对话、立绘或音频。

故事大纲卡片仅在清单非空时于右下角显示“待补充”按钮，表格模式也提供同一入口。点击后打开可键盘聚焦、可用 Escape 关闭的详情弹窗。用户后续补齐某项时，必须在确认内容已写入正式条目后删除对应缺口；全部补齐后移除 `missingItems`，按钮自动消失。

## 遇到的问题

普通 YAML 列表只能直接表达字符串，但缺口展示需要同时具有类型、所属模块和具体说明；如果只写“缺 CG”，后续无法判断属于哪个演出段落，也容易在素材补齐后留下过期记录。

## 解决方法

采用稳定的三段式文本约定，由界面按全角竖线解析。维护时逐项核对正式内容与缺口清单：已补齐项立即删除，未补齐项继续保留。
