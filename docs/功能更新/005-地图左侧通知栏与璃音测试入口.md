# 地图左侧通知栏与璃音测试入口

## 本次实现思路

这次功能的目标，是在地图界面里补一个更像日式 RPG 的即时通知栏，用来提示“获得了什么”或“失去了什么”，而不是把这类信息塞进大对话框里。

实现时主要分成两部分：

1. **先做一个独立的地图通知组件**
   - 新增 `GameNotificationBar` 组件。
   - 让它专门负责显示多条短通知，不和对话框逻辑混在一起。
   - 样式上采用半透明矩形、从左到右渐变、左侧强调色条，保持偏日式 RPG 的信息提示感。

2. **再把通知队列接到 `GameView`**
   - 在 `GameView` 内维护通知数组和对应定时器。
   - 每条通知进入后显示 3 秒，再自动移除。
   - 如果短时间内连续触发多条通知，就纵向分开堆叠显示。

3. **给璃音对话增加一个测试入口**
   - 不额外做临时调试按钮。
   - 直接把测试入口接到现有 NPC 对话里，让测试方式更贴近实际游玩流程。
   - 当玩家在璃音对话中选择“试试看左侧通知栏。”时，会连续触发几条获得 / 失去提示，方便直接观察效果。

## 相关代码路径

- `src/components/base/GameNotificationBar.vue`

  - 负责通知列表渲染、不同类型文案标记、进入/离场动画和整体视觉样式。

- `src/views/GameView.vue`

  - 给璃音现有占位对话增加“试试看左侧通知栏。”选项。
  - 新增一段过渡说明文本，作为测试入口后的回应节点。

## 具体实现说明

### 1. 通知栏显示位置

通知栏不是放在整个页面最外层，而是挂在 `GameView` 的地图区域内部。

这样处理有两个好处：

- 通知会明确贴着地图出现，而不是跑到整个页面布局外面。
- 后续如果地图区域继续加战斗提示、地点标题、任务提醒，也更容易统一管理。

本次通过给 `.map-panel` 增加相对定位，再把通知栏组件绝对定位到左上区域，实现“地图左侧显示”的效果。

---

### 2. 多条通知堆叠与自动消失

在 `GameView` 中新增了通知数组 `mapNotifications`，每次触发通知时都会压入一条新记录。

每条通知包含：

- `id`
- `text`
- `type`

通知创建后会启动一个 `setTimeout`：

- 默认显示 3 秒
- 到时后从数组中移除

由于组件是按数组顺序渲染，所以多个通知在短时间内出现时，会自然纵向堆叠成多条。

同时这次也补了定时器清理逻辑：

- 单条通知移除时会清理自己的 timer
- 整个界面重置或组件卸载时，会统一清理所有通知 timer 和测试序列 timer

这样可以避免页面切换后仍有旧通知延迟弹出。

---

### 3. 样式表现

通知条的视觉重点不是华丽特效，而是“短、轻、清楚”。

这次样式处理包括：

- 半透明深色底板
- 从左到右逐渐变淡的背景渐变
- 左侧 4px 强调色条
- 根据类型区分颜色
  - `gain` 偏金色
  - `loss` 偏粉红 / 红色
  - `neutral` 偏冷色提示
- 使用 `TransitionGroup` 做列表进入、位移动画、淡出动画

进入时从左侧轻微滑入，消失时淡出并轻微左移，整体尽量贴近 RPG 地图提示那种不抢主视线、但足够明确的反馈。

---

### 4. 璃音对话测试入口

这次没有为了测试单独加一个开发按钮，而是直接复用现有 NPC 对话结构。

处理方式是：

1. 在 `dialogues.json` 的璃音占位问题列表中新增一个选项
2. 选择该选项后，先切到一段说明文本节点
3. 在 `handleDialogChoice()` 里识别这个测试选项 ID
4. 触发一组连续通知演示

当前测试演示内容为：

- 获得 `野莓果酱 ×1`
- 获得 `旧钥匙 ×1`
- 失去 `铜币 ×12`

这些通知之间带有短间隔，用来确认多条通知的堆叠展示效果是否正常。

## 开发过程中遇到的问题

### 问题 1：通知条需要贴着地图，但不能影响 Phaser 容器本身

**现象：**

- 如果直接把通知放在页面外层，视觉上会更像全局网页提示，而不是地图内提示。
- 但如果直接修改 Phaser 容器本体，又容易让 UI 结构混乱。

**解决方法：**

- 保持 `#phaser-game-container` 继续只负责 Phaser 挂载。
- 在外层 `main.map-panel` 上增加相对定位。
- 将 `GameNotificationBar` 作为地图区域中的独立覆盖层挂上去。

这样既保留了 Phaser 挂载点的单一职责，也让通知条稳定出现在地图左侧。

---

### 问题 2：自动消失之外，还要处理“延迟批量触发”的定时器清理

**现象：**

- 测试入口不是只弹一条通知，而是连续弹出多条。
- 如果玩家在演示过程中退出页面或重置界面，延迟中的通知仍可能继续出现。

**解决方法：**

- 除了给每条通知单独记录移除 timer，还单独维护一组“测试序列 timer”。
- 在 `clearAllNotifications()` 中统一清空这两类 timer。

这样可以保证 UI 重置后不会有旧通知残留或延迟冒出。

---

### 问题 3：测试入口要方便验证，但不能破坏现有对话结构

**现象：**

- 如果直接在页面上加调试按钮，虽然实现快，但会让当前 RPG 界面显得像开发面板。
- 如果硬插在不合适的位置，又会让对话节点逻辑变乱。

**解决方法：**

- 直接复用璃音当前的占位问答结构。
- 把测试入口设计成一个正常可选的对话项。
- 再新增一个简单说明节点承接，保持对话流转完整。

这样既方便测试，也不会破坏当前世界里“找 NPC 交谈”的游玩方式。

---

### 问题 4：需要确认构建与实测都通过后再补文档

**现象：**

- 按项目规则，功能真正完成不能只看代码写完，还要经过构建检查和用户实际验证。

**解决方法：**

- 先执行 `npm run build:web`，确认本次改动没有引入编译错误。
- 再由用户实际测试通知栏与璃音测试入口。
- 用户确认“没问题了”后，再补写本份文档。

## 当前实现结果

本次完成后，地图界面已经具备以下能力：

1. 地图左侧可显示短条状通知
2. 通知支持“获得 / 失去 / 提示”三种基础类型表现
3. 多条通知会自动分开堆叠显示
4. 每条通知会在显示约 3 秒后渐渐消失
5. 通知层不会影响 Phaser 地图容器本身
6. 璃音对话中已提供实际可点击的测试入口
