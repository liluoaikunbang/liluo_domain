# 057-大地图相机边界锁定

## 实现思路

本次修复的是大地图不缩放、由相机跟随玩家查看地图时，角色走到地图边缘后镜头仍继续移动，导致画面里出现过多地图外黑色区域的问题。

核心思路是把相机可移动边界从“整张 Tiled 地图文件尺寸”收紧为“实际可渲染地图内容边界”。这样在大地图模式下，玩家仍然由相机跟随；但当相机视口已经贴近实际地图内容边缘时，Phaser 相机会被 bounds 锁住，不再继续把空白外框或地图外黑色区域卷入画面。

同时，为了让这段逻辑可以被 Node 单测直接验证，将纯相机布局计算拆到了无 Phaser、无地图归一化依赖的 `cameraLayoutRules.ts` 中。原有 `cameraLayout.ts` 继续作为地图内容边界计算和相机布局导出入口，`worldSceneRuntime.ts` 的调用路径保持不变。

本次没有修改任何地图的 `map.json`，也没有新增 `src/assets/game` 下的素材图片。

## 相关代码路径

- `src/game/systems/map/cameraLayoutRules.ts`
  - 新增纯相机布局计算入口 `computeCameraLayout()`。
  - 新增 `getCameraBoundsForDisplayBounds()`，统一用实际显示内容边界计算相机 bounds。
  - bounds 的宽高至少补到当前相机世界视口大小，避免小地图或窄方向上出现非法/过小边界。

- `src/game/systems/map/cameraLayout.ts`
  - 保留 `computeMapContentBounds()`，继续负责从地图 tile layer 和 object 中计算实际内容边界。
  - 重新导出 `computeCameraLayout()`、`MapViewportConfig`、`WorldBounds`，保持运行时代码原有导入方式稳定。

- `src/game/systems/map/worldSceneRuntime.ts`
  - 未直接改动逻辑。
  - 仍通过 `computeCameraLayout()` 取得 viewport、zoom、bounds、focusTarget，并调用 `camera.setBounds(...)` 应用边界。

- `scripts/tests/camera-layout.test.mjs`
  - 新增“大地图跟随相机应锁定到实际可渲染内容边界”的回归测试。
  - 保留房间静态居中相机相关测试，避免小地图显示逻辑被误伤。

## 开发过程中遇到的问题

### 1. 大地图使用 full map bounds 会把空白外框也算进可移动范围

原先 `computeCameraLayout()` 在大地图不自适应缩放时，会落回整张地图的 `fullMapBounds`。如果地图文件尺寸比实际铺设内容更大，或边缘有未渲染区域，玩家走到边缘时相机仍认为那些空白属于可移动范围，画面就会出现较多黑色区域。

解决方法：

- 统一使用 `computeMapContentBounds()` 得到的实际内容边界作为 `preferredDisplayBounds`。
- 大地图和小地图都基于 `preferredDisplayBounds` 生成相机 bounds。
- 只在内容边界缺失时，才回退到完整地图尺寸。

### 2. 相机 bounds 不能比当前视口的世界尺寸更小

如果某个方向上的地图内容比相机世界视口更小，直接把 bounds 设置成内容尺寸，可能导致 Phaser 相机在该方向的边界计算不稳定，或和居中视口逻辑冲突。

解决方法：

- `getCameraBoundsForDisplayBounds()` 使用 `Math.max(displayBounds.width, cameraWorldViewWidth)` 和 `Math.max(displayBounds.height, cameraWorldViewHeight)`。
- 小地图仍可通过 viewport 收口居中显示，大地图则在边缘停止相机移动。

### 3. 直接在 Node 单测中导入原 `cameraLayout.ts` 会遇到扩展名解析问题

`cameraLayout.ts` 依赖 `runtimeMapNormalizer`，源码中使用的是 Vite 可处理的无扩展名导入。Node 直接运行 `.mjs` 测试导入该文件时，会因为 ESM 扩展名解析找不到依赖。

解决方法：

- 将纯计算逻辑拆到 `cameraLayoutRules.ts`，该文件没有外部运行时依赖。
- 单测直接导入 `cameraLayoutRules.ts`。
- 原 `cameraLayout.ts` 继续导出相同能力，供 Vite 构建和运行时代码使用。

## 后续注意

1. 后续新增大地图时，优先保证地图实际内容边界能被 `computeMapContentBounds()` 正确识别，不要依赖地图文件外框来控制相机范围。
2. 如果某张地图确实需要保留边缘留白，应优先通过地图内容或专门的 viewport 配置表达，而不是让相机默认暴露地图外黑色区域。
3. 相机逻辑调整应优先补 `scripts/tests/camera-layout.test.mjs`，避免房间静态居中、小地图自适应和大地图跟随互相回归。
