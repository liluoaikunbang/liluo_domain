# 主角特殊四帧外观与hop移动表现接入

## 本次实现思路

这次实现的核心，不是单独给 `liluo_full_body_bondage.png` 做一条临时特判，而是把 `src/game/data/playerCharacter.ts` 这条主角外观定义链路扩成：

**每个外观自己声明 spritesheet 切图信息、四方向动画帧配置，以及可选的移动表现风格。**

这样主角外观就不再默认强绑定“12 帧、四方向各 3 帧 walk”的固定模板，而是可以同时支持：

1. 标准三帧行走图；
2. 只有四方向站立帧的特殊外观；
3. 后续继续扩展其它特殊主角状态，而不需要重写控制器链路。

本次接入的 `src/assets/game/sprite/liluo_full_body_bondage.png` 是一张 `32 x 128` 的竖排图，本质是：

- 4 行 × 1 列；
- 每帧仍然是 `32 x 32`；
- 只提供四方向站立图，没有传统的三帧步行动画。

因此这次没有去伪造多张额外帧，而是采用两层处理：

1. **动画层**：为每个方向保留单帧 `walk` / `idle` 动画 key，保证现有控制器状态机无需改写；
2. **运行时表现层**：在 `worldSceneRuntime.ts` 中，当外观 `movementStyle === 'hop'` 且角色正在移动时，通过 display origin 的 Y 轴偏移实现轻微起跳感。

按你的后续要求，这次最终保留了 `full_body_bondage` 这套特殊外观与 hop 能力，但把主角的**默认初始外观切回**了标准的 `src/assets/game/sprite/liluo_walk_source.png`，方便后续通过事件链路再引入这种特殊状态。

## 相关代码路径

- `src/game/data/playerCharacter.ts`
  - 扩展主角外观注册表 `playerAppearanceSpriteSheets`；
  - 为每个外观分别声明：
    - `spriteSheetFileName`
    - `spriteSheetConfig`
    - `animationProfile`
    - `movementStyle`
    - `movementSpeedMultiplier`
    - `hopAmplitude`
    - `hopSpeed`
  - 新增 `full_body_bondage` 外观；
  - 默认初始外观最终切回 `default -> liluo_walk_source.png`。

- `src/game/systems/character/playerController.ts`
  - 保持原有“按 `walk | idle + direction` 播放动画”的机制不变；
  - 通过 `getCharacterDefinition()` 继续兼容不同外观的动画 key。

- `src/game/systems/map/worldSceneRuntime.ts`
  - 增加 hop 运行时表现：
    - 记录玩家基础 display origin；
    - 仅在 `movementStyle === 'hop'` 且移动中时计算 Y 偏移；
    - 停止移动、切换外观时重置偏移；
    - 切换外观后重新刷新当前动画。

- `scripts/tests/player-spritesheet-normalization.test.mjs`
  - 从“所有主角外观都固定 `endFrame: 11`”改成按 appearance 分别校验；
  - 标准外观仍验证 12 帧；
  - `full_body_bondage` 验证 4 帧配置。

## 开发过程中遇到的问题

### 问题 1：原有主角外观链路默认假定所有外观都是 12 帧标准步行图

之前 `playerCharacter.ts` 默认把四方向的步行动画帧结构写死为：

- down: `[0, 1, 2, 1]`
- left: `[3, 4, 5, 4]`
- right: `[6, 7, 8, 7]`
- up: `[9, 10, 11, 10]`

这会导致新的 4 帧竖排图虽然尺寸合法，但无法按现有模板安全接入。

### 解决方法

把“动画帧结构”从全局固定模板，改成外观自己的 `animationProfile`：

1. 标准外观继续复用旧三帧 walk 配置；
2. `full_body_bondage` 单独声明四方向单帧配置；
3. 动画 bundle 统一由 `createPlayerCharacterAnimationBundle()` 按 profile 生成。

这样后续新增其它特殊图时，不需要再回头拆控制器。

---

### 问题 2：只有四张站立图时，单靠单帧 walk 会显得像在地图上滑行

如果只是把每个方向的 `walk` 都写成单帧重复，视觉上虽然状态机仍能运行，但人物会更像“贴地滑动”，缺少被束缚状态应有的挪动感。

### 解决方法

在 `worldSceneRuntime.ts` 中增加 hop 表现层：

1. 读取当前外观的 `movementStyle`；
2. 若为 `hop`，则在角色移动期间按节奏计算一个 Y 轴 display origin 偏移；
3. 停下或切换外观时立即清零，避免残留抖动。

这让特殊四帧图不依赖额外贴图，也能得到“跳着挪动”的基本观感。

---

### 问题 3：hop 偏移如果不统一回收，切换外观或停下时会残留错位

这种运行时表现不是动画帧本身，而是额外叠加到 sprite 显示原点上的位移。

如果没有在正确时机回收，就可能出现：

- 停止移动后人物仍然上浮；
- 切回普通外观后仍带着偏移；
- 场内刷新动画后人物脚底没有踩回地面。

### 解决方法

在 `worldSceneRuntime.ts` 中把 hop 收口为统一函数：

- `capturePlayerDisplayOriginBase()`：记录基础原点；
- `resetPlayerMovementPresentation()`：重置 hop offset 与 phase；
- `updatePlayerMovementPresentation()`：每帧仅在 hop 移动中更新；
- `setPlayerAppearance()`：切换外观时先更新纹理，再重置表现状态。

这样 hop 逻辑就不会泄漏到剧情、UI 或其它地图系统里。

---

### 问题 4：默认初始外观一度切成了 `full_body_bondage`，但你后续希望恢复标准默认图

为了方便第一轮观察，我一开始把主角默认外观切成了 `full_body_bondage`，便于直接在地图里看效果。

但最终你要求：

- 默认外观恢复 `liluo_walk_source.png`；
- hop 外观保留，留待以后通过事件引入。

### 解决方法

最终把 `src/game/data/playerCharacter.ts` 中的：

- `defaultPlayerAppearanceId`

重新设回 `default`，这样：

1. 游戏起始仍使用标准主角步行图；
2. `full_body_bondage` 保留在外观注册表中；
3. 以后仍可通过 `playerAppearanceChange.appearanceId = "full_body_bondage"` 引入 hop 状态。

## 最终验证结果

本次实现后的状态如下：

1. 主角外观定义已支持不同 spritesheet 帧结构与不同动画 profile；
2. `liluo_full_body_bondage.png` 已作为新的 `full_body_bondage` 外观接入；
3. `full_body_bondage` 已具备基于运行时 Y 偏移的 hop 移动表现；
4. 普通三帧行走图链路保持兼容，无需重写控制器；
5. 默认初始外观已恢复为 `liluo_walk_source.png`；
6. 以后可继续通过事件 / 对话外观切换链路，引入 `full_body_bondage` 特殊状态。

本次实现过程中的构建验证命令：

```bash
npm run build:web
```

验证结果：

- 构建通过；
- 仍只有项目里原有的 tileset `new URL(...) doesn't exist at build time` 警告；
- 未因这次主角外观扩展新增新的构建错误。
