# 图鉴场景地点分组与大图内导航

本次在旅途菜单的图鉴栏中增加了独立的“场景”分类，并将场景图从按单张图片展示调整为按地点展示。

场景图统一存放在 `src/assets/game/scenes/`。图鉴列表中的一个条目代表一个地点；打开地点大图后，玩家可以通过画面两侧的方向箭头，在该地点内部的不同画面之间移动。方向箭头不会跳转到其他地点。

当前首个地点为“璃落的小窝”，默认画面是“阁楼”：

- 在阁楼画面点击左箭头，进入“阁楼楼梯”；
- 在阁楼楼梯画面点击右箭头，返回“阁楼”。

## 实现思路

1. 在图鉴分类中增加“场景”，与人物、CG、职业/技能、物品和装备并列。
2. 场景图片通过 `import.meta.glob` 从 `src/assets/game/scenes/` 第一层目录加载，不扫描子文件夹。
3. 使用独立 JSON 人工定义地点、地点包含的场景图、默认画面以及画面间的方向关系。
4. 菜单数据根据 JSON 中的文件名匹配真实图片资源，一个地点生成一个图鉴卡片。
5. 场景卡片只显示地点预览，不显示方向箭头。
6. 打开大图后才显示地点内部的方向箭头；场景模式禁用 CG 原有的上一条、下一条切换，避免导航跨越地点。
7. 图鉴一级分类标签改为动态伸缩，空间足够时共同占满一行，只有确实放不下时才换行。

## 地点 JSON 结构

地点配置位于 `src/game/data/global/sceneGallery.json`，主要字段如下：

- `locations`：地点列表。
- `key`：地点或场景的稳定标识。
- `title`：地点或场景的显示名称。
- `defaultScene`：打开地点后默认显示的场景。
- `fileName`：对应 `src/assets/game/scenes/` 下的图片文件名。
- `navigation`：当前场景可用的方向跳转。
- `direction`：箭头方向，当前使用 `left` 和 `right`。
- `target`：目标场景的 `key`，只能指向当前地点 `scenes` 内的场景。
- `label`：按钮的无障碍说明。

新增地点时，需要人工把属于同一地点的图片放进同一个 `scenes` 数组，并明确每张图的导航关系。仅把图片放入素材目录不会自动决定地点归属。

## 相关代码路径

- `src/assets/game/scenes/`
  - 统一存放场景图素材。
- `src/game/data/global/sceneGallery.json`
  - 人工定义地点、地点内场景、默认场景和方向导航。
- `src/game/data/global/gameMenuData.js`
  - 加载场景图片，按 JSON 组装地点条目并接入图鉴分类。
- `src/game/views/components/base/CompendiumMenuPanel.vue`
  - 展示地点卡片，管理大图中的当前场景和地点内导航。
- `src/game/views/components/base/gameMenuOverlay.css`
  - 处理图鉴标签动态伸缩及场景大图方向箭头样式。

## 处理过的问题

### 1. 单纯按文件名扫描无法表达地点归属

问题：最初每张场景图都会独立生成图鉴条目，无法表达“阁楼”和“阁楼楼梯”属于同一个地点。

解决：增加 `sceneGallery.json`，由人工定义地点与场景图的从属关系。资源扫描只负责把文件名解析成可用图片地址，不再决定内容结构。

### 2. 复用 CG 左右切换会跳到其他地点

问题：CG 大图的左右箭头用于切换整个图鉴条目。如果场景直接复用这套逻辑，箭头会从当前地点跳到另一个地点。

解决：场景大图关闭 CG 的相邻条目切换，改为读取当前地点中当前场景的 `navigation`。目标只在当前地点的 `scenes` 中查找，因此不会跨地点。

### 3. 方向箭头不应出现在地点卡片上

问题：地点列表只承担浏览和选择作用，若在缩略预览中放入方向箭头，会混淆“打开地点”和“地点内移动”两种操作。

解决：地点卡片仅显示默认场景、地点名称和画面数量；方向箭头只在打开大图后叠加于画面边缘。

### 4. 新增分类后装备标签被挤到第二行

问题：图鉴一级分类原本使用固定列数，增加“场景”后无法根据实际文字宽度分配空间，导致装备栏提前换行。

解决：一级分类改为可伸缩的 Flex 布局。各标签根据内容保留最小宽度，并共同伸展填满一行；只有容器确实无法容纳时才换行。

### 5. Windows 构建输出目录出现短暂占用

问题：连续执行构建验证时，Vite 第二次清理 `dist/assets` 遇到 `ENOTEMPTY`。检查后没有发现遗留的 `vite build` 进程，项目相关 Node 进程只有正常的 `npm run dev` 和 Vite 开发服务。

解决：保留正在运行的开发服务，改用 `scripts/tests` 下的独立临时输出目录完成 Vite 构建验证，成功后删除临时目录。该问题属于 Windows 输出目录的短暂文件占用，不是场景功能的编译错误。

## 当前结果

- 图鉴栏已增加“场景”分类；
- 场景素材集中存放在 `src/assets/game/scenes/`；
- 图鉴列表以地点为单位展示；
- “璃落的小窝”包含阁楼和阁楼楼梯两张场景图；
- 默认进入阁楼，并可通过大图箭头在两张地点内画面间往返；
- 缩略预览不显示箭头；
- 场景箭头不会切换到其他地点；
- 地点归属和导航关系由 JSON 人工维护；
- 图鉴分类标签在空间足够时保持同一行并填满宽度；
- Vite 构建验证通过。
