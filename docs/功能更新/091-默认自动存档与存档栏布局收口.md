# 默认自动存档与存档栏布局收口

## 本次实现思路

这次围绕存档系统补了一条默认置顶的 `autosave` 槽位，并顺手把存档界面里容易被内容撑出框的布局隐患收住。

自动存档的目标不是新增一个让玩家手动管理的普通档位，而是给冒险流程兜一个稳定的“最近进度”入口：

- 地图切换成功后，自动覆盖 `autosave`。
- 事件成功触发后，自动覆盖 `autosave`。
- 新旅程重新开始后，只要触发第一个有效事件，也会写入同一个 `autosave`。
- `autosave` 始终排在存档列表最上方。
- `autosave` 在存档页不显示覆盖、删除按钮，用户不需要手动调控它。

布局部分则重点处理两类问题：

- 存档界面最上方的当前进度栏内容需要在栏内纵向居中，不能挤出栏目。
- 存档卡片要按内容自然撑开，高度保持一致，按钮区和文字区之间保留间距，避免内容多时溢出框外。

## 具体实现说明

### 1. 固定自动存档槽位

`saveStorage.ts` 中把自动存档槽位收口成常量：

```ts
export const AUTO_SAVE_SLOT_ID = 'autosave';
```

这样 Vue 侧、存档列表组件和存档排序都使用同一个标识，避免以后出现某处手写字符串不一致的问题。

在读取存档列表时，排序逻辑会先判断左右两侧是否为 `autosave`，保证它始终排在最上方。普通手动档位仍然沿用原来的排序规则。

### 2. 地图切换和事件触发后自动覆盖

`GameView.vue` 中新增 `handleAutoSaveGame()`，复用当前手动存档的数据生成逻辑，把当前地图、位置、主角状态、资源、时间等信息写入 `autosave`。

自动存档触发点分成两条：

- `onMapChange`：地图切换成功后写入。
- `onEventExecute`：事件成功执行后写入。

事件触发链路由 `WorldScene` 在 `eventRunner.runEvent()` 返回成功执行结果后回调，避免只要尝试交互就误写档。

### 3. 避免进入地图时误覆盖

新旅程或读档进入地图时，本身也会经过一次地图加载和切换回调。如果这时立刻自动存档，就可能把玩家刚选择的读档状态覆盖到 `autosave`，或者让重新开始的初始进入动作提前写档。

因此 `GameView.vue` 增加了 `shouldSkipNextMapAutosave`：

- 新旅程启动前置为 `true`。
- 读档进入前置为 `true`。
- 下一次地图切换回调只刷新地图会话状态，不写自动存档。
- 后续真实地图切换或事件执行再正常写入。

这样可以满足“重新开始后触发第一个事件也写入自动存档”，同时避免“刚点读档就把 autosave 改掉”的问题。

### 4. autosave 不提供手动管理按钮

`SaveSlotList.vue` 中根据 `slotId === AUTO_SAVE_SLOT_ID` 判断自动存档。

在存档页里：

- 普通档位显示覆盖、删除按钮。
- `autosave` 不显示覆盖、删除按钮。
- 按钮区保留一个不可见占位，避免自动存档卡片因为少了按钮区而比其他卡片矮。

这样视觉上不会参差不齐，语义上也能明确区分“系统自动维护”和“玩家手动管理”。

### 5. 存档栏布局收口

这次重点修的是 CSS 的结构隐患，而不是单纯把某个高度写死。

顶部当前进度栏改为网格布局：

- 外层按“信息区 + 操作按钮”分列。
- 信息区内部固定角色小图宽度，其余文本列使用 `minmax(0, 1fr)` 一类可收缩轨道。
- 移动端再切回单列，避免窄屏把内容挤出栏目。

存档卡片部分则改成：

- 卡片用纵向 flex，自然按内容撑开。
- 列表网格使用 `align-items: stretch`，让同一行卡片高度一致。
- 状态、资源等内容允许换行，不再用固定高度强行裁掉。
- 按钮区使用 `margin-top: auto` 推到底部，并增加 `padding-top`，让按钮和文字之间有空隙。

## 开发过程中遇到的问题

### 问题 1：自动存档不能被新旅程和读档入口误覆盖

**现象：**

地图进入本身会触发地图切换回调。如果不加区分，新旅程开始或读档进入的一瞬间也会写入 `autosave`。

**解决方法：**

增加 `shouldSkipNextMapAutosave`，只跳过进入流程带来的第一次地图切换自动存档。后续地图切换和事件执行仍然正常写入。

### 问题 2：事件尝试触发和事件成功执行不能混在一起

**现象：**

如果只在交互入口处写自动存档，就可能出现玩家按了交互键但事件没有真正执行，也生成了自动存档。

**解决方法：**

把回调放在 `WorldScene` 的事件运行结果之后，只有 `eventResult.didExecute` 为真时才通知 Vue 侧写档。

### 问题 3：autosave 少按钮后卡片高度容易不一致

**现象：**

`autosave` 不需要覆盖、删除按钮，但直接移除按钮区会导致它比普通存档卡片矮，列表看起来参差不齐。

**解决方法：**

为 `autosave` 保留不可见的 `.save-slot-actions-empty` 占位。用户看不到按钮，也不会误操作，但布局仍按普通卡片保留底部动作区高度。

### 问题 4：存档内容多时容易超出卡片边界

**现象：**

存档状态、资源、按钮等内容叠在卡片里时，如果靠固定高度或强行隐藏，很容易出现文字显示不全、按钮贴得太近、内容溢出框外。

**解决方法：**

把卡片改成内容自然撑高的结构，并让状态文本和资源信息可换行；按钮区与正文之间增加顶部间距。列表网格再负责让同一行的小卡片适配较高卡片，而不是压缩内容更多的卡片。

## 后续可继续扩展的方向

- 后续如果要做首页“继续旅程”，可以考虑优先读取 `autosave`，但仍保留玩家选择手动档位的能力。
- 如果自动存档以后需要提示，可以做成地图左侧轻量通知，而不是弹出确认框，避免打断探索节奏。
- 存档卡片未来如果继续增加字段，优先扩展现有卡片的自然撑高与换行规则，不再回到固定高度裁切内容的方式。
