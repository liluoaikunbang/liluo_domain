# 璃落房间离开事件触发修复

## 本次实现思路

这次修复的目标，是让角色站在 `src/game/data/liluo_room/map.json` 地图门口的 `role` 位置时，能够正常触发离开房间事件，并回到 `src/game/data/liluo_house_living_room/events.json` 中对应的“璃落的房间”门口位置。

实际排查后确认，问题不在客厅入口，也不在地图跳转本身，而是在 `liluo_room` 的离开事件绑定方式：

- 原先 `src/game/data/liluo_room/events.json` 里的 `liluo_room_leave` 使用的是一组手写 `zones` 坐标；
- 但当前地图运行时会先经过归一化与裁边，手动事件注册又是基于运行时地图坐标进行判定；
- 这导致旧的硬编码坐标和当前门口实际可交互位置已经不再对齐，所以站在 `role` 位置时不会命中事件。

这次修复没有继续手调一组新坐标，而是直接把离开事件改成绑定地图里的 `role` 标记图层：

- 使用 `tileMarker: { mapId: "liluo_room", layerName: "role" }`

这样事件触发点就直接跟随地图标记本身，后续即使地图内容再整理，只要 `role` 标记还在，离开事件就不会再次因为旧坐标失效。

## 相关代码路径

- `src/game/data/liluo_room/events.json`
  - `liluo_room_leave` 原先使用 `zones` 硬编码门口触发区。
  - 本次改为使用 `tileMarker.layerName = "role"` 作为离开事件触发标记。
  - 事件触发后仍然跳转到 `liluo_house_living_room`，并使用 `spawnId: "liluo_room_event"` 回到客厅里璃落房间门口。

- `src/game/data/liluo_room/map.json`
  - 提供 `role` 标记图层。
  - 该图层本次被直接作为离开事件的触发来源。

- `src/game/systems/map/manualEventRegistry.ts`
  - 手动事件注册时会同时处理 `zones` 和 `tileMarker`。
  - `tileMarker` 会读取目标图层中所有非空 tile，并把它们注册为可交互事件点。

- `src/game/systems/map/runtimeMapNormalizer.ts`
  - 地图运行前会先做归一化与裁边处理。
  - 这也是旧 `zones` 坐标失效的根本背景原因之一，因为运行时事件判断依赖的是整理后的地图坐标。

- `scripts/tests/liluo-room-leave-event.test.mjs`
  - 本次新增的回归测试。
  - 用来确认 `liluo_room_leave` 已绑定到 `role` 图层，且地图里的 `role` 图层确实存在有效触发格。

## 开发过程中遇到的问题

### 问题 1：表面现象像“事件没注册”，实际是旧坐标与运行时地图不再一致

从表现上看，是站在门口按 Space 没反应，容易第一时间怀疑：

- 事件没进注册表；
- 交互输入没触发；
- 地图跳转失效。

但逐层排查后发现，`mapTransition` 本身是正常的，问题卡在“门口这个格子根本没有命中 `liluo_room_leave` 事件”。

### 解决方法

对比了：

1. `liluo_room/events.json` 的触发定义；
2. `liluo_room/map.json` 中 `role` 图层的实际标记；
3. `manualEventRegistry.ts` 的手动事件注册逻辑；
4. `runtimeMapNormalizer.ts` 的地图归一化处理。

最终确认，旧 `zones` 坐标是历史手填值，已经没有和当前运行时门口位置保持一致。

---

### 问题 2：继续改硬编码坐标，后续仍然容易再次失效

如果这次只是重新手填一组新的 `tileX/tileY`，短期可能能用，但以后地图再裁边、再调整图层内容时，仍然可能再次偏掉。

### 解决方法

直接复用现有地图标记层机制，把离开事件绑定到 `role` 图层，而不是继续依赖一组脆弱的硬编码门口坐标。

这样做的好处是：

- 配置和地图本体保持一致；
- 和客厅入口事件使用同一类思路；
- 后续维护时更容易看懂，也更不容易漏改。

---

### 问题 3：需要给这类地图事件问题补一个最低限度的回归保护

这类问题很容易在后续整理地图时再次出现，而且光靠肉眼看 JSON 不容易第一时间发现。

### 解决方法

本次新增 `scripts/tests/liluo-room-leave-event.test.mjs`，至少覆盖两件事：

1. `liluo_room_leave` 必须绑定到 `role` 图层；
2. `role` 图层里必须真的存在有效非空触发格。

虽然这不是完整的场景 E2E，但足以防止事件配置又悄悄退回到无效状态。
