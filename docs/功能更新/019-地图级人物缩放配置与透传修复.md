# 地图级人物缩放配置与透传修复

## 本次实现思路

这次调整的目标，是把主角显示比例从“全局固定值”改成“可按地图单独配置”。

原因很直接：

1. 璃落庄园地图范围较小，人物如果保持原始大小，会显得偏大，所以仍然需要缩小。
2. 客厅地图是室内场景，角色如果继续沿用庄园的缩小比例，又会显得太小。
3. 后续地图尺寸和表现风格可能继续变化，因此人物比例不能再写死在全局角色定义里。

所以这次采用的方案是：

- 把 `playerCharacterDefinition.scale` 调整为角色原始基础比例 `1`。
- 在各地图自己的 `meta.ts` 中新增 `playerScale` 配置。
- 地图运行时优先读取当前地图的 `playerScale`。
- 如果某张地图没有配置 `playerScale`，则自动回退到角色基础比例 `1`。

这样之后新增地图时，只需要在 `data/<mapId>/meta.ts` 里补一个数字，就能单独控制该地图中的主角显示大小，不用再去改全局角色定义。

---

## 相关代码路径

- `src/game/data/playerCharacter.ts`
  - 将主角基础 `scale` 从原先的缩小值改为 `1`，作为默认原始大小。

- `src/game/data/liluo_estate/meta.ts`
  - 为璃落庄园新增 `playerScale: 0.8`，保持当前庄园中的缩小效果不变。

- `src/game/data/liluo_house_living_room/meta.ts`
  - 为客厅地图新增 `playerScale: 1`，让室内场景恢复角色原始大小。

- `src/game/data/registry.ts`
  - 为地图注册项新增 `playerScale?: number`。
  - 注册地图时把各自 `meta.ts` 中的 `playerScale` 一并挂入注册表。

- `src/game/systems/map/MapLoader.ts`
  - 扩展 `WorldSceneInitRequest` 和 `WorldSceneInitData`，让 `playerScale` 可以跟随地图初始化数据一起流转。
  - 在解析地图初始化数据时，把注册表中的 `playerScale` 写入结果。
  - 修复“已有 `mapId + mapData` 时没有把 `playerScale` 一起透传”的问题。

- `src/game/systems/map/worldSceneRuntime.ts`
  - 创建玩家精灵时，改为优先使用 `worldSceneInitData.playerScale`。
  - 如果当前地图没有配置，则回退到 `playerCharacterDefinition.scale`。

## 具体实现说明

### 1. 角色基础比例改回 1，地图再按需覆盖

以前主角缩放写在 `playerCharacterDefinition.scale` 里，这意味着所有地图都会默认共享同一个比例。

这次把它改成：

- `playerCharacterDefinition.scale = 1`

这样角色定义只负责“原始尺寸”，而不是直接决定所有地图中的最终表现比例。

真正进入地图后，再由地图配置决定是否缩小：

- 庄园：`0.8`
- 客厅：`1`
- 未配置地图：默认 `1`

这比继续把缩放写死在全局角色定义里更适合多地图扩展。

---

### 2. 在地图 meta 中声明人物比例

本次没有新造单独配置文件，而是直接沿用现有地图元数据入口：

- `src/game/data/liluo_estate/meta.ts`
- `src/game/data/liluo_house_living_room/meta.ts`

分别新增：

- `playerScale: 0.8`
- `playerScale: 1`

这样每张地图自己的显示策略仍然集中在自己的 `meta.ts` 中，和地图名、默认出生点、图集渲染配置放在一起，后面维护也更清晰。

---

### 3. 通过注册表和初始化数据把比例传到运行时

仅仅把比例写进地图 `meta.ts` 还不够，还必须保证它能一路传到 `WorldSceneRuntime`。

这次链路是：

1. `meta.ts` 提供 `playerScale`
2. `registry.ts` 收录到地图注册项
3. `MapLoader.ts` 解析当前地图时写入 `WorldSceneInitData`
4. `WorldScene` 创建运行时
5. `worldSceneRuntime.ts` 创建玩家精灵时调用 `player.setScale(resolvedPlayerScale)`

最后实际使用的是：

- `worldSceneInitData.playerScale ?? playerCharacterDefinition.scale`

因此配置存在时按地图走，不存在时自动使用角色原始比例。

## 开发过程中遇到的问题

### 问题 1：第一次接入后，庄园地图看起来没有恢复缩小

**现象：**

- 客厅地图看起来逻辑是对的。
- 但庄园地图进入后，人物没有按 `0.8` 缩小，看起来像仍然使用了 `1`。

**原因：**

- `MapLoadingScene` 会先解析一遍地图初始化数据。
- 之后 `WorldScene.create()` 又会再次调用 `resolveWorldSceneInitData(data)`。
- 在 `MapLoader.ts` 里，原先“请求里已经带了 `mapId + mapData`”这条分支只保留了 `mapId`、`spawnId`、`mapData`，却漏掉了 `playerScale`。
- 结果就是地图比例在进入 `WorldScene` 之前被丢失，最终回退成默认 `1`。

**解决方法：**

- 给 `WorldSceneInitRequest` 补上 `playerScale?: number`。
- 在 `resolveWorldSceneInitData()` 的这条分支里，把 `request.playerScale` 一起透传出去。

修完后，庄园的 `0.8`、客厅的 `1`、未配置地图的默认 `1` 才真正形成完整闭环。

---

### 问题 2：要支持多地图差异，但不能破坏已有主流程

**现象：**

- 这个改动虽然只是“缩放比例”，但它跨了地图配置、注册表、加载场景、世界场景和运行时几个层级。
- 如果只在某一个点临时写死，很容易出现换图后失效，或者只有初始地图生效的问题。

**解决方法：**

- 沿用当前已有的地图注册与初始化链路，不另外造一套旁路配置。
- 只在必要的数据结构里增加 `playerScale` 字段，让它和 `mapId`、`spawnId` 一样作为标准地图初始化数据的一部分流转。

这样后续新增地图时，不需要额外记住新的特殊入口，仍然走现有主流程即可。

## 最终验证结果

本次已完成并确认：

- 璃落庄园使用 `playerScale: 0.8`，人物保持当前偏小尺寸。
- 璃落家客厅使用 `playerScale: 1`，人物恢复原始大小。
- 后续地图如果未配置 `playerScale`，会默认回退到 `1`。
- 已修复 `playerScale` 在 `MapLoadingScene -> WorldScene` 之间丢失的问题。
- 用户已实际试玩确认：**当前效果没问题**。
- 使用 `npm run build:web` 已成功通过构建验证。

## 后续可继续扩展的方向

如果后面地图数量继续增加，可以继续沿这个方向往下扩：

1. 把 `playerScale` 进一步扩展为角色在不同地图中的完整显示配置，比如额外支持独立的 `depth`、偏移或特殊站位修正。
2. 如果后续加入 NPC，也可以考虑让 NPC 支持按地图或按角色类型配置显示比例，避免室内外场景比例失衡。
3. 如果某些地图需要更细调的表现，还可以在保持当前结构不变的前提下，再补“出生点级别”的局部覆盖规则。

当前这一步已经先把最核心的多地图人物比例差异问题稳定落地，后续扩展空间也保留下来了。
