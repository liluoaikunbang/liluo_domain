# 对话右侧NPC立绘接入与栏位切换

## 本次实现思路

这次调整的目标，是让地图内触发对话时的左右栏位更像真正的冒险 RPG 对话场景：

1. 左侧继续固定显示主角立绘；
2. 右侧在平时仍显示地图信息栏；
3. 一旦进入对话，右侧就临时切换成当前 NPC 的立绘展示；
4. 对话结束后，再自动恢复为原来的地图信息栏。

为了避免左右两边以后各写一套立绘样式，这次没有额外再做左右专用组件，而是把立绘显示统一收进同一个 `GamePortraitPanel`，由 `GameView` 在左右栏位分别复用。这样后续如果还要继续扩展更多 NPC、加不同地图的对话人物，主要只需要补对话数据和资源，不用重复改 UI 结构。

另外，NPC 立绘资源没有硬塞进全局入口，而是放在对应地图自己的对话数据文件里声明，再通过地图级资源 bundle 一起参与加载。这样更符合现在项目里“地图数据归地图自己管理”的分层方式，也更方便以后每张地图维护自己的人物与剧情资源。

---

## 相关代码路径

- `src/game/views/GameView.vue`
  - 左侧继续固定挂载主角立绘；
  - 右侧改成根据 `showDialog` 在 `GameInfoPanel` 与 `GamePortraitPanel` 之间切换；
  - 对话态下右侧标题保持为“当前位置：地名”，内容替换为 NPC 立绘。

- `src/game/views/GamePortraitPanel.vue`
  - 抽成左右共用的立绘展示内容组件；
  - 保持黑底、边框和空态文案；
  - 图片使用统一的铺满容器逻辑，避免左右显示风格继续分叉。

- `src/game/views/GameInfoPanel.vue`
  - 保留非对话态下的右侧信息栏职责；
  - 不再承担对话期间 NPC 展示逻辑。

- `src/game/views/composables/useGameDialogueBridge.ts`
  - 对桥接态中的 `activeDialogue` 继续透传 `npcPortrait`；
  - 保证对话开始、切换节点、结束时，右侧 UI 有稳定的响应式数据来源。

- `src/game/core/EventRunner.ts`
  - 给对话节点与分支对话统一支持 `npcPortrait`；
  - 在解析当前对话节点时，优先使用节点自身立绘，没有时回退到整段对话级立绘配置。

- `src/game/data/dialoguePortraits.ts`
  - 提供对话立绘数据结构定义；
  - 统一约束 `key`、`src`、`alt`、`statusText` 等字段。

- `src/game/data/liluo_estate/dialogues.ts`
  - 在庄园地图对话数据里声明璃音立绘；
  - 通过 `liluoEstateDialogueAssetBundle` 把对应图片资源并入地图级加载清单；
  - 在 `estate_time_of_day_selection` 对话中接入 `npcPortrait`，作为当前右侧立绘展示来源。

## 开发过程中遇到的问题

### 问题 1：右侧原本是信息栏，不能直接承担对话立绘展示

最初右侧栏位默认承担的是当前位置说明、描述和交互按钮。这个结构在自由移动时没问题，但一旦进入对话，就会和“右侧显示 NPC 立绘”的目标冲突。

### 解决方法

在 `GameView.vue` 里直接按对话状态切换右侧内容：

- `showDialog === false` 时，继续显示 `GameInfoPanel`；
- `showDialog === true` 时，改为显示 `GamePortraitPanel`。

这样切换逻辑集中在视图外壳层，信息栏和立绘面板各自只负责自己的内容，不会把职责搅在一起。

---

### 问题 2：如果左右各写一套立绘结构，后续很容易样式漂移

左侧本来就已经有主角立绘区域，如果右侧再单独写一个 NPC 专用组件，短期能用，但以后只要改其中一边的铺图方式、边框、黑底或空态文案，两边就会很快出现风格不一致。

### 解决方法

这次直接让左右两边共用 `GamePortraitPanel`。

外层标题仍由 `GameSidePanel` 负责，内容区只专注“展示一张立绘或者展示空态”。这样既保住了统一性，也避免以后每次微调立绘样式都要改两处。

---

### 问题 3：NPC 立绘资源更适合跟随地图剧情，而不是挂到全局入口

这次要接的是对话对象立绘，本质上更接近“地图剧情资源”，而不是主角那种全局常驻资源。如果直接塞到 Boot 或全局资源表里，会让后续地图越来越难维护。

### 解决方法

把立绘配置放进对应地图的 `dialogues.ts` 中，并单独导出地图级资源 bundle。

当前庄园地图里，璃音立绘就在：

- `src/game/data/liluo_estate/dialogues.ts`

中声明，并通过 `liluoEstateDialogueAssetBundle` 交给地图资源链路统一处理。这样后续新增 NPC 时，也能沿用“哪个地图要用，就在哪个地图的数据目录里声明”的方式继续扩展。

---

### 问题 4：右侧标题和立绘内容一度混在一起，阅读感不稳定

在迭代过程中，右侧对话态标题文案一度混入了状态信息，导致栏位标题和立绘内容的分工不够清晰，看起来也不如左侧稳定。

### 解决方法

后面把结构重新收口：

- 栏位标题仍由外层统一负责；
- 右侧对话态标题恢复为“当前位置：地名”；
- 立绘内容只放进共用的 `GamePortraitPanel`。

这样右侧在自由态和对话态之间切换时，结构更稳定，也更符合当前三栏舞台的视觉节奏。

---

## 最终验证结果

这次调整后，当前已达到的结果是：

1. 对话开始时，左侧仍保持主角立绘不变；
2. 右侧会从原来的地图信息栏切换为 NPC 立绘展示；
3. 对话结束后，右侧会恢复为信息栏；
4. 左右两边已经共用同一套立绘内容组件；
5. 庄园里的璃音对话已经接入地图级立绘配置，可作为当前验证入口。

本次代码侧执行并通过了以下验证：

```bash
npm run build:web
```

结果：

- `vite build` 构建通过；
- 构建产物中可以看到 `LiYin` 立绘资源被正常打包。

另外，这轮实现实际使用到了 `src/assets/game/role/LiYin.png` 这张角色立绘，因此已同步补充素材清单记录。
