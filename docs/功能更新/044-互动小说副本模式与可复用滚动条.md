# 044-互动小说副本模式与可复用滚动条

## 实现思路

本次把旧页面 `src/components/Domain/ChamberShop/Chamber1.vue` 中写死在 Vue 模板里的互动小说流程，迁出到 `src/game` 体系下，先落成一套可复用的互动小说副本底座。

新的互动小说不再把正文、选项和状态逻辑混在组件模板里，而是采用独立副本目录：

- `scenario.json`：剧本文本、节点、分支、线索、任务等外部数据。
- `assets.ts`：副本使用的背景图、立绘等资源引用。
- `meta.ts`：副本基础信息。
- `index.ts`：副本统一导出。

运行时由 `InteractiveFictionRunner` 负责处理：

- 开始副本。
- 根据选项推进节点。
- 记录已访问节点。
- 维护已发现线索。
- 维护进行中/已完成任务。

UI 上保持游戏原本三栏结构：

- 左侧仍然显示主角立绘栏。
- 中间地图栏保持 Phaser 容器不卸载，互动小说作为覆盖层显示在地图上方。
- 右侧切换为互动小说副本信息栏，展示任务、线索、重新开始副本、离开副本。

同时新增 `GameScrollArea` 组件，统一 game 内滚动区域的滚动条风格，避免浏览器默认滚动条破坏游戏 UI 的暗紫像素风氛围。

## 开发过程中遇到的问题

### 1. 旧 Chamber1.vue 的内容耦合太重

旧 `Chamber1.vue` 里把每个步骤都写成一个 `DomainLayout v-if`，正文、按钮、状态跳转都散在模板中。

如果直接照搬到 game UI，会继续形成难维护的大模板，也不利于以后增加新的互动小说剧本。

解决方法：

- 新增 `interactive_fictions/<scenarioId>/` 副本目录。
- 剧本文本改为 `scenario.json`。
- 正文使用 `paragraphs` 数组。
- 分支使用 `choices` 数组。
- 线索与任务使用纯 JSON 字段声明，避免在剧本里掺杂函数。

### 2. 离开副本后地图黑屏

最初互动小说进入时，中间地图栏使用 `v-if/v-else` 切换。这样会把 `#phaser-game-container` 从 DOM 中卸载。

Phaser 画布原本挂在旧容器里，离开副本后 Vue 重新创建了一个新的同名容器，但 Phaser 实例不会自动重新挂载到新容器，于是地图区域变成黑屏。

解决方法：

- `GameView.vue` 中保留 `#phaser-game-container` 常驻 DOM。
- 互动小说 UI 改为覆盖层显示在地图容器上方。
- 离开副本时只移除覆盖层，不动 Phaser 容器与画布。

### 3. 互动小说正文遮罩影响背景可读性

初版正文区域类似普通半透明面板，用户反馈背景图看不清，代入感不足。

解决方法：

- 中间正文层改为铺满整个地图栏。
- 背景图保持可见。
- 正文层使用更低透明度的暗色遮罩。
- 正文加轻微文字阴影，保证文字清晰。

### 4. 右侧底部按钮溢出

右侧面板一开始把任务、线索和底部按钮放在同一个滚动容器里，并且组合了 `height: 100%`、`padding`、`margin-top: auto` 等样式，导致按钮从面板底部突出。

解决方法：

- 右侧面板拆成两个区域：
  - `interactive-fiction-panel__content`：任务/线索滚动区域。
  - `interactive-fiction-panel__actions`：底部固定按钮区域。
- 外层 `interactive-fiction-panel` 使用 `overflow: hidden`。
- 只有内容区负责滚动，底部按钮永远留在面板内部。

### 5. 默认滚动条不符合游戏 UI

互动小说正文、右侧任务线索栏、剧情对话框正文都出现了浏览器默认滚动条，和当前暗紫色游戏 UI 不协调。

解决方法：

- 新增 `src/components/base/GameScrollArea.vue`。
- 在组件内部统一定义 Firefox 与 WebKit 滚动条样式。
- 已接入：
  - `GameInteractiveFictionView.vue`
  - `GameInteractiveFictionPanel.vue`
  - `DialogBox.vue`

## 后续维护建议

1. 后续继续迁移 `Chamber1.vue` 正文时，优先补 `scenario.json` 的 `nodes`，不要再把正文写回 Vue 模板。
2. 新增互动小说副本时，沿用 `src/game/data/interactive_fictions/<scenarioId>/` 目录结构。
3. 副本 JSON 保持纯数据化：文本、节点、选项、线索、任务都用字段描述，不在 JSON 中写函数式逻辑。
4. 涉及滚动区域时优先复用 `GameScrollArea`，避免每个组件单独写滚动条样式。
5. 互动小说模式应继续作为地图上的副本覆盖层存在，不要卸载 Phaser 地图容器。
