# 房间地图静态居中相机修复

## 本次实现思路

这次修复的是 `liluo_room` 和 `mumu_room` 这类室内房间地图在中间地图栏目中的显示位置问题。

两个房间都不应该被自动放大，也不应该因为主角出生点偏下或偏左而让整张房间图偏移。它们的目标表现是：

1. 地图保持原始比例和默认大小；
2. 如果某个方向完整放得下，就在该方向居中；
3. 如果某个方向放不下，就让该方向占满地图栏并保留相机可显示范围；
4. 房间地图默认使用静态居中视角，不跟随主角出生点重新偏移。

第一版修复只增加了 `static-centered` 相机模式，但仍沿用了旧的“小地图必须宽高都放得下才居中”的判断。用户实际测试后发现 `liluo_room` 仍然横向占满、纵向顶格，下方留白。

最终修复思路是把相机 viewport 的居中判断从“宽高一起判断”改为“横向和纵向分别判断”。这样 `liluo_room` 这种“横向放不下、纵向放得下”的房间，会保持横向占满地图栏，同时在纵向居中。

---

## 相关代码路径

- `src/game/data/registry.ts`
  - 给地图级 `viewport` 配置补充 `cameraMode?: 'follow-player' | 'static-centered'`。

- `src/game/data/liluo_room/meta.ts`
  - 给 `liluo_room` 增加 `cameraMode: 'static-centered'`。
  - 保持 `smallMapAdaptiveFit: false`，房间地图不自动放大。

- `src/game/data/mumu_room/meta.ts`
  - 给 `mumu_room` 增加 `cameraMode: 'static-centered'`。
  - 与 `liluo_room` 使用同一套房间静态视角规则。

- `src/game/systems/map/cameraLayout.ts`
  - `computeCameraLayout()` 增加 `focusTarget` 和 `shouldFollowPlayer` 输出。
  - 将原本的 `shouldCenterSmallMapViewport` 拆成：
    - `shouldCenterSmallMapViewportX`
    - `shouldCenterSmallMapViewportY`
  - viewport 的 `x / width` 与 `y / height` 分别按轴计算，避免某一轴放不下时拖累另一轴无法居中。

- `src/game/systems/map/worldSceneRuntime.ts`
  - 读取地图级 `cameraMode`。
  - 默认仍是 `follow-player`，避免影响庄园、客厅等原有地图。
  - `static-centered` 地图不调用 `startFollow(player)`。
  - `static-centered` 地图使用 `layout.focusTarget` 作为相机中心。

- `scripts/tests/camera-layout.test.mjs`
  - 增加房间地图启用静态居中相机的回归测试。
  - 增加相机布局源码守卫，确认当前实现保留 X/Y 分轴居中判断和静态居中视角逻辑。

## 开发过程中遇到的问题

### 问题 1：误以为问题只来自主角跟随

最开始观察到 `liluo_room` 没有居中时，先定位到房间地图进入后相机会跟随主角。由于 `liluo_room` 的出生点在房间偏下偏左位置，跟随主角确实会让地图显示看起来偏移。

因此第一步修复新增了 `cameraMode: 'static-centered'`，让房间地图不再跟随主角，而是对准地图内容中心。

### 解决方法

在地图 meta 中给 `liluo_room` 和 `mumu_room` 配置静态相机模式：

```ts
viewport: {
  smallMapAdaptiveFit: false,
  cameraMode: 'static-centered'
}
```

同时在 `worldSceneRuntime.ts` 中让 `static-centered` 地图跳过 `startFollow(player)`，并改用 `layout.focusTarget` 调整相机中心。

---

### 问题 2：璃落房间仍然纵向顶格

用户实际测试后确认，第一版修复后 `liluo_room` 仍然是：

- 横向占满整个地图栏；
- 纵向顶在地图栏上方；
- 下方留下空白；
- 没有在纵向居中。

这说明问题不只是“是否跟随主角”，而是相机 viewport 的尺寸和位置本身没有按轴居中。

### 解决方法

复查 `cameraLayout.ts` 后确认，原逻辑只有在地图宽度和高度都小于当前相机视口时，才会把 viewport 缩到地图尺寸并居中。

`liluo_room` 的运行时内容宽高约为 `544x400px`。在某些窗口尺寸下，它会出现：

- 宽度大于地图栏，横向放不下；
- 高度小于地图栏，纵向放得下。

旧逻辑因为“宽度放不下”，整体不进入居中分支，导致纵向也没有居中。Phaser 相机 bounds 又会把 Y 轴夹到 `0`，于是地图顶在上方。

最终改为 X/Y 轴分别判断：

```ts
const shouldCenterSmallMapViewportX =
  !shouldZoomSmallMap && preferredDisplayBounds.width <= cameraWorldViewWidth;

const shouldCenterSmallMapViewportY =
  !shouldZoomSmallMap && preferredDisplayBounds.height <= cameraWorldViewHeight;
```

viewport 的横向和纵向也分别计算：

```ts
viewport: {
  x: shouldCenterSmallMapViewportX ? (viewportWidth - centeredViewportWidth) / 2 : 0,
  y: shouldCenterSmallMapViewportY ? (viewportHeight - centeredViewportHeight) / 2 : 0,
  width: shouldCenterSmallMapViewportX ? centeredViewportWidth : viewportWidth,
  height: shouldCenterSmallMapViewportY ? centeredViewportHeight : viewportHeight
}
```

这样 `liluo_room` 会横向继续占满地图栏，纵向则收缩到房间地图高度并居中。

### 问题 3：Node 原生测试无法直接导入 `cameraLayout.ts`

新增测试时曾尝试直接从 `scripts/tests/camera-layout.test.mjs` 导入：

```js
import { computeCameraLayout } from '../../src/game/systems/map/cameraLayout.ts';
```

但 `cameraLayout.ts` 内部使用了项目源码中的 extensionless import：

```ts
import { isKnownTransparentTileGid, shouldHideRuntimeTileLayer } from './runtimeMapNormalizer';
```

Vite 构建可以正常处理这类导入，但 Node 原生 ESM 测试环境不能直接解析这个路径，于是报：

```text
ERR_MODULE_NOT_FOUND
```

### 解决方法

没有为了测试去改动项目源码导入风格，避免扩大影响面。

最终测试改为：

1. 直接导入两个房间的 `meta.ts`，确认房间地图配置了 `static-centered`；
2. 读取 `cameraLayout.ts` 和 `worldSceneRuntime.ts` 源码文本，做轻量守卫，确认当前实现保留：
   - X/Y 分轴居中判断；
   - `static-centered` 不跟随主角；
   - 静态相机使用 `layout.focusTarget` 居中。

这不是最理想的纯函数测试，但在当前项目测试环境下足够轻量，也避免为了一个回归测试牵动源码模块解析方式。

## 最终验证结果

本次修复完成后，用户已经实际进入游戏测试并确认：

1. `liluo_room` 不再纵向顶格；
2. 房间地图在地图栏目中按预期居中；
3. 当前显示无报错；
4. `mumu_room` 保持同样的房间静态居中规则。

本次验证命令：

```bash
node --test scripts\tests\camera-layout.test.mjs
npm run build:web
```

验证结果：

- `camera-layout.test.mjs` 通过；
- `npm run build:web` 通过；
- 构建中仍有项目原本存在的两个 tileset `new URL(...) doesn't exist at build time` warning；
- 这些 warning 不是本次相机修复引入的问题；
- 已由用户实际测试确认当前房间地图显示正常，因此本次功能修复可以视为完成并沉淀记录。
