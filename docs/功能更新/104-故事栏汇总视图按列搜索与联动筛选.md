# 故事栏汇总视图按列搜索与联动筛选

## 本次实现思路

本次更新继续完善旅途菜单“故事”栏的汇总视图，让它更适合在大量故事大纲元信息中检索内容。

原本汇总视图只展示各个字段的统计项，例如 `storyTags`、`tags`、`specialGameplay`、`characters` 等。现在每个字段列头都增加了搜索框：

- 在某一列输入关键词后，会动态筛选命中的故事节点。
- 筛选不是只影响当前列，而是先得到命中的节点集合，再用这些节点重新汇总所有列。
- 多个列同时输入关键词时，按“同时满足所有搜索条件”的方式筛选。
- 筛选后展示出来的汇总项仍然保持可点击，点击后继续打开匹配条目弹窗。
- 汇总项中命中的字符会变成高亮颜色，方便确认命中位置。
- 搜索框有内容时，右侧会一直显示清除按钮，不再依赖浏览器原生的 hover 才出现的清除入口。

这样汇总视图可以作为故事元信息的快速筛选器使用。例如在 `tags` 中搜索一个玩法关键词后，`characters`、`locations`、`requiredAbilities` 等列会同步收敛到这批故事节点对应的内容，而不是只让搜索列自己变化。

## 具体实现说明

### 1. 每列搜索框跟随字段定义生成

汇总表头不再手写每个字段列，而是遍历 `SUMMARY_FIELD_DEFINITIONS`。

这样后续如果汇总字段继续扩展，只要补充字段定义，表头搜索框、列内容和筛选逻辑就能沿用同一套结构。

### 2. 模糊搜索按字符顺序匹配

搜索逻辑使用轻量的字符顺序匹配。

例如输入 `社绑` 时，可以命中包含“社……绑”的条目；输入完整关键词时，也可以按正常顺序命中对应字段值。

当前没有引入额外搜索库，避免为了一个菜单汇总筛选功能增加不必要依赖。

### 3. 联动筛选先筛节点，再重建汇总列

初版搜索只对当前 `field.items` 做过滤，所以会出现“只有查找列变化，其它列仍显示全量统计”的问题。

本次调整后，汇总组会保留该分类下的原始节点列表：

1. 读取所有当前有输入内容的搜索列。
2. 对每个分类组的 `nodes` 做筛选。
3. 判断节点是否在对应字段中包含匹配值。
4. 得到筛选后的节点集合。
5. 用筛选后的节点重新调用汇总生成逻辑，生成所有列的统计项。

因此任意一列搜索都会带动整行所有列一起变化。

### 4. 清除按钮改为自定义常驻按钮

浏览器原生 `type="search"` 的清除按钮在部分环境中只有鼠标悬停或输入聚焦时才出现，不符合当前菜单操作预期。

本次隐藏原生清除按钮，并在输入框右侧渲染自定义 `×` 按钮：

- 只有搜索框有内容时显示。
- 一旦显示就常驻可见。
- 点击后清空对应列的搜索条件。

## 开发过程中遇到的问题

### 问题 1：只筛当前列会造成其它列信息不一致

**现象：**

在某一列输入关键词后，只有当前列下面的条目减少，其它列仍然显示未筛选前的全量统计。用户会误以为其它列也属于筛选结果。

**解决方法：**

把筛选层级从 `field.items` 提升到故事节点层级。筛选条件先用于得到匹配节点，再用匹配节点重新汇总每个字段。

### 问题 2：搜索命中需要保留可点击状态

**现象：**

如果为了高亮把按钮文本直接改成纯文本片段，容易破坏原本点击汇总项打开匹配弹窗的交互。

**解决方法：**

保留外层 `button`，只把按钮内部的文本拆成普通片段和命中片段。这样高亮不影响按钮语义和点击行为。

### 问题 3：原生搜索框清除按钮显示时机不稳定

**现象：**

搜索框有内容时，清除入口并不总是可见，有的浏览器或状态下需要鼠标悬停才出现。

**解决方法：**

隐藏原生 search 清除按钮，改为由 Vue 根据当前字段搜索内容渲染自定义清除按钮。
