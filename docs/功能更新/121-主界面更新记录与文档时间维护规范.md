# 主界面更新记录与文档时间维护规范

创建时间：2026-07-19

## 更新时间记录

- 2026-07-19：首次创建；补充主界面更新记录入口、全屏记录面板、历史文档记录整理及文档时间同步规范。
- 2026-07-19：更新记录改为按月份分组；最近月份默认展开，其他月份默认折叠，并限制同一时间最多展开一个月份。

本次在主界面的“继续旅程”下方增加“更新记录”入口，以功能更新文档为来源，从近到远展示项目变化；同时把文档创建时间、修改历史和界面记录的同步要求写入项目维护规则。

## 实现思路

1. 新增独立的更新记录数据文件，以功能文档编号作为唯一 ID，并根据文档创建时间排序。
2. 在主界面菜单中接入“更新记录”，保留鼠标和键盘导航，并在打开、关闭面板时正确转移焦点。
3. 更新记录面板采用时间线式列表，显示日期、编号、标题和一段更新摘要；面板打开时使用整个视口，长列表在内部滚动。
4. 整理历史功能文档时合并重复的 107 编号，界面只保留一个对应条目。
5. 在 `AGENTS.md` 中规定：今后新增或实质修改文档时，必须同步功能更新目录与界面记录；创建时间保持不变，每次修改追加更新时间和摘要。
6. 更新记录按年月分组，默认只打开最近月份；月份按钮共享一个展开状态键，打开新月份时自动收起原月份。

## 开发过程中遇到的问题

### 1. 历史文档缺少可靠更新时间

问题：部分旧文档没有在正文中记录时间，Git 提交时间也不能准确代表文档最初出现的时间。

解决：历史记录统一采用文件创建时间；从本规则生效后的新文档则把创建时间写进正文，后续不再依赖文件系统时间推断。

### 2. 功能文档存在重复编号

问题：两个不同文档同时使用 107，若直接生成界面列表，会出现重复 ID 和不稳定的渲染键。

解决：把两个 107 文档的内容合并成一篇综合记录，并同步合并功能更新目录，保持文档编号与界面记录一一对应。

### 3. 全屏样式存在重复选择器

问题：更新记录放大到全屏后，主界面样式中残留了重复且层级错误的选择器，可能影响移动端布局维护。

解决：保留单一的全屏容器规则，清理错误后代选择器和媒体查询中的重复声明，使桌面与移动端沿用同一套状态样式。
