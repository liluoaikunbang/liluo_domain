# 054-存档栏布局与编号整理

## 实现思路

本次是在 `053-存档菜单条目化与布局收口` 后，继续根据实际测试反馈整理存档栏 UI 与存档编号规则。

目标是让存档栏在存档较多时仍然像 RPG 存档列表，而不是因为文字、按钮或滚动条细节显得拥挤：

- 存档卡片最多两列展示，窄屏回落为单列。
- 地图名去掉“地图：”前缀，卡片内只展示地点名。
- “人物状态：”缩短为“状态：”。
- “覆盖这个存档”改为“覆盖存档”，并新增“删除存档”按钮。
- 覆盖与删除按钮并排展示，删除前弹出确认。
- 存档列表使用项目内已有 `GameScrollArea` 同风格滚动条。
- 新建存档编号统一为 `save001`、`save002`、`save003`。
- 旧 `default`、`save-001` 这类历史编号会在列出存档时迁移到新格式。
- 删除编号存档后会自动压紧排序，不留下空号。

本次没有修改地图 `map.json`，也没有新增素材图片。

## 开发过程中遇到的问题

### 1. “覆盖这个存档”按钮容易在窄卡片中溢出

存档卡片在列表空间不足时，按钮和文本缺少统一的 `max-width`、`box-sizing`、换行和收缩约束，导致按钮可能超出卡片。

解决方法：

- 给菜单内元素补充 `box-sizing: border-box`。
- 给按钮补充 `max-width: 100%`、`white-space: normal` 和 `overflow-wrap: anywhere`。
- 将存档卡片操作区整理为稳定的两列按钮布局。

### 2. 存档较多时卡片会显得拥挤

最初使用自动适配网格后，列数会随容器宽度变化，存档多时视觉密度不稳定；长地图名也可能影响卡片高度和布局。

解决方法：

- 存档列表固定为最多两列。
- 地图名使用单行省略，并通过 `title` 保留完整信息。
- 其他状态、时间与按钮允许自然换行，卡片高度自动增高。

### 3. 存档列表滚动条与项目风格不一致

存档较多后出现浏览器原始滚动条，和游戏 UI 中已定义的滚动条风格不一致。

解决方法：

- 将 `GameScrollArea` 中的 `scrollbar-width`、`scrollbar-color` 和 `::-webkit-scrollbar` 系列样式复用到 `.save-slot-list`。

### 4. 存档编号不符合期望

旧逻辑使用 `default` 或 `save-001` 这类编号，不符合用户希望的 `save001`、`save002` 顺序显示。

解决方法：

- 新建存档默认生成 `save001` 起步的连续编号。
- 兼容并迁移 `default`、`save-001` 等历史编号。
- 保留手动传入的非编号自定义 slot id 兼容能力。

### 5. 删除存档后编号会空缺

只在新建时查找空号会导致删除前面的存档后留下空位，不符合“始终动态排序”的期望。

解决方法：

- 在存储层新增编号压紧逻辑。
- `listGameSaveFiles()` 和 `deleteGameSaveFile()` 都会触发编号整理。
- 只整理 `save###` 编号存档，不强制改动非编号自定义 slot id。

## 后续维护建议

1. 后续如继续扩展存档栏操作，仍应保持“存储层负责真实数据变更，菜单组件只负责展示和 emit 事件”的分层。
2. `save###` 编号现在会动态压紧；如果未来需要“永久存档编号”或“按创建时间不可变编号”，需要先确认设计目标再调整。
3. 非编号自定义 slot id 当前仍保持兼容，避免导入旧数据或调试数据时被强制改名。
4. 存档栏 UI 后续增加更多信息时，应优先保持两列上限、卡片自适应高度、列表内部滚动的约束。
