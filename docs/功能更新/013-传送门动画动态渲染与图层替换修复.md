# 传送门动画动态渲染与图层替换修复

## 本次实现思路

这次修复的重点，不是单纯让右上角传送门“动起来”，而是把地图中的动态动画显示方式整理成一套更稳的规则：

1. 地图上的静态 tile 图层仍然可以正常作为默认显示来源。
2. 只有当某个动画在地图动画配置里**明确声明要作为世界对象渲染**时，`WorldScene` 才会额外创建动画精灵。
3. 只有当对应动画已经注册成功，并且配置里明确要求隐藏源图层时，才会跳过渲染原始静态图层。
4. 如果动画没有注册，或者没有声明世界对象配置，则继续保持原本静态图层显示，不做隐式替换。

这样既修掉了当前传送门静止的问题，也避免把“某个特例”硬编码进 `WorldScene`，后面别的地图如果也有火把、光柱、机关、特效门等动态物件，都可以走同一套配置方式接入。

---

## 根本问题

这次的根因不是“动画没注册”，而是：

- `portal_idle` 确实已经注册到了 Phaser 动画系统里。
- 但地图上实际显示出来的，是 `Portal` 图层里的静态 tile。
- 原先 `WorldScene` 只会在找到特定对象锚点时，才额外创建一个播放 `portal_idle` 的精灵。
- 当前地图里并没有这个对象锚点，因此动画精灵从来没有被创建。

结果就是：

- 动画系统里有 `portal_idle`
- 画面上却仍然只看到静态 tile

所以问题的根本不在动画注册阶段，而在**地图显示阶段没有把已注册动画真正实例化到场景里**。

## 相关代码路径

- `src/game/data/animations.ts`
  - 给 `GameAnimationDefinition` 增加 `worldObject` 配置
  - 用于描述某个动画是否要作为地图中的动态对象渲染，以及绑定哪个图层/对象

- `src/game/data/liluo_estate/animations.ts`
  - 为 `portal_idle` 增加 `worldObject`
  - 明确声明它绑定 `Portal` 图层，并在动画生效时隐藏静态源图层

- `src/game/scenes/WorldScene.ts`
  - 新增按当前地图动画配置统一渲染世界动画的逻辑
  - 仅对声明了 `worldObject` 且动画已存在的配置创建精灵
  - 仅对声明 `hideSourceLayer: true` 的动画源图层跳过静态渲染
  - 当没有对象锚点时，可从指定图层中反推该动态对象的摆放位置

## 具体实现说明

### 1. 给动画定义增加世界对象配置

这次没有把“传送门”单独写死在 `WorldScene` 里，而是在动画定义层增加了可选的 `worldObject`：

- `objectName`：优先使用地图对象作为动画锚点
- `layerName`：没有对象时，可从指定 tile 图层反推摆放位置
- `hideSourceLayer`：动画生效时是否隐藏对应静态图层
- `scale / depth / originX / originY`：世界内渲染参数

这样后面别的地图动画如果也要在世界里替换静态图层，不需要再为每一个对象加一套硬编码判断。

---

### 2. WorldScene 只渲染“已声明”的世界动画

`WorldScene` 现在会从当前地图注册表里取动画配置，然后逐条判断：

1. 有没有 `worldObject`
2. 该动画 key 是否真的已经注册成功
3. 能否找到可用的摆放位置

只有这三个条件都满足时，才会创建对应动画精灵。

这保证了：

- 注册了普通动画，但没打算摆到地图上的，不会被误创建
- 没注册成功的动画，不会把静态图层错误隐藏掉
- 以后地图内容扩展时，动态对象接入规则更清楚

---

### 3. 静态图层只在“动画真正接管显示”后才隐藏

这次还补了一层保护：

- 不是看到图层名叫 `Portal` 就直接不渲染
- 而是要满足“当前动画配置声明绑定这个图层 + `hideSourceLayer: true` + 动画已存在”三个条件，才隐藏源图层

这样可以避免把某个图层名写成全局特判，也避免后续你只是注册动画、但暂时不想替换静态显示时，渲染逻辑被提前改掉。

---

### 4. 当前传送门改为通过配置接管 `Portal` 图层

`liluo_estate` 当前的 `portal_idle` 配置里，已经明确声明：

- 绑定 `Portal` 图层
- 动画接管后隐藏该图层
- 使用统一的深度和原点配置

这样现在右上角传送门会真正以动画精灵显示，而不再停留在静态 tile 状态。

## 开发过程中遇到的问题

### 问题 1：动画已经注册，但地图显示还是静止

**现象：**

- `portal_idle` 已存在
- 但地图上的传送门一直是静态图块

**原因：**

- 注册动画只代表 Phaser 知道这套帧数据
- 不代表场景里已经有某个精灵正在播放它
- 当前地图显示的实际来源仍然是 `Portal` 图层静态 tile

**解决方法：**

- 在 `WorldScene` 中补上“按地图动画配置创建世界动画精灵”的步骤

---

### 问题 2：如果直接为传送门写死特判，后续会越来越难维护

**现象：**

- 最直接的修法，是在场景里专门写一套 `portal_idle` / `Portal` 图层判断
- 但后面一旦再加别的动态地图对象，就会继续堆更多 if/else

**解决方法：**

- 把“是否作为世界对象渲染”下沉到动画配置层
- 用 `worldObject` 作为统一入口，让场景逻辑只处理通用流程

---

### 问题 3：不能因为存在某个图层就强制替换成动画

**现象：**

- 如果只要看到 `Portal` 图层就隐藏它，再自动创建动画
- 会导致“用户不想替换静态图层时”也被强制接管

**解决方法：**

- 只有动画配置显式声明 `worldObject` 且动画 key 确实存在时，才接管显示
- 没声明时继续保留静态 tile 图层，避免引入隐式副作用

---

本次修复在解决当前问题的同时，也把地图世界内动画对象的接入方式整理成了可继续复用的结构。
