# 角色动画系统

## 本次实现思路

这次角色动画的调整，核心分成两部分：

1. **修正角色精灵图的加载方式**
   - 之前在 `BootScene` 中直接使用 `'/src/assets/images/liluo_walk_source.png'` 作为路径。
   - 在 Vite 运行时，这种写法可能导致资源地址不被正确处理，从而出现 404。
   - 现在改为通过 `new URL('../../assets/images/liluo_walk_source.png', import.meta.url).href` 获取最终可访问地址，确保 Phaser 能正确加载角色图。

2. **按新角色图的真实布局重新配置动画帧**
   - 新角色图尺寸为 **96×128**。
   - 每帧尺寸为 **32×32**。
   - 总布局为 **3 列 × 4 行**。
   - 每一行对应一个朝向，中间列是站立帧，两侧列是移动帧。
   - 因此不再沿用之前对旧图的估计切法，而是按当前图片结构重新建立帧映射。

## 相关代码路径

- `src/game/scenes/BootScene.ts`
  - 负责角色精灵表的预加载
  - 处理资源加载失败日志

  - 在角色图缺失时使用 fallback 纹理，避免场景直接崩溃

## 当前角色图规格

- **文件路径**: `src/assets/images/liluo_walk_source.png`
- **总尺寸**: `96 × 128`
- **单帧尺寸**: `32 × 32`
- **布局**: `3列 × 4行`

### 行方向映射

按当前图片内容，方向映射如下：

- 第 1 行：`down`
- 第 2 行：`left`
- 第 3 行：`right`
- 第 4 行：`up`

### 每个方向的帧规则

每个方向使用 3 个基础帧：

- 第 1 列：移动帧 A
- 第 2 列：站立帧
- 第 3 列：移动帧 B

因此当前动画配置为：

```ts
down  = { walk: [0, 1, 2, 1], idle: 1 }
left  = { walk: [3, 4, 5, 4], idle: 4 }
right = { walk: [6, 7, 8, 7], idle: 7 }
up    = { walk: [9, 10, 11, 10], idle: 10 }
```

说明：

- `walk` 使用 `左脚 / 站立 / 右脚 / 站立` 的循环，更适合当前这种 3 帧角色图。
- `idle` 固定使用每行中间那一帧，保证停止移动时角色姿态稳定。

## 动画命名规则

系统仍保持四方向、两类动画的命名方式：

- `walk_down`
- `walk_left`
- `walk_right`
- `walk_up`
- `idle_down`
- `idle_left`
- `idle_right`
- `idle_up`

这样后续如果要替换角色图，只要保持相同命名规则和方向语义，场景逻辑基本不需要重写。

## 开发过程中遇到的问题

### 问题 1：角色图资源 404

**现象**：

- 浏览器控制台报错：`Failed to load resource: the server responded with a status of 404`
- Phaser 报错：`Texture "liluo_walk" not found`

**原因**：

- 资源路径直接写成了 `/src/assets/...`。
- 在 Phaser + Vite 运行时，这种写法不够稳妥，可能无法得到构建后真实可访问地址。

**解决方法**：

- 改为：

```ts
const liluoWalkSpriteSheetUrl = new URL(
  '../../assets/images/liluo_walk_source.png',
  import.meta.url
).href;
```

- 再使用该 URL 交给 `this.load.spritesheet()`。

---

### 问题 2：纹理不存在导致动画系统崩溃

**现象**：

- 在纹理缺失时继续创建动画并播放，触发：
  - `Texture "liluo_walk" not found`
  - `Cannot read properties of undefined (reading 'duration')`

**原因**：

- 角色图没有成功加载，但 `WorldScene` 仍然按正常流程创建和播放动画。

**解决方法**：

- 在 `WorldScene.create()` 中增加 `this.textures.exists('liluo_walk')` 判断。
- 如果角色图不存在：
  - 使用 fallback 纹理生成一个临时角色占位图
  - 跳过动画创建与播放
- 在 `updateCharacterAnimation()` 中再次保护，避免空纹理时继续切换动画。

---

### 问题 3：新角色图的元素切片不准确

**现象**：

- 角色可以显示，但移动时动作和朝向不够准确。

**原因**：

- 之前的帧映射是按旧图或估计结构设置的，不完全匹配现在的新图。

**解决方法**：

- 重新确认当前图片尺寸是 `96×128`。
- 按 `3列 × 4行` 的真实结构重建帧映射。
- 统一改成“中间站立、左右摆腿”的配置。

## 当前代码实现要点

### 1. BootScene 中的资源加载

- 正确加载角色图
- 记录加载失败日志，方便后续排查资源问题

### 2. WorldScene 中的动画配置集中化

- 使用一个 `animationFrameMap` 管理四个方向的帧索引
- 避免四个方向分别手写一大段重复动画代码
- 后续换图时，只需要改这一份配置

### 3. fallback 保护

- 即使角色图暂时加载失败，地图仍然可以进入
- 不会因为动画系统报错导致整个场景中断

## 后续扩展建议

如果后面还会继续换角色图，建议尽量保持以下规范：

1. 单帧统一为 `32×32`
2. 朝向顺序固定为 `down / left / right / up`
3. 每个方向尽量保持 `3 帧`：
   - 左移动
   - 站立
   - 右移动
4. 如果以后改成 `4 帧` 或更多帧，再单独扩展 `animationFrameMap`

这样后续扩展更多角色时，整个动画系统会更稳定，也更适合长期作为冒险 RPG 的基础角色表现层。
