# 045-地图数据目录分组整理

## 实现思路

本次整理目标是让 `src/game/data` 下的内容域更清晰，避免地图数据、互动小说数据和全局数据工具混在同一层级。

新的分层约定为：

- `src/game/data/maps/`：地图内容数据。
- `src/game/data/interactive_fictions/`：互动小说/副本数据。
- `src/game/data/*.ts`：全局注册、共享资源、主角配置、公共类型与工具。

地图本身仍统一由 `src/game/data/registry.ts` 汇总，互动小说仍由 `src/game/data/interactive_fictions/registry.ts` 汇总，没有新增并行入口。

## 开发过程中遇到的问题

### 1. 地图目录移动后相对路径失效

地图目录多了一层 `maps/`，原本的：

- `../assets`
- `../animations`
- `../dialoguePortraits`
- `../../../assets/game/...`

都需要对应上移一层。

解决方法：

- 公共数据类型改为 `../../assets`、`../../animations` 等路径。
- 素材 URL 改为 `../../../../assets/game/...`。
- `liluo_estate/dialogues.ts` 中给 `dialoguePortraits` 补上 `.ts` 后缀，避免 Node ESM 测试解析失败。

### 2. 测试脚本仍读取旧地图路径

部分测试直接读取 `src/game/data/liluo_room/...` 或 `src/game/data/mumu_room/...` 的 live 数据。

解决方法：

- 将测试路径统一改为 `src/game/data/maps/<mapId>/...`。
- 保持测试继续读取真实地图数据，而不是改用伪数据。

### 3. mumu 房间传送测试锁死了旧文案

`mumu-room-teleport-events.test.mjs` 原本在验证传送点绑定时，也锁死了旧按钮文案和 `description`。迁移后测试能读到新路径，但因为 live 数据中的文案已经更新而失败。

解决方法：

- 将该测试收窄为验证事件契约：`eventId`、`triggerType`、`mapTransition`、`tileMarker`、`actionId`。
- 不再把按钮显示文案作为传送点绑定测试的核心断言。

## 后续维护建议

1. 新增地图时，使用 `src/game/data/maps/<mapId>/`，并接入 `src/game/data/registry.ts`。
2. 新增互动小说/副本时，使用 `src/game/data/interactive_fictions/<scenarioId>/`，并接入互动小说 registry。
3. `src/game/data` 根目录只放跨内容域的全局配置、资源工具、主角配置和注册入口。
4. 不为了清空根目录而把全局工具塞进 `maps/` 或 `interactive_fictions/`。
