# 剧情图对话框轻量化与背景预览

## 本次实现思路

这次调整的是带 `sceneImage` 的对话显示体验，重点针对 `liluo_room` 床铺相关对话。

床铺对话已经有专属背景图，如果仍然使用普通底部大对话框，会长期遮住背景图下方内容；但如果把背景图单独完整展示，又会让对话和事件画面割裂。最终采用“剧情图模式 + 临时看图”的组合：

1. 当当前对话声明了 `sceneImage.assetKey` 时，自动进入剧情图对话模式；
2. 剧情图对话框变得更矮、更贴近底部、更透明，减少对背景图主体的遮挡；
3. 对话框仍保留暗色遮罩、文字阴影和选项高亮，保证文字可读；
4. 剧情图模式下提供“查看背景”按钮；
5. 玩家按住“查看背景”按钮，或按住 `V` 键时，对话框会临时淡出，背景图遮罩也会变淡，方便查看完整背景；
6. 松开按钮、松开 `V`、指针释放或窗口失焦时，都会自动恢复对话框，避免卡在隐藏状态。

这套方案只调整 Vue 侧对话与剧情图展示，不改动 `dialogues.json`、地图数据和事件执行逻辑。

## 相关代码路径

- `src/game/views/GameView.vue`
  - 根据 `activeDialogue.sceneImage.assetKey` 判断是否进入剧情图对话模式。
  - 维护 `isSceneImagePreviewing` 状态。
  - 将 `scene-mode`、`scene-previewing` 和 `scene-preview-change` 传给 `DialogBox`。
  - 背景图遮罩在预览状态下降低暗度。
  - 背景图 URL 先从当前地图资源中查找，找不到时再从 `mapRegistry` 中所有已注册地图资源兜底查找。
- `src/components/base/DialogBox.vue`
  - 新增 `sceneMode` 与 `scenePreviewing` props。
  - 新增 `scene-preview-change` 事件。
  - 有剧情图时切换到更矮、更透明的 `.dialog-shell--scene` 样式。
  - 新增“查看背景”按钮。
  - 支持按住 `V` 临时隐藏对话框。
  - 增加 `pointerup`、`blur` 等恢复保护。
- `src/components/base/DialogChoiceList.vue`
  - 延续半透明对话风格，选项区域保持更轻的透明底色和清晰 active 高亮。
- `src/game/data/liluo_room/dialogues.json`
  - 床铺对话 `liluo_room_bed_dialogue` 已声明：

```json
"sceneImage": {
  "assetKey": "liluo-room-bed-background"
}
```

- `src/game/data/liluo_room/dialogues.ts`
  - `liluoRoomDialogueAssetBundle` 注册了 `liluo-room-bed-background` 对应的床铺背景图资源。
- `src/game/data/registry.ts`
  - `liluo_room` 通过 `mergeAssetBundles(liluoRoomAssetBundle, liluoRoomDialogueAssetBundle)` 将地图资源与对话资源合并。

## 开发过程中遇到的问题

### 问题 1：普通对话框透明度不够明显

最初只是给普通对话框降低了一点不透明度，但实际观看时仍然像一块较实的深色面板，地图和剧情图的氛围透不出来。

### 解决方法

多次微调 `DialogBox.vue` 和 `DialogChoiceList.vue` 的背景色：

- 降低主框 `rgba` 透明底色的不透明度；
- 保留横向暗色遮罩，避免文字直接落在复杂背景上；
- 加强文字阴影；
- 让选项列表也同步变轻，但保留 active 选项高亮。

最终效果是普通对话框也带有更明显的透明色，而不是纯色块。

---

### 问题 2：床铺对话有背景图，但没有触发新功能

用户实测后反馈 `src/game/data/liluo_room/dialogues.json` 里的床铺对话明明有背景图，却没有看到剧情图对话模式和“查看背景”功能。

排查后发现，第一版实现把剧情图模式的启用条件写成了“背景图 URL 已经成功解析”。这会让 UI 状态依赖资源查找结果：只要当前地图状态或资源解析时机没有对上，就算对话本身已经声明 `sceneImage`，`scene-mode` 也不会启用。

### 解决方法

将剧情图模式的判定改为直接依赖对话数据：

```ts
const hasActiveSceneImage = computed(() => {
  return showDialog.value && Boolean(activeDialogue.value.sceneImage?.assetKey);
});
```

也就是说，只要对话 payload 中带有 `sceneImage.assetKey`，就进入剧情图对话模式。

背景图 URL 解析只负责图片是否能显示，不再决定对话框是否启用剧情图样式。

---

### 问题 3：背景图资源可能不在普通地图 asset bundle 中

床铺背景图不是定义在 `src/game/data/liluo_room/assets.ts`，而是定义在 `src/game/data/liluo_room/dialogues.ts` 的 `liluoRoomDialogueAssetBundle` 中。

虽然 `registry.ts` 已经把地图资源和对话资源合并，但为了降低 UI 对当前地图状态的耦合，仍然需要更稳的兜底查找。

### 解决方法

`GameView.vue` 中查找剧情图 URL 时：

1. 先从当前地图的 `assets` 中查找；
2. 如果找不到，再遍历 `mapRegistry` 中所有已注册地图资源；
3. 找到第一个匹配 `assetKey` 的 image 资源后返回 URL。

这样 `liluo-room-bed-background` 这类对话专属资源，即使当前地图状态有短暂不同步，也能被正确解析。

## 最终验证结果

本次功能完成后，用户已经实际进入游戏测试并确认：

1. `liluo_room` 床铺对话可以看到剧情图对话模式；
2. 对话框变矮、变透明，不再长期遮住背景图主体；
3. “查看背景”按钮可用于临时隐藏对话框；
4. 按住 `V` 也可以临时查看背景图；
5. 松开后对话框可以正常恢复；
6. 当前功能无报错。

本次验证命令：

```bash
npm run build:web
```

验证结果：

- `npm run build:web` 通过；
- 构建中仍有项目原本存在的两个 tileset `new URL(...) doesn't exist at build time` warning；
- 这些 warning 与本次剧情图对话框调整无关；
- 已由用户实际测试确认床铺对话的新交互正常，因此本功能可以视为完成并沉淀记录。
