# 182-图像生成与文档写回低绕圈执行

日期：2026-08-02

## 更新时间记录

- 2026-08-02：建立 authority / 直接消费者 / 生成型写回三道执行顺序，并把图像生成任务的低 token 装配策略接到项目级治理 authority。

## 背景

这一轮暴露出的两个问题，其实互相放大：

1. 图像生成任务与文档治理任务里，模型容易把“所有长期规则都带上”，导致 prompt、说明和检查输出快速膨胀。
2. 文档同步时如果把 authority、技能说明、用户入口、审计报告和生成器混在一起，经常会先在沙箱里撞上一次 `EPERM`，再解释报错、再重跑、再补同步，表面像 authority 附近绕圈，实际是写回路径没有先分型。

这两个问题都不是某一页海报或某一种文档独有，而是项目级图像生成与文档写回流程的公共摩擦。

## 本次调整

- 在 `docs/系统说明/项目图像生成判层与治理系统.md` 中补上“低 token 与低绕圈执行顺序”：
  - 单次 prompt 只装配命中的 authority / prompt / QA 层，不再默认把全部长期规范全文塞进一次生成。
  - 图像任务涉及文档写回时，固定顺序为 `authority -> 直接消费者 -> 生成型写回`。
  - 审计、manifest、批量摘要等生成型输出放到任务末尾，只执行一次。
- 在 `docs/系统说明/Codex命令授权治理系统.md` 中把这套分道规则上升为所有文档类型通用的低绕圈路线，并把 `npm run site:visual:audit` 纳入已知稳定 `EPERM` 的生成型写回命令。
- 在 `docs/运行规范/未解决问题/Codex会话提交异常与上下文预算问题.md` 中追加本轮实测观察，明确“混跑 authority 与生成型写回”本身就是 token 膨胀源。
- 更新 `AGENTS.md`、`docs/用户命令目录.md` 与 `docs/技能说明/liluo-grok-image-generation.md`，让入口规则、用户表达和技能默认行为保持一致。
- 在 `src/content/site/imageGenerationGovernance.js` 中新增共享执行计划辅助函数，把“只装配命中层级”和“authority / 直接消费者 / 生成型写回”的固定顺序沉成可复用逻辑。

## 结果

- 图像生成任务默认不再为了“怕漏掉规范”而整批展开长期规则。
- 图像生成与文档治理之间的同步顺序固定下来，减少了先失败一次、再解释一次、再重跑一次的无信息往返。
- `site:visual:audit` 这类已知会落报告的命令不再假装是普通文本编辑路径，后续可直接按正确权限路线执行。
- 这属于项目级执行策略修复，不等同于平台沙箱本身被消除；平台或宿主更严格的权限策略仍可能要求最终审批。
