# 073-状态驱动的移动表现与失明遮罩

## 实现思路

本次把主角行走图、移动速度、移动方式和视觉遮罩从“立绘/外观变化”中拆出来，统一改为由人物状态驱动。

此前 `full_body_bondage` 等外观本身还携带跳跃移动、速度倍率等功能含义，导致“更改立绘”同时改变角色行动能力。调整后，外观只负责视觉资源；真正的功能效果集中到状态规则中解析。这样后续继续扩展“状态影响行走图”的规则时，只需要维护状态规则表，不需要把功能逻辑散落在对话、立绘或地图运行时代码里。

当前状态效果：

- `no_shoes`：移动速度降低 10%。
- `barefoot`：移动速度降低 5%。
- `hands_bound`：移动速度降低 5%，行走图切换为 `liluo_walk_bondage`。
- `legs_bound`：移动速度降低 50%，行走图切换为当前分层 `legs_bound` / `bondage_legs_bound` 外观，移动方式改为 hop 蹦跳。
- `confined`：行走图切换为 `liluo_full_body_bondage`，不能移动，但仍可按方向键转向。
- `blind`：地图上人物周围圆形区域可见，外部叠加黑色遮罩。

减速采用加法叠加。例如无鞋子、赤脚、双手被缚和双腿被缚同时存在时，总减速为 `10% + 5% + 5% + 50% = 70%`，最终速度倍率为 `30%`。为避免 JavaScript 浮点误差导致 `0.2999999999999999` 这类结果，速度倍率输出时做了小数归一化。

行走图规则采用状态组合解析。当前禁锢仍高于其它状态；双腿被缚会切换为四方向站立帧 + hop 移动，但不会吞掉双手被缚图层：双手与双腿同时被缚时使用 `bondage_legs_bound` 组合外观。

失明状态在地图运行时增加一层 `Graphics` 遮罩。遮罩以世界坐标绘制并跟随玩家刷新：人物周围 2 格半径完全可见，外侧 1 格范围做柔和渐变，再外部为 90% 不透明黑色，使玩家仍能隐约看到地图轮廓，但失明压迫感更明显。

## 遇到的问题与解决方法

### 1. 立绘/外观残留功能性

问题：原本对话里会通过 `playerAppearanceChange` 直接把主角切到 `full_body_bondage`，而该外观又携带跳跃移动和速度倍率。这会让“立绘变化”承担功能逻辑，不利于后续扩展状态规则。

解决：保留 `playerAppearanceChange` 的基础能力，但把行走速度、移动方式、行走图覆盖都收口到 `playerMovementPresentationRules.ts`。璃落房间床铺拘束睡袋分支改为写入 `legs_bound` 状态，解除时清空状态，不再直接切外观。

### 2. 移除状态时不能把所有减速都清掉

问题：如果把减速做成单个累计值，移除某个状态时容易误把其他状态的减速也一起清除。

解决：每次都从当前状态列表重新解析总减速。这样移除 `hands_bound` 时只会少掉它自己的 5%，`no_shoes`、`barefoot`、`legs_bound` 等其他状态仍然保留自己的贡献。

### 3. `0` 速度容易被当成无效倍率

问题：原移动控制器里速度倍率小于等于 0 时会回退到默认速度。如果禁锢只把速度倍率设成 0，反而会被当成无效值并恢复移动。

解决：新增 `canMove` 字段。禁锢状态设置 `canMove=false`，控制器先判断能否移动，再计算速度。这样禁锢时可以明确阻止坐标变化，同时保留方向键转向。

### 4. 禁锢需要能转向但不能移动

问题：完全阻断输入会让角色无法转向，不符合“可以转向，但不能移动”的要求。

解决：手动移动逻辑仍读取方向键并更新方向，但当有效速度为 0 时直接返回 `isMoving=false`，不改坐标。动画刷新使用对应方向的 idle 帧，因此角色能原地转向。

### 5. 失明遮罩初版不够有失明感

问题：最初外部遮罩为 80% 不透明、完全可见范围 3 格，实际体验上仍能看清较多地图，失明效果不明显。

解决：根据后续反馈，把完全可见范围收窄到 2 格，外部遮罩提高到 90% 不透明，同时保留 1 格渐变边缘。最终效果是在人物周围保留清晰小范围，其余区域只隐约保留轮廓。

### 6. 失明遮罩需要软边而不是硬边

问题：硬边圆形可见区看起来像简单裁切，视觉上不够自然。

解决：遮罩渲染按行绘制。中心半径内不绘制遮罩；中心半径到外半径之间逐像素计算距离，并按距离递增 alpha；外半径之外绘制完整黑色遮罩。这样边缘有一圈柔和过渡。
