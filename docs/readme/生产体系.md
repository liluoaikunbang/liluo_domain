# 璃落宇宙生产体系

`璃落宇宙` 不是把一堆设定文档塞进仓库里就结束的项目。它想做的是一套能把同一叙事持续生产成多种正式体验的体系，而像素风冒险 RPG 仍然是当前最重要的旗舰载体。

![璃落宇宙五层生产系统底图](../assets/readme/generated/five-layer-production-system-base.png)

## 这套体系在做什么

它把同一个宇宙里的世界、角色、关系、状态和约束保留下来，再让这些内容进入不同的正式输出形态：

- 进入故事大纲，形成长期主线与支线结构。
- 进入生产设计，拆成可执行的地图、对话、事件和玩法节点。
- 进入互动小说、副本或资料页，作为较轻但正式的验证形态。
- 进入 Phaser 运行时，变成真正可探索、可触发、可存档的游戏段落。

这意味着 AI 在项目里的角色，不是替人写完一切，而是帮团队维持同一宇宙的持续生产能力。

## 同一宇宙如何穿过角色、状态、地图与事件

![璃落宇宙状态与事件网络底图](../assets/readme/generated/universe-state-event-network-base.png)

项目真正要维持的，不只是“世界观设定还在”，而是下面这些东西能持续互相对得上：

- 角色身份、长期关系和世界位置不能在不同形态里散掉。
- 状态变化、事件后效和关系压力要能继续进入后续章节，而不是只停在单次文本里。
- 地图、对话、互动小说和资料页虽然轻重不同，但都要回到同一套来源约束。

这也是为什么 README 里会把“角色统一性”“六域结构”“真实运行证据”和“自动统计”放在同一轮升级里，而不是分开做成几块互不相干的展示页。

## 当前已经落地的层

### 1. 来源层

- 六大世界的公开结构已经固定。
- 世界来源 JSON、故事大纲、情节库与关系图谱都在持续扩展。
- 角色状态、关系与长期约束有独立的治理文档与数据源。

### 2. 生产设计层

- 项目已经把“同一故事如何进入多种形态”当成正式路径，而不是临时备选。
- `production:coverage` 脚本会给出每个世界/系列当前真实可证的最高阶段。
- 互动小说、副本、地图章节与资料页都被当成正式输出，而不是废案堆放处。

### 3. 运行层

- 当前仓库内能直接确认到 Phaser 地图运行、旅途菜单、图谱面板、对话系统、存档/读档结构和互动小说入口。
- `/#/game` 是当前真实的旗舰运行入口。
- `npm run build:web` 已在 2026-07-31 成功验证。

## 从故事走到可玩，要跨过哪些段

![十三号病院故事到可玩链路板](../assets/readme/composites/story-to-playable-case-asylum-board.png)

对这个项目来说，“有故事”与“能玩到故事”之间隔着很长一段真实工作：

- 把节点拆成地图目标、角色站位、事件条件和反馈。
- 把局部冲突拆成可运行的对话、调查、触发和回流。
- 把轻型验证形态先放进互动小说、副本或资料页，再选择值得进入地图运行时的部分。

当前已经能拿来做公开案例的，是互动小说副本 `十三号病院`：它的旧页面流程来源于 `src/components/Domain/ChamberShop/Chamber1.vue`，正式运行数据沉淀在 `src/game/data/interactive_fictions/asylum_for_lunatic/scenario.json`，并已由 `docs/功能更新/048-asylum互动小说流程补全与结局状态.md` 和测试脚本支撑。这比单纯一张“概念案例底图”更接近真实生产链。

因此页面里所有“已经进入运行层”的表述都刻意保守，避免把生产设计说成已完成玩法。

## 这套体系为什么适合公开协作

它不是“先做一堆图再说”的项目，也不是“只剩工具没有内容”的项目。协作者加入后，可以直接落在明确的生产链路上：

- 写故事的人，能看到自己的内容如何进入章节和玩法。
- 做地图与程序的人，能接到已经定义了情绪和用途的生产设计。
- 做美术与 UI 的人，能围绕真实世界结构和真实玩法入口去设计。
- 做资料治理和测试的人，能通过脚本与证据页确认项目到底走到了哪一步。

## 成熟度不是一句“快做完了”

![璃落宇宙成熟度阶梯底图](../assets/readme/generated/production-maturity-ladder-base.png)

这里更看重的是每条内容当前站在哪一级，而不是把所有线统一说成“都在开发中”：

- `outline`：已经有正式世界与故事承载，但还没进入可运行设计。
- `skeleton`：已经出现明确骨架，能往玩法和局部章节推进。
- `productionDesign`：已经进入更具体的制作设计层，离落地更近，但仍不等于已可玩。

这种分级方式让公开协作更诚实，也让后来接手的人知道自己接的是概念、骨架，还是即将运行的段落。

## 图谱与统计为什么也属于生产体系

![璃落宇宙关系与图谱展示底图](../assets/readme/generated/relationship-graph-display-base.png)

这个项目不是先把内容做完，最后再补治理。相反，关系图谱、节点统计、截图清单和证据页本身就是生产体系的一部分，因为它们决定团队有没有能力持续判断：

- 哪些世界仍然只停在概念层。
- 哪些角色和关系已经进入长期记忆。
- 哪些公开说法已有真实证据，哪些还只是制作目标。

## 边界

- AI 概念图不能冒充游戏截图。
- 文件数量不能冒充可玩程度。
- 只有真实截图、构建验证、代码证据和脚本统计，才能支撑“已完成”“可玩”“已验证”这类表述。
