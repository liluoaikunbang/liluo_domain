# 情节安置提问模板

本模板用于“从情节库选取一条情节，对照故事大纲给出落点，经用户批准后再聚焦提问”。它与「故事大纲随机提问」对称：后者从有缺口的大纲节点出发；本模板从情节条目出发。

## 一、情节选择范围

1. 用户指定 `plot-xxx` 或唯一标题时，直接使用该条目。
2. 用户说“随机”“随便”“抽一个未用情节”或未指定条目时，从真实候选池随机抽取，不得因熟悉度主动指定。
3. 默认候选为 `usageStatus` 为 `unused` 的条目，以及 `partial` 条目中仍待定的部分；已完全 `used` 的条目仅在用户点名时纳入。
4. 可叠加筛选：偏向世界、大情节分组、普通/紧缚标签、关键词、最近已问排除表。
5. 有筛选或种子时如实报告；无种子的轻量抽取不必编造种子。

## 二、落点检索

1. 先读选定情节的 `summary`、`development`、`characters`、`worldBiases`、`notes` 与使用状态。
2. `worldBiases` 非空时，优先在这些世界的故事大纲中检索；为空时标明跨世界通用，再按人物、冲突、地点或玩家流程匹配。
3. 默认给出 1–3 个落点候选，每个必须写明：
   - 目标节点或主线备忘的稳定 key 与中文路径；
   - 扩充既有节点，还是新建子节点；
   - 主线还是支线（`side`）；
   - 适配证据（人物、冲突、阶段位置、缺口或空位）。
4. 默认扩充最贴近的既有普通节点或主线备忘；仅当内容需要独立可玩范围、进入/完成条件与制作生命周期，或用户明确要求拆分时，才建议新建子节点。
5. 不得编造节点、稳定 key 或未读来源中的设定。
6. 落点批准前不进入访谈，不写回大纲，不更新情节库 `usedBy`。

## 三、批准门禁

1. 先输出：抽中/指定的情节、世界偏向、1–3 个落点选项与理由。
2. 用户可多选、组合、修改或全部否定；只有明确批准的落点才继续。
3. 用户要求只评估不适配时，报告结论后结束，不硬凑访谈。
4. 落点冲突（例如同时要求写进互斥主线）时，指出冲突并请用户取舍。

## 四、批准后的访谈

1. 读取已批准目标节点的来源 JSON 与 Markdown；若在主线下，再读最近相关主线备忘。
2. 输出顺序：选定情节、批准落点、已确认节点上下文、情节与节点的衔接缺口、4–7 个问题、预计回写文件。
3. 问题优先把情节的前提、升级、转折与后果接到节点的目标、进入离开、关系、状态、分支与玩法。
4. 问题写法、选项支架、冲突处理与回答后写回规则，遵循 [故事大纲随机提问模板](./故事大纲随机提问模板.md) 第五至七节；写回执行 `liluo-story-outline-authoring`。批准后的事件写入 `plotRefs`；另有可复用知识或玩家规则时，再分别写入 `ragRefs` / `gameplayRefs`。不得恢复任何 Tag 字段。
5. 首次成功采用写回后，将真实故事 key 追加到情节 `usedBy`，`usedByLabels` 写成“世界名-主线名-节点名”，并按剩余缺口设为 `partial` 或 `used`。

## 五、与相邻入口的边界

| 用户意图 | 应走 |
| --- | --- |
| 随机抽未完善大纲节点提问 | `random-story-outline-interview` |
| 只列出未用情节或给已定节点找候选 | 未应用情节盘点 / 缺口发现 |
| 已定情节与已定节点、只要写入 | 情节补进大纲 + `liluo-story-outline-authoring` |
| 只登记情节、不关联大纲 | 情节条目系统（情节库） |
| 从情节出发选落点并访谈 | 本模板 / `liluo-plot-placement-interview` |
