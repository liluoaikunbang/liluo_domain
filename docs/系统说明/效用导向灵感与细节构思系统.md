# 效用导向灵感与细节构思系统

## 当前契约

`liluo-purpose-driven-ideation` 是所有“想几个方案、补充细节、设计选项、比较可行方案、找灵感、检查候选价值”请求的项目入口。它只产生、验证和筛选候选，不写入正式 canon、故事、地图或代码。

它适用于新模块和既有节点，也覆盖剧情事件、对话分支、互动小说选项、地图互动、道具线索、角色反应、CG 细节、玩法和小游戏、UI 文案、音频/场景表现。纯格式改写、错别字、代码修复、迁移、Schema 校验和用户明确要求的机械原样操作不单独触发。

## 职责边界

| 能力 | 负责内容 |
| --- | --- |
| 效用导向构思 | 定义目标与缺口，生成、硬测、筛选候选 |
| 故事缺口发现 | 判断故事体系是否真的缺少内容，并提交待审批候选 |
| 故事大纲撰写 | 将已确认候选写入正式大纲 |
| 连续性审查 | 检查 canon、时间线与角色事实冲突 |
| 内容验证 | 检查数据、引用、状态与结构 |
| 自然表达 | 在候选通过筛选后清理最终措辞 |

候选没有获得用户或既有工作流要求的确认前，不得作为 canon；本系统不得替代连续性或内容验证。

## 执行规则

任务按 Micro、Standard、Large 分级：Micro 仅保留 0—3 项，Standard 仅保留 0—5 项，Large 才建立完整“玩家体验/剧情变化 → 真实缺口 → 候选”机会树，并在实施前确认范围。Micro 默认禁止新增组织、世界规则、力量体系、核心人物、大地图和 canon；Standard 的局部新增也必须必要。

每次候选必须有当前事实依据、具体行动、可观察反馈和明确变化，并通过删除、替换、差异、因果、成本、依据六项测试。没有足够依据证明需要新增内容时，合法结论是“不建议新增”。候选先做效用判断、假设检查和优先级筛选，最后才进行自然表达清理。

详细执行合同、上游谱系和示例见 [项目 Skill](../../.agents/skills/liluo-project/liluo-purpose-driven-ideation/SKILL.md) 与其 `references/examples.md`。
