# 叙事路线模拟与逻辑验证系统

本系统在不启动完整游戏、不修改真实存档的前提下，对事件路线做确定性审查。权威实现位于 `scripts/content-production/route-validation.mjs`；fixture 只放 `scripts/tests/fixtures/content-production/`。

## 模式

- `static`：检查入口、重复/缺失目标、不可达节点、无法抵达结局的环、正式入口。
- `simulate`：按条件和有序转移推进，记录状态与 trace，并以步数上限阻止无限运行。
- `save-resume`：从隔离 snapshot 恢复节点与状态，验证继续到结局。
- `browser`：真实入口、画面、控制台和本地存档复核；当前没有 Playwright/E2E harness，只能作为可选人工层。

命令：

```powershell
npm run narrative:routes:validate -- --input scripts/tests/fixtures/content-production/route-valid.json
npm run narrative:routes:simulate -- --input scripts/tests/fixtures/content-production/route-valid.json
npm run narrative:routes:resume -- --route <route.json> --snapshot <snapshot.json>
```

静态可达不等于运行时条件可达；调试入口也不等于正式入口。当前事件系统主要持久化地图会话 flag，尚无统一任务/关系状态，因此涉及长期任务进度的路线必须报告存档缺口，不能用 fixture 冒充运行时已支持。
