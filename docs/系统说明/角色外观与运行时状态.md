# 角色外观与运行时状态

角色外观与运行时状态负责主角在 UI、对话和地图中的显示一致性。

## 当前入口

- `src/game/core/playerRuntime.ts`
- `src/game/data/playerCharacter.ts`
- `src/game/data/globalAssets.ts`
- `src/game/data/dialoguePortraits.ts`
- `src/game/data/dialoguePortraitLayerRules.ts`
- `src/game/data/portraits/`
- `src/game/data/assets.ts`
- `src/game/data/animations.ts`
- `src/game/systems/animation/`
- `src/game/systems/character/`

## 当前职责

- 静态角色配置优先放在 `data/playerCharacter.ts`。
- 全局共享角色、通用图片等资源优先放在 `data/globalAssets.ts` 或 `data/assets.ts`。
- 全局动画定义或公共动画配置放在 `data/animations.ts`。
- 地图专属动画放在 `data/maps/<mapId>/animations.ts`。
- 运行时外观、立绘和状态优先通过 `playerRuntime` 收口。
- 旅途菜单人物栏也应通过 `resolvePlayerRuntimeCharacterDefinition()` 读取当前状态下的实际角色表现，不要在 UI 内单独复制状态到行走图的判断规则。
- 对话立绘与左侧展示立绘继续可以通过 `dialoguePortraits.ts` 读取；角色立绘素材、图层规则和预设优先沉淀到 `data/portraits/`。
- 需要多张素材组合时，可以使用 `layers` 分层立绘，不必强行合成单张整图。
- 默认主角 partial 拼装、立绘操作面板选项、后背匹配规则集中放在 `data/portraits/layerRules.ts`；`dialoguePortraitLayerRules.ts` 只保留旧引用兼容。
- UI 只消费整理后的 `layers`、`backLayers` 和图层选项，不直接解析素材文件名。

## 分层立绘

`DialoguePortraitData` 支持两种展示方式：

- `src`：单张立绘图片。
- `layers`：按数组顺序从底层到上层叠加的立绘图层。
- `backLayers`：可选的背面预览图层，按数组顺序从底层到上层叠加，并显示为主立绘右上角的小预览。

左侧人物面板和旅途菜单人物栏都应支持这两种方式。新增角色分层立绘时，应优先在 `data/portraits/<character>.ts` 中集中注册素材路径、图层顺序、默认预设和后背解析，再通过 `data/portraits/registry.ts` 暴露给 UI 或对话资源入口。

主舞台菜单按钮旁的“立绘”入口用于临时筛选当前主角正面 partial 图层。它只列出非后背图层，并把清洗后的关键词展示为复选项。玩家勾选图层后，左侧主立绘立即按选中图层叠加；未勾选的图层不显示。

当前默认主角立绘 `portrait_liluo_default` 会优先从 `src/assets/game/standee/partial/` 自动寻找正面 partial：

1. `素体-上身`
2. `素体-下身`
3. `通用-头部`

三类正面图层都要求文件名不属于后背版本，并且能解析出 `(x-x)` 层级。`x-x` 中前者是组图层，优先级最高；后者是组内图层，只在组层一致时比较。任意关键正面图层缺失时，默认立绘回退到 `src/assets/game/standee/LiLuo.png`。

后背版本的文件名规则是：去掉扩展名和末尾 `(x-x)` 层级标记后，基础文件名必须以 `-后背` 结尾。不要为了匹配逻辑修改后背素材文件名。

当默认正面 partial 完整，或玩家通过立绘操作面板改变当前正面图层时，系统会根据正面图层关键词继续查找对应的后背图层。关键词根据 `-` 拆分；用于后背匹配和面板展示时，结尾的 `+脖颈` 会被去掉，只保留前面的关键词。只有每个当前正面图层都能找到对应背面图层时，才会生成 `backLayers`。背面图层按自己的 `(x-x)` 层级排序，不沿用正面层级。

背面预览框按当前 partial 画布比例 `457 / 1024` 显示，主舞台左侧立绘栏和旅途菜单人物栏都应保持这一比例，避免预览框比图片大太多或遮挡主立绘。右上角小立绘可以点击与主立绘互换：主立绘显示正面时，小栏显示“后背”；主立绘显示后背时，小栏显示“前身”。小栏文字标注应放在预览框外侧下方，不占用小立绘画面空间。

当前“日式捆绑”立绘使用 `portrait_liluo_japanese_binding`，图层顺序为：

1. `src/assets/game/standee/partial/头.png`
2. `src/assets/game/standee/partial/腿.png`
3. `src/assets/game/standee/partial/裙子.png`
4. `src/assets/game/standee/partial/双臂缚.png`
5. `src/assets/game/standee/partial/胸部缚.png`

## 运行时状态

玩家运行时状态仍通过 `playerRuntime` 管理。地图动作、对话事件或其他系统需要改变主角状态时，应通过运行时入口追加或设置状态，不要只在 UI 组件里改显示。

当前“日式捆绑”会追加 `hands_bound`，表示双手被缚。后续若该状态影响移动、互动、道具使用或剧情分支，应继续围绕这个运行时状态扩展，而不是重新创建一套 UI 局部标记。

## 主角地图行走分层帧缓存

默认主角的地图行走母版模板是 `src/assets/game/sprite/liluo.png`。它只用于推导统一裁剪坐标，不直接作为运行时精灵表加载，也不再生成 `liluo/` 同名帧目录。

正式行走图由分层母版组成：`LiLuo_body_down.png` 作为下身底层，`LiLuo_body_up.png` 作为普通上身层，`bondage_body_up.png` 作为双手被缚上身层，`bondage_body_down.png` 作为双腿被缚下身覆盖层，`LiLuo_head.png` 作为头部顶层。每张母版都按 `liluo.png` 推导出的固定模板裁剪坐标，输出 4 行 × 5 列对应的 20 张独立帧。

`legs_bound` 状态会把行走表现切换为四个方向的站立帧，并由状态规则切换为 hop 蹦跳；即使其它图层也有 20 张子图，也不会继续播放普通行走循环。它不会吞掉其它身体图层：只有双腿被缚时使用 `LiLuo_body_up`，双手与双腿同时被缚时仍保留 `bondage_body_up`，最后再把 `bondage_body_down` 叠到腿部区域最上层。

双腿被缚的移动表现和移动速度要一起维护。当前 `legs_bound` 的 hop 参数为 `hopAmplitude: 18`、`hopSpeed: 0.02`，实际移动速度减速为 50%。状态减速仍然按加法叠加，例如无鞋、双手被缚、双腿被缚同时存在时，速度倍率为 `1 - 10% - 5% - 50% = 0.35`。

帧目录由 `scripts/assets/build-liluo-character-frames.ps1` 维护。源图更新、模板更新、缓存目录缺失或帧文件不完整时，`predev` / `prebuild:web` 会自动重建；缓存完整且未过期时直接复用。

新增同类 NPC 或新衣装图层时，优先复用这个脚本生成“与母版同名的帧目录”，再在角色数据中登记独立图片资源和对应动画序列。不要再生成合成 `walk` 图、固定 32×48 图或调试图。

## 设计原则

- 主角地图行走图、对话立绘、左侧展示状态应尽量来自同一条运行时链路。
- 事件可以驱动外观变化，但要保证当前地图里的精灵同步刷新。
- 特殊外观可以有特殊移动表现，但要做好恢复和清理，避免残留错位。
- UI 不应自己散落拼业务状态，应优先通过 selector 或桥接层读取整理后的结果。
- UI 中需要展示行走图预览时，应复用当前运行时角色定义；如果要表现 `hop` 等移动方式，可以只补展示动画，不应重新定义状态含义。
