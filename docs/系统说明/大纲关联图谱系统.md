# 大纲关联图谱系统

关联图谱是「大纲」模块内的统一可视化投影层，用于浏览与校准璃落宇宙中故事、情节、玩法、人物、组织、地点、物品与 RAG 之间的**多对多**联系。

它不是第二套主数据，也不会因为打开图谱、拖动节点或自动推断而改写正史。

## 入口

游戏内旅途菜单 → 侧栏「大纲」→ 顶部分栏 **关联图谱** 或 **RAG 网络**。

既有「故事｜情节｜玩法｜人物/组织」分栏保持不变；RAG 网络与关联图谱同级，前者专供知识漫游，后者专供全宇宙结构浏览。

## 五种模式

| 模式 | 用途 | 节点显示 |
|---|---|---|
| 全图 | 宏观宇宙关系网，强调整体感与规模 | **只显示名称**（可带极少量状态角标） |
| 聚焦 | 选中节点 + 一层/两层邻域，用于校准 | 名称 + 短摘要 + 类别 |
| 层级树 | 只在 RAG 网络中按卡片上下位关系展开，可浏览任意层深 | 名称 + 层级连线 |
| 筛选 | 按类别、关系、校准状态或快捷组合过滤 | 名称 + 受控摘要 |
| 汇总 | 统计卡与质量缺口 | 列表/统计为主 |

硬性规则：全图模式不得渲染摘要文本。

## 节点类别

故事（世界为一级、条目为二级）、情节、玩法、人物、组织、地点、物品与 RAG。普通 Tag、紧缚 Tag 与独立 Style-RAG 节点类型已经停用。

**不再投影「细节概念」独立节点/泳道。** 分层浏览只看紧缚 RAG。
**世界与系列不单开泳道**：系列根并入世界卡，世界再与故事同列成树（按世界名前缀数字 1…6 排序）。

### 故事双层结构

```text
世界（storyLayer: category，按编号排序）
└── 故事条目（storyLayer: concept）
```

### 情节双层结构

```text
大情节 groups（plotLayer: category）
└── 小情节 entries（plotLayer: concept）
```

- 权威源：`plot_outline/catalog.json` 的 `groups` → `entries.groupId`。
- 泳道树状布局与故事 / 玩法 / RAG 相同：大情节加粗 `▸`，小情节缩进 `└`。
- 筛选预设：「只看大情节 / 小情节」。

### 玩法双层结构

```text
大玩法 categories（gameplayLayer: category）
└── 小玩法 entries（gameplayLayer: concept）
```

- 权威源：`gameplay_outline/catalog.json` 的 `categories` → `entries.categoryId`。
- 泳道树状布局同上；筛选预设：「只看大玩法 / 小玩法」。

### 已退役 Tag 层

`tag`、`bondage_tag`、`tagged_with` 与 `bondage_tagged_with` 不再生成。旧 `plotTags`、`bondageTags`、`specialGameplay` 只允许出现在迁移追溯记录中，不能重新成为主数据或图谱泳道。

故事通过 `plotRefs`、`ragRefs`、`gameplayRefs` 连接实际承载内容；情节通过 `plotKind` 区分 `ordinary`、`restraint`、`mixed`，并以 `ragRefs` 连接知识卡。

### 紧缚 RAG 双层结构

```text
上位类别 RAG（ragLayer: category）
└── 具体概念 RAG（ragLayer: concept）
```

- 图谱边 `narrower` / `broader` 连在 **RAG ↔ RAG** 之间。
- **画布上只保留概念原名词一个主节点**；知识 / 表达 / 原文证据只在右侧详情页签区分，不再投影「知识｜…」「表达｜…」子节点（避免重复实现）。
- 权威分层字段为知识卡的 `ragLayer` 与 `parentCardIds`；双分支字段见 [紧缚专业RAG双分支系统](./紧缚专业RAG双分支系统.md)。
- 故事与情节通过稳定 `ragRefs` **直接**连到对应 RAG（`references`），不再经过 Tag 或概念中间层，也不分别连知识/表达节点。
- `conceptRegistry.js` 仅作分层种子与抽查 ID 后台，不进入图谱主视觉。
- 筛选预设：「只看紧缚专业 RAG 上位/具体」「只看紧缚专业 RAG 与大纲/情节」。

### RAG 原文证据与路径视图（schemaVersion ≥ 4）

- 「RAG 网络」是与关联图谱同级的独立分栏：以无泳道的自由画布显示 RAG 卡、原文证据片段与来源文章，以及它们之间的关系。
- 范围筛选可切换为「仅 RAG 条目」「含证据与来源」或「纳入关联节点」；最后一种会加入与 RAG 直接相连的故事、情节、玩法等节点，用于从知识漫游到项目内容。
- 工具栏模式依次为「全图｜聚焦｜层级树｜筛选｜汇总」；其中「层级树」专用于理清 RAG 卡片，按 `parentCardIds` 递归展开，不限二级。多父卡只保留一张实体卡，稳定挂在排序最靠前的有效父卡下；其他父卡关系仍以跨枝连线保留，避免把同一知识复制成多个节点。
- 普通全图默认不投影证据与来源节点；筛选中的「RAG 证据路径（条目→片段→来源）」仍可只看单纯的证据链，避免画布拥挤。
- 选中紧缚 RAG 后，右侧「原文证据」页签：
  - **原文证据**：可展开条目，展开后显示对应段落（摘录 + 前后文预览）；
  - **原始来源**：只列出小说名（来自 catalog title）。
- 抽查/核验命令属于 AI 工作流入口，**不在图谱界面展示**；人用图谱只看关联与详情。
- 共享证据库仍在 `external-knowledge/evidence/`；Claim 核验写入 `reviews.json`。
- 公开导出（`publicSafe`）省略 `publicExport: false` 的证据正文，但可保留小说名与定位元数据。

所有 RAG 卡以 `ragDomain` 区分紧缚专业、通用创作与正史，且都固定拥有知识/表达分支；候选关系默认待确认，不得与已确认关系混同。详见 [RAG增量提议与来源关联图谱系统](./RAG增量提议与来源关联图谱系统.md)。

### 紧缚 RAG 内容

仍是抽象知识卡（术语 / 情节模式 / 表达 / 画面结构等）。图谱装载 `external-knowledge/cards/`，并对尚未落盘的 `card-rules.json` 规则做候选投影。知识卡用 `linkedConceptIds` 挂分层种子；`concepts[]` 只放可读名称/别名。

原始语料中能找到直接说明时，应补入自然、可核验的摘要、`claims` 与精确 `evidenceRefs`/`sourceRefs`；只出现同名词、比喻或无关语境时不得据此补写。没有可靠说明的卡继续保持 `stub` / `missing`，不以常识伪装成已有来源。

### 内容缺口提示

下列节点在全图中使用橙色框，并计入 `contentGapCount`：

- 内容为空或紧缚 RAG 仍为骨架卡；
- 缺少来源；
- 故事仍有 `missingItems`；
- 情节尚未被任何故事引用；
- 节点没有有效关系。

选中与邻接高亮仍优先改变描边，节点底色继续保留缺口语义。

## 关系语义与颜色

每条边含：`relationType`、起终点、来源、置信度、审核状态、是否自动生成。

常见颜色（与紫色主题协调，深色底可读）：

| 关系族 | 颜色倾向 |
|---|---|
| 层级 / 包含 / parent | 浅紫白 |
| 紧缚 RAG 上位/具体 (broader / narrower) | 金绿 |
| 人物 / 组织 / 地点 / 物品 | 蓝 |
| 紧缚 RAG | 绿 |
| 时间 / 前后 | 橙 |
| 待校准 / 冲突 | 红 |

图例支持：单击只看某类关系、再次恢复、全部显示、隐藏全部关系、隐藏节点类别。

## 交互

- 幕布：`GameScrollArea` 显示横向/纵向滚动条；鼠标拖拽平移；滚轮滚动；Ctrl/⌘ + 滚轮缩放。
- 图例：左侧栏，可隐藏；图例与详情正文均使用项目 `GameScrollArea` 自制滚动条。
- 节点位置只读：不支持拖拽节点或修改布局。
- 树状泳道（故事 / 情节 / 玩法 / 紧缚 RAG）一级↔二级只画折线 stubs，不再叠画贝塞尔关系线；RAG 网络的全图使用自由画布，层级树则只为 RAG 卡画递归层级连线，其他关联仍用曲线。
- 点击节点：右侧详情面板（不跳转其他页面、不自动切到聚焦模式）；同时高亮该节点相连关系线，并压暗其余连线。
- 详情标题旁「聚焦模式」：显式切换为当前节点邻域聚焦；「取消聚焦」回到全图并保留详情。
- 详情内关联节点：画布定位 + 高亮关系 + 详情切换；支持上一节点 / 下一节点 / 返回初始。
- 搜索：名称、别名、稳定 ID、情节、RAG、人物与地点。
- 布局种子缓存于转换层；视口滚动与缩放可写入 `localStorage`。
- 导出 JSON：工具栏「导出JSON」下载当前投影（节点、关系、统计与元信息）；文件名 `liluo-outline-relation-graph.json`。导出物是投影快照，不替代正史权威源。

## 数据层

权威源仍是现有 JSON / 注册表：

- 故事：`src/game/data/story_outline/sources/`
- 情节：`plot_outline/catalog.json`
- 玩法：`gameplay_outline/catalog.json`
- 人物/组织派生：`storyCharacterOutline.js`
- 紧缚 RAG：`external-knowledge/cards/`（可补充 `card-rules.json` 候选）
- 共享证据层：`external-knowledge/evidence/`（excerpts / reviews）
- 来源目录：`external-knowledge/catalog/sources.json`
- 抽查状态：`docs/知识检索校准/registry.json`
- 概念种子：`src/game/data/outline_relation_graph/conceptRegistry.js`（仅分层种子，不投影为图谱节点）

转换入口：`buildOutlineRelationGraph()`。运行时由 `loadOutlineRelationGraph.js` 记忆化装载；CLI 可随时重建投影统计。导出 JSON 为 `exportVersion: 2`，默认 `publicSafe` 不泄漏私有原文。

## 校准闭环

1. 在图谱中发现孤立、缺来源、低置信度、有概念无 RAG 等缺口
2. 打开详情查看来源与关联
3. 使用既有 `rag:audit:*` 记录问题
4. 按既有流程升级 Skill / 重建受影响索引
5. 图谱「重建」刷新投影后再抽查
