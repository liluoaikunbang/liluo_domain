# 项目知识索引系统

## 系统目标

索引用于减少 Codex 重复扫描长 JSON、Markdown、代码与素材目录的 token 消耗，支持跨世界、跨系统定位、正反向关系导航和新会话恢复。它不生成正典、不替代源码、内容校验、连续性审查或测试。

当前项目同时维护多世界故事大纲、玩法总表、地图事件、Vue/Phaser/Pinia 代码、系统文档和大量素材，尤其适合使用分层索引。节省主要发生在“寻找正确原始文件”阶段：Codex 先按领域执行紧凑查询，再只打开命中的少量权威来源，避免为了一个节点或引用反复读取完整世界 JSON、长 Markdown 或整个素材目录。

索引不是每个任务的强制前置步骤。已经明确单一文件的小改动可直接读取该文件；跨文件、跨世界、跨系统或未知入口任务才优先查询索引。根 `AGENTS.md` 已规定这一默认路由，后续 Codex 会在没有更高优先级冲突指令时自动遵循，无需用户逐次提醒。

## 目录结构与分层

- `project-index/`：已生成索引。`INDEX.md` 是 L0；各领域 `SUMMARY.md` 是 L1；JSON 实体、树和关系分片是 L2。
- 原始 JSON、Markdown、代码、注册表、素材与系统文档是 L3 权威来源，不复制进索引。
- `scripts/project-index/`：确定性构建、检查、查询、验证工具。
- `project-index.config.json`：唯一配置，定义版本、输出、分片与排除项。

## 已启用领域

- `story`：6 个世界的节点、树、缺失项和解析问题。
- `gameplay`：玩法分类与条目，按大类分片。
- `game`：地图、事件、对话、互动小说和注册入口。
- `code`：`src/game` 模块、Vue、Scene、system、store 与轻量 import。
- `assets`：运行时/候选路径、类型、大小和哈希，不含图片内容。
- `docs`：系统、Skill、Agent、更新记录等 Markdown。
- `graph`：故事父子关系及玩法/地图到故事的反向引用。

`lore` 当前为 `not-enabled`：仓库缺少独立稳定的权威实体资料库，第一版不从故事正文猜测完整角色、组织或地点实体。

## 字段规范

`id`/`key` 是稳定标识；`sourcePath` 是 `/` 分隔的仓库相对路径；`sourceHash`/`sourceHashes` 是 SHA-256；`summary` 配合 `summarySource` 说明摘要依据；`references` 与 `relationType` 表示已确认关系；`indexVersion` 标记记录格式。不存在的字段不编造。

## 新鲜度与增量更新

`status.json` 保存源路径到内容哈希的快照，识别新增、修改、删除和同哈希重命名。状态为 `current`、`partial`、`stale`、`error` 或 `not-enabled`。第一版增量是领域级：变化源触发对应领域与依赖图重建；schema、生成器、批量移动或关系格式变化使用全量构建。生成先写入临时目录，成功后逐文件替换；失败保留旧索引。

## 查询方法

```powershell
npm run project:index:check
npm run project:index:query -- --domain story --query "笨璃璃小镇" --limit 5
npm run project:index:query -- --domain gameplay --key gameplay-118 --fields id,title,sourcePath --format json
npm run project:index:query -- --domain graph --reverse-reference gameplay-118
npm run project:index:changed
npm run project:index:validate
```

默认结果数和字符数受限；用 `--fields` 进一步压缩。查询后只打开命中的必要原文件。

## Codex、Skills 与 Agents

复杂任务先读 `project-index/INDEX.md`，选择最小领域，重要事实与正式修改前核验原文。索引 stale 时只能辅助定位候选；先更新相关领域，无法更新则直接读原文并报告。`liluo-project-index-maintenance` 负责维护流程；项目 Agent 可用索引调查但保持只读；主 Codex 决策和写入；确定性脚本生成与验证。索引不替代世界观审查或代码测试。

## Git 管理

核心文本索引、配置、脚本和关系分片进入版本控制。临时目录、查询输出、缓存、二进制与运行日志不提交。本版全部生成索引约 1 MB 量级，不使用 Git LFS。

## 故障恢复

缺失、损坏、manifest 不一致、哈希不符或构建中断时，先保留权威源文件，运行 `npm run project:index:build`，再运行 validate 与 check。解析失败必须显示在状态、清单或验证问题文件，不能静默跳过正式源。
