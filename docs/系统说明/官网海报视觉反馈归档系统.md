# 官网海报视觉反馈归档系统

本文定义官网海报视觉体系如何记录、抽象并回写用户反馈，使角色风格、世界风格和批量 prompt 可以长期一致迭代。

## 适用范围

- 角色身份与外观反馈
- 六界 `palette`、`materials`、`atmosphere` 等世界风格反馈
- 镜头、材质、构图、页面节奏等跨页面视觉反馈
- Image 2 海报批次的长期提示词约束

## 基本流程

1. 用户原始反馈先进入 `visualFeedbackLedger`，保留当次语境。
2. 账本把反馈拆成 `appliesTo`、`abstractedTraits`、`promptEffects` 和 `writebackTargets`。
3. 已确认的抽象结果回写到角色或世界权威字段，再进入后续批量生成。

## 归档绝对化规则

- 用户原话可以出现“更弱气”“更浅一些”“少一点”“再日常一点”这类相对描述。
- 进入长期账本的抽象层后，必须改写成绝对、可复用、可直接执行的目标描述。
- `abstractedTraits`、`promptEffects`、角色权威字段和世界权威字段中，不得保留缺少参照物的相对词。
- 如果确实需要保留比较关系，必须同时写明基线对象；没有基线的比较句只能停留在一次性评注，不能替代正式归档字段。

## 权威字段

### 角色层

- `liluoProfile.summary`
- `liluoProfile.fixedTraits`
- `liluoProfile.hairColorProfile`
- `liluoProfile.variableTraits`
- `liluoProfile.stylePreferences`
- `liluoProfile.publicSafety`
- `characterShowcaseCompositionRules`

### 世界层

- `worlds[].palette`
- `worlds[].materials`
- `worlds[].atmosphere`
- `worlds[].liluoLooks`

### 反馈层

- `visualFeedbackArchiveRules`
- `visualFeedbackLedger[].appliesTo`
- `visualFeedbackLedger[].abstractedTraits`
- `visualFeedbackLedger[].promptEffects`
- `visualFeedbackLedger[].writebackTargets`

## 维护原则

- 原始反馈记录真实说法，抽象结果负责消除歧义。
- 角色反馈与世界反馈都必须写明归属对象，避免“全站默认”误伤不相关系列。
- 一次性口味不自动升级为长期规范；只有明确确认后才回写权威字段。
- prompt 模板继承的是抽象后的绝对规则，不直接继承聊天里的相对措辞。

## 人物展示与发色参数

- 专门展示人物时，默认优先完整全身展示，让发型、服装、袜子与鞋履同时可读。
- 只有当一张图的主要任务是解释背景、空间关系或页面信息层时，才允许使用中近景或半身构图。
- 璃落的发色可以使用参数化锚点：日常光线下以稳定的基础色、阴影色、高光色和反光色为准，再根据光线明暗做同色系微调。
- 光线调整只改变明暗与色温，不改变发色归属；不得把璃落画成橙金、棕灰或紫黑头发。
