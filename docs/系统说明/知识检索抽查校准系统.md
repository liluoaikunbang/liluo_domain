# 知识检索抽查校准系统

## 定位

在**不推倒**现有紧缚 RAG（`liluo-external-fiction-knowledge`）、Style-RAG（`liluo-style-rag`）、细节概念种子与情节目录的前提下，提供人工抽查 → 问题归档 → Skill 抽象升级 → 受影响重建/校验的渐进闭环。

## 原则

1. 现有索引与目录先正常使用，不因紧缚领域理解风险而停用。
2. 初期只做人工抽查，不要求全量重做。
3. 单次错误不得膨胀 Skill。
4. 重建必须 dry-run、限定范围、保留快照、不改外部原文、不自动人工批准。
5. 不引入 embedding、向量库、领域本体或专用训练。
6. 细节概念与情节**不并入** RAG 库；只共用抽查归档与升级门禁。
7. **关联共改**：修正任一抽查对象时，必须检查其关联项（概念 ↔ RAG ↔ 情节 / Style 邻居等）；有需要补充或调整的，与主条目**一并处理**，禁止只改单点留下命名、摘要或挂接矛盾。可用 `*:audit:related --asset <id>` 列出邻居。
8. **紧缚 RAG 默认卡审**：抽样默认只出知识卡；人工判描述、存在价值与分层。不把读外部小说原文当作用户主审步骤；对照原文由执行侧按需核验。
9. **定性评价先协商**：用户说「太抽象」等时，不得立刻原样 `record`；须先协商修改方向与改稿计划，确认改好或明确「暂时这样」后再写卡/归档。源条目抽样仅作 opt-in（`--include-sources` / `--asset-kind source|all`）。
10. **RAG / Style-RAG 文案走自然表达**：编写或改写知识卡正文、Style 抽象说明、评权旁白、卡审协商与向用户解释抽查结论前，先应用 `liluo-natural-expression` light；说清「这张卡干什么、和邻居差在哪」，避免口号空话。字段名、ID、命令、路径不润色。

## 抽查通道

| 通道 | 候选来源 | 记录目录 | 重建/校验 |
|---|---|---|---|
| `rag` | 默认知识卡；源条目须 `--include-sources` / `--asset-kind source\|all` | `records/rag/` | `external:knowledge:update` + validate |
| `style-rag` | 文章 registry | `records/style-rag/` | inventory + style validate |
| `concept` | `conceptRegistry.js` 分层种子（后台） | `records/concept/` | 人工改种子 + `outline:graph:validate` |
| `plot` | `plot_outline/catalog.json` | `records/plot/` | 人工改目录 + `outline:graph:validate` |
| `all` | 四通道混合抽样 | 批次可含多通道 | 按各条记录的 channel 分流 |

说明：关联图谱**不投影**细节概念节点；分层与浏览以紧缚 RAG 为准，故事与情节通过显式引用直连 RAG。`concept` 抽查通道仍可校准分层种子命名与挂接。

## 问题类别

见 `project-navigation/rag-audit-categories.json`：

- 紧缚 RAG：事实错误、来源错误、分块不合理、召回遗漏、内容混淆、错误摘要；卡审时注意与邻居**分层/合并**，以及 `linkedConceptIds` 是否指向正确上位类别或具体概念
- Style-RAG：文风标签错误、紧缚/非紧缚分类错误、权重不合理、作者错误、范例不适用、剧情污染、紧缚概括失真
- 细节概念：命名不一致、别名冲突、父概念错误（须为上位类别）、缺 RAG 挂接、孤立概念、可见性不当、错误摘要；概念仅两层（上位类别 → 具体概念）
- 情节：`plotKind` 错误、RAG 引用不匹配、错误摘要、人物关联错误、安置不明、缺 Style 提示、重复、未使用孤立
- 共通：擅自补全、无证据、错误推断、重复条目、过时索引等

## Skill 升级阈值

满足任一才建议升级（仍须用户批准与抽象规则）：

- 用户明确「以后都这样 / 写入规范」
- 同类问题 ≥3 条独立来源抽查
- 严重类别（正史污染、来源/版权/连续性/索引结构）
- 已有错误例、正确例与可验证规则

优先抽象规则示例：

- 原文未说明则 `unknown`，不得按常见情况补全
- 紧缚文件夹只说明题材，不代表质量
- 紧缚 RAG 管事实，Style-RAG 管表达，细节概念管命名枢纽，情节管可复用桥段目录
- Style-RAG 不得继承范例人物/道具/剧情
- 文章评分优先于作者先验
- 低置信度字段进入待复核

## 重建边界

- 默认禁止 `--full` 全库
- 仅处理 `needsIndexRebuild=true` 的抽查记录范围
- RAG：`external:knowledge:update`（增量）+ validate
- Style-RAG：`writing:external:inventory` + validate
- concept / plot：人工修正权威文件后跑 `outline:graph:validate`；不自动改写正史
- 日志与前后快照：`docs/知识检索校准/rebuild-logs/`

## 与大纲关联图谱

游戏内「大纲 → 关联图谱」可作为抽查发现入口：筛选孤立节点、待抽查、缺来源、有概念无 RAG、有情节无 Style-RAG 等。图谱不替代本系统的 record/rebuild 流程，也不直接修改正史。详见 [大纲关联图谱系统](./大纲关联图谱系统.md)。
