# 开放权重双模型写作管线

## 定位

璃落正式小说段落的生产基础管线：正史核验 → 写作合同 → 显式选择 DSR1-14B / Qwen3-32B / 双模型对照 → OpenAI-compatible 调用 → 工作区候选 → `liluo-natural-expression` → 用户批准 → 黄金/对照归档 → 现有故事 Skill 写入正式内容。

固定模型：

- `Zhihu-ai/Zhi-Create-DSR1-14B`
- `Zhihu-ai/Zhi-Create-Qwen3-32B`

当前不宣布永久主模型。StyleRAG / embedding / 向量库全部暂缓。

## 命令

```bash
npm run writing:models:validate
npm run writing:models:status
npm run writing:models:health -- --live --model both
npm run writing:prose:draft -- --model dsr1 --contract docs/写作资产/工作区/requests/example.json
npm run writing:prose:compare -- --contract docs/写作资产/工作区/requests/example.json
npm run writing:assets:validate
npm run writing:gaps:remind -- --topic formal-prose-generation
```

未加 `--live` 时一律 mock，不访问网络。Routine / CI / 静态 eval 禁止 live。  
Live 前须由用户确认 Hugging Face endpoint 为 Running；控制台显示 Running 后默认再等约 5 分钟，再对本次要用的模型（默认双模型 `--model both`）跑 live health。细则见 [写作模型API配置与用户操作指南](./写作模型API配置与用户操作指南.md)「Live 验证前预检」。

## 安全边界

- API Key 只来自进程环境或 `.env.writing.local`，不进 Git / 日志 / manifest。
- 远程 URL 必须 HTTPS；localhost HTTP 可例外。
- 候选正文不得直接写入 canon。
- 推理内容（`reasoning_content` / `<think>`）不进入正文与默认归档。

## 缺口提醒

开放缺口登记在 `project-navigation/manual-gaps.json`，由导航扫描合并。用户询问写作模型、黄金正文、个人旧作、StyleRAG 或启用未配置能力时，主智能体应 `writing:gaps:remind` 并只提示相关开放项。
