# 机器可读工作流与可视化执行规范系统

成熟、易漏步骤、多 Skill/子智能体的复杂任务，以 `project-workflows/definitions/*.json` 为唯一事实来源；Markdown 过程规范、Mermaid 图、导航投影和运行报告均由此生成，不得反向覆盖定义。

## 分层

| 层 | 路径 | 职责 |
| --- | --- | --- |
| 定义 | `project-workflows/definitions/` | 节点、边、必需资源、完成门禁、不可变约束 |
| 注册表 | `project-workflows/registry.json` | active 版本索引（由校验生成） |
| 生成物 | `project-workflows/generated/<wf-id>/` | `PROCESS.md`、流程图、导航投影 |
| 运行记录 | `project-workflows/runs/` | 单次执行状态与调用证据（默认不提交临时日志） |
| Schema | `schemas/workflows/` | 定义与运行记录结构合同 |
| 运行时 | `scripts/project-workflows/` | 校验、调度、任务书、门禁、报告 |
| Skill | `liluo-executable-workflow` | Agent 执行入口与简化路径 |

轻量用户向工作流摘要仍由 `project-navigation/workflows.json` 承载；可执行定义通过投影合并进去，不另造平行能力注册表。

## 执行模型

```text
选择工作流 → 创建运行记录 → 只生成当前节点任务书
→ 调用声明资源并记录证据 → 验证采用决定
→ 完成节点 / 阻塞 → 更新可视化状态 → 流程门禁 → 报告
```

必需资源默认 fail-closed：缺调用、缺结果摘要、主流程未读、无采用决定、或主 Agent 替代 `selfExecutionAllowed=false` 的资源时，节点不得完成。

## 简化路径

- 一次性小修、开放讨论、未稳定探索：不用本系统，走专项 Skill。
- 只需发现入口：`npm run project:workflow:list`。
- 正式重复任务：dry-run 演练 → 按节点任务书推进 → `finish`。

## 常用命令

```bash
npm run project:workflow:validate
npm run project:workflow:list
npm run project:workflow:create-run -- --workflow wf-story-mainline-restructure --mode dry-run
npm run project:workflow:brief -- --run <runId> --node <nodeId>
npm run project:workflow:record-invocation -- --run <runId> --node <nodeId> --kind agent --ref agent-liluo-content-auditor --main-read --adoption accepted --downstream-use "..."
npm run project:workflow:complete-node -- --run <runId> --node <nodeId>
npm run project:workflow:finish -- --run <runId>
npm run project:routine -- workflow
```

## 可视化

**默认（任务介绍）**：每个可执行工作流的过程规范  
`project-workflows/generated/<wf-id>/PROCESS.md`  
在文首嵌入 Mermaid **流程概览**，文末嵌入详图。这是给人看的主入口；Cursor / GitHub 预览即可。

**附带文件**：同目录 `flow-simple.mmd` / `flow-detail.mmd`（生成副本，勿手改后反向覆盖 JSON）。

**交互大图（少用）**：`project-workflows/viewer/index.html`  
仅当用户明确说「动态大图 / 交互图 / 打开大图」时再刷新并打开；日常介绍与改任务说明不依赖它。

## 校验与重生成（勿频繁写图）

| 命令 | 何时 | 是否写生成物 |
| --- | --- | --- |
| `project:workflow:validate` | 日常 / Skill·Agent 变更门禁 | **否**；检查定义、引用，并检测 PROCESS/图是否过期 |
| `project:workflow:generate` | **重大修改**定义后（节点、边、必需资源、门禁、输入输出） | **是**；重写该流程 PROCESS 与静态图，并刷新 viewer 数据 |
| `project:workflow:generate:all` | 批量重大迁移后 | **是**；全部流程 |

Skill 正文小改、错别字、说明润色：**不要** generate。生成物过期时 validate 会失败并提示 generate，而不是每次静默重写。

## 与现有系统

- Skills / Agents：资源 ID 与导航一致（`skill-*` / `agent-*`），校验时核对真实文件；ID 变更会使工作流校验失败直至定义同步。
- 能力导航：扫描时合并可执行工作流投影。
- 质量门禁：定义/脚本，以及 `.agents/skills/**`、`.codex/agents/**` 变更，都会触发 workflow 校验与图刷新；不把临时 run 日志默认入库。
- 子智能体：审查类节点标记 `selfExecutionAllowed=false`；平台无法自动委派时阻塞并等待回填。
