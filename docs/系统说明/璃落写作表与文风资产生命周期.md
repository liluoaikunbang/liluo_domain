# 璃落写作表与文风资产生命周期

## 资产分层

| 层级 | 路径 | 生产 pack | 说明 |
| --- | --- | --- | --- |
| 工作区候选 | `docs/写作资产/工作区/` | 否 | draft/compare 临时产物 |
| 个人旧作 | `docs/写作资产/个人历史作品/` | 条件允许 | 用户所有权确认；不自动当黄金 |
| 修改对照 | `docs/写作资产/修改对照/` | 是（校准对） | before/after 表达修复 |
| 黄金正文 | `docs/写作资产/璃落黄金正文/已批准/` | 是 | 项目文风最高 tier |
| 外部风格研究 | `docs/写作资产/外部风格研究/` | 已评且达标 | 清单 + 评权 + 抽象卡 |
| 璃落写作表 | `docs/写作资产/璃落写作表/` | 批准后是 | 表达宪法 |

统一索引：`docs/写作资产/registry.json`。

## 璃落写作表

### 路径

- 当前：`docs/写作资产/璃落写作表/current.json`
- 草稿：`drafts/draft-latest.json`
- 版本：`versions/<timestamp>.json`

### 生命周期

```
awaiting-assets → draft → approved (需 --user-approved)
```

- 无证据或仅未批准外部文章 → 保持 `awaiting-assets`
- 外部文章**不能单独**定义璃落文风；需黄金/校准等锚定证据
- 批准后写入 `current.json`，并可在文风包 `writingSheet` 节渲染

### 命令

```bash
npm run writing:style:sheet:draft
npm run writing:style:sheet:approve -- --user-approved
```

## 文风包组装顺序（证据优先级）

策略 `sourcePrior` 近似顺序：

1. golden-approved (1.0)
2. calibration-pair (0.9)
3. personal-history (0.6)
4. external-article (0.5)
5. external-style-card (0.45)

单 pack 上限见 `style-rag-policy.json` → `packLimits`。

## 晋升规则

| 动作 | 需要 |
| --- | --- |
| 个人旧作 → 登记 | 用户所有权确认 |
| 候选 → 黄金正文 | 用户批准 + `writing:golden:sync` |
| 修改 → 校准对归档 | 用户批准 + 成对保留 |
| 外部 → 抽象风格卡 | 用户批准 + 版权表示审查 |
| 外部 → 写作表证据 | 已评 + 批准 sheet |
| 任何 → 正史 canon | 故事 Skill + 用户批准（非 StyleRAG） |

无自动晋升。Style feedback 只影响后续检索权重，不改 tier。

## 校准与 Skill 升级

≥3 条同类别独立批准校准对可**建议**写作表或规范更新；仍须用户批准 sheet / 治理流程，单次修改不自动改 Skill。

## 空资产行为

无已批准匹配资产时，文风包 `awaiting-assets`——允许继续用 V0 显式 ID 或无可参考写作。
