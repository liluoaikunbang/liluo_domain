# 叙事生产包设计

## 目标

叙事生产包是连接正式故事与具体输出形态的中间合同。它的工作，不是另存一份剧情，而是把一个已经批准的故事节点整理成可持续复用的制作包。

## 生产包至少要回答什么

- 这段叙事服务哪个正式故事锚点。
- 哪些事实不可改写。
- 这次要优先验证什么体验价值。
- 当前适合哪些输出形态。
- 每种输出形态的最小必须项是什么。
- 素材应该先准备哪些槽位，哪些可以后补。
- 完成后会沉淀哪些状态、标记或后续入口。

## 推荐结构

一个最小可用的叙事生产包至少包含：

- `storyAnchor`：故事锚点、世界、系列与当前节点。
- `canon`：正式来源与不可改写事实。
- `narrativeIntent`：核心情绪、关系推进、玩家感受和成功判定。
- `experienceForms`：当前适配的输出形态及其优先级。
- `assetSlots`：立绘、CG、音频、地图资源和 UI 表达槽位。
- `productionSlices`：按阶段拆分的最小交付切片。
- `validation`：这次生产结束时要留下哪些证据。

## 它不负责什么

- 不代替故事大纲本身。
- 不自动创造正史事实。
- 不把地图实现细节、对话全文或素材文件全部内嵌进去。
- 不绕过用户审批直接进入正式写入。

## 与现有系统的关系

- 它以上游故事节点为事实来源。
- 它为故事转可玩、互动小说、副本、CG 和玩法合同提供共同语言。
- 它可以是模板合同、规划中间层或后续自动化的输入，但不能成为新的权威剧情库。
