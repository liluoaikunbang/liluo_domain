# 运行时素材瘦身与外置治理系统

这套系统处理的是 `src/assets/game` 的长期膨胀问题，但它不是公开图床方案的延伸。

这里的默认前提已经固定为：

- 游戏离线版优先
- 运行时素材优先保证本地可运行
- 敏感资源不进入公开 R2
- 需要外置的私有资源优先依赖 Nutstore 本地同步

双轨总规则见 [公开展示资产与离线私有素材双轨分发系统](./公开展示资产与离线私有素材双轨分发系统.md)。

## 私有同步入口

下面这个命令会检查私有线是否已经准备好：

```powershell
npm run assets:runtime:private:status
```

它会读取：

- `.env.runtime-assets.local`
- `docs/assets/registry/runtime-private-asset-manifest.json`

只读报告：

- 哪些目录属于私有线
- 它们当前在仓库里占多大
- 本机 Nutstore 根目录是否已配置
- 对应目标目录是否已同步到本机

真正建立私有镜像时，走下面这条命令：

```powershell
npm run assets:runtime:private:sync -- --group authoring-cg-standee-sources --group authoring-scene-sources --group pixel-map-sources --group map-and-layout-sources --group candidate-reference-boards --live
```

完成复制后，不应直接手动删 repo 目录；先跑第二阶段审计：

```powershell
npm run assets:runtime:private:audit -- --write-report
```

它会额外生成：

- `docs/assets/registry/runtime-private-removal-audit.json`

并明确哪些组只是“清理引用后可移除”，哪些组还被运行时阻塞。

它当前遵循的合同是：

- 默认可先不带 `--live` 做 dry-run。
- live 只复制/覆盖，不删除仓库原件。
- `cg-finals` 与 `standee-sources` 共用私有父目录 `game/visual/cg/`，方便后续在成品和制作源之间切换。

## 结论

这条线的目标不是把 `src/assets/game` 全部搬去公网，而是：

1. 保住本地运行和离线包。
2. 先把制作源、参考源和原始地图源从主仓库剥离。
3. 再按私有同步线治理大型运行时 CG。
4. 每次准备删主仓库副本前，先跑 `assets:runtime:private:audit`，不要靠肉眼猜。
