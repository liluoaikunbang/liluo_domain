# 项目上下文装载与配置分层系统

## 目标

项目配置、规则、索引、历史与外部知识可以继续变多；模型默认装载范围必须分层。本系统只定义“读什么、何时读、预算如何裁剪”，不压缩项目能力，也不引入第三方正文写作模型。

机器可读唯一策略：`project-navigation/context-policy.json`。Schema：`schemas/workflows/context-policy.schema.json`。创作组参与档位另见 `project-navigation/team-routing.json`。

## 五层模型

| 层级 | 名称 | 默认行为 |
| --- | --- | --- |
| L0 | 会话入口与最高权威 | 每次任务加载 `AGENTS.md` 与上下文策略 |
| L1 | 路径局部规则 | 当前编辑路径命中时加载薄适配或导航 |
| L2 | 任务能力与专业合同 | Skill、选中 Agent、系统说明、Schema、工作流按需加载 |
| L3 | 查询型证据 | 索引、能力表、外部知识仅查询后读少量结果 |
| L4 | 历史、派生与打包材料 | 默认不加载；只在追溯或验证时读取 |

## 权威优先级

固定顺序：当前用户指令 → `AGENTS.md` → 当前路径权威 → 任务 Skill → 系统说明 → 设计记忆 → 生成索引 → 外部参考 → 历史。

超出预算时先裁剪 L3/L4，再裁剪无关 L2；不得裁剪当前用户要求、`AGENTS.md` 或当前路径权威源。

## Cursor / Codex 适配边界

- 共同事实只写普通权威文件。
- Cursor 只能有一个 Always 规则（`.cursor/rules/00-project-entry.mdc`），只指向 `AGENTS.md` 与 `context-policy.json`。
- Codex 根入口仍以 `AGENTS.md` 为主；`.codex/agents/*.toml` 只保留技术 ID、最小职责、权限、最小读取顺序和共同路径，不复制灵魂卡或完整 Skill。
- `.cursor/` 与 `.codex/` 长期并存，不得互相覆盖、镜像或用链接统一。

## 查询型知识

- `project-index/**`：只用于定位，修改前必须核验原始权威文件。
- `external-knowledge/**`：搜索后读取少量相关结果，不得默认批量注入，不得当 canon。
- `docs/功能更新/**`：历史追溯，不是当前规则来源。
- `project-workflows/generated/**` 与上下文包清单：派生材料，默认不进入普通任务上下文。
- 灵魂卡只在对应成员被选中后读取。

## 解析与审计命令

```bash
npm run project:context:resolve -- --task "任务说明" --paths "path/a,path/b"
npm run project:context:audit
```

`resolve` 输出建议装载范围、`teamTier`、候选成员、理由与预算；它是辅助工具，不自动读取全部文件，也不取代主智能体判断。`audit` 校验 Schema、分类冲突、Always 规则数量、双端并存、禁止默认装载 L3/L4，以及人格配置冲突。

## 常见示例

- 修正 README 错别字 → `solo`，仅 L0/必要 L1。
- 补写正式故事段落 → 故事 Skill + 自然表达；通常 `micro-consult` 砚秋。
- 统一跨世界时间并写入长期规则 → `council`（最多三名）。
- 调整地图事件与 Pinia 数据流 → `micro-consult` 时雨；测试不自动再调凌音。
- 外部题材灵感检索 → L3 query-only；未达其他风险时可 `solo`。
