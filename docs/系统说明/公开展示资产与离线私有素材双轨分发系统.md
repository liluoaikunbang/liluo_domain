# 公开展示资产与离线私有素材双轨分发系统

这套系统把项目里的图片与运行素材拆成两条长期并行的资产线：

- 公开展示线：给 `README`、官网、Pages、公开画册、对外展示截图使用。
- 离线私有线：给游戏离线版、本地开发、敏感运行素材、制作源和参考源使用。

核心原则不是“所有图片都上传图床”，而是：

- GitHub / Pages 只放需要公开展示的内容。
- Cloudflare R2 只放公开展示资产的外链变体。
- 游戏敏感资源和离线优先资源不进入公开 R2，不作为公开仓库展示资产。
- 这类私有资源优先依赖本地 Nutstore 同步，再服务离线包构建。

## GitHub Pages 发布边界

GitHub Pages 只发布项目海报网站，也就是由根 `README` 及其公开子页面逐步扩展出来的对外展示站。它负责说明项目定位、六大叙事域、角色、真实证据、生产体系、协作入口和公开路线图；后续可以继续丰富成更完整的官网、图册、证据页和协作页。

GitHub Pages 不作为游戏主体发布渠道。完整游戏、运行时入口、可操作地图、互动小说副本和大型运行素材默认通过离线包发布，并沿用 [离线发行与 GitHub Release 流程](离线发行与GitHub-Release流程.md)。Pages 构建不得默认导入完整应用路由、`/#/game` 入口、Phaser 运行层或离线私有素材；仓库源码可以照常提交到 GitHub，但 Pages artifact 只应包含项目海报网站实际引用的公开展示文件。

当前 Pages 技术入口固定为：

- `index.pages.html`
- `src/readme-pages-main.js`
- `vite.config.mjs` 中的 `mode === 'pages'` 分支
- `.github/workflows/pages.yml`

普通 Web / 本地开发构建仍走 `npm run build:web`，离线发行仍走 `npm run build:offline`、`npm run package:offline` 或 `liluo-offline-release-pipeline`。

## 当前边界

### 1. 公开展示线

宿主：

- GitHub 仓库中的 manifest、说明文档和公开索引
- Cloudflare R2 公网地址
- GitHub Pages / 未来官网页面

适合放这里的内容：

- README 首屏海报
- 官网 Hero、角色页、世界页、Gallery
- 明确筛选过的公开截图
- 路线图、证据板、开发日志配图

当前权威文件：

- `docs/assets/registry/website-r2-manifest.json`
- `scripts/assets/visual-asset-manager.mjs`
- `docs/系统说明/视觉资产图床与R2管理系统.md`

### 2. 离线私有线

宿主：

- 本地工作目录中的运行素材
- Nutstore 同步到本机的私有资产根目录
- 离线发行打包流程

适合放这里的内容：

- `src/assets/game/cg/` 里的运行时 CG 成品
- `.psd`
- 私有 manifest 中登记的制作源、地图制作素材与候选参考板

当前权威文件：

- `docs/assets/registry/runtime-private-asset-manifest.json`
- `scripts/assets/runtime-private-asset-status.mjs`
- `scripts/assets/runtime-private-asset-sync.mjs`
- `docs/系统说明/运行时素材瘦身与外置治理系统.md`

## 为什么要这样分

原因有三层：

1. 游戏是离线版优先，运行时资源必须先保证本地可用和离线可打包。
2. `cg`、制作源、参考图既占空间，也不适合公开暴露到 Pages 或公开图床。
3. 公开展示图和游戏私有资源的生命周期完全不同，混在一条线上会让删除、替换、同步和计费一起失控。

## Nutstore 私有线的第一版合同

当前已经先用“安全复制”建立第一批私有镜像，但仍然先不删除仓库里的原件，先把迁移目标、同步入口和核对规则固定下来。

### 本地配置

复制：

- `.env.runtime-assets.example` -> `.env.runtime-assets.local`

目前最关键的只是一项：

- `LILUO_RUNTIME_ASSET_SYNC_ROOT`

它应该指向你本机 Nutstore 已同步下来的私有资产根目录，例如：

```text
D:\Nutstore\liluo-universe-private-assets
```

### 私有清单

当前私有线清单在：

- `docs/assets/registry/runtime-private-asset-manifest.json`

它当前登记六组对象：

1. `runtime-cg-finals`
2. `authoring-cg-standee-sources`
3. `authoring-scene-sources`
4. `pixel-map-sources`
5. `map-and-layout-sources`
6. `candidate-reference-boards`

每组都明确：

- 现在仓库里的来源目录
- Nutstore 中的目标子目录
- 是否允许进入公开 R2
- 是否应进入离线包

其中 `runtime-cg-finals` 和 `authoring-cg-standee-sources` 共用私有父目录 `game/visual/cg/`：

- `game/visual/cg/finals`
- `game/visual/cg/standee-sources`

这样后续在“运行成品 CG”和“制作源 standee / CG 来源”之间切换时，路径会更直观。

### 状态检查命令

```powershell
npm run assets:runtime:private:status
```

它会只读检查：

- `.env.runtime-assets.local` 是否配置
- 私有 manifest 是否存在
- 每个私有资产组当前在仓库里有多少文件、多少体积
- 对应 Nutstore 目标目录是否已经在本机同步好

这个命令不会上传、删除、搬运任何文件。

### 实际同步命令

```powershell
npm run assets:runtime:private:sync -- --group authoring-cg-standee-sources
npm run assets:runtime:private:sync -- --group authoring-cg-standee-sources --group authoring-scene-sources --group pixel-map-sources --group map-and-layout-sources --group candidate-reference-boards --live
```

在真正删除主仓库副本前，还要先做第二阶段可移除审计：

```powershell
npm run assets:runtime:private:audit -- --write-report
```

审计结果会写入：

- `docs/assets/registry/runtime-private-removal-audit.json`

并把每个私有 group 划分为：

- `ready-now`
- `ready-after-reference-cleanup`
- `blocked-by-runtime-references`

这条命令的默认行为是：

- 不加 `--live` 时只做 dry-run，报告将复制多少文件、目标目录在哪。
- 加 `--live` 时只做“复制/覆盖”，不删除仓库原件，也不清理 Nutstore 旧文件。
- 真正删除仓库副本前，必须先人工确认 Nutstore 镜像与离线包都可用。

## 迁移顺序

### Phase 1：先立合同，不迁真实文件

目标：

- 固定公开线和私有线边界
- 先有 manifest、env 模板和状态命令
- 避免后续一边迁一边改规则

### Phase 2：先迁制作源和参考源

优先迁出的不是运行时成品，而是私有 manifest 中的 5 组制作源/参考源：

- `authoring-cg-standee-sources`
- `authoring-scene-sources`
- `pixel-map-sources`
- `map-and-layout-sources`
- `candidate-reference-boards`

原因：

- 它们最不适合继续压在主仓库里
- 又不会直接影响公开展示站点
- 也不应该进公开图床

2026-08-01 已完成第一批安全复制，并在第二阶段完成后正式从主仓库移除：

- `authoring-cg-standee-sources` -> `game/visual/cg/standee-sources`
- `authoring-scene-sources` -> `game/visual/scenes/sources`
- `pixel-map-sources` -> `game/authoring/pixel-maps`
- `map-and-layout-sources` -> `game/authoring/map-sources`
- `candidate-reference-boards` -> `game/reference/mode-boards`

也就是说，这 5 组现在既有 `私有素材库` 镜像，也不再继续占用主仓库。

### Phase 3：再处理运行时 CG 成品

2026-08-01 这一步已经继续推进：

- `src/assets/game/cg/` 下 `214` 个 CG 成品、约 `364.89 MB` 已同步到 `私有素材库/game/visual/cg/finals`
- 但 `runtime-cg-finals` 仍不能从主仓库移除，因为当前运行时代码和打包内故事内容仍直接引用 `src/assets/game/cg/`
- 第二阶段审计已把它标记为 `blocked-by-runtime-references`

`cg/` 是体积大头，但不能直接照抄公开图床方案。后续要按“离线优先”做：

- 先保证离线包继续能完整打包
- 再决定 repo 中是否保留全部副本
- 如需外置，也应走私有同步线，而不是公开 R2

## 删除与替换策略

公开线和私有线分别处理：

### 公开线

- 同一路径替换：R2 覆盖上传即可
- 改 slug / 改用途目录 / 删条目：再跑 `npm run assets:r2:prune`

### 私有线

- 不做“仓库删了就默认远端也删”的自动行为
- `assets:runtime:private:sync` 只负责复制/覆盖，不负责 prune 或删除
- 先确认 Nutstore 中已有正确副本，再删除 repo 里的旧文件
- 真正删除私有副本前，要同时确认离线包和本地开发不再依赖它

截至 2026-08-01，第二阶段审计补充结论是：

- `assets:runtime:private:audit` 只负责判断“能不能删”和“为什么还不能删”，不做自动清理
- 真正执行 repo 移除前，先看 `docs/assets/registry/runtime-private-removal-audit.json`
- `authoring-cg-standee-sources`、`authoring-scene-sources`、`pixel-map-sources`、`map-and-layout-sources`、`candidate-reference-boards` 这一批已经完成引用清理并正式移除
- `runtime-cg-finals` 仍属于 `blocked-by-runtime-references`

## 当前结论

后续这套项目的图片与素材治理，不再是“全部上图床”，而是：

1. 公开展示资产走 GitHub/Pages + R2。
2. 离线私有游戏资源走本地 + Nutstore 私有同步。
3. 运行时 CG、制作源和参考源默认不进入公开图床。
4. GitHub Pages 只发布 README/项目海报网站，不发布游戏主体。
5. 真正删仓库副本前，先用 manifest、状态检查和安全复制把边界钉死。
