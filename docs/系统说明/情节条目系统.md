# 情节条目系统

## 目标

在故事与玩法之间建立跨世界的情节资料库。大情节（`groups`）只是整理视图，不自动等于故事或 RAG 上位类。小情节保存**一次性叙事发生**：谁（或角色槽位）在某种条件下做了什么/遭遇了什么，并使局面变化。情节可以未安置、不完整或从故事抽取；可跨故事复用的概念应进入 RAG，而不是把情节本体原样复用。

层级边界、判断树与逐条确认迁移见 [故事情节RAG边界治理系统](./故事情节RAG边界治理系统.md) 与 CDR-010。

## 用户表述路由

用户明确说“情节”“桥段”或“情节库”时，直接在本系统的正式目录中登记或修改；不得因为内容看似能接入某世界、主线或节点，而改写为故事大纲任务、候选卡或审批等待。用户明确说“大纲”“主线”或“节点”时，才进入故事大纲来源。只有用户明确要求同一内容同时进入两库时，才分别写入并建立采用关系；术语不明时才询问，不能自行猜测或跨库。

## 数据契约

正式数据位于 `src/game/data/plot_outline/catalog.json`，顶层包含：

- `groups`：大情节列表；每条具有稳定 `id`、简短 `title` 和解释收纳边界的 `summary`。
- `entries`：小情节列表。

每条小情节包含：

- `id`：稳定编号，格式为 `plot-001`。
- `number`：三位展示编号。
- `groupId`：所属大情节的稳定 ID；每条小情节必须且只能归入一个大情节。
- `title`：使用“主要人物-短情节名”格式；默认主角璃落不列入人物，其他主要人物最多列三名，超过三名时第三名后写“等”，整体保持简短。
- `summary`：情节本身的完整描述。
- `worldBiases`：偏向世界列表；空列表表示通用。
- `plotKind`：`ordinary`、`restraint` 或 `mixed`。
- `ragRefs`：情节涉及的正式 RAG 卡 ID。
- `characters`：实际出现在情节中的人物列表，包含主角璃落；与标题中省略璃落的规则相互独立。
- `isUsed`：是否已经被正式故事采用。
- `usageStatus`：`unused`、`partial` 或 `used`；前因已采用但回收仍待定时使用 `partial`。
- `usedBy`：采用该情节的故事节点 key；未使用时为空列表。
- `usedByLabels`：与 `usedBy` 对应的中文层级名称，统一为“世界名-主线名-节点名”，供界面显示。
- `notes`：使用边界或仍需决定的事项。
- `development`：面向正式展示与后续写作的原创四段式发展结构，固定包含 `premise`（核心前提）、`escalation`（升级链）、`turn`（关键转折）和 `consequence`（持续后果）。四项都必须结合当前情节本身填写，不能保存外部知识卡 ID、来源名称或原文摘录。
- 可选层级元数据（不决定“是不是情节”）：`maturity`、`placementStatus`、`origin`。既有条目中的 `layerReviewStatus`、`migratedToRagId` 等字段仅保留已确认迁移的历史追溯，不再产生新的审核流程数据。

`isUsed` 必须与 `usedBy` 是否非空一致。存在已应用片段时为 true；仍有待定后续时，`usageStatus` 保持 `partial`。具有明确前因、回收或因果关系的内容应保存在同一小情节中，不按章节或应用状态机械拆分。大情节不是故事树父节点，不参与 `usedBy`，也不改变故事节点结构。

外部知识库只作为后台资料室。升级情节时可以检索术语卡和情节模式卡，但正式目录只保存原创重组后的 `summary` 与 `development`；运行界面只展示正式结果，不展示外部来源链。这样用户只需提出“升级这个情节”，无需维护卡片关系。

登记零散灵感前必须先比较已有小情节。新内容若延续同一核心冲突、因果链、前因回收，或本来就是同一主题小情节计划持续收纳的段落，应扩写已有条目的 `summary` 与 `notes`，并保留其稳定 ID、使用位置和使用状态；仅有相同世界、标签、人物或宽泛主题不足以合并。无法明确判断拆分还是合并，或新内容与既定结构矛盾时，先向用户确认。

世界入口、异境停留、灾域展开、能力获得或阵营介绍本身不构成情节。只有形成可从原章节中抽出、具有明确冲突与转折、并能在其他节点或世界中复用的桥段时，才进入情节目录。删除既有情节时保留稳定 ID 空档，不重排后续编号。

普通 Tag、紧缚 Tag 与 `isBondagePlot` 已退役，不得重新写入。界面按 `plotKind` 筛选；`mixed` 同时进入普通与紧缚的宽口径结果，但底层仍只有一个情节实体。

## 界面

旅途菜单 → 大纲 → 「情节」分栏浏览情节库（三列：大情节 / 小情节 / 详情）。

跨模块关系（情节 ↔ 故事 / RAG / 玩法等）可在同级「关联图谱」分栏中可视化浏览；图谱为投影层，不替代本目录的权威编辑入口。

大纲栏目顺序为“故事、情节、玩法、人物/组织、关联图谱”。情节栏目提供关键词、使用状态、偏向世界和 `plotKind` 筛选。栏目采用“大情节 / 小情节 / 详情”三栏布局：第一栏选择大情节，第二栏浏览该组内经过筛选的小情节，第三栏展示摘要、四段式情节发展、类型、RAG 引用、世界偏向、使用位置和备注。窄屏按相同顺序纵向排列。界面只读，不在运行界面直接编辑 JSON，也不展示外部来源正文。

首批归类中，“封闭规训机构”收纳医疗保护、行为矫治、监护疗养等通过专业、教育或保护话术限制成年女性自主权的桥段，后续可扩展古风闺秀教育、西幻中世纪礼仪教育等世界化变体。“都市 DID”统一收纳现代都市环境中的绑架、诱捕、人质、转运、囚禁、逃脱与追查桥段，允许持续增加大量不同场景的小情节；拇指女仆等以微型族群和尺度差异为核心的内容归入“小人国”。“狩猎游戏”统一收纳把人作为猎物的封闭猎场，目前包含古风权贵禁苑、现代豪门夜猎和科幻直播穹顶三个世界化变体。“科技消费陷阱”除代理消费、异地规则和金融条款外，也收纳虚拟现实产品把用户意识与现实身体分离后产生的安全陷阱，例如玩家登录期间现实身体遭绑架、运输途中又被迫观看自身受缚影像的虚实错位事件。“室外游乐场”与“室内游乐场”分开归类：邮轮观光与社团雪地玩耍归入室外游乐场，温泉竞赛和充气城堡归入室内游乐场；雪地玩耍中的羽绒服摔跤、捆绑雪仗、暴露惩罚与高处跳入异常深雪区属于同一场冬日活动，不拆分成多个换皮条目。“童话改编”收纳黑暗童话、寓言绘本与末日童话迷城等不同改编方向；“灰姑娘水晶镣”等具体桥段可以继续归入对应小情节，不必每个段落单独建条。“极限拘束与折磨”统一收纳拘束、折磨或羞辱持续突破身体、感官或心理承受边界的跨世界桥段，包括馒头诱爬、雪刑感官折磨、缝眼缝嘴并以螺丝和铁片形成最终金属封嘴的末日监禁、绑哭不解、末日热熔胶滴蜡封耳、古风武侠语境中挑断手脚筋脉的典型酷刑，以及科幻智能细绳从鼻腔、咽喉和食道方向触发喷嚏、咳嗽、吞咽与异物感反射的无损伤内感官折磨；璃落以刺青覆盖伤疤并由武侠转入仙侠，是筋脉受创情节造成的长期后果，不改变其折磨类归属。末日、灰巷等环境只作为世界倾向和情节标签，不另设宽泛的“末日生存与人性”大情节。“紧缚挣扎”则收纳受缚者持续寻找发力点、破坏环境并迫使施害者升级限制的主动反抗过程；璃落在末世中为保护他人而整日挣扎、以脚趾破坏沙发并最终遭到束趾倒吊压制的桥段归入此组。“戏弄与霸凌”收纳利用人数、身份、场所、规则或器具优势迫使他人参与互动的情节，从偏可爱的戏弄延伸到恶意霸凌。使用医用开口器固定张嘴后强行灌酒，若主要目的在取乐和羞辱而非逼供或严重伤害，属于其中恶意较强的一侧；把受害者双手分别包成圆球状、使其看起来只能出“石头”后仍强迫猜拳，则可以表现成较轻的可爱戏弄。具体强度由小情节标签与后果区分，自愿趣味游戏不计入此类。“动物拘束”按动物、虫群和生物材料建立系列：现有《误入灵蛛谷》的蛛丝缠身、牵引丝和蛛网巢穴归为蜘蛛条目；蜂群则以蜂蜡拘束、接吻喂入信息素、全身包裹吸收和最终成为幼蜂体液供养奴隶构成另一条完整转化链；小蜘蛛进入口、鼻、耳并在体内织网封住舌头、牙齿与感官通道，则因强制度、身体边界和感官封禁目的明显不同，作为第三个独立条目。三者共享动物拘束母题，但材料使用、情节强度和长期目的不同，不相互合并。

## Skill 使用规则

随机访谈和指定故事撰写前，可检索未使用条目及部分使用条目中的待定部分。匹配项只能作为灵感候选，不得自动写入大纲。用户确认采用后，同步正文、来源 JSON、`usedBy` 与 `usageStatus`；用户明确提出的情节或桥段直接进入情节库并保持未使用，除非用户同时明确要求采用到大纲。

从情节库出发、需要先选落点再访谈时，使用 `liluo-plot-placement-interview` 与 [情节安置提问模板](./情节安置提问模板.md)：按 `worldBiases` 优先对照大纲，给出主线/支线与扩充/新建建议，落点批准后再提问写回。大纲节点优先的随机访谈仍走 `random-story-outline-interview`。
