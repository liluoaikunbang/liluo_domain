# 项目规范治理与设计记忆系统

## 当前契约

- 系统职责：判断什么值得长期保存，把规则写入唯一权威位置，并追踪必要消费者。
- 默认入口：`liluo-project-governance-memory`；普通任务只做 light 判断。
- 权威导航：`docs/规范治理/` 三份注册表；设计理由：`docs/设计记忆/`。
- 必须遵守：当前规范、历史实现、用户入口和设计理由分层；项目索引不替代权威源。
- 禁止事项：保存聊天流水账、每次全量审计、按相似度自动删除、给每句话编号或复制完整规则。
- 详细设计：`docs/设计记忆/架构决策/ADR-002-规范与设计记忆分层治理.md`。

## 目标与职责分层

系统解决长期要求漏沉淀、用户工作流漏登记、规则消费者漏同步和设计理由丢失。各类文档的保存边界见 [文档职责矩阵](../规范治理/文档职责矩阵.md)：`AGENTS.md` 只留最高层门禁与路由；系统说明保存当前契约；Skill 保存执行流程；Agent 保存角色合同；用户命令目录保存触发入口；功能更新保存历史；设计记忆保存理由。

## Light / Deep

light 是默认模式：先查 `document-registry.json`、`rule-registry.json` 与 `impact-map.json`，再读一份权威文档和最多三份直接消费者。无长期影响时立即结束。

deep 仅用于用户明确要求的全局规范整理、跨系统架构迁移、大范围重复与冲突审查或文档结构重构。它可以扩大读取和运行重复报告，但仍不得自动删改历史。

## 最小验证预算

【璃落指出：检查要按一次任务的真实变化和风险统一合并，不能按调用的 Skill 数量机械叠加；一项已经覆盖的内容，不再换个入口重复检查。】

普通任务默认只运行一项目标验证。只有一项无法覆盖多个实质变化面，而且第二项的结果会改变完成结论时，才增加至多一项相关综合验证。各 Skill、文档同步和内容工作流提出的检查先进入同一份验证候选清单，由主 Codex 按覆盖范围去重后选择最小集合，不形成逐个 Skill 追加命令的队列。

| 变化类型 | 默认验证 | 默认不做 |
| --- | --- | --- |
| 纯文档、措辞、静态内容 | 一项直接覆盖改动的格式、结构或编码检查 | Web 构建、全量测试、多个相近文档 profile |
| Skill 触发或合同 | 变更 Skill 的结构校验；行为脚本存在时跑目标测试 | 为无关 Skill 跑测试、因措辞调整建立完整功能记录 |
| 小型确定性逻辑 | 实现与目标测试一起完成，执行一次目标测试 | 为证明“代码尚未写”制造 RED |
| 回归缺陷、高风险或行为不明 | 先用测试复现真实失败，再修复并复跑 | 用猜测替代复现 |
| UI、构建、资源或浏览器运行时 | 目标测试，加直接受影响的构建或浏览器检查 | 与变化面无关的治理或内容审计 |
| 治理、用户命令、索引 | 对应的最小定向校验；被索引源变化时末尾增量刷新一次 | 局部规则变化触发历史功能文档全量审计、已知只报告无关旧问题的审计 |

纯故事正文修改若未改变 frontmatter、JSON、key、父子关系或运行时引用，不自动追加 story frontmatter、全内容或治理审计；选择直接相关的写作、原创性或改动范围检查即可。局部 Skill 文案、治理消费者或设计说明修改，默认使用注册表/结构定向校验，不运行会扫描全部历史功能编号的治理全量审计。全量审计只用于用户明确要求、注册表/目录职责重构、批量迁移或确有跨历史范围风险的变化。

目标验证已被综合 profile 包含时不重复执行；相关文件没有再次变化时不重跑。外部来源原创性门禁和被索引源的末尾增量刷新属于条件性完成门禁，只在实际触发时保留，不因此追加别的测试或 profile。失败只在可能改变本次结论时触发调试路线；已确认与当前改动无关的历史问题记录一次即可，不扩展为新的修复任务。差异审查保持简短，正式多轴代码审查仅用于合并、发布、安全、架构或较大重构。

## 持久性门禁

任务结束前判断是否改变长期要求、用户可重复调用功能、系统行为/目录职责/数据契约，或已确认的架构与创作决策。

- 明确长期：更新唯一权威源并检查影响映射。
- 明确临时或未形成结论：不沉淀。
- 确实无法判断且影响未来：询问一次是仅本次还是长期规范。

分类包括 transient、persistent、user-facing、architectural、creative、unresolved 与 historical。机械分类命令可用 `npm run docs:impact -- --text "要求"`，最终判断仍由主 Codex 结合语境负责。

## 可避免绕圈复盘

任务中实际出现额外失败、重复读取、重复检查或无效重试时，结束前只做一次轻量复盘，判断它是否能被已有规则、稳定命令写法或更准确的首次权限路线避免。

只有同时满足以下条件才在同一任务沉淀：原因已确认；以后有合理概率再次出现；规则能跨越本次具体文件复用；修改范围小且权威归属明确。优先补充既有权威规范与一个必要消费者，不为每次故障新建规则、脚本、功能记录或设计决策。

偶发外部故障、平台临时状态、一次性手误、原因未明的问题和只对当前命令有效的修补不自动写入规范。复盘最多执行一轮，复盘产生的文档修改不递归触发新的复盘；它与原任务共用最小验证预算，不追加一套全量检查。若候选规则会扩大权限、改变安全边界或显著改变后续工作流，必须另行取得用户明确授权。

## 分工

- 主 Codex：决定、写入、同步和最终汇报。
- `liluo-project-governance-memory`：分类、权威定位、影响分析、决策记录与完成门禁。
- `liluo_project_memory_curator`：按需只读追踪权威、消费者、冲突和持久意图；不写文件。
- `liluo-project-documentation-sync`：功能编号、功能文档、目录、更新记录和 Skill 说明等机械同步，不决定持久性或权威位置。
- 确定性脚本：验证注册表、设计记忆、用户命令和已知结构；只报告，不自动修复。

## 单一事实源与注册表

`document-registry.json` 只登记项目级入口、重要当前说明与直接消费者；`rule-registry.json` 只登记真正跨系统的重要规则；`impact-map.json` 把常见变化映射到必查位置。三者不保存正文、不登记全部历史文档，也不替代项目知识索引。

新增规则时先选择权威文档，再登记确实需要同步的消费者。消费者可以有本地必要合同，但不复制权威文档的完整背景、理由和禁止项。

## 设计记忆

[项目宪章](../设计记忆/项目宪章.md) 保存最稳定的项目身份；[设计原则](../设计记忆/设计原则.md) 保存未来取舍原则。ADR 记录工程与工作流理由，CDR 记录长期创作理由；状态支持 proposed、accepted、superseded、deprecated、rejected。只有用户确认或已有充分采用证据的决定标为 accepted，未确认且确实影响后续的事项进入 [待确认决策](../设计记忆/待确认决策.md)。

## 用户入口与功能记录

新增或改变用户可调用的 Skill、Agent 或稳定脚本时，同步 `docs/用户命令目录.md`、对应说明、当前系统说明、功能更新和项目索引。普通内部脚本、一次性调试命令和局部 bug 修复不强制登记。

命令授权决定由独立的 [Codex 命令授权治理系统](./Codex命令授权治理系统.md) 管理：`.codex/rules` 是执行规则权威，批准注册表保存脱敏决定历史。只有整体权限模式、网络/Git 默认策略或项目与全局边界改变时，才进入本系统的 ADR 与跨文档治理；普通单条精确命令变化不新建功能记录。

## 文档压缩

`docs:compact:report` 首先报告非历史文档中的完全重复长段落。相似文本只作为人工审查线索；压缩必须遵守 [文档压缩规范](../规范治理/文档压缩规范.md)，不自动删除或大规模改写。

## 常用命令

```powershell
npm run docs:impact -- --type architecture-decision
npm run docs:impact -- --rule single-authority
npm run docs:governance:validate
npm run docs:memory:validate
npm run docs:commands:validate
npm run docs:governance:audit
npm run docs:compact:report
```

被索引源发生变化时，在任务末尾运行一次 `npm run project:index:changed` 和 `npm run project:index:validate`；没有变化时不运行。

## 故障恢复与限制

注册表验证失败时先修正路径、ID 或状态，不通过删除权威文档掩盖失败。索引 stale/partial 时核验原文件并更新索引。当前分类器只提供保守提示，不理解全部自然语言语境；完全重复报告不判断语义等价；注册表需人工维护少量高价值关系。这些限制是有意的，以避免治理系统成为新的高成本知识库。
