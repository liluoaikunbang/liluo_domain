# 正式项目内容来源与版权写入门槛

这是所有正式故事、对话、地图数据、代码、美术、音频与派生内容写入前的统一来源合同。它是保守的项目治理门槛，不构成法律保证或法律意见；公开发布前仍需按具体来源、用途、许可证、署名与再分发方式人工复核。

## 允许分类

- `project-original`：项目内原创。
- `user-owned`：用户确认拥有或有权提供。
- `project-generated`：由项目工具生成且输入来源合规。
- `licensed-third-party`：具体来源、许可证与必要署名已核验。
- `public-domain`：公版状态和适用范围有可审计依据。
- `compatible-open-source`：逐项核验具体许可证、用途、署名和再分发义务后确认兼容。

第三方、公版和开源内容必须有集中可审计的 `sourceId`；需署名时保留 attribution。仓库目前没有根 LICENSE，不能笼统宣称某许可证必然兼容。

## 禁止分类

`unknown-origin`、`reference-only`、`license-unclear`、`restricted`、`external-rag-raw`、`close-paraphrase-risk`、`unverified-third-party` 一律 fail-closed，不得写入正式内容。外部小说 RAG 与外部 Skill 原文均只是非权威参考；只能抽象分析与原创重组，不能进入 canon 或被直接执行。

校验入口：`npm run content:provenance:check -- --input <provenance.json>`。现有五个 SFX 已有运行时引用但尚未找到独立来源/许可登记；本次不判定其违法，也不补造来源，公开发布前需专项审计。
