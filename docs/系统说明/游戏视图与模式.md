# 游戏视图与模式

游戏视图的核心职责是承载 RPG 主界面，并在不同模式之间切换或覆盖。

## 当前入口

- `src/game/views/GameView.vue`
- `src/game/views/shell/`
- `src/game/views/modes/`
- `src/game/views/composables/`
- `src/game/views/components/base/`

## 结构原则

- `GameView.vue` 应尽量保持入口和调度职责，不继续膨胀成所有 UI 与桥接逻辑的集合。
- 通用外壳放在 `shell/`。
- 地图模式、互动小说模式等具体体验放在 `modes/`。
- Vue 与 Phaser 的桥接逻辑放在 `composables/`。
- `src/game` 自用基础 UI 放在 `views/components/base/`，不再从外部 `src/components` 引用。

## 当前模式

- 地图模式是主体验，应该常驻并优先保证可玩。
- 互动小说副本作为覆盖层出现，离开副本后应回到地图流程。
- UI 覆盖层需要阻断底层地图点击，避免对话、菜单、副本期间误触发地图行为。

## 地图动作区

地图右侧栏中的区域动作优先通过 `src/game/data/mapPanelActions.ts` 配置，不应直接写散在 `GameView.vue`。

当前链路为：

- `mapPanelActions.ts`：定义某张地图、某个条件下可出现的动作。
- `GameMapActionPanel.vue`：渲染右侧动作按钮栏。
- `GameMapActionChoiceDialog.vue`：渲染动作的二级选项框。
- `MapMode.vue`：承接地图模式中的动作按钮、选项框和左侧立绘数据。
- `GameView.vue`：负责根据当前地图选择动作、响应点击、应用结果和维护 UI 覆盖层。

这样后续不同房间或地区要向动作区增加按钮时，可以优先补动作配置和小组件能力，而不是把上级入口组件变成所有地图行为的集合。

当前已接入的地图动作为：璃落房间 `liluo_room` 中的“自缚”。角色站在门口时，既有“离开房间”按钮仍会和地图动作区协调显示。
