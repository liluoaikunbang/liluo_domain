# 用户命令目录

这里集中记录用户可以直接向 Codex 表达的常见任务，防止工作流增多后只能依赖聊天记忆。下列句子是自然语言意图示例，不是必须逐字输入的“魔法口令”；意思相同即可触发对应工作流。

## 故事与世界观

| 可以这样说 | 会执行什么 | 主要工作流 |
| --- | --- | --- |
| “随机抽一个未完善故事问我” / “继续随机访谈” | 从不完整节点中抽取一个，读取上下文后进行聚焦访谈 | `random-story-outline-interview` |
| “完善/扩写这个故事节点” | 同步故事源 JSON 与 Markdown，补齐剧情、地图、事件、玩法和状态 | `liluo-story-outline-authoring` |
| “分析这个节点/系列/世界还缺什么” / “给我可审批的故事候选” | 读取项目证据，识别真实缺口与重复功能，按需参考外部抽象模式，并提交候选卡；不自动写正式故事 | `liluo-story-gap-discovery` |
| “把这个节点移动到……下面” / “修复故事树断链” | 安全修改 parentKey、插入、移动、拆分、合并或重命名节点 | `liluo-story-outline-graph-maintenance` |
| “检查人物、时间线或世界观有没有矛盾” | 只读连续性审查，以正式项目知识为准 | `liluo-world-bible-continuity-audit` |
| “评估这个玩法循环是否适合当前游戏” | 把想法审查为可开发的 2D 像素 PVE RPG 循环 | `liluo-gameplay-loop-audit` |

## 知识库与资料检索

| 可以这样说 | 会执行什么 | 主要工作流 |
| --- | --- | --- |
| “查询项目知识索引里的……” | 先检查新鲜度，再查询最小领域并核验权威文件 | `liluo-project-index-maintenance` |
| “更新/重建项目知识索引” | 按变化范围增量更新或全量重建，并验证索引 | `liluo-project-index-maintenance` |
| “从外部小说素材找……灵感” / “查询某种表达或场景模式” | 查询非正式外部参考，返回抽象结论与来源定位 | `liluo-external-fiction-knowledge` |
| “更新外部知识库” | 从本机权威目录哈希增量同步镜像，再增量索引和验证 | `liluo-external-fiction-knowledge` |
| “检查这段内容是否照搬原文” | 运行连续字符与 n-gram 相似性风险检查 | `liluo-external-fiction-knowledge` |

外部知识库更新默认自动处理普通镜像删除，不询问逐项确认；只删除同步清单管理的镜像文件，不修改本机权威源。一次删除超过 20% 会自动停止。

## Git 与发布

| 可以这样说 | 会执行什么 |
| --- | --- |
| “提交并上传 GitHub” | 审查整个工作区，排除密钥、`.local` 配置、临时文件和构建产物；未限定范围时提交任务范围内全部有效新增、修改和删除并推送 `main` |
| “只提交这些文件……” | 仅暂存明确列出的范围，其他用户改动保持不动 |
| “创建分支/PR” | 只有明确要求时才建立分支或 PR；否则项目默认直接同步 `main` |
| “生成可以双击启动的离线包” | 构建带 `启动游戏.bat` 的多文件离线版本、校验本机启动器与相对引用，并生成 ZIP；不访问 GitHub |
| “把离线包上传到 v0.1.0 Release” | 重新构建、校验、压缩后上传到指定标签；标签必须显式给出，不提交或推送源码 |

以上离线打包、一键启动器版本和 Release 上传需求统一由 `liluo-offline-release-pipeline` 自动编排；若承接功能开发，还会先完成必要文档同步和验证。离线包解压后双击 `启动游戏.bat`，不要直接打开 `index.html`。

## 常用脚本命令

### 项目运行与构建

```powershell
npm run dev
npm run build:web
npm run build:offline
npm run package:offline
npm run release:offline -- --tag v0.1.0 --dry-run
npm run release:offline -- --tag v0.1.0
npm run preview
npm run docs:check-encoding
npm run assets:build-liluo-character-frames
```

### 项目知识索引

```powershell
npm run project:index:check
npm run project:index:query -- --domain story --query "关键词" --limit 5
npm run project:index:changed
npm run project:index:build
npm run project:index:validate
```

### 规范治理与设计记忆

```powershell
npm run docs:impact -- --type new-user-invokable-workflow
npm run docs:impact -- --rule single-authority
npm run docs:governance:validate
npm run docs:memory:validate
npm run docs:commands:validate
npm run docs:governance:audit
npm run docs:compact:report
```

### 璃落创作组陪伴

```powershell
npm run team:presence:check
npm run team:presence:update -- --topic="本次主题" --members="璃落,知遥"
npm run team:roster:validate
npm run team:notes:validate
npm run team:literary-names:validate
npm run team:literary-names:list
npm run team:literary-names:available
```

工作中名称会尽量显示为“知遥（资料与出处）”等形式；若 Codex 客户端仍显示技术 ID 或 Agent 类型，属于平台渲染限制，仓库配置不能强制覆盖。

### 故事缺口候选

```powershell
npm run story:gaps:test
npm run story:gaps:examples
npm run story:gaps:validate -- planning/story-gaps/active/<candidate>.json
```

普通候选只在对话中展示；只有明确要求保存时才进入 `planning/story-gaps/`。`proposed`、`held`、`rejected` 都不会写入正式大纲。

`docs:impact` 用于轻量影响分析；其余命令是只读验证或报告，不会自动删除、压缩或改写文档。普通局部任务不需要运行整套治理审计。

### 外部虚构题材知识库

```powershell
npm run external:knowledge:check
npm run external:knowledge:sync
npm run external:knowledge:update
npm run external:knowledge:build
npm run external:knowledge:validate
npm run external:knowledge:query -- --query "古堡 逃脱" --mode and --limit 8 --format markdown
npm run external:knowledge:copy-check -- --input "待检查文件.md"
```

其中 `external:knowledge:update` 是日常推荐入口，会自动执行“权威源同步 → 来源级增量索引”。单独的 `sync` 只同步镜像，不更新索引。

## 维护规则

- 新增项目 Skill、固定自然语言工作流或面向用户的脚本命令时，同步更新本目录。
- 根 `README.md` 保持精简，只放长期入口和最高频命令；详细参数留在本目录、系统说明或对应 Skill 文档。
- 命令行为变化时先更新权威系统说明，再更新这里的摘要，避免形成第二套互相冲突的规范。
- 一次性调试命令、内部实现细节和已废弃入口不登记为长期用户命令。
