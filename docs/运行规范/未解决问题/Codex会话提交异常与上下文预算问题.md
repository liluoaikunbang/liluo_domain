# Codex 会话提交异常与上下文预算问题

## 状态

- 状态：未完全解决，持续观察。
- 首次记录：2026-07-25。
- 权威范围：璃落项目工作区内的 Codex 会话提交、上下文累积与工具调度异常；不把它误写为游戏运行时故障。

## 已确认现象

1. `Error submitting message` 只在本项目出现；对照项目未复现。
2. 新开本项目对话可立即正常提交，但同一对话通常在 3–4 次交互后再次出现；可见聊天内容仍可能不多。
3. 不触发项目索引、长 Skill 或宽范围检查的轻量对话较稳定；重型上下文读取后更容易出现。
4. 一次补丁提交曾出现约 39 秒的异常工具调度等待，虽最终写入成功；它是相关观察，不等同于已证明的根因。

## 已排除或未支持的解释

- `.codex/config.toml` 仅保留 `[agents]`，不存在 `default_permissions` 或 `[permissions.*]`。
- 当前会话 writable root 为项目根目录，未见 `.agents\\.codex`、`docs\\src` 等交叉嵌套路径。
- 极小只读操作约 2.9 秒，故意不匹配的补丁预检约 0.2 秒；未复现约 57 秒的稳定调度延迟。
- `.codex/hooks.json` 的 `hooks` 为空；仓库存在脚本不表示其已注册为生命周期 Hook。

## 当前工作假设与已实施缓解

最强工作假设是：项目初始规则、Skill/Agent 元数据与同会话中读取的长 Skill、索引、检查输出共同累积，使提交载荷或会话状态在数轮后越过内部阈值。该假设尚未被平台日志证实。

已实施的项目内缓解包括：按需读取 Skill 与索引；小任务不做宽范围检查；Agent 使用最小任务包和短报告；长任务后以可验证交接摘要开启新会话；`build:web` 与 `build:pages` 改为 Vite `--logLevel warn`，避免构建时逐项打印大批图片、音频和字体体积清单。详见 `docs/功能更新/155-Agent上下文分层与最小任务包.md` 与 `docs/功能更新/179-Codex上下文预算缓解与静默构建.md`。

## 再次出现时的处理

当用户提到“Error submitting message”、消息提交失败、同一问题又出现、对话数轮后卡住，或工具调度异常等待时：

1. 先读取本文，不要求用户重复已记录的现象、对照与排除项。
2. 只询问本文缺少且会改变诊断的事实，例如发生时间、当前对话轮次、是否刚读取长 Skill/索引/检查输出、完整新错误文本。
3. 将用户补充或可复核的工具观察追加到下方“观察更新”，标明日期、来源和是否已验证；不保存聊天流水账、隐含推理或无关内容。
4. 将新事实与既有假设分开。除非证据充分，不宣称已定位平台根因；项目内优先继续采用最小上下文策略。
