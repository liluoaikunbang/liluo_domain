# 功能更新目录

这个目录用于统一登记 `docs/功能更新/` 下的功能实现文档，方便按时间顺序、功能主题和代码路径回查。

> 最新补充：169-大纲关联图谱视图（支持导出投影 JSON），详见 `docs/功能更新/169-大纲关联图谱视图.md`。


## 定位

`docs/功能更新/` 是历史记录区，不是当前系统说明区。

- 想知道“现在该怎么扩展系统”，优先看 [系统说明](./系统说明/README.md)。
- 想知道“当时为什么这样改、遇到过什么问题”，再查这里的编号文档。

## 编号规则

功能更新文档统一采用：

```text
序号-功能标题.md
```

约定：

1. 序号使用三位数字，从 `001` 递增。
2. 新文档默认接在当前最大序号后。
3. 旧文档原则上不随意改名、合并或删除，避免破坏历史引用。
4. 每篇功能文档至少记录实现思路、相关代码路径、问题与解决方法、验证结果。

历史上出现过两个 `017` 文档，本目录保留这个事实，并用 `017-a` / `017-b` 区分索引项；后续新增文档继续从当前最大序号后递增。

## 后续维护建议

后续每次功能真正完成，并且经过用户实际测试确认无报错后：

1. 在 `docs/功能更新/` 新增一篇对应编号文档。
2. 同步把新文档补进本目录。
3. 如果改动改变了当前系统的维护方式，再同步更新 `docs/系统说明/` 中对应说明。
4. 文档统一以 UTF-8 保存；如果在终端里查看中文，优先使用能正确输出 UTF-8 的命令或编辑器预览，避免把终端显示错码重新写回文件。

## 乱码防护

- 仓库根目录的 `.editorconfig` 固定了 Markdown、TypeScript、Vue、JSON 等文本文件使用 `utf-8`。
- 提交或保存大量文档前，可以运行 `npm run docs:check-encoding` 扫描 `docs/**/*.md` 中明显的错码字符、私用区字符和 UTF-8 解码问题。
- PowerShell 里直接 `Get-Content` 有时会因为控制台编码显示成乱码；这不一定代表文件损坏。判断真实内容时，以编辑器 UTF-8 读取或编码检查脚本为准。
