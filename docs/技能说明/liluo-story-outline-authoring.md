# liluo-story-outline-authoring

## 项目索引协作

复杂定位先查询 current 的 story/graph 索引，正式撰写前核验来源 JSON 与 Markdown；修改后运行领域级增量更新和索引验证。

## 用途与边界

撰写、扩写或按模板重构指定故事节点，同步来源 JSON 与 Markdown。用户要求随机访谈、纯图结构移动、只读连续性审查或地图代码接入时不触发。

## 路径与资源

- Skill：`.agents/skills/liluo-project/liluo-story-outline-authoring/`
- references：`maturity-decision.md`、`authoring-checklist.md`、`mainline-reference.md`
- 输入：用户说明、条目模板、世界选项、来源节点、正文及必要父子/引用资料
- 输出：与真实成熟度相符的 JSON/Markdown、具体 `missingItems` 和验证结果

## 流程、限制与验证

先检查来源节点的 `status`。普通节点重建上下文，判断最高可诚实支持的成熟度，仅写已确认内容，同步两层来源并检查 key、标题、目录和 parentKey。`status: 主线任务` 的节点只使用“主线备忘”结构保存总体方向，供以后拆写普通剧情节点参考；不进入三档成熟度，不使用 `isTemplated`、`missingItems`、模块类型、玩法流程、状态字段、制作引用或验收内容。撰写主线下的普通节点时，必须沿 `parentKey` 读取最近的相关主线备忘及仍有效的上层备忘：已确认方向作为连续性约束，推荐阶段只作设计参考，待确认事项仅在影响当前节点时转化为提问或该节点的 `missingItems`，不得整份复制。主线备忘不能替代普通节点自身的地图、事件、玩法、状态和制作证据。不得编造 ID、用占位语填充、复制候选库或连带重构亲属节点。用户明确表示普通节点中的某个灵感“还没想好”“待定”或“待做”时，只保留已确认方向，把未决事项登记为具体 `missingItems`；主线备忘的未决方向则写入正文参考清单，不进入结构化缺口队列。不得代为补完、升级成既定剧情、添加出场/引用或编造实现细节。“待定”只表示工作流状态，不作为正文填充语。删除普通节点最后一项 `missingItems` 前，必须把来源内容、之前各轮已接受或写入的答案、本轮答案、当前成熟度与体量合并复审；既检查新缺口，也复查旧答案是否仍不完整或与新决定冲突。旧问题回答完不代表条目完整，仍缺可执行流程、玩法规则、状态变化、衔接或首版边界时，应登记下一层具体缺口。运行故事大纲测试、内容验证和 UTF-8 检查。图结构变更交给 `liluo-story-outline-graph-maintenance`，随机提问交给 `random-story-outline-interview`。

## 维护要点

模板、成熟度规则、字段或验证命令变化时同步更新 Skill、references 与本文。

大型跨节点任务可委派 `liluo_context_explorer` 重建只读上下文；涉及人物、时间线或跨世界规则时可委派 `liluo_continuity_reviewer`。子智能体不修改故事，JSON 与 Markdown 由主智能体统一写入。

## 情节条目联动

撰写或完善大纲时读取 `src/game/data/plot_outline/catalog.json`，参考未使用条目及部分使用条目中的待定部分。在提出可能导致大纲回写的问题前，或执行仍需故事决策的用户授权大纲改动前，按已确认的世界、人物、地点、冲突和玩家流程检索匹配项；确有可能合适的真实条目时，在同一个问题中把条目名称和适配理由作为可选方案一起询问。没有匹配项时正常提问，不为凑选项塞入无关情节。候选不得自动并入正文；用户明确采用后才追加真实节点 key，并按剩余缺口设为部分使用或已使用。具有明确前因与回收关系的内容保存在同一条目中，不按章节拆分。

登记新灵感前先比较已有小情节。若它延续同一核心冲突、因果链、前因回收，或属于既定小情节要持续收纳的段落，就扩写原条目并保留稳定 ID、使用位置与状态；相同世界、标签、人物或宽泛主题本身不足以合并。拆分与合并难以判断或存在矛盾时先询问用户，只有真正独立的内容才分配新 ID。

情节标题统一写成“主要人物-短情节名”：默认主角璃落不列入人物，其他主要人物最多列三名，超过时追加“等”，情节名保持简短。`usedBy` 保存稳定 key，`usedByLabels` 按“世界名-主线名-节点名”保存对应中文层级供界面展示。

`characters` 单独登记所有实际出现人物，包括璃落。`storyTags` 独立表示世界内故事风格；非紧缚的题材、场景、身份与结构标签写入 `plotTags`，紧缚方式或紧缚主题写入 `bondageTags`。不得恢复旧 `tags` 字段，也不能因为应用情节存在某标签就自动继承紧缚标签。
