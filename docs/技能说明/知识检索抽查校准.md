# liluo 知识检索抽查校准

## 用途

对紧缚 RAG、Style-RAG、细节概念与情节做人工抽查、归档问题、在阈值满足时建议抽象 Skill 升级，并仅重建/校验受影响范围。

## 触发

- “抽查 RAG / Style-RAG / 细节概念 / 情节”
- “这条索引不对，记下来”
- “RAG 准不准 / 紧缚索引有没有问题”
- “概念命名对不对 / 情节 Tag 有没有挂错”
- “重建受影响索引”

## 入口命令

- `npm run knowledge:audit:sample|status`（四通道混合；其中 RAG 默认只抽知识卡）
- `npm run rag:audit:sample|record|status`（默认知识卡；`--include-sources` / `--asset-kind source|all` 才含源；无问题用 `--category confirmed-ok`）
- `npm run style-rag:audit:sample|record|status`
- `npm run concept:audit:sample|record|status`
- `npm run plot:audit:sample|record|status`
- `npm run rag|style-rag|concept|plot:audit:related`（列出应共查的关联项）
- `npm run rag|style-rag|concept|plot:rebuild:affected`
- `npm run external:knowledge:evidence:review`（核验证据是否支持某条知识陈述）

## 卡审与落盘

- 批次面向卡审：definition / 邻居 / 三问；图谱 RAG 详情「原文证据」可展开看段落与书名，不以通读原文为主审材料。
- 用户确认无问题：`--category confirmed-ok`，之后抽中概率降低但仍可被回归抽到。
- 用户给出「太抽象」等定性评价时：先协商修改方向与改稿计划，确认后再写卡/`record`；不得原样归档评语后结束。
- 写卡、改卡、向用户解释抽查结论前，先走 `liluo-natural-expression` light；说清用途与邻居差别，不用口号空话。

## 相邻边界

- 普通检索：`liluo-external-fiction-knowledge`
- 文风检索：`liluo-style-rag`
- 关联图谱发现入口：大纲 → 关联图谱
- 不替代评权流程 `writing:external:review:*`
- 不把细节概念/情节并入 RAG 主库
- **改一处必查关联并共改**：`*:audit:related` 列出邻居；有需要则与主条目一并调整
