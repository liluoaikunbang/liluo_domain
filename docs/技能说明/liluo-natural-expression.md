# liluo-natural-expression

- 正式路径：`.agents/skills/writing/liluo-natural-expression/`
- 用途：为非技术、面向读者的璃落文本改善节奏、声音、潜台词和自然度，同时保护事实锚点，并优先检查动作、物体反馈与空间关系是否可信。
- 默认触发：故事大纲叙事段落、小说、游戏对话、项目组对话、手记、玩家文案、公开开发叙事，试笔/测试写作/点名绑法草稿，以及紧缚 RAG 知识卡正文、Style-RAG 抽象说明、评权/抽查协商与改稿说明；默认 `light`。主智能体须先读本 Skill 再动笔。
- 操作：`compose`、`revise`、`diagnose`；强度：`off`、`light`、`deep`。交付前对命名绑法做名称↔姿态自检；正式入库可再委派内容审计 Agent。
- 排除：代码、数据合同、schema、路径、测试日志、权限规则、字段名/ID/命令、逐字引用与原样保存内容。
- 输入：已确认文本/材料、文本类型、用途、事实与状态锚点；deep 模式可追加风格档案。
- 输出：通过动作可信度门禁的自然表达稿、局部修订稿或带证据的诊断，不新增故事事实，也不为追求含蓄临时制造缺乏依据的操作技巧。
- 场景门禁：环境简洁但不能缺席；动作采用最小充分细节，普通的“抱住”“扶稳”已经清楚时不继续拆解，紧急场面只加一个短促修饰词提速；束缚状态直说；人物行为服从风险时机；转折和段尾不使用虚假逻辑或作者式评价。
- 意义门禁：不以没有回答者、调查路径或行动后果的设问制造神秘感；问题必须指向可查证对象、实际选择或具体待解事项。
- 过程场景：若“怎么绑”或“怎么完成”本身就是看点，写出起始固定、阶段顺序、可见路径、姿态变化与结果；允许宽泛结法、圈数和松紧变化，但不把每一步都写成参数齐全的现实教程。
- 术语门禁：固定绑法名称必须与关键姿态和动作骨架一致；先辨认目标绑法，再写过程，不能用另一种绑法的步骤代替。
- 修饰门禁：不为短促指令、对话附注或普通动作外挂与场景无关的抽象比喻（如“像在核对一门功课”）；比喻须来自人物经验与场景材料，否则改回直说语气、音量、停顿或具体动作。
- 用户校准：逐轮反馈中形成的可复用判断必须在同一任务同步到权威规范，不能只改当前文案；叙事性来源说明统一见系统文档中的“璃落的校准说明”。
- 资源：快速合同、8 类文本配置、6 份风格档案、来源谱系、路由/锚点脚本和评测 fixture。
- 束缚题材：项目角色统一按成年人处理，不再为年龄不明设置额外分支；实际创作或修订前按需求做低 token 检索路由——写法与场景机制查小说库，术语、命名姿态、世界构建或视觉标签查已导入的束缚研究包；只有两类需求都重要时才各查一次。
- 相邻边界：故事事实由 `liluo-story-outline-authoring` 等决定；连续性由 `liluo-world-bible-continuity-audit` 检查；外部题材检索与知识卡由 `liluo-external-fiction-knowledge` 负责；文风包与评权由 `liluo-style-rag` 负责——撰写/改写其阅读向文案时仍须先走本 Skill `light`。
- 验证：`node --test --test-isolation=none scripts/tests/natural-expression.test.mjs`，以及系统总体验证。

详细当前合同见 [璃落自然表达与文气塑形系统](../系统说明/璃落自然表达与文气塑形系统.md)。
