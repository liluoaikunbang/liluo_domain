# ADR-002：规范与设计记忆分层治理

## 当前结论

长期规则、当前系统说明、用户入口、历史更新和设计理由分层保存；以轻量门禁判断是否沉淀，以有限注册表追踪跨文档消费者。

## 背景与决策

项目已有大量文档、Skills、Agents 和命令。只靠聊天记忆容易漏同步，复制完整规则又会产生膨胀与冲突。因此新增按需治理 Skill、只读策展 Agent、设计记忆和确定性校验，但不把全部历史文档注册成第二套数据库。

## 核心理由与替代方案

分层治理能保留“现在怎么做”和“为什么这样做”，同时维持单一事实源。未采用每次任务全量审计，也未采用为每条语句编号或批量重写旧文档，因为维护与 token 成本会超过收益。

## 影响与重新评估

长期或用户可调用行为变化需执行完成门禁；普通局部任务不触发完整流程。当注册表维护成本持续高于漏同步成本，或现有索引原生覆盖权威关系时重新评估。
