# ADR-015：旧页面参考迁移与按需索引入口

## 当前结论

旧页面式游戏继续保留为可运行的参考 legacy，不作为近期迁移目标，也不得因新 Phaser RPG 迭代而被默认删除。新功能仍以地图探索、事件和 Phaser 运行时为主轴；只有在具体功能需要时，才从旧页面迁移可复用内容。

项目索引是生成的查询层：跨文件任务先执行领域查询，再打开命中的原始权威文件。完整 `project-index/INDEX.md` 不再作为默认上下文。

## 理由与代价

- 保留 legacy 避免丢失仍可访问的内容与实现参考；代价是短期内存在双入口，迁移任务必须显式标注来源、目标和验收范围。
- 查询优先保留索引的定位价值，同时避免把大型索引注入普通任务上下文；代价是需要多一次确定性查询。

## 重新评估条件

- 用户确认旧页面的某个区域不再需要运行或参考时，才可单独制定迁移或退役计划。
- 索引查询无法稳定定位跨域权威来源时，可调整查询体验，但不得恢复默认整份索引装载。
