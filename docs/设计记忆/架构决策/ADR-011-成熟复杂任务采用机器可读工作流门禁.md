# ADR-011：成熟复杂任务采用机器可读工作流门禁

## 当前结论

成熟、可重复、高风险或多 Skill/子智能体任务，以 `project-workflows/definitions/*.json` 为唯一过程真源；运行记录分离存放；必需资源默认 fail-closed，并分开验证“已调用”与“结果已被主流程采用”。一次性小修与开放探索不强制流程化。复用现有 `skill-*` / `agent-*` / `command-*` ID 与能力导航投影，不平行注册能力系统。

## 背景与理由

项目已有大量 Skill、子智能体与导航摘要工作流，但长任务仍易漏调用、漏采用独立审查结果，且流程说明、流程图与实际执行缺少统一数据源。自然语言规则不足以阻止跳步；需要确定性脚本门禁，同时保留平台无法自动委派时的人工回填路径。

## 主要替代方案与代价

- 继续只靠自然语言 AGENTS/Skill 约束：实现成本低，但不同模型执行差异大，放弃作为成熟流程的唯一手段。
- 另建平行 BPM/工作流平台：过重，且与现有导航、Skill、质量门禁重复，放弃。
- 把所有任务都流程化：会让小修与探索过度僵化，明确排除。

## 影响范围

- 新增 `project-workflows/`、`schemas/workflows/`、`liluo-executable-workflow` 与 `project:workflow:*`
- 能力导航扫描合并可执行工作流投影
- `project:routine -- workflow` 与 changed quality gate 接入校验/测试
