# ADR-005：命令授权采用项目规则与决定注册分层治理

## 当前结论

璃落项目将 `.codex/rules/*.rules` 作为项目内命令执行规则权威，以 `.codex/approval-decisions.json` 追踪脱敏长期决定，以生成文档提供人类摘要。单次与会话授权不持久化；项目工具不自动修改或删除用户级规则，也不宣称能够覆盖平台沙箱或管理员要求。

## 背景与理由

只依赖聊天记忆会反复询问相同低风险命令；把 TUI “始终允许”一律留在用户级又可能把项目专用前缀扩大到其他仓库。项目化规则让稳定命令可审查、测试和版本化，决定注册表则保留来源、状态、撤销与 supersede，而不把文档变成第二套执行规则。

未采用宽泛解释器 allow、自动迁移/删除用户级规则或 Full Access。前者允许任意代码执行，后两者扩大授权范围并可能与客户端、管理员或其他项目的真实意图冲突。

## 代价与重新评估

Codex 当前规则是字面前缀匹配，不能表达命令终止或完整 PowerShell 语义，因此必须使用具体脚本、为已知危险参数增加更严格规则，并通过正反样例验证。不同 Codex 客户端对项目规则的自动加载与沙箱豁免可能不同；若官方提供稳定的项目级加载、精确参数谓词或独立 sandbox placement 策略，可重新评估实现，但不取消最小权限、作用域明确和不自动改用户规则的边界。

## 2026-07-23 收口

真实审批回放证明“为每个测试文件和解释器命令单独建 allow”既脆弱又无法解决子进程沙箱。项目改为允许两个受测试的稳定 npm 入口：`project:routine` 只分派固定检查、测试、构建和索引动作，`project:skill:init` 只包装官方 Skill 脚手架并限制名称、区域与资源。当前客户端另保存同样的精确前缀，用于弥合项目 execpolicy 与平台沙箱加载之间的差异；不建立宽泛解释器授权。
