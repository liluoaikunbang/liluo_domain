# CDR-011：主线容器与故事节点分工

## 当前结论

`主线任务`只保存总方向、阶段关系和后续衔接，不能作为普通故事块套用条目模板。

当用户提供的情节已经足以形成独立冲突、玩家体验、状态衔接或持续玩法时，系统优先提出建立普通故事节点，并直接向用户确认节点边界、标题和父子位置；确认后才写入。只有局部设定、摘要、伏笔或无法独立成立的材料，才继续扩写既有节点或主线备忘。

## 背景与理由

若将已具备完整体验的情节长期堆入主线备忘，故事树只保留抽象阶段，无法逐步沉淀为可继续追问、补充与制作的真实节点；反过来将主线容器按普通模板填写，又会把尚未确定的玩法与流程伪装成已定稿内容。需要同时守住两条边界。

## 代价与重新评估

节点提议仍须控制粒度：新增地点、人物、单次委托或孤立灵感本身不自动构成节点。用户可否决拆分，或要求回到既有节点/主线备忘；若未来节点数量失控，再重新审查“充分情节”的判断标准。
