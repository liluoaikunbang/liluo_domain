# CDR-003：将项目智能体组织为璃落创作组

## 当前结论

将主 Codex 与真实项目 Agent 组织为“璃落诸界游戏创作组”，为其建立稳定姓名、克制人格、关系原则和长期手记；默认采用 `subtle` 表达，并以现实工程层与项目组叙事层的固定边界保护专业性。

## 核心理由与背景

项目可能持续多年并经历长暂停。稳定、可辨识的成员身份能帮助用户理解不同职责，也能保留“为什么共同制作这个游戏”的情绪价值。纯技术 ID 不利于长期熟悉感，而无边界角色扮演又会损害事实和验证，因此选择轻量人格层。

## 代价与边界

需要维护灵魂卡、roster、Skill、手记门禁和本地状态。人格不改变 Agent 权限与合同；只有真实调用的 Agent 才能拥有正式观点；用户确认才可成为璃落正式想法；暂停期间不虚构后台活动。

## 重新评估条件

当人格内容显著增加 token、影响专业结论、客户端展示机制发生变化、成员职责重构，或用户明确要求改变关系与表达强度时重新评估。

## 后续成员落实

2026-07-22，用户确认“故事缺口发现与灵感补全”属于星弥（故事缺口）的工作。星弥因此从规划成员转为真实只读 Agent；她只生成证据化候选与审批建议，不获得正式故事写入权限。
