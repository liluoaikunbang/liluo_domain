# 璃落创作组雕龙文号体系

本目录是创作组文号来源、标准写法、分配与状态的权威来源。成员完整署名采用“姓名｜雕龙文号｜职司”；日常 `subtle` 模式通常只称姓名，正式展示或 `immersive` 模式可使用三层署名。`team-roster.json` 保存当前成员映射，`source-registry.json` 保存机器可读来源，`diaolong-name-pool.json` 保存五十篇篇名及占用状态。

## 来源核验与书目信息

- 书名：《文心雕龙》；作者：刘勰。
- 时代：刘勰为南朝齐梁之际的文学理论家，作品通常归入南朝梁。
- 性质：系统讨论文学创作、文体与批评的古典文论著作；全书五十篇。
- 核验日期：2026-07-22。
- 篇次底本：以中国哲学书电子化计划所列《四部丛刊初编》本及其图文对照目录为篇次核验基础，并以北京大学图书馆、浙江图书馆的机构资料核验作者、时代、性质与篇数。
- 项目写法：采用现代简体规范字，如“熔裁”“序志”；机器池用 `variantForms` 记录常见繁体或异体写法，如“鎔裁”“序誌”。不同传本、校注本与字符转换可能形成字形差异，未来分配时仍须回查底本。

来源链接见 [source-registry.json](./source-registry.json)。原典属于古典公版文本；项目不收录现代校注、白话译文或论文的大段内容，只保存书目信息、篇名、必要的简短概述和项目自行撰写的适配说明。

## 为什么选择《文心雕龙》

璃落创作组同时处理构思、材料溯源、世界连续性、系统组织、内容审查、运行验证、外部参考、缺口发现与设计记忆。这些职责不是互不相干的工具列表，而是同一完整创作过程的不同环节。《文心雕龙》的五十篇覆盖创作根基、文体、构思、组织、表达、材料、批评与作者修养，篇名风格统一且数量足以支持谨慎扩展，因此适合作为长期文号来源，也契合璃落宇宙的文学表达、多世界探索与游戏制作气质。

## 分配与状态规则

1. 先确认 Agent 具有独立、长期且不与现有成员重复的职责；一次临时任务不能产生文号。
2. 从 `available` 篇名中筛选，回查原篇主题与标准写法，区分原典关联和项目适配。
3. 检查与现有文号的语义距离，提出候选与影响范围，等待用户批准后才更新 roster、篇名池、灵魂卡、真实 Agent 配置、说明、治理记录与索引。
4. 不为占用好听篇名而创建 Agent；不自动把全部篇名预分配给未来成员。
5. 状态为 `available`（未分配）、`reserved`（计划成员预留）、`active`（正式成员使用）、`historical`（曾使用）、`retired`（保留历史且不再使用）、`unsuitable`（当前语境不适合）。一个 active 文号只能对应一个 active 成员，历史或退役文号不得立即重用。

## 字段迁移与公开展示

roster schema 2 使用 `name`、`literaryName`、`dutyTitle` 与 `literaryNameSource`。旧 `penName` 曾混合承担人格笔名和职责称号，现已移除：原“寻迹、经纬、机枢”等转为 `dutyTitle`；原主身份“旅记”被新的三层模型替代为“璃落｜神思｜总枢”。消费者不得重新赋予 `penName` 第二种含义。

GitHub 读者可以从这里理解每个名称的来源、成员在完整创作流程中的位置，以及古典文论如何与现代游戏开发和 Agent 协作相接。文号不改变 Agent 权限、事实标准、测试结果或用户审批权。
