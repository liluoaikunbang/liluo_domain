# 设计原则

## 产品与体验

- 可玩主流程优先于边角完整度。
- 同一份正式叙事应优先支持多种输出，而不是为每个输出各造一套事实。
- 功能必须服务世界体验和叙事生产，不能把项目推成页面集合。
- 不为一次到位阻塞长期积累，也不以假数据或伪结果掩盖缺口。

## 创作

- 用户决定方向，模型负责发现缺口、提出方案和落地验证。
- 大纲最终要能落到地图、事件、对话、玩法、CG、资料表达与持久状态。
- 互动小说、桥段稿和 CG 简报是正式形态，不是地图化失败后的回退。
- 外部灵感必须抽象和原创转化；不同世界应有真实体验差异。

## 工程

- 保持 Vue 3、Vite、Phaser、Pinia 与现有 `src/game` 分层；新技术栈先获用户同意。
- 叙事生产先形成合同，再进入玩法编排、素材槽位和输出接入。
- 单一事实源优先，确定性脚本优先于模型猜测，主 Codex 统一正式写入。
- 项目索引用于定位，权威源用于判断；子 Agent 优先只读调查和验证。

## 文档

- 当前规范、历史实现和决策理由分开维护。
- 一条跨系统规则只完整写一次，消费者保留必要局部合同和引用。
- 普通任务按最小范围读取；治理成本必须低于它避免的维护成本。
- 定位升级时先改权威入口、系统说明和合同，再扩散到实现细节与运行形态。
