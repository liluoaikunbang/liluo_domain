# 璃落的城堡文档入口

这里是项目文档的统一入口。

这个项目首先是一个长期生长的像素风冒险 RPG。文档也按这个目标来整理：一部分记录历史，一部分说明当前应该怎么理解和维护系统。

## 推荐阅读顺序

1. 先看 [项目概览](./项目概览.md)，了解项目目标、技术栈、运行命令和当前目录职责。
2. 不确定该如何向 Codex 下达任务时，看 [用户命令目录](./用户命令目录.md)。
3. 需要查当前系统设计时，看 [系统说明](./系统说明/README.md)。
4. 需要选择项目 Skill 或 Agent 时，看 [技能说明](./技能说明/) 和 [智能体说明](./智能体说明/项目子智能体体系.md)。
5. 需要了解重要设计为什么这样决定时，看 [设计记忆](./设计记忆/README.md)；追溯某次实现时再看 [功能更新目录](./功能更新目录.md)。
6. 需要维护长期规范或检查文档影响时，看 [规范治理](./规范治理/README.md)。
7. 涉及 `src/assets/game` 下图片素材时，看 [游戏素材图片清单](./游戏素材图片清单.md)。

## 维护规则

- 新功能完成并经过用户实际测试确认无报错后，继续在 `docs/功能更新/` 新增下一编号文档。
- 如果改动影响了某个长期系统的当前用法，同时更新 `docs/系统说明/` 下对应文档。
- 如果新增了 `src/assets/game` 下的图片素材，同时更新 `docs/游戏素材图片清单.md`。
- 新增固定用户指令、Skill 或长期脚本命令时，同时更新 `docs/用户命令目录.md`。
- 新增长期规则或重要设计决策时，使用 `liluo-project-governance-memory` 更新唯一权威源、必要消费者和设计记忆。
- 根 `README.md` 只维护项目总入口和最高频命令，详细文档继续收口到本目录。
